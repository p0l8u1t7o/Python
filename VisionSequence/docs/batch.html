批次測試：影像集、暫存的逐張結果、資料洞察與調參

「批次測試」頁（側欄 /batch）讓您選一條流程，用一組影像批量執行，每次執行的逐張結果都暫存下來：為影像標記期望 OK／NG 即得命中率與混淆矩陣，洞察卡會沿判定節點的輸入值算出建議門檻；在同一頁改參數重新執行同一影像集比較前後，滿意後寫回流程、存為配方或帶回編輯器；也可請 AI 助手依這批資料諮詢或調整，結果同樣成為新的一次執行。編輯器頂列的「批次測試」會開啟此頁並預選流程（有未儲存草稿時可勾「使用編輯器未儲存的草稿」）。

1. 概念：影像集與執行

  • 影像集（BatchSet）：一組批量測試用的影像（上傳或從影像來源擷取，一個影像集最多 VISION_BATCH_MAX_IMAGES＝200 張），檔案存在伺服器；期望標記（OK／NG）屬於影像，同一組影像重複執行時保留。flow 只是建立時的歸屬（淘汰也按它計）——影像集是測試資料，可以拿去測任何看得見的流程。
  • 批次執行（BatchRun）：用某份 graph 快照把影像集跑一遍；逐張結果（狀態、耗時、具名輸出、各節點狀態與純量輸出、錯誤）與 summary 一起暫存。執行可標 parent（由哪一次調參而來），來源 origin＝manual／draft／autotune／ai_tune。flow 記錄這次用哪個流程測（與影像集的流程不同時前端標出流程名稱），空＝影像集的流程。
  • 與 Golden Set 的分工：Golden Set 是正式回歸基準（少量、期望值精確、進 CI）；批次測試是調機工作台（多量、可反覆重跑、資料會淘汰）。批次頁勾選影像可一鍵「存入 Golden Set」。

2. 操作流程

  1. 「新增影像集」：上傳影像檔，或從影像來源擷取 N 張（影像集清單跨流程，目前測試流程的排前面）。
  2. 頂列「測試流程」＝要用哪個流程測（從編輯器「批次測試」帶入，或選影像集時自動帶成它建立時的流程）。同一組影像可以換流程再測一次，兩次執行都掛在同一個影像集，能直接比較。
  3. 「以「流程名稱」執行」：背景執行、執行紀錄顯示進度，可中斷；用別的流程測的執行會標出流程名稱。
  4. 「影像集」分頁為每張影像標記期望 OK／NG（或全部 OK／NG）；「結果」分頁的期望欄也可改。命中率、混淆矩陣立即更新。
  5. 「洞察」分頁：未命中影像、出錯節點、判定門檻建議、具名輸出分佈（依期望分兩色）、歷次執行趨勢；「套用建議並重新執行」直接產生新的一次執行。
  6. 「調參」分頁：現場調機參數（teach）分組編輯 → 「重新執行」（新執行的 parent＝目前選取的執行）→ 「比較」分頁逐張對照。
  7. 右下角的全域 AI 助手（脈絡＝批次測試頁，選定已完成的執行後）：提問（諮詢）、依資料調整；調參面板的「自動調參」；結果都成為新的一次執行。
  8. 滿意後「寫回流程」（擁有者／管理員）、「存為配方」（參數差異 → FlowRecipe）或「帶回編輯器」（成為草稿）。

4. 執行方式（apps/vision/batch/jobs.py）

  • 背景執行緒（同時最多 VISION_BATCH_MAX_RUNNING＝2 個、同一影像集只能一個），runner.compiled_for(flow, graph_override=graph) 只編譯一次（來源／資產在呼叫者執行緒預先開好），每張直接 engine.execute(...)。
  • 不走 runner 佇列：不累計流程統計、不發 SSE、不寫 FlowRun、不隱含套預設配方（配方改為建立執行時明確指定 recipe_id）；影像進獨立快取桶 BATCH_FLOW_ID=-1 並在每張跑完立即 store.drop_run，200 張批次不會把編輯器的試執行影像擠出快取。
  • 每 10 張或 2 秒把進度與已完成列 update() 回 DB；前端每秒輪詢；「中斷」設旗標，執行到目前那張為止，狀態 cancelled。
  • 伺服器重啟時殘留的 running 執行，讀取時自動標成 failed（「伺服器重新啟動，執行中斷」）。
  • autotune 模式：先用影像集的標記做座標下降（未命中的影像優先抽樣、最多 40 張；不動公差／期望數量／範圍這類規格），再用調好的 graph 全量重跑，meta.autotune 記錄前後命中與變更。

5. 資料洞察與建議門檻（apps/vision/batch/insights.py）

  • 命中率、混淆矩陣（期望 NG 為 positive：tp 抓到、fn 漏檢、fp 誤判、tn 正確）、未命中清單（≤20）、出錯節點次數與訊息、最慢影像與最耗時節點、具名數值輸出依期望／實際分組的統計。
  • 建議門檻：走訪 if_number／in_range／tolerance_judge 節點，沿 value 輸入邊找上游 (節點, 埠)，從逐張的節點純量輸出取值，依期望分成 OK／NG 兩群：
    • if_number（gt／ge／lt／le）：由分支接到的 judge 判定方向（true→OK 或 true→NG），在相鄰值中點掃描命中率最高的門檻，嚴格高於目前才建議。
    • in_range：只移動有 NG 值的那一側邊界到 NG 與 OK 的中點；另一側維持現值。
    • tolerance_judge：只列偏差分佈，不建議（公差是規格）。
  • 有 parent 時另算與上一次的差異（判定改變、改善、退步、參數變動）。text[] 是繁中條列句，離線諮詢與 LLM 上下文共用；GET /batch/runs/{id}/insights 另回 suggestions[]（可直接套用的 {node, key, value}）。

6. 調參、寫回、配方、Golden Set

  • 調參面板的工作圖取自目前選取執行的 graph（或勾選的編輯器草稿）；只列 teach=True 的參數（與參數卡頁同一套 teachGroupsOf），有變更的參數左側有藍線。
  • 「重新執行」＝ POST /batch/sets/{id}/runs {graph, parent_run_id}；「寫回流程」＝ PATCH /flows/{id}（版本 +1）；「存為配方」＝ 工作圖與流程現圖的參數差 → POST /flows/{id}/recipes；伺服端另有 POST /batch/runs/{id}/to-recipe 直接由某次執行的 graph 建配方。
  • 「存入 Golden Set」直接複製影像檔建立案例（期望取自標記或指定執行的判定），不經影像快取，不會「影像已釋放」。

7. AI 諮詢與調整（apps/vision/agent/consult.py）

  • 諮詢 POST /agent/consult {batch_run_id, question, graph?}：一律先算規則洞察；LLM 可用時把流程 graph、洞察條列、逐張資料（未命中優先、≤50 列，含判定節點的輸入值）與最多 4 張未命中影像交給模型，回答尾端可附 SUGGESTIONS: {"suggestions":[{node,key,value,reason}]}，伺服器驗證節點／參數存在且流程仍有效才回前端；離線或失敗時以洞察條列組成回答（依問題關鍵詞挑段落），suggestions 來自建議門檻。
  • 請 AI 調整：POST /agent/tune／代理模式 POST /agent/jobs(task=tune) 帶 batch_run_id：影像從磁碟載入、逐張資料與洞察併進批次摘要，調整後的流程在同一影像集重跑，結果直接落成新的一次執行（origin=ai_tune、parent=原執行），回應含 batch_run_id。離線時指令對不上規則而有標記 ≥2 張，改走資料驅動自動調參。
  • 自動調參：批次頁用 POST /batch/sets/{id}/runs {mode:"autotune"}（背景、可中斷）；POST /agent/autotune 也接受 batch_run_id。

9. 保留策略與設定（.env）

變數預設說明
VISION_BATCH_MAX_IMAGES200一個影像集最多幾張
VISION_KEEP_BATCH_SETS10每條流程保留最近幾個影像集（超過自動刪最舊，含檔案；有執行中的不刪）
VISION_KEEP_BATCH_RUNS20每個影像集保留最近幾次已結束的執行
VISION_BATCH_MAX_RUNNING2同時執行的批次數
磁碟：影像以 PNG 原樣保存（不縮圖，否則會改變檢測結果），200 張相機原圖可能達數百 MB；影像集卡片顯示大小，超過保留數會自動清除，也可手動刪除。
