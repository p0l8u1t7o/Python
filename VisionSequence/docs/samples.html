Example templates and their synthetic sample images

The example templates live in the template gallery — "Create from template" on the flows page, "Load template" in the editor toolbar, 34 built-in templates in all — so they do not clutter the flow list. manage.py seed_demo (or dev.ps1 -Setup) creates everything that goes with them: two demonstration flows, one set of synthetic sample pictures for every template, stored as fixed images that travel with the template, the reference pictures (locator templates, the golden print, the white reference) as fixed images wired into the tools' picture inputs, and the statistical template, shape model and taught-model assets. Create a flow from a template and leave the source alone — every template starts with a Fixed image step holding its own sample pictures, so it runs as it is — the acquire step becomes a Fixed image step that cycles through the samples (the fourth is usually the deliberate reject). 82 of the 132 built-in tools appear in at least one template, so opening any of them shows you how that tool is actually wired up and what its parameters look like in practice.

Each set has four images (three for the tutorial), and the last one is deliberately a reject. The source loops, so running continuously — or pressing Run repeatedly — gives you OK → OK → OK → NG. Coordinates and tolerances match the nominal values of the synthetic images, so nothing needs tuning before it works.

Where the images and assets live

  • Sample images: data/samples/<set>/01.png…, generated by apps/vision/demo_images.py. If the folder already holds PNGs they are reused. To regenerate, delete the folder and run manage.py seed_demo again.
  • Fixed images: every sample picture and reference picture is stored once under ASSET_DIR/fixed/<sha>.png (content-addressed, so re-seeding never duplicates) and referenced from the template graphs; instantiate turns the {SOURCE} acquire step into a fixed_image step holding the set. No folder sources or image assets are created any more (an older seed's "Example: …" folder sources and picture assets are removed when nothing refers to them).
  • Assets: the statistical template (an .npz file asset) built from 30 jittered good prints, the bracket shape model built from the first shape-match picture, and the taught models, in the "Examples" group. The two locator templates, the golden print and the stamped-part outline are cropped from the first sample picture into fixed images, and the white reference for the flat-field template is a fixed image too.
  • seed_demo is safe to run repeatedly: existing sources and assets are reused, and flow graphs are updated to the current version.

Tools that no template uses

Deep learning: ai_pose (needs images of people), ai_obb (needs training or DOTA-style images), and ai_classify, dl_instance and dl_detect (wired up exactly like their counterparts that are covered). dl_classify, dl_detect, dl_segment and dl_instance all need a model asset trained on the deep-learning teaching page first. write_modbus and read_modbus need a real Modbus connection, python_script holds code you write yourself, and save_image writes a file on every run, which does not belong in a looping example. See each tool's own description, plus Deep-learning teaching and Modbus.

How this stays true

Deep-learning templates: tests/test_demo.py actually runs both taught-model templates (seeding trains them in a few seconds on CPU). The three stock-model wiring templates need the deep-learning dependencies, so only their graphs are checked there; they are really run by VISION_TEST_DL=1 manage.py test tests.test_dl_live, where five sign samples come out OK, OK, OK, NG, NG.

tests/test_demo.py seeds the whole example set into a temporary environment on every test run and executes each built-in template against its matching sample source, which pins down the line "every template runs, with no node in error". Break a template or a tool and it goes red immediately.
