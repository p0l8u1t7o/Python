Golden Set 回歸測試、流程匯出／匯入與 CLI

對應 visionsequence-plan-v0.2.md §3.2、§3.3。目標：改一個閾值，幾分鐘內知道哪幾張影像從 PASS 變 FAIL；流程能進 git、能 code review、能在 CI 跑。DB 仍是執行期的權威來源。

1. 概念

  • Golden case：一張影像＋期望結果（expect_status：ok／ng／any，與可選的 expect_outputs）。影像落地在 ASSET_DIR/golden/<flow_id>/<uuid>.png，不進 ImageStore；回歸時直接從路徑讀。
  • 回歸（regress）：把該流程所有 golden case 用非 preview 模式跑一遍（不保留中間影像，幾百張也不會爆記憶體），逐張跟期望值比對得到 match／mismatch，並與上次基準比較得出 regressed／improved。只對 mismatch 的 case 再跑一次 preview 取影像 ref（上限 20 張）供前端檢視。
  • 基準（baseline）：某個流程版本跑回歸時每個 case 的結果快照（{case_id: {status, outputs, duration_ms}}）。save_baseline 就新增一列，取最新的當比較對象。

2. 資料模型（apps/golden/models.py）

模型欄位說明
GoldenCaseid、flow FK、name、image_path、expect_status(ok|ng|any)、expect_outputs JSON、note、created_at刪除 case 時一併刪影像檔；流程刪除時 CASCADE（檔案留在磁碟，可手動清 golden/<flow_id>）。
GoldenBaselineflow FK、flow_version、results JSON、created_at每次 save_baseline 新增一列；GoldenBaseline.latest_for(flow_id) 取最新。

3. 期望值與比對規則

一個 case match 的條件：

  1. expect_status 是 ok 或 ng 時，run 的 status 必須相同（failed 永遠不算 match）；any 不比對狀態。
  2. expect_outputs 每個 key 都要在 run 的具名輸出（output 工具）裡出現且相符：
{"hole_count": 5,                          // 等值：數值以 float 比較；字串、bool、list 直接相等
 "width_mm":  {"value": 12.4, "tol": 0.2},  // 數值容差：|now - 12.4| <= 0.2
 "code":      {"value": "A123"}}            // 只有 value 也可

混淆矩陣以 expect_status 為真值，ng 是正例；預測「不是 ok」（ng 或 failed）算正例。expect_status=any 的 case 不計入。

預測 ng／failed預測 ok
期望 ngtpfn（漏檢，最嚴重）
期望 okfp（誤殺）tn

4. Golden Set API

權限沿用流程規則：可見即可看／跑（_visible_flows），擁有者或管理員才可增刪改與儲存基準（_editable_flow），執行前 principal.can_execute()（引擎鎖定時 423）。

方法／路徑說明
GET /api/vision/flows/{id}/golden{items:[{id, name, expect_status, expect_outputs, note, created_at, image_url}], total, can_manage, baseline_version, baseline_at, flow_version}
POST /api/vision/flows/{id}/golden（multipart）images[]（≤200 張）＋ 可選 form expect_status、note、expect_outputs（JSON 字串）；每張一個 case，name = 檔名。回 201 {items, created}。
POST /api/vision/flows/{id}/golden（JSON）{"from_batch": [{"image_ref", "name", "expect_status", "expect_outputs", "note"}]}：從批次測試回傳的 image_ref（仍在影像快取內）建立；任何一個 ref 已不在快取 → 404 image_gone，整批不建。
GET /api/vision/flows/{id}/golden/baseline{baseline: {id, flow_version, results, created_at, case_count} | null, flow_version, case_count}
GET /api/vision/flows/{id}/golden/{case_id}/image?max=&fmt=&q=縮圖／原圖（jpeg 或 png）。給 <img> 用，接受 ?token=／?api_key=。
PATCH /api/vision/flows/{id}/golden/{case_id}{name?, expect_status?, expect_outputs?, note?}
DELETE /api/vision/flows/{id}/golden/{case_id}204；刪影像檔。
POST /api/vision/flows/{id}/regress{graph?, save_baseline?, fail_under?} → 回歸報告（下節）。graph 可帶編輯器裡未存檔的圖（同 preview）；fail_under 0～1，只影響 passed。

5. 回歸報告

{
  "flow_id": 1, "flow_name": "hole_count", "flow_version": 7, "graph_override": false,
  "total": 320, "match": 316, "mismatch": 4, "match_rate": 0.9875,
  "regressed": [{"case_id": 42, "name": "0042.png", "was": "ok", "now": "ng", "node": "ng-judge", "error": "", "reasons": ["status ng != ok"]}],
  "improved":  [{"case_id": 7,  "name": "0007.png", "was": "ng", "now": "ok", "node": null, "error": ""}],
  "confusion": {"tp": 118, "fp": 2, "tn": 198, "fn": 2},
  "cases": [{"case_id": 42, "name": "0042.png", "expect": "ok", "expect_outputs": {},
             "status": "ng", "outputs": {"hole_count": 4}, "duration_ms": 12.3,
             "match": false, "reasons": ["status ng != ok"],
             "was": "ok", "was_match": true, "changed_since_baseline": true,
             "node": "ng-judge", "error": "", "image_ref": "<run>:src:image", "preview_run_id": "..."}],
  "duration_ms": 4210, "baseline_version": 6, "baseline_at": "...",
  "fail_under": 0.98, "passed": true, "baseline_saved": false
}
  • regressed：基準結果符合期望、這次不符合。improved：反過來。兩者都以目前的期望值評估基準結果，所以改了 case 的期望值不會誤報 regressed。
  • node：出錯節點（status error）或第一個判 ng 的節點；error 是該節點訊息。
  • changed_since_baseline：status 或 outputs 與基準不同；沒有基準時為 null。
  • image_ref 只有 mismatch 的 case 才有（上限 20），用 GET /api/vision/images/{ref} 取；golden 影像本身永遠可用 image_url。
  • 回歸的 run 以 trigger="regress" 進統計與 FlowRun（受 PERSIST_RUNS 控制）；preview 補跑不入庫。

自動調參

Golden Set 頁的「自動調參」（POST /flows/{id}/golden/autotune，body {graph?, max_evals?, deadline_s?}）用全部案例的期望狀態與期望輸出當標記，對流程（或未儲存的草稿 graph）做座標下降搜尋現場調機參數（teach=True；不動公差、範圍、期望數量），嚴格變好才採納；回 {graph, before:{match,total}, after, change_text[], evals, elapsed_ms, improved, budget_hit, cases, skipped[]}。不寫回流程：前端「帶回編輯器」把結果放進草稿，由使用者檢視後儲存。細節見 AI 助手 › 自動調參。

6. CLI：manage.py regress

manage.py regress <flow_id|name> [--fail-under 0.98] [--json] [--save-baseline] [--graph file.flow.json --source <id>]
退出碼意義
0match 率 ≥ 門檻（--fail-under 預設 1.0：任何 mismatch 都失敗）
1match 率低於門檻
3該流程沒有任何 golden case

文字輸出重點放 REGRESSED 清單（哪幾張從 PASS 變 FAIL、哪個節點），--json 則印完整報告。--graph 用匯出檔內的圖取代 DB 的圖，適合在 CI 驗證 PR 裡改過的流程檔。

7. 流程匯出格式（apps/vision/serialize.py）

{
  "schema_version": 1,
  "exported_at": "2026-08-28T06:00:00Z",
  "name": "hole_count",
  "description": "零件孔數檢測",
  "continuous_interval_ms": 0,
  "graph": {
    "nodes": [
      {
        "id": "blob",
        "type": "blob",
        "label": "孔 blob",
        "enabled": true,
        "params": {
          "max_area": 60000,
          "min_area": 300,
          "min_circularity": 0.6,
          "sort_by": "area"
        },
        "position": {
          "x": 1540,
          "y": 40
        }
      },
      {
        "id": "src",
        "type": "image_source",
        "label": "取像",
        "enabled": true,
        "params": {
          "source_id": "{SOURCE}"
        },
        "position": {
          "x": 40,
          "y": 40
        }
      }
    ],
    "edges": [
      {
        "id": "e-blob-count-cmp-value",
        "source": "blob",
        "source_handle": "count",
        "target": "cmp",
        "target_handle": "value"
      }
    ]
  }
}

為了讓 git diff 有意義，序列化是穩定的：

  • 頂層 key 固定順序；節點 key 順序 id, type, label, description, enabled, continue_on_error, color, params, position, width, height，其餘字母序；params 內容遞迴依 key 排序；邊 key 順序 id, source, source_handle, target, target_handle。
  • 節點依 id 排序、邊依 (source, target, source_handle, target_handle) 排序 → 畫布拖動、重新連線不產生 diff。
  • position（與 width/height）四捨五入到整數 → 微調位置不產生 diff。
  • image_source.source_id 換成 {SOURCE} 佔位符（複用範本庫 templatize），匯入時用 --source／source_id 換回；沒給則：新建的流程留空字串（仍可用送圖方式執行），更新既有流程時沿用原流程取像步驟的來源（同 id 優先，否則任一取像步驟的來源），不會把現場設好的來源清掉。
  • 先過 validate_graph，所以省略的 source_handle／target_handle 會被補齊後匯出。
  • 2 空格縮排、ensure_ascii=False、UTF-8 無 BOM、LF、檔尾一個換行。
  • exported_at 是真實匯出時間；要可重現（byte-identical）時設環境變數 SOURCE_DATE_EPOCH=<unix 秒>（reproducible-builds 慣例）。驗收測試 tests/test_flow_cli.py 以此驗證 export → import → export 兩次輸出完全相同。
匯入不改 graph JSON 格式，也不把 Flow.graph 搬出資料庫：檔案只是 DB 內容的穩定投影。

8. CLI：manage.py flow

manage.py flow export <id|name> -o flows/hole_count.flow.json     # 省略 -o 印到 stdout
manage.py flow import flows/hole_count.flow.json [--source 3] [--owner kevin]
manage.py flow run <id|name|file> [--source 3] [--images ./samples] [--json]
  • import 依 name upsert：存在則更新 graph／description／間隔並 version+1；不存在則建立（--owner 指定擁有者，未給為共用流程）。schema_version 不符、來源不存在、檔案不存在都以 CommandError 結束。
  • run 的第一個參數可以是 DB 裡的流程，也可以直接是 .flow.json 檔（不寫進 DB，用 graph_override 跑）。給 --images 資料夾就每張影像以 input_image 各跑一次（非 preview），逐張印 status ms 檔名 outputs；否則跑一次（用流程的來源取像）。--json 印 {flow, items[], total, ok, ng, failed}。有任何 failed（含無法解碼）退出碼 2。
  • run 的 trigger 是 cli，會進統計與 FlowRun。

9. 匯出／匯入 API（apps/vision/api_flowio.py）

方法／路徑說明
GET /api/vision/flows/{id}/export同格式 JSON 下載，Content-Disposition: attachment; filename="<name>.flow.json"；?download=0 不加下載檔頭。可見即可匯出。
POST /api/vision/flows/importJSON body：整份流程檔（可加 source_id）或 {"doc": {...}, "source_id": 3}；multipart：file ＋ form source_id。回 {flow, created}，新建 201、更新 200。更新既有流程需為擁有者或管理員（否則 404）；新建的擁有者是呼叫者。
路由順序：/flows/import 必須在 /flows/{flow_id} 之前註冊（ninja 的路徑參數不帶型別轉換），所以 config/api.py 把 flow-io 與 golden router 排在 vision router 前面。

10. 進 CI

# 1. 把流程檔匯入乾淨的測試 DB，並指到 CI 用的來源（或不給來源，靠 --images 送圖）
manage.py migrate
manage.py flow import flows/hole_count.flow.json
# 2. golden 影像另外以 API 建（或事先備份 ASSET_DIR/golden 與 DB）
# 3. 回歸；rate < 0.98 就讓 pipeline 失敗
manage.py regress hole_count --fail-under 0.98 --json > regress.json

PR 只改了 .flow.json 時，可以不匯入直接 manage.py regress hole_count --graph flows/hole_count.flow.json --source 3，用 PR 裡的圖對既有 golden set 跑。
