NI Vision 功能對照：ROI、影像格式、檢測工具

本頁對照 NI Vision for LabVIEW User Manual（371007B-01）的功能面，記錄平台的 ROI 工具種類與實作方式、多位深影像格式的處理設計，以及 NI 檢測工具在平台上的對應（含本輪新增與刻意不做的項目）。

本頁目錄

  • 1. ROI 工具種類與實作
  • 2. 影像格式（位深）設計
  • 3. 檢測工具對照表
  • 4. 刻意不做／外掛路徑

1. ROI 工具種類與實作

NI 的 ROI 工具面板（手冊 Table 3-1）對照。region 是自由 dict（tools/roi.py 檔頭是唯一格式定義），所有工具走同一組 helper：bounding_rect / mask_for / crop / region_overlay / region_center / transform_region；前端 ImageViewer 的 roiEditor.ts／geometry.ts 提供繪製、把手編輯、命中判定。

NI 工具平台 shape狀態實作重點
Rectanglerect原有8 向把手
Rotated Rectanglerotated_rect原有旋轉把手＋量測工具 crop(upright=True) 擺正
Ovalellipse（cx, cy, rx, ry, angle）本輪新增兩軸半徑把手＋旋轉把手；遮罩 cv2.ellipse、overlay 以 36 邊形近似
Pointpoint（x, y）本輪新增單像素遮罩；灰階統計工具的 light-meter point 對照
Lineline原有端點把手、Shift 15° 吸附
Broken Linepolyline（points）本輪新增不閉合折線：頂點拖曳／雙擊邊插點／右鍵刪點（沿用 polygon 編輯路徑）；線剖面工具用
Polygonpolygon原有頂點編輯；標記編輯器另有逐點繪製
Annulus（含起迄角）annulus（＋選填 a0/a1）扇形角度本輪新增內外半徑把手＋（有 a0/a1 時）兩顆角度把手；遮罩＝外圓扇形填滿再挖內圓
Freehand Region / Freehand Line—不做polygon／polyline 逐點已覆蓋用途；自由手繪對產線 ROI 重現性差

ROI 一律可經 region 輸入埠動態傳入（定位工具的跟隨 ROI），transform_region() 支援所有形狀的平移／旋轉。

2. 影像格式（位深）設計

NI 的影像型別：Grayscale U8／I16／SGL（浮點）、Complex、RGB U32、HSL U32、RGB U64。平台以 numpy dtype 對應（tools/imgfmt.py）：

NI 型別平台表示說明
Grayscale U8／RGB U32uint8（HxW 或 HxWx3 BGR）預設；所有工具都支援
Grayscale I16uint1616-bit PNG/TIFF 讀檔（IMREAD_UNCHANGED）原樣保留；I16 語意上偏移為無號
RGB U64uint16 ×3（BGR）每通道 16-bit
Grayscale SGLfloat32浮點 TIFF／FFT 與校正中間結果
HSL U32—（編碼方式）不需原生儲存：color_convert 取 H/S/L/V 通道處理、color_stats 輸出 HSV 統計
Complex—（工具內部）fft_filter 內部使用，不進資料流

中央接縫：工具以 Tool.accepts = ("u8",…) 宣告可吃的位深；ToolContext.image() 對宣告外的位深自動 normalize_u8（u16 右移 8＝線性可預期、浮點 min-max；產生新陣列不動輸入）——任何工具丟任何位深都不會炸。cv2 原生支援多位深的工具（crop／resize／blur／morphology／arithmetic／apply_mask／grayscale／rotate_flip／save_image／convert_depth／fft_filter／line_profile／warp_perspective）宣告放寬、原樣進出。顯示端 encode_image 本來就會把非 u8 正規化後編碼。要顯式控制轉換用「位深轉換」工具。

4. 刻意不做／外掛路徑

  • Geometric matching／Color pattern matching／Color location：演算法量體大且 template_match＋DL 工具（dl_detect/dl_instance）已覆蓋多數場景；需要時以外掛工具導入（擴充外掛）。
  • OCR／字元驗證、Instrument readers（meter/LCD）：現代做法是 DL——用深度學習頁教導或掛 OCR 外掛；text_presence 提供「有沒有字」的輕量檢查。
  • 非線性鏡頭畸變標定（error map／correction table）：需要標定板工作流；先以 warp_perspective（透視）＋calibration（比例）覆蓋，畸變標定留待外掛或後續版本。
  • Freehand ROI：見 §1。
  • Complex 影像型別：只在 fft_filter 內部存在，不作為埠型別（避免資料流複雜化）。
