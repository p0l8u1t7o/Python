# Inspection capabilities: ROIs, image formats, tools

Measured against what a mainstream machine-vision package offers: which ROI shapes the platform has and how they are implemented, how multiple bit depths are handled, and how each class of inspection maps onto a tool here — including what was added recently and what is deliberately left out.

## 1. ROI shapes and how they work {#roi}

The ROI palette covers the shapes the industry expects. A region is a free-form dict — the header of `tools/roi.py` is the only definition of the format — and every tool goes through the same helpers: `bounding_rect`, `mask_for`, `crop`, `region_overlay`, `region_center` and `transform_region`. On the front end, `roiEditor.ts` and `geometry.ts` handle drawing, handle editing and hit testing.

| Shape | Platform shape | Status | How it works |
|---|---|---|---|
| Rectangle | `rect` | original | Eight handles |
| Rotated rectangle | `rotated_rect` | original | A rotation handle; measurement tools straighten it with `crop(upright=True)` |
| Oval | `ellipse` (cx, cy, rx, ry, angle) | **added** | Two radius handles plus a rotation handle; the mask is a filled ellipse, the overlay a 36-sided approximation |
| Point | `point` (x, y) | **added** | A single-pixel mask, for spot readings with the grayscale statistics tool |
| Line | `line` | original | Endpoint handles, Shift snaps to 15° |
| Broken line | `polyline` (points) | **added** | An open polyline: drag a vertex, double-click an edge to insert, right-click to remove (the same editing path as polygon). Used by the line profile tool |
| Polygon | `polygon` | original | Vertex editing; the labelling editor also draws point by point |
| Annulus, optionally a sector | `annulus` plus optional `a0`/`a1` | sector angles **added** | Inner and outer radius handles, plus two angle handles when a0/a1 are set. The mask fills the outer sector then punches out the inner circle |
| Multiple regions and exclusion zones | `composite` (ops: union / subtract / intersect, nestable) | **added** | Not drawn on the canvas: `region_from_shape` steps each hold one drawn shape and `region_combine` builds the composite at run time, which then goes into any tool's region input. `mask_for` applies the ops in order, `bounding_rect` is the union of the added parts (a subtraction never widens it), the overlay is the real outline including the holes, and ROI follow moves every part. Every tool that goes through `crop()` / `mask_for()` honours it; rectangle-only measurement tools fall back to its bounding box |
| Freehand region or line | — | not done | Polygon and polyline already cover the use; freehand ROIs repeat badly on a production line |

Any ROI can also arrive through the `region` input port, and `transform_region()` translates and rotates every shape. Position correction rides on that: wire a locate offset into a step's `_transform` input and `ToolContext.roi()` moves the drawn region before the tool ever sees it, so crops, masks and marks stay in full-image coordinates and no tool needs to know.

**Surface defects on a textured face** (scratches, hairs, fine cracks) have their own filter, `surface_filter`: it averages along the mark and differentiates across it, at eight angles by default, and keeps the strongest answer, so a long thin mark stands out while the grain does not. It pairs with `fft_filter` — a frequency low pass is the right tool when the background repeats (a weave, a screen), this one when it does not (brushed, blasted, hairline). The cost is one convolution per angle: about 25 ms on 640×480 and 90 ms on 1280×960 for eight angles, so give it a region when the part is larger than the area you care about.

**A whole edge at once** is `edge_defect`: calipers are laid along a straight or round edge — the region drawn on the canvas, or better, the line or circle the previous step actually found — and every stretch that strays from that ideal edge comes back as a fault with a kind attached. A nick or a burr is a run that sits too far in or out, a chip is a run where the edge vanished altogether, a mismatch is a sudden step between neighbours, and in pair mode the width between the two edges is checked directly. Each fault carries its box, its length along the edge and its area, so a flow can judge on the worst one or on how many there are. It shares its baseline-and-segment logic with `profile_defect`, which is the right tool when the radius series itself is wanted for something else.

## 2. Image formats and bit depth {#depth}

The image types a machine-vision package deals with are grayscale U8, I16 and float, complex, RGB U32, HSL U32 and RGB U64. The platform maps them onto numpy dtypes (`tools/imgfmt.py`):

| Common type | Here | Notes |
|---|---|---|
| Grayscale U8 / RGB U32 | `uint8` (HxW or HxWx3 BGR) | The default; every tool supports it |
| Grayscale I16 | `uint16` | 16-bit PNG and TIFF are read and kept as they are; signed 16-bit is treated as unsigned with an offset |
| RGB U64 | `uint16` ×3 (BGR) | 16 bits per channel |
| Grayscale float | `float32` | Floating-point TIFF, FFT and calibration intermediates |
| HSL U32 | — (an encoding) | No native storage needed: `color_convert` pulls out H, S, L or V, and `color_stats` reports HSV statistics |
| Complex | — (inside a tool) | Used inside `fft_filter` only; it never travels along the graph |

**The seam that makes this safe**: a tool declares what it can take with `Tool.accepts = ("u8", …)`, and `ToolContext.image()` normalises anything else with `normalize_u8` — u16 shifted right by 8 (linear and predictable), floats min-max scaled — into a new array, never touching the input. **So no tool blows up on an unexpected depth.** Tools whose underlying algorithm handles more depths natively (crop, resize, blur, morphology, arithmetic, apply_mask, grayscale, rotate_flip, save_image, convert_depth, fft_filter, line_profile, warp_perspective) declare the wider set and pass the data through untouched. On the display side `encode_image` has always normalised before encoding. Use the bit-depth conversion tool when you want to control the conversion yourself.

## 3. What each capability maps to {#tools}

### Frame buffers and ROI write-back {#frame-buffers}

`frame_accumulate` keeps the current flow's recent frames in flow variables and emits a mean, minimum or maximum once the requested count is ready, or on every run for live tuning. Preview runs, `flow_id<=0` and explicit sandbox contexts write only to the variable overlay, so trial runs do not advance production accumulation. `previous_image` reads a named node output from the in-process image cache for the previous run, or an older run by `k`, and takes `not_found` when the cache no longer has it. `paste_back` closes the ROI loop: crop a region, process the small image, then place it back into the full image by region or `x`/`y`, replacing, blending or using a mask while clipping at image edges.

### Conveyor tracking {#conveyor-tracking}

A single-camera conveyor pick flow should connect `image_source` → `ai_segment` → `edge_filter` → `track_objects` → `format_text` → an output writer. The stereo-Z variant starts with `stereo_grab` and inserts `stereo_depth` before or after `track_objects`: before tracking measures every match, after tracking measures only `new_confirmed` matches that will be sent to the robot. `ai_segment` preserves its original match fields and adds per-instance `polygon`, `centroid` and `mask_area`; the centroid is measured from the largest connected mask component and falls back to the box centre when no mask is available. `edge_filter` checks top, bottom, left and right margins independently, where 0 disables a side. `track_objects` assigns the platform ID, keeps it monotonic across resets, marks an object as confirmed after `confirm_frames`, and emits `new_confirmed` only on that first confirmed frame.

## 4. Deliberately left out, or left to a plugin {#skip}

- **Colour pattern matching, colour location**: `shape_match` (geometric matching on edge directions) and `template_match` together with the deep-learning tools cover what they are used for; colour-specific matching can come in as a plugin tool when you need it ([Plugins](/docs/plugins.html)).
- **Instrument readers (meters, LCD digits)**: read the digits with `ocr_read` (a taught font for seven-segment displays) and convert the string in `formula`; a dedicated needle-gauge reader is plugin territory.
- **Full 3D hand-eye calibration** (camera pose on the robot arm): the [Hand-eye wizard](calibration.md#hand-eye) records a fixed or moving camera, fits a 2D pixel-to-robot affine mapping from actual point pairs and optionally finds the tool's centre of rotation. Solving the camera's full 3D pose from robot poses remains with the robot program or a plugin.
- **Freehand ROIs**: see §1.
- **The complex image type**: it exists only inside `fft_filter` and is not a port type, which keeps the dataflow simple.

## Barcode quality grading — what the parameters mean {#barcode-grading}

The `barcode_grade` step measures a symbol the way a verifier does and reports every parameter with its own grade (A = 4 down to F = 0). The overall grade is the **lowest** parameter grade for 2D symbols, and for linear symbols the average of ten scan lines (each scan line taking its lowest parameter). It reads 8-bit grey levels as reflectance and models the optical aperture as a disc filter, so the numbers match a verifier's magnitude; it is not a certified verifier, and no lighting or reflectance calibration is applied. The *Parameters* output lists every value, grade and a note, which is where a C is explained.

### 2D symbols — ISO/IEC 15415 (Data Matrix, QR) {#grading-2d}

| Parameter | What it measures | Typical cause when it drops | Grade thresholds |
|---|---|---|---|
| Decode | Whether the symbol decodes at all | Missing quiet zone, too many damaged modules, wrong symbology filter | A when decoded, F otherwise (nothing else is graded) |
| Symbol contrast | Brightest minus darkest reflectance across the symbol and its quiet zone (0–1) | Weak ink, glossy or dark substrate, under-exposure | ≥ 0.70 A, ≥ 0.55 B, ≥ 0.40 C, ≥ 0.20 D |
| Modulation | How far each module sits from the global threshold, relative to the contrast: 2·\|R − GT\| / SC for the worst module. Modules below a level count as damaged codewords, and the error-correction budget decides whether the level is still reached | Blur, noise, ink spread or voids, uneven lighting | Per module ≥ 0.50 A, ≥ 0.40 B, ≥ 0.30 C, ≥ 0.20 D; combined with unused error correction |
| Fixed pattern damage | The finder and clock patterns (Data Matrix: the solid L and the alternating clock track; QR: the three finders, timing, alignment and format information) and the quiet zone, compared with what they must be | Dirt on the edge of the symbol, print cut off, marks in the quiet zone | Damaged fraction 0 A, ≤ 9% B, ≤ 13% C, ≤ 17% D (finders by damaged module count 0/1/2/3; format information by bit errors) |
| Axial non-uniformity | Difference between the horizontal and vertical module pitch, relative to the mean | Camera not square to the part, stretched print, non-square pixels | ≤ 0.06 A, ≤ 0.08 B, ≤ 0.10 C, ≤ 0.12 D |
| Grid non-uniformity | Largest deviation of any module edge from the ideal grid, in module units, measured along every row and column | Warped label, perspective, jitter in a marking head | ≤ 0.38 A, ≤ 0.50 B, ≤ 0.63 C, ≤ 0.75 D |
| Unused error correction | The share of the error-correction capacity still unused after decoding (1.0 = no errors corrected) | Damaged, flipped or missing modules | ≥ 0.62 A, ≥ 0.50 B, ≥ 0.37 C, ≥ 0.25 D |

### Direct part marks — AIM DPM (ISO/IEC TR 29158) {#grading-dpm}

Marks on metal or plastic rarely reach the contrast a printed label has, so the DPM standard replaces two parameters and adds one, and allows a median pre-filter and a smaller aperture (50% of the module). Decode, fixed pattern damage, axial and grid non-uniformity and unused error correction are graded as above.

| Parameter | What it measures | Grade thresholds |
|---|---|---|
| Cell contrast | (mean of light cells − mean of dark cells) / mean of light cells — uses the cell means, not the extremes | ≥ 0.30 A, ≥ 0.25 B, ≥ 0.20 C, ≥ 0.15 D |
| Cell modulation | Each cell's distance from the threshold relative to the light or dark cell mean, with the same error-correction allowance as modulation | ≥ 0.50 A, ≥ 0.40 B, ≥ 0.30 C, ≥ 0.20 D |
| Minimum reflectance | Darkest point as a fraction of the brightest — an exposure check | ≥ 5% A, otherwise F (the image is under-exposed for DPM) |

### Linear symbols — ISO/IEC 15416 (EAN, UPC, Code 128, Code 39) {#grading-1d}

Ten scan lines are taken across the bar height (10% to 90%); each is graded on the parameters below and takes its lowest; the overall value is the mean of the ten (3.5 and above A, 2.5 B, 1.5 C, 0.5 D). Linear symbols always grade under 15416 whichever standard is selected.

| Parameter | What it measures | Grade thresholds |
|---|---|---|
| Decode | Whether the scan line decodes to the same content | A or F per scan |
| Symbol contrast | Rmax − Rmin along the scan | ≥ 0.70 A, ≥ 0.55 B, ≥ 0.40 C, ≥ 0.20 D |
| Minimum reflectance | The darkest bar must be at most half as bright as the brightest space | Rmin ≤ 0.5·Rmax A, otherwise F |
| Edge contrast | Smallest contrast between any adjacent bar and space | ≥ 0.15 A, otherwise F |
| Modulation | Edge contrast / symbol contrast | ≥ 0.70 A, ≥ 0.60 B, ≥ 0.50 C, ≥ 0.40 D |
| Defects | Largest spot in a space or void in a bar (element reflectance non-uniformity) / symbol contrast | ≤ 0.15 A, ≤ 0.20 B, ≤ 0.25 C, ≤ 0.30 D |
| Decodability | How close the bar and space widths are to their nominal multiples of the module (1 − 2·worst deviation) | ≥ 0.62 A, ≥ 0.50 B, ≥ 0.37 C, ≥ 0.25 D |

Set *Minimum grade* to what the customer specification demands (automotive and medical labels usually ask for C or better, sometimes B); the step passes when the overall grade is that or better. The reference grid for 2D symbols is refined from the symbol's own fixed patterns, so the grade does not depend on which decoder found the symbol.
