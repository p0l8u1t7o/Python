## 快速參考 {#quick-reference}

### 快速上手 {#quick-start}

1. **建流程** 到「流程」頁按「新增流程」，或複製示範流程。流程屬於產線而不是個人：每位工程師都能看到並修改，「擁有者」欄只記錄是誰建立的。
2. **取像** 從工具箱插入「影像來源」步驟，選影像來源庫裡的資料夾、合成或擷取端相機來源；或用頂列「上傳暫存影像」只為試執行放一張圖（不進來源庫）。相機由相機所在電腦上的擷取端程式驅動（影像來源庫「下載擷取端」）：連到伺服端後新增「擷取端相機」來源，選擷取端與通道即可。
3. **加工具** 把工具箱的工具拖到畫布（或點選插到最右邊），把上一步的輸出埠拉線接到下一步的輸入埠；同色的埠才能相接。
4. **ROI** 有「區域」參數的工具：在工具頁或側欄按「在影像上編輯」，直接在影像視窗拖曳畫出矩形／圓／多邊形等；座標是該步驟輸入影像的像素座標。
5. **試執行** 頂列「試執行」用目前畫布（未存檔）的圖執行一次，保留所有中間影像；「用上次影像重跑」可固定同一張影像調參。點選步驟名稱旁的圖示開「工具頁」，改參數會自動重跑到該步驟並顯示前／後影像與直方圖。
6. **判定** 用「判定」工具給出 OK／NG；用「具名輸出」把要回傳給自動化系統的值命名。
7. **儲存** Ctrl+S 或頂列「儲存」。「執行一次」與「連續執行」用的是已儲存的版本。
8. **自動化觸發** 外部系統以 HTTP POST /api/vision/flows/{id}/run（可附影像）或 TCP 指令觸發；結果經回應或 SSE 取得。細節見「自動化接口」分頁。
9. **範本畫廊** 「流程」頁「從範本建立」或編輯器頂列「載入範本」：18 個內建範本涵蓋計數、量測、缺陷、顏色、讀碼與深度學習（官方底模、教導模型）；選對應的「Example: …」影像來源即可直接執行。自己的流程也可「存為範本」。
10. **AI 助手** 「AI 助手」頁：上傳影像、在影像上圈選檢測位置（ROI01、ROI02…可各配提示）、以一句話描述需求；助手先確認資訊足夠再生成流程並在該影像實跑。為縮圖標記應判的結果，助手會依標記排名候選方案並自動調參；以文字微調後「存成流程」。「歷史」可還原過去的工作階段，「AI 技能」可寫自己的要領；工作模式選「代理模式」時助手逐步試執行、修改與驗證並顯示時間軸。右下角的全域 AI 助手在任何頁面都可開啟：依文件回答問題並附連結、在編輯器修改目前流程、在批次測試頁依資料諮詢或調整。
11. **批次測試與 Golden Set** 側欄「批次測試」：選流程、上傳或從來源擷取影像建立影像集，每次執行都保留逐張結果。為影像標記期望 OK／NG 即可看命中率、洞察與建議門檻；改參數重跑同一影像集並比較，再寫回流程或存為配方。也可請 AI 助手依資料諮詢或調整。勾選案例可存入 Golden Set 作為回歸基準。
12. **深度學習教導** 側欄「深度學習」：建立教導專案、收集樣本（上傳或從來源取像）、標記類別或形狀（含智慧選取）、訓練並匯出模型到資產庫，再於流程中以 DL 工具使用。
13. **來源與資產群組** 影像來源庫與資產庫皆支援群組：用清單上方的晶片篩選，「管理群組」可改名、刪除。範例來源與資產都在「Examples」群組。

### 鍵盤快捷鍵 {#shortcuts}

| 按鍵 | 動作 |
|---|---|
| `Ctrl+S` | 儲存流程 |
| `右鍵點選步驟` | 步驟選單：開啟工具頁、複製、停用、刪除、複製／貼上參數 |

| `Ctrl+C / Ctrl+V` | 複製／貼上選取的步驟（含內部連線） |

| `雙擊影像` | 符合視窗 |

### 自動化接口 {#automation-entry}

**HTTP 觸發**

```
POST /api/vision/flows/{id}/run?wait=1
Headers: X-API-Key: <金鑰>（或 Authorization: Bearer <token>）
multipart: image=<檔案>   或   JSON: {"context": {...}}
→ 200 RunReport（wait=1）／202 {"queued": true}（wait=0）
```

**試執行（工具頁同款）**

```
POST /api/vision/flows/{id}/preview
{"graph": {...}, "reuse_image_ref": "...", "until_node": "blob", "analysis": true}
```

**暫存影像 / 重置**

```
POST /api/vision/flows/{id}/scratch-image（multipart image）→ {ref,width,height,name}
DELETE /api/vision/flows/{id}/recent → 清除記憶體內的執行紀錄與統計（SSE 送出 cleared）
```

**事件串流（SSE）**

```
GET /api/vision/flows/{id}/stream?since=<seq>
事件：run_started / run_finished（帶 run）/ stats / continuous / lock / cleared / ping（15 秒心跳）
```

**擷取端（相機在別台電腦）**

```
影像來源庫 →「下載擷取端」→ 在相機電腦解壓執行 VisionSequenceCapture.exe
連線：伺服端位址與埠 9100（VISION_CAPTURE_PORT）、擷取端名稱、金鑰（伺服端有設 VISION_CAPTURE_AUTH 或 API_KEY 時）
通道：選相機、開啟、開始取像；圈 ROI 就只傳該區域
網頁：新增影像來源 kind=capture {client, channel, mode: on_demand|stream, timeout_ms, fresh, encoding}
無介面：VisionSequenceCapture-console.exe --headless --connect（工作排程器或服務包裝用）
```

**TCP**

```
一行一個指令（\n 結尾、大小寫不拘），一行 JSON 回應：
RUN <flow id 或名稱> [key=value ...] → {"ok": true, "status": "ok|ng|failed", "judge": "OK", "outputs": {...}, "duration_ms": 12.3, "run_id": "..."}
TRIGGER <flow>   → 只觸發不等結果 {"ok": true, "queued": true}
STATUS [flow]    → 統計；不帶流程回容量與引擎鎖定
START <flow> / STOP <flow> → 連續模式
LOCK [reason="..." ttl=600] / UNLOCK → 佔住硬體：網頁只能編輯不能執行
LIST / PING
影像用 POST /api/vision/sources/{id}/push 推進 kind=upload 的影像來源。
```

### 帳號與引擎鎖定 {#accounts-quick}

- 第一次使用時系統沒有任何帳號，登入頁會直接讓您建立第一個管理員。
- 管理員：管理帳號、角色權限與系統設定。工程師（預設）：建立與修改流程、來源、資產、深度學習教導、批次測試與 Golden Set。操作員：執行檢測、啟停連續模式、換線，以及在參數卡頁調整現場參數。
- 角色權限：上述分工是出廠設定，不是固定規則。管理員在「使用者」頁逐項勾選工程師與操作員能用哪些功能——深度學習、批次測試、操作紀錄、主動輸出的連線。管理員永遠全開，且伺服器每個請求都會檢查，所以沒勾的功能直接輸入網址也進不去。
- 流程屬於產線而不是個人：每位工程師都能看到並修改每一條流程，「擁有者」欄只記錄是誰建立的。
- 整合方（自動化系統）以 API 金鑰（X-API-Key）呼叫，永遠可以執行流程。
- 引擎鎖定：整合方經 HTTP（POST /api/vision/lock）或 TCP（LOCK）取得，所有連續執行停止，其他人只能編輯、不能試執行或執行。畫面上方的橫幅顯示是誰持有與原因；管理員或持有者可從橫幅解鎖，鎖定也可設定到期自動解除。
- 顯示名稱與密碼在「設定」頁自行修改；管理員可在「使用者」頁重設他人密碼、改角色、停用帳號。
