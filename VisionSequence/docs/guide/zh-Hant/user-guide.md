# 使用者指南

本指南依側欄由上到下介紹：每個頁面的位置、頁面內容與可執行的操作。每一節都以截圖開頭，圖上的編號標記對應下方編號清單。截圖顯示英文介面；中文介面版面相同，只是標籤已翻譯。本指南也是產品內的說明頁（側欄 › 說明），會依介面語言顯示，並與工具目錄一起提供。

### 1-1. 從另一台 PC 使用站台 {#another-pc}

您的 PC 不需要安裝任何項目：在 Chrome、Edge（111 或更新）、Firefox（128+）或 Safari（16.4+）開啟站台位址，例如 `https://<station name>/`，或管理員提供的位址。第一次在新 PC 上使用時，瀏覽器可能提示憑證警告：管理員有一個小檔案 `root.crt`，匯入一次即可（[方式](/docs/deployment.html#https)）。語言與主題會與帳號一起儲存，因此您從任何 PC 登入都會看到相同外觀；共用 PC 上離開時請登出，這會清除該瀏覽器中的助手對話與命令歷史。若頁面保持空白並顯示瀏覽器版本通知，代表該 PC 的瀏覽器需要更新；站台本身正常。

## 2. 登入、角色與權限 {#login}

<figure class="shot"><img src="/docs/img/users.jpg" alt="使用者頁"><figcaption><b>使用者</b>（側欄 › 使用者，僅管理員）
<ol class="callouts">
<li data-n="1"><strong>新增使用者</strong>：使用者名稱、顯示名稱、角色與密碼。</li>
<li data-n="2">帳號表：變更角色、停用帳號、重設密碼。</li>
<li data-n="3"><strong>角色權限</strong>：逐項勾選工程師與操作員可使用哪些功能。</li>
</ol></figcaption></figure>

- 尚無使用者時，登入頁會提供「建立第一個管理員」，並以該帳號登入。整合方使用 API 金鑰，從不登入。
- 系統有**三種角色**；下表是出廠設定，角色權限卡可調整：

| 角色 | 可執行 | 不可執行 |
|---|---|---|
| 管理員 | 全部功能，包含帳號、連線與系統設定 | — |
| 工程師 | 建立與編輯流程、影像來源與資產；深度學習教導、批次測試、Golden Set 回歸；變更任何參數 | 帳號、主動輸出連線、系統設定 |
| 操作員 | 執行檢測、啟停連續模式、換線（切換綁定配方）、在參數卡調整**現場參數**、檢視統計 | 變更流程結構、訓練模型、批次測試、編輯來源或連線 |

- **角色權限**：可從工程師移除深度學習教導，將批次測試或操作紀錄交給操作員，或委派主動輸出連線。管理員永遠擁有全部功能且無法取消勾選，因此不會把自己鎖在外面。伺服端會檢查每個請求，未勾選的功能即使直接輸入網址也無法進入；側欄與按鈕會直接消失。
- **流程屬於產線，不屬於個人**：每位工程師都能看到並編輯每條流程（Owner 欄只記錄建立者），因此工程師離職不會留下無人擁有的流程。
- **現場參數**是工具作者標為教導參數的項目，例如門檻或 blob 的最小面積。操作員在參數卡變更這些值會直接寫回流程；變更其他參數或結構會被伺服端拒絕。哪些參數屬於現場參數，會顯示在工具頁參數表的「On-site」欄。

**範本畫廊**有六十多個內建範本，並**依類別分組**：教學、計數、量測、品質、缺陷、識別，接著是您的自訂範本；卡片上方有篩選列。每個內建範本都帶有合成樣本圖：來源保持「範本的樣本圖」時，擷取步驟會成為 **Fixed image** 步驟，每次執行取下一張樣本圖（多數組別第四張是刻意安排的 NG），因此新流程可立即執行；相機準備好後再選真實來源。您自己的流程也可存為範本供其他人重用。詳見[範例範本](samples.md)。

匯出與匯入使用穩定 JSON 格式，因此流程可放進版本控制並在站台間移動；匯入時頁面會詢問要綁定哪個影像來源。請參考 [Golden Set 與匯出](golden.md)。

### 3-1. 檢測任務頁：不必接線就能建立檢測 {#inspect}

**檢測任務**頁（流程頁每一列的按鈕，或編輯器工具列；路徑 `/flows/:id/inspect`）用「任務清單」建立檢測，而不是一個個步驟與連線。任務清單上方的**新增任務**會開啟三步驟的引導：先選任務種類（定位工件、量直徑、量距離、邊緣缺陷、讀碼驗證……），再在影像上畫出區域，最後填寫規格（標稱值、上下公差、單位、標定）並按**建立任務**；旁邊的**移除任務**刪除目前選取的任務。頁面會替您建好步驟、連線與整體合格判定，全程不需要工具箱，也不需要接線。

- **每個任務就是一個內建工具**：在這裡新增的任務（或 AI 助手替您加的任務）會以工具箱「檢測任務」分類裡對應的內建檢測工具（見[複合工具](#composite)）放到畫布上，一個任務一個實例，任務清單以工具徽章標示。區域與規格就是這個工具的參數，所以同一個任務也能在工具頁調整，進階流程裡只看到一個步驟而不是好幾個。這次改版之前建立的流程仍保留原本的多步驟任務，兩種任務一起列出、用法相同。
- **影像來源**：選擇來源、加入固定影像，或**上傳暫存影像**。沒有影像時**試執行**會被擋下並提示原因。
- **讀值與狀態**：每個任務顯示合格、不合格、量不到、定位失敗、錯誤、跳過或尚未執行。必要任務不合格或被跳過，整體就判不合格——被跳過的檢查絕不算通過。定位失敗時，依賴它的任務會顯示定位失敗，而不是量到錯的位置。
- **過期**：改了規格之後，上次的讀值會標為**過期**，直到您再按一次**試執行**。
- **上次的讀值存在伺服器**：試執行後頁面會把這條流程的讀值摘要存到伺服器，所以換一台電腦或用全新的瀏覽器重開，也看得到上次的讀值；流程之後若有變更，讀值會標為過期。影像與教導功能需要重新試執行。
- **毫米**需要標定：表單會要求您先選一份標定，而不是默默回報像素值。
- **自訂**：如果在**進階流程**裡改動了任務的步驟（加了步驟、換了工具、改了內部連線），該任務會標為**自訂**並列出原因，規格表單隨之隱藏；可從原因旁的連結跳到該步驟。移動步驟位置，或修改任務沒有管理的參數，任務仍可在此頁編輯。
- **儲存**會寫回流程；若其他人在這段期間已經儲存過，會出現儲存衝突對話框，讓您載入對方的版本、覆蓋或取消。**進階流程**隨時可開啟完整流程圖查看與除錯。

定位可能旋轉的工件：在**定位工件**從目前影像裁出定位標記當範本，勾選允許旋轉並設定角度範圍；第一次試執行後，以這次結果教導基準姿態。定位標記請避免每 90° 對稱的圖形——單純的十字在角度範圍大時會有歧義。

AI 助手也能從對話建出同樣的任務清單，請參考[從對話產生檢測任務清單](agent.md#tasklist)。

### 3-2. 工程筆記 {#notes}

**工程筆記**（側欄 › 影像檢測 › 工程筆記，路徑 `/notes`）把設定背後的理由——決策、經驗、打光、標定、限制、公差依據、已知問題——記在它所適用的流程旁邊。筆記可連結專案、料號、流程、配方與影像來源，附上佐證影像與執行 ID、適用條件與流程版本範圍。檢測規格本身永遠以流程為準。

- 新筆記一律是**草稿**，只有**確認**後的筆記才會被 AI 助手引用。預設工程師可以確認自己的草稿；站台也可以改成必須由另一位工程師確認（`VISION_ENGINEERING_NOTE_SELF_CONFIRM=0`）。
- 建立取代筆記會寫出一份取代舊筆記的新草稿：儲存後舊筆記立即不再出現在助手的搜尋結果，但歷史會保留。撤回筆記不會刪除它。
- 編輯器與檢測任務頁都有「此流程的筆記」連結；助手對話裡記下的工程決策，也可以一鍵存成筆記草稿。

影像視窗工具列包含**十字線**按鈕。開啟後會顯示一條水平線與一條垂直線，拖曳任一條線即可量測影像位置。視窗會顯示交點的影像 X/Y 座標，並讀取該點像素值。滑鼠移過影像時也會顯示游標資訊列，包含影像座標與目前灰階或 RGB 值；縮放與平移不會改變座標系。

當編輯器同時有選取步驟的輸入與輸出影像時，主視窗可把第二張影像疊在第一張上。使用影像視窗工具列中的**疊圖透明度**混合前後影像。若兩張影像尺寸不同，疊圖會依自身尺寸置中，而不是拉伸到主影像大小，且視窗會標示尺寸不符。

使用影像視窗列的 **Grid** 可把編輯器切到格狀檢視。選擇 1、2、4、6 或 9 格，再把每一格綁到某個步驟與影像輸出埠。格狀版面與綁定會依流程記在此瀏覽器中，常用調整視圖可重開，不必重新建立。

1. 將判定工具的分支埠接到步驟的 `_flow` 埠，可讓該步驟成為條件式；每個步驟也會在 `_image` 埠直通影像，因此只產生數值的工具仍可放在影像鏈中間。
2. Ctrl+S 會儲存。未儲存變更會保留為草稿，離開後再回來仍存在，並另存一份在此瀏覽器，重新整理或分頁當掉也不會遺失：回到編輯器時可選擇**還原草稿**或**放棄**（期間若有人儲存過該流程則不提供還原）；「執行一次」與「連續執行」使用已儲存版本，「試執行」使用草稿。
3. 流程從資料夾來源或 Fixed image 步驟擷取影像時會出現**影像序列試執行**。它一次試執行一張影像，顯示目前影像序號與 OK/NG 計數，且可暫停或停止。它仍只是試執行：不進生產歷史或統計。
4. Ctrl+F 開啟節點搜尋。它會比對步驟 id、標題、工具類型與已填參數值；Enter 跳到下一筆，Esc 關閉。復原與重做共用同一份編輯歷史：Ctrl+Z 復原，Ctrl+Shift+Z 或 Ctrl+Y 重做。
5. **時間花在哪裡？** 試執行後，每個步驟會顯示耗時與細條：該次最慢步驟為紅色，超過其一半者為橙色。「結果」分頁也有**區間耗時**：選來源步驟與目標步驟後，會加總兩者之間資料流路徑上的所有步驟，分支路徑只算一次。右鍵點選步驟並選 **Run to here**，只執行該步驟與其之前步驟；調整單一步驟時不必等完整流程。
6. **連線上的數值**：試執行後每條連線會顯示它傳送的值（數字、文字、true/false、清單的項目數）；影像不顯示。底部縮放列的標籤鈕可以開關。旁邊的自動排列鈕會依資料流從左到右排列，並依每個步驟實際的高度排列行距。
7. **清除結果**只清除目前顯示內容：步驟顏色、耗時熱度、標記、影像視窗標示與「結果」分頁。不會編輯草稿、儲存流程或呼叫伺服端；下次試執行或執行會再次填入結果。
8. **未選取任何項目**時，側欄顯示**流程設定**（描述、連續執行間隔、流程逾時、並行度、啟用與「NG 時停止」），並在**更多設定**下顯示三個按鈕，各自開啟一個對話框：**變數**，也就是此流程在執行間保留的值（計數、前一個零件、設備傳來的批號），可在該處讀取、變更或清除；**看板設定**，也就是此流程的操作員看板內容（見 [7-1](#board)）；以及**結果回報**，也就是每次執行後由哪個連線接收格式化文字行（見[自動化](/docs/automation.html)）。
9. **尚未選擇影像來源？** 編輯器頂端會出現黃色橫幅；從橫幅下拉選單挑選來源，或上傳暫存影像，即可立刻試執行。選取擷取步驟時，側欄會以含預覽縮圖的下拉選單顯示目前來源，並可直接切換來源。
10. **完全沒有相機？** 加入 **Fixed image** 步驟（Source 類別）取代影像來源，並上傳一張或多張圖片到該步驟；它們會隨流程儲存，匯出時一併帶走，而且每次執行（包含試執行）會取下一張，因此反覆按 Run 可走完整組影像。同一步驟若 role 設為 "reference"，可透過影像輸入埠把範本、Golden 樣本或白參考交給定位、Golden 比對或平場工具，不需要資產。
11. **想寫一小段 Python？** Logic 類別有 "Python script" 工具：在工具頁的程式碼編輯器撰寫 `def run(ctx)`，可讀取 `ctx.image`、`ctx.inputs` 中的上游值、現場參數 `ctx.params['p1'..'p3']` 與 `ctx.roi()` 的區域，並回傳數值、布林、文字、資料、新影像與標記，選擇通過或失敗分支。輸出埠固定為 value、result、text、data、image。腳本在引擎行程中受限制執行，包含允許清單匯入、逾時與唯讀輸入影像；**只有管理員可編輯並儲存它，這也代表核准**。其他人可檢視與執行已核准腳本，並在參數卡調整現場參數，不需接觸程式碼。

### 4-1. 複合工具 {#composite}

**複合工具**是用其他工具建立的工具：幾個步驟接好線，加上一份**對外介面**，宣告哪些內部埠是它的輸入與輸出、哪些內部參數出現在它的參數表。儲存後它放在**工具庫**（檢測資源 › 工具庫），並像內建工具一樣出現在工具選擇器；拖到畫布、接線、在工具頁調參數。所有使用它的流程都跑同一份實作。

- **封裝成工具**（主路徑）：在畫布上選取步驟，按右鍵選「封裝成工具…」（或用多選面板的按鈕），取名、給鍵與分類。選取的步驟換成一個步驟；跨越選取範圍的連線變成它的埠，已發布的輸出名稱搬到新步驟上。
- **編輯工具**：雙擊複合工具步驟、從它的選單選「開啟工具畫布」，或在工具庫按「編輯」。工具的畫布就是一般的編輯器，右側多了**對外介面**面板：勾選要對外的內部埠、拖曳或用箭頭排序、取顯示名稱，勾選要對外的內部參數並標記操作員可教導的。試執行會把暫存影像送進每一個對外影像輸入。
- **版本**：每次儲存只要改到工具的步驟或介面就是新的一版（工具庫看得到版本號）。放到畫布上的步驟會記住放入時的工具版本並一直執行那一版，所以修改工具不會在您不知情時改變產線流程。工具有新版時，步驟上會出現小小的 **v*n*** 徽章，側欄提供**查看差異**（參數、埠、步驟哪裡不同）與**更新到 v*m***；儲存工具前仍會先列出使用它的流程與工具。內建檢測工具一律執行最新版。仍在使用中的工具不能刪除。
- **只有兩層**：流程使用工具，工具由內建工具組成。複合工具裡不能再放複合工具，所以工具畫布上的工具選擇器不列複合工具、「封裝成工具」也不可用。
- **內建檢測工具**：工具選擇器的**檢測任務**分類裡，每一種檢測方式各有一個複合工具（量直徑或真圓度、以範本／形狀模型／註冊圖定位工件、以邊對或孔心量距離、計數、以範本／blob／印刷檢查有無、邊緣缺陷（直線或自由輪廓）、讀碼、讀文字並核對）。拖到畫布、接上影像、畫區域、在工具頁填規格即可。它們唯讀；要調整就在工具庫**另存複本**。
- **匯出與匯入**：工具可下載成 `.tool.json`（含巢狀的工具）並在另一站台匯入；流程匯出時會內嵌它用到的複合工具，流程檔單獨就能匯入。
- 內建的複合工具唯讀；在工具庫用**另存複本**取得可編輯的版本。

## 5. 工具頁與 ROI {#tool}

<figure class="shot"><img src="/docs/img/tool.jpg" alt="工具頁"><figcaption><b>工具頁</b>（編輯器 › 側欄 › 開啟工具頁，路由 <code>/flows/:id/tools/:step</code>）
<ol class="callouts">
<li data-n="1">此步驟的<strong>參數</strong>，依群組排列並含說明文字；區域參數會改畫在影像上。</li>
<li data-n="2"><strong>輸入影像</strong>，也就是步驟收到的影像，ROI 會畫在此處。</li>
<li data-n="3">帶有步驟標記的<strong>輸出影像</strong>。</li>
<li data-n="4"><strong>參考資訊</strong>：直方圖、統計與步驟輸出值。</li>
<li data-n="5"><strong>執行到此步驟</strong>會試執行流程到此處。</li>
<li data-n="6"><strong>儲存</strong>把參數草稿寫回流程。</li>
<li data-n="7"><strong>上傳暫存影像</strong>提供一張只供試執行使用的影像，不影響來源庫。</li>
<li data-n="8"><strong>返回</strong>編輯器，若有未儲存參數會先詢問是否捨棄。</li>
</ol></figcaption></figure>

- 變更參數**預設不會**執行任何內容；按「執行到此步驟」才會看到結果。開啟「自動套用」後，每次變更 500 ms 後試執行，只送出一連串變更中的最後一次。
- 參數變更會暫存在草稿中：「儲存」才會寫回流程，帶著未儲存變更離開時會詢問是否捨棄。
- ROI：有區域參數的工具，在開啟工具頁時會立即顯示 ROI。在輸入影像上繪製矩形、旋轉矩形、圓、橢圓、環形（可選扇區）、多邊形、折線、線或點。座標是該步驟輸入影像的像素座標；正角度為畫面順時針。
- 「用上次影像重跑」會固定同一張影像以便調整；定位或 Golden 比對使用的範本可由目前影像上的方框建立，並直接存為資產。
- 有影像清單參數的工具可直接把目前試執行影像的一個裁切加入該清單；按 Add from current image，畫出矩形或旋轉矩形，再確認。自由形狀邊緣缺陷工具也可從目前影像教導輪廓模型。
- **埠**（參數下方）：勾選哪些輸入與輸出埠要畫在畫布上、拖曳列或用箭頭調整順序、替輸出取一個發布名稱。已接線的埠一律顯示（要隱藏請先移除連線）；「依下游位置排序」會把輸出排到連線不交叉。把未接線的必填輸入藏起來不會讓問題消失：步驟會掛紅色徽章、檢查照樣不通過。預設規則見[埠](#ports)。

### 6-1. 站台參數卡與自訂群組 {#station-teach}

Teaching 群組下的**站台參數卡**頁，會把每條可見流程的現場參數收在同一份清單。站台有多條流程處理不同相機面或治具時，可使用 Flow、Tool 與 Search 篩選。每列都顯示流程、步驟、工具與參數，因此值永遠不會脫離它將更新的流程 graph。

儲存時使用與單流程參數卡相同的流程更新路徑：頁面會為每條已變更流程建立一個 graph patch，並分別送出 `PATCH /api/vision/flows/{id}`。若某條流程儲存成功、另一條被拒絕，結果面板會逐條列出成功或失敗，而不是隱藏部分結果。操作員仍然只能變更標為現場教導參數的項目；變更非 teach 參數會被伺服端拒絕。

自訂群組是儲存在帳號偏好中的個人捷徑。群組只記錄 `flow_id`、`node_id` 與參數 key；目前值永遠來自流程 graph。若捷徑指向已刪除的流程、步驟或參數，頁面會把它標為無效，並讓您移除它，不影響頁面其餘內容。每位使用者最多可保留 32 個群組。

### 新一批檢測工具的位置 {#new-tools}

工具選擇器會依類別整理每個工具，因此演算法批次新增的工具會出現在符合用途的位置：**前處理** — Polar unwrap 與 Polar restore（環、齒輪、螺紋）、Flat-field correction（不均勻照明）、Lens undistortion、Photometric stereo（四向打光表面形狀，用於浮凸與凹刻標記）；**定位** — Shape match（可承受遮擋與照明變化的邊緣方向比對）、Region from shape 與 Region combine（排除區）；**量測** — 輪廓鏈（Contour find、filter、geometry、match）、Circular caliper 與 Profile defects（圓邊缺口）、Form and position tolerance（直線度、圓度、平行度等）、Real-world coordinates；**檢測** — Statistical template compare、Anomaly detection（只有良品）、OCR read 與 OCV verify、Barcode quality grade。每個工具都有可直接使用的範本，樣本圖會顯示預期用途，[檢測能力](vision-capabilities.md)頁則列出每項量測內容與精度。

### 7-1. 操作員看板 {#board}

**選擇看板顯示內容。** 在流程編輯器中未選取任何項目時，「設定」分頁會有**看板**卡：勾選要顯示的具名輸出，為每個輸出指定標籤、單位、小數位數與最小／最大值（超出範圍會在看板與總覽變紅），選擇要顯示哪個步驟的影像（預設最後一張），列出要顯示的變數，並切換判定、今日計數與標記是否顯示。儲存後再開啟看板。總覽會遵循相同設定，因此即時面板也會用相同數值與顏色。

每個零件檢測完成時看板都會更新；計數每十五秒刷新一次。若要自行建立畫面，一個請求 `GET /api/vision/flows/{id}/board` 就會回傳此頁顯示的完整內容，包含公差判定（[自動化](/docs/automation.html#board)）。

### 7-2. 運行介面 {#dashboard}

**運行介面**頁（`/dashboards`）列出操作員可用 kiosk 模式開啟的站台運行介面。每列顯示運行介面名稱、是否為預設、元件數、最後更新時間與可用動作。操作員可開啟運行介面。工程師可從空白版面、預設版面或內建範本建立運行介面，將某個運行介面設為預設、複製、刪除，並開啟視覺版面設計器。

#### 設計版面 {#dashboard-design}

**運行介面設計器**（`/dashboards/:id/design`）是工程工作區，可先不編輯 JSON 就變更運行介面。左欄是元件目錄，中間畫布是列與欄的格線，右欄顯示版面、元件與進階設定。在畫布頂部變更列數與欄數，點選儲存格選取，拖過相鄰儲存格合併，使用 Split 將合併格還原為單一格，並把元件從目錄拖入任一儲存格。已在儲存格中的元件可選取、移到另一格、重新排序、複製或刪除。

屬性面板會依運行介面 元件規格 建立可用控制。布林選項用核取方塊，數字選項用有界數字欄位，選項用選擇器，顏色用色票，表格欄位、分頁、規則與影像牆項目等清單型選項則用精簡列編輯器。來源設定讓工程師選擇元件要讀流程輸出、變數、影像、狀態、計數、SPC 序列或設備值。已選流程會在資訊已知時控制可用輸出、變數與影像 key。

| 元件 | 用途 |
|---|---|
| 子運行介面 | 嵌入另一個運行介面，深度一層。該子運行介面內的巢狀 子運行介面 會在檢視器中隱藏，伺服端也只收集子運行介面的直接流程引用。 |

使用**儲存**修補運行介面版面，**預覽**會在右側面板顯示縮放後的 kiosk 檢視，**範本**會以內建起始版面取代目前版面，**匯出 JSON** 或 **匯入 JSON** 可在站台間移動版面。進階分頁仍包含完整 JSON 編輯器，可做精確變更與疑難排解。帶著未儲存變更離開設計器時會詢問確認。

全螢幕檢視器（`/dashboard/:id`，或預設運行介面的 `/dashboard`）使用伺服端儲存的 layout JSON。中央區域是儲存格格線。版面啟用時，頂列與底列會顯示標題、時鐘與設備狀態。檢視器會訂閱版面引用的每條流程，因此影像、判定與數值會在執行完成時更新；運行介面資料封包每十五秒刷新一次，提供今日計數、站台變數與設備狀態。

**編輯 layout JSON。** 開啟**編輯版面**，變更 `rows`、`cols`、`cells`、`bars`、`default_flow_id`、`widgets` 與 `theme` 欄位後儲存。每個元件有 `id`、`type`、`cell`、選填 `props` 與選填 `source`。伺服端會驗證版面，JSON 無效時回傳需要調整的確切元件與欄位。使用**載入預設版面**重置文字框，**匯出 JSON** 下載目前版面，**匯入 JSON** 貼上已儲存的版面檔。

### 統計頁上的量測與精度 {#measurements}

統計頁有兩種檢視。**良率**就是前述 OK/NG 歷史。**量測值**是一個具名輸出的管制圖：選擇輸出、圖表（每次執行一個值時用 I-MR，批次來料時用帶 subgroup size 的 X̄-R）與期間（24 h、7 d、30 d）。圖表會畫出中心線與由資料算出的管制界限；若 *Tolerance judge* 步驟綁到同一個值，也會畫規格界限（USL/LSL，虛線），此綁定同時提供 Cp 與 Cpk。觸發 Nelson 規則的點（一點超過 3σ、連續九點在同側、連續六點上升或下降等）會畫成紅色，規則列在圖下。數值來自量測紀錄，會獨立於執行歷史保留一年，因此即使執行明細已清除，仍看得到過去三個月的漂移。

若流程**目前**正在漂移或超出規格（最新點觸發規則，或最近三十筆包含超規值），總覽會顯示量測警示並連到該流程統計。系統沒有推播通知；警示顯示在畫面上。

**精度研究**卡位於良率檢視底部，會用驗證器方式執行流程：同一張圖執行 N 次（重複性），或同一零件擷取 N 次（再現性），並回報每個數值輸出的 σ 與 range，附可複製報告。多個零件的 Gauge R&R 由命令列執行（`manage.py precision`，見 Performance）。

### 10-2. 標定：毫米、鏡頭畸變與機械手臂座標 {#calibration}

<figure class="shot"><img src="/docs/img/calibration.jpg" alt="標定頁"><figcaption><b>標定</b>（側欄 › 標定，路由 <code>/calibration</code>）
<ol class="callouts">
<li data-n="1">三種教導方式與各自提供的結果。<strong>標定板</strong>：幾張印刷板影像同時提供鏡頭校正與比例。<strong>機械手臂點位</strong>：在影像上標記位置並輸入機械手臂回報的座標，讓位置可直接交給機械手臂。<strong>已知距離</strong>：標記兩點、輸入真實距離即可。</li>
<li data-n="2">取像用的<strong>影像來源</strong>；也可上傳既有照片。</li>
<li data-n="3"><strong>擷取</strong>會拍一張圖。在標定板模式下，每張圖都會立即搜尋標定板，並列出找到的點數，因此能立刻知道該角度是否有效。</li>
<li data-n="4"><strong>標定板</strong>：圖案，以及以<em>內角點</em>表示的尺寸（10 x 7 格的板是 9 x 6）與相鄰兩點間距。填錯時找不到標定板；頁面會明確說明，而不是靜默失敗。</li>
<li data-n="5">圖面與機械手臂使用的<strong>單位</strong>。</li>
<li data-n="6"><strong>計算</strong>會算出結果，但<em>不會</em>儲存：您會先看到吻合度。</li>
<li data-n="7"><strong>儲存標定</strong>會把它存成資產。之後可在 Lens correction、Real-world coordinates 或 Pixel calibration 步驟中選用。</li>
</ol></figcaption></figure>

<figure class="shot"><img src="/docs/img/calibration-stereo.jpg" alt="標定 › 立體高度"><figcaption><b>立體高度</b>（左右相機對量測物件高度，用於機械手臂取料）
<ol class="callouts">
<li data-n="1"><strong>立體高度</strong>模式：兩台相機從略有差異的位置看同一條皮帶；兩個視角間差異會給出各物件距離。</li>
<li data-n="2">若相機對已在其他地方完成標定，可<strong>匯入 stereo_config.json</strong>；只讀取兩台相機模型與相對位姿，其餘在此重新計算。</li>
<li data-n="3"><strong>擷取成對影像</strong>會同時拍兩張圖，並列出每一對的時間差與擬合誤差；至少五對同一塊標定板影像後，依序計算與儲存。</li>
</ol></figcaption></figure>

**皮帶高度參考。** 在影像對清單下方，量一次空皮帶並輸入該皮帶表面對應的機械手臂 Z；之後 Stereo depth 步驟會把每個物件頂面回報為絕對機械手臂 Z，而不只是距相機的距離。沒有該參考時，步驟仍會回報距離並讓 Z 保持空值。

**選擇方式。** 若只需要毫米量測，*已知距離*一分鐘即可完成：在已量測物件上標兩點並輸入距離。若鏡頭讓角落附近直線明顯彎曲，或同一零件在視野中央與邊緣量測不同，請使用*標定板*：以不同傾角與距離拍三張以上，盡量填滿畫面。若機械手臂需要前往取件，請用*機械手臂點位*：將機械手臂 jog 到三個以上可見位置，並輸入每一點回報的座標。

**儲存前先讀誤差。** 每種方法都會回報吻合度。標定板標定會顯示每張圖的重投影誤差，因此可刪除模糊影像後重算。機械手臂點位會顯示*每個*點的誤差，最差的一點會在影像上標紅，通常代表機械手臂 jog 到錯誤位置，或座標輸入錯誤。結果會給出清楚判定：good、fair 或 do it again。

**點位標記容錯。** 點選孔、印刷點或角落附近，標記會吸附到中心，因此不必精準點到單一像素。若確實要使用點選的位置，可關閉吸附。

**在流程中使用。** 一份已儲存標定可供三個步驟共用：*Lens correction* 會拉直影像（放在影像來源後、任何量測前），*Pixel calibration* 的 "from a calibration" 模式會把長度轉成毫米，*Real-world coordinates* 會把位置轉成機台使用座標，並同時轉換長度與角度。因為它們都讀同一資產，重新標定站台會一次更新每條流程，不需要逐步尋找手輸數值。

如果相機之後移動、重新對焦或更換，請重新標定。全解析度建立的標定在流程以半解析度執行時仍有效：鏡頭校正會自動縮放，若長寬比不同，步驟會明確說明，而不是悄悄套用錯誤校正量。

1. 樣本：上傳圖片或 zip、從來源 burst 取像、匯入資料集資料夾，或從影片抽取；重複項會自動跳過。點選縮圖即可標記。
2. 標記：分類時，點選縮圖並選擇類別；分割與偵測時，繪製多邊形或方框，也可用「智慧選取」點選物件並自動描出外形。
3. 訓練後的「用此模型建立流程」會建立 acquire → inference 流程並在編輯器開啟。

訓練器、GPU 設定與匯出格式請見[深度學習教導](dl.md)。

## 13. AI 助手頁：從影像產生流程 {#agent}

<figure class="shot"><img src="/docs/img/agent.jpg" alt="AI 助手頁"><figcaption><b>AI 助手</b>（側欄 › AI 助手，路由 <code>/agent</code>）
<ol class="callouts">
<li data-n="1"><strong>上傳影像</strong>：一張或多張影像；在其上畫出要檢測的區域。每個 ROI 都有編號（ROI01、ROI02…），也可帶 "good"、"bad" 或 "locator" 等提示。</li>
<li data-n="2"><strong>需求</strong>：一句話，例如 "there should be 5 holes"、"measure the diameter, 17.5 ± 0.4 mm"、"ROI01 is good and ROI02 is bad, find the difference"。</li>
<li data-n="3"><strong>生成</strong>：助手會詢問仍缺少的資訊，產生流程並在每張影像上執行，為每張縮圖標記 OK 或 NG。</li>
<li data-n="4"><strong>AI 供應商</strong>：離線規則引擎，或 Claude、GPT、Gemini 搭配您自己的金鑰（儲存在伺服端並綁定帳號）；儲存時會測試連線，「列出模型」顯示該金鑰可用模型，工作模式可選單次或代理模式。</li>
<li data-n="5"><strong>技能</strong>：助手遵循的內容，並在每個技能下加入您自己的或站台的備註。</li>
</ol></figcaption></figure>

1. 可選擇為每張縮圖標記它應得到的判定；ROI 提示為 "good" 或 "bad" 的影像會自動標記。提示為 "locator" 的 ROI 代表固定特徵，當零件可能移動時，流程會在前方加入定位補正。
2. 規則引擎會產生多個候選方案，依您的標記挑選最佳者，結果卡也讓您切換方案；有兩張以上已標記影像時會自動調參。
3. 用文字微調，例如 "too many false rejects"、"expect 4 instead"、"tolerance ±0.2"，然後「存成流程」以在編輯器開啟。結果卡上的讚或倒讚會影響之後是否在類似影像重用這些參數。
4. 歷史會顯示過去工作階段，「還原」會帶回影像、ROI、需求與標記並重新執行。代理模式下，助手會逐步草擬、嘗試、編輯與驗證，顯示可中斷或回覆問題的時間軸。

請參考 [AI 助手](agent.md)。

## 快速參考 {#quick-reference}

### 快速上手 {#quick-start}

1. **建流程** 到「流程」頁按「建立檢測任務」（任務頁）或「建立進階流程」（畫布），或複製示範流程。流程屬於產線而不是個人：每位工程師都能看到並修改，「擁有者」欄只記錄是誰建立的。
2. **取像** 從工具箱插入「影像來源」步驟，選影像來源庫裡的資料夾、合成或擷取端相機來源；或用頂列「上傳暫存影像」只為試執行放一張圖（不進來源庫）。相機由相機所在電腦上的擷取端程式驅動（影像來源庫「下載擷取端」）：連到伺服端後新增「擷取端相機」來源，選擷取端與通道即可。
3. **加工具** 把工具箱的工具拖到畫布（或點選插到最右邊），把上一步的輸出埠拉線接到下一步的輸入埠；同色的埠才能相接。線也可以直接放在下一個步驟上，會自動接到第一個可接的空閒埠，沒有可接的埠時會提示。
4. **ROI** 有「區域」參數的工具：在工具頁或側欄按「在影像上編輯」，直接在影像視窗拖曳畫出矩形／圓／多邊形等；座標是該步驟輸入影像的像素座標。
5. **試執行** 頂列「試執行」用目前畫布（未存檔）的圖執行一次，保留所有中間影像；「用上次影像重跑」可固定同一張影像調參。點選步驟名稱旁的圖示開「工具頁」，改參數會自動重跑到該步驟並顯示前／後影像與直方圖。
6. **判定** 用「判定」工具給出 OK／NG；用「具名輸出」把要回傳給自動化系統的值命名。
7. **儲存** Ctrl+S 或頂列「儲存」。「執行一次」與「連續執行」用的是已儲存的版本。
8. **自動化觸發** 外部系統以 HTTP POST /api/vision/flows/{id}/run（可附影像）或 TCP 指令觸發；結果經回應或 SSE 取得。細節見「自動化接口」分頁。
9. **範本畫廊** 「流程」頁「從範本建立」或編輯器頂列「載入範本」：六十多個內建範本涵蓋計數、量測、缺陷、顏色、讀碼與深度學習（官方底模、教導模型）；選對應的「Example: …」影像來源即可直接執行。自己的流程也可「存為範本」。
10. **AI 助手** 「AI 助手」頁：上傳影像、在影像上圈選檢測位置（ROI01、ROI02…可各配提示）、以一句話描述需求；助手先確認資訊足夠再生成流程並在該影像實跑。為縮圖標記應判的結果，助手會依標記排名候選方案並自動調參；以文字微調後「存成流程」。「歷史」可還原過去的工作階段，「AI 技能」可寫自己的要領；工作模式選「代理模式」時助手逐步試執行、修改與驗證並顯示時間軸。右下角的全域 AI 助手在任何頁面都可開啟：依文件回答問題並附連結、在編輯器修改目前流程、在批次測試頁依資料諮詢或調整。
11. **批次測試與 Golden Set** 側欄「批次測試」：選流程、上傳或從來源擷取影像建立影像集，每次執行都保留逐張結果。為影像標記期望 OK／NG 即可看命中率、洞察與建議門檻；改參數重跑同一影像集並比較，再寫回流程或存為配方。也可請 AI 助手依資料諮詢或調整。勾選案例可存入 Golden Set 作為回歸基準。
12. **深度學習教導** 側欄「深度學習」：建立教導專案、收集樣本（上傳或從來源取像）、標記類別或形狀（含智慧選取）、訓練並匯出模型到資產庫，再於流程中以 DL 工具使用。
13. **來源與資產群組** 影像來源庫與資產庫皆支援群組：用清單上方的晶片篩選，「管理群組」可改名、刪除。範例來源與資產都在「Examples」群組。

### 自動化接口 {#automation-entry}

**HTTP 觸發**

```
POST /api/vision/flows/{id}/run?wait=1
Headers: X-API-Key: <金鑰>（或 Authorization: Bearer <token>）
multipart: image=<檔案>   或   JSON: {"context": {...}}
→ 200 RunReport（wait=1）／202 {"queued": true}（wait=0）
```

**試執行（工具頁同款）**

```
POST /api/vision/flows/{id}/preview
{"graph": {...}, "reuse_image_ref": "...", "until_node": "blob", "analysis": true}
```

**暫存影像 / 重置**

```
POST /api/vision/flows/{id}/scratch-image（multipart image）→ {ref,width,height,name}
DELETE /api/vision/flows/{id}/recent → 清除記憶體內的執行紀錄與統計（SSE 送出 cleared）
```

**事件串流（SSE）**

```
GET /api/vision/flows/{id}/stream?since=<seq>
事件：run_started / run_finished（帶 run）/ stats / continuous / lock / cleared / ping（15 秒心跳）
```

**擷取端（相機在別台電腦）**

```
影像來源庫 →「下載擷取端」→ 在相機電腦解壓執行 VisionSequenceCapture.exe
連線：伺服端位址與埠 9100（VISION_CAPTURE_PORT）、擷取端名稱、金鑰（伺服端有設 VISION_CAPTURE_AUTH 或 API_KEY 時）
通道：選相機、開啟、開始取像；圈 ROI 就只傳該區域
網頁：新增影像來源 kind=capture {client, channel, mode: on_demand|stream, timeout_ms, fresh, encoding}
無介面：VisionSequenceCapture-console.exe --headless --connect（工作排程器或服務包裝用）
```

**TCP**

```
一行一個指令（\n 結尾、大小寫不拘），一行 JSON 回應：
RUN <flow id 或名稱> [key=value ...] → {"ok": true, "status": "ok|ng|failed", "judge": "OK|NG|FAILED|NONE", "outputs": {...}, "duration_ms": 12.3, "run_id": "..."}
TRIGGER <flow>   → 只觸發不等結果 {"ok": true, "queued": true}
STATUS [flow]    → 統計；不帶流程回容量與引擎鎖定
START <flow> / STOP <flow> → 連續模式
LOCK [reason="..." ttl=600] / UNLOCK → 佔住硬體：網頁只能編輯無法執行
LIST / PING
影像用 POST /api/vision/sources/{id}/push 推進 kind=upload 的影像來源。
```

### 帳號與引擎鎖定 {#accounts-quick}

- 第一次使用時系統沒有任何帳號，登入頁會直接讓您建立第一個管理員。
- 管理員：管理帳號、角色權限與系統設定。工程師（預設）：建立與修改流程、來源、資產、深度學習教導、批次測試與 Golden Set。操作員：執行檢測、啟停連續模式、換線，以及在參數卡頁調整現場參數。
- 角色權限：上述分工是出廠設定，不是固定規則。管理員在「使用者」頁逐項勾選工程師與操作員能用哪些功能——深度學習、批次測試、操作紀錄、主動輸出的連線。管理員永遠全開，且伺服器每個請求都會檢查，所以沒勾的功能直接輸入網址也無法進入。
- 流程屬於產線而不是個人：每位工程師都能看到並修改每一條流程，「擁有者」欄只記錄是誰建立的。
- 整合方（自動化系統）以 API 金鑰（X-API-Key）呼叫，永遠可以執行流程。
- 引擎鎖定：整合方經 HTTP（POST /api/vision/lock）或 TCP（LOCK）取得，所有連續執行停止，其他人只能編輯、無法試執行或執行。畫面上方的橫幅顯示是誰持有與原因；管理員或持有者可從橫幅解鎖，鎖定也可設定到期自動解除。
- 顯示名稱與密碼在「設定」頁自行修改；管理員可在「使用者」頁重設他人密碼、改角色、停用帳號。
