深度學習教導：平台內標記、訓練、匯出

「深度學習」頁（/dl）讓使用者不出平台完成一輪教導：建立教導專案 → 收集樣本（上傳或從影像來源連抓）→ 標記（含自動標記加速）→ 在伺服端訓練（可看 GPU／加速器資訊並選擇裝置）→ 模型自動匯出成資產，在流程的「DL 分類」等工具直接選用。模型種類（trainer）是 registry，之後導入其他深度學習模型共用同一套 UI，前端不用改。

1. 教導流程（使用者視角）

  1. 建立教導專案：取名、選模型種類、定義類別（例如 OK, NG；之後可隨時增減）。
  2. 收集樣本：「上傳影像」（多選，也接受 zip 批次包）或「從來源取像」（選影像來源連抓 N 張，可預先標記）。上傳一律以像素 SHA256 去重——同一張圖重傳（或 zip 裡重複）自動略過並回報張數。
  3. 標記（分類）：兩種檢視——網格（點一個類別按鈕，再點縮圖即標記，適合大量快速標記；hover 縮圖有放大與刪除鈕）與大圖（左縮圖牆＋右原圖檢視器，可縮放／1:1 看細節，下方類別按鈕或 0~9 標記、←/→ 換張）。兩種檢視共用篩選條件。
  4. 訓練：右側面板調超參數（表單由 trainer 的宣告產生）、選裝置、給模型資產名稱 → 開始。進度條與指標（訓練／驗證正確率）即時更新；訓練跑在背景，不占用檢測執行緒池。
  5. 使用：完成後模型出現在資產庫（kind=model），流程裡加「DL 分類」工具、選這個模型、labels 貼上類別清單即可（trainer 會回報建議參數，內建分類器與工具預設前處理完全一致，其餘參數用預設值就對）。

2. 自動標記

標記是導入最花時間的一步，所以每個 trainer 可實作 suggest()：對未標記樣本提出「建議類別＋信心分數」。內建分類器用特徵空間的 cosine kNN（k=3）——只要每類標了幾張就開始有用，秒回、不用等訓練。

  • 按「自動標記」→ 未標記的縮圖出現虛線框建議（NG? 87%）→「接受全部」批次寫入，或個別點掉重標。
  • 自動標記的樣本記為 labeled_by=auto（縮圖上有 ~87% 標示、可用篩選「自動標記（待確認）」複查）；人工改標後轉為 human。
  • 只有 human 標記會拿來當 kNN 參考，避免自動標記自我增強。

3. 伺服端資源與裝置設定

訓練與推論都用伺服器的資源。頁面頂端顯示偵測到的加速器與 GPU（GET /dl/devices）：

4. shapes 標記編輯器（分割／偵測）

label_mode=shapes 的模型（語意分割、實例分割）用標記編輯器：一張影像多個 polygon／bbox 實例，各有類別。座標一律 0~1 正規化儲存（與 YOLO txt 一致），只在畫布上換算像素。

  • 編輯：畫布左側是大圖示工具欄（選取／多邊形／框／自動優化／刪除／還原，各鈕標示快捷鍵），上方是狀態列（上一張/下一張、樣本尺寸、標記數、繪製提示、未儲存指示、快捷鍵說明、儲存）與大顆類別按鈕（色點＋數字鍵標示＋計數）。
  • 多邊形＝逐點繪製，點數不限：按 N（或工具欄）後每點選加一個頂點，畫面即時顯示折線與到游標的虛線；雙擊、點回第一點或按 Enter 閉合，Backspace 退一點、Esc 取消。完成後自動回到選取模式並選中新形狀，可再拖曳頂點、雙擊邊線插點、Alt+點刪點微調。方框（B）維持拖曳畫出。
  • 智慧選取（SAM 點擊出輪廓）：按 S（魔杖）後點選物件，伺服端用 SAM 分割出輪廓、簡化成 polygon 掛上目前類別，可連續點下一個物件；Ctrl+Z 可還原。權重預設 mobile_sam.pt（約 40MB，第一次使用自動下載到 ASSET_DIR/dl/weights/）；需要 pip install ultralytics onnx onnxslim（與 yolo_seg 同一套可選依賴，缺件會提示指令）。
  • 其他操作：Delete 刪形狀、Ctrl+Z 還原、Ctrl+S 儲存（切換影像會攔未儲存變更）；快捷鍵 V/N(P)/B/S/O、←/→ 換張、0~9 指定類別。
  • 自動優化（輪廓貼邊）：前端純 JS——在降到最長邊 1280 的灰階梯度圖上，沿各頂點法線搜尋最強邊緣（帶位移懲罰）、迭代 3 次並平滑、Douglas–Peucker 簡化到 ≤120 點。不自動儲存，Ctrl+Z 可還原。
  • 縮圖牆巡檢：左側縮圖直接畫上標記輪廓，快速看出哪些張標壞了；有自動標記建議的顯示「?」。
  • 自動標記：shapes 模式的建議是整張圖的形狀集合（半透明畫在編輯器與縮圖上），可單張「接受建議」或整批接受；接受後記為 auto 待人工複查。

5. 資料集管理（去重、分割、版本）

  • 重複偵測：每張樣本存「解碼後像素的 SHA256」（DlSample.sha256），上傳／zip 匯入／從來源連抓／資料夾匯入都在同專案內去重，回報 duplicates 數；靜態畫面連抓 N 張只會留一份。
  • train/val/test 分割：右欄「資料集」面板顯示各分割張數；「自動分割」輸入驗證與測試比例後分層隨機指派（classes 依類別、shapes 依有無標記；會重新指派全部樣本）。個別樣本可在標記工作區狀態列點分割 chip 循環切換（訓練→驗證→測試→未指定），縮圖網格也有角標、篩選下拉可只看某個分割。
  • 訓練如何用分割：指定 val 的樣本當驗證集（沒指定就按 val 比例隨機）；指定 test 的樣本不進訓練（保留給訓練後的盲測，指標會回報 test_holdout）。yolo_seg 匯出暫存資料集時同樣尊重指定（未指定者隨機補 val）。
  • 版本凍結：「凍結」把當下的樣本＋標記＋分割匯出成 zip 存進資產庫（kind=dataset）並記錄統計（總數／各類張數／分割數）——shapes 專案是 YOLO 樹（images/labels/{train,val,test}+data.yaml）、classes 專案是類別資料夾＋manifest.json。版本清單可下載 zip 或刪除（zip 一併刪）。

資料增強（超參數的「增強」群組，預設關閉不影響既有行為）：mlp_classify 開啟後訓練集加入水平翻轉＋亮度 ±擾動副本（驗證集不動，指標回報 augmented 張數）；patch_segment 每張追加水平翻轉版本的取樣（標記同步翻轉）；yolo_seg 直接曝露 ultralytics 的 degrees／fliplr／mosaic。

訓練面板會顯示 loss／mAP 曲線（分割任務優先 (M) mask 指標；fitness 可能 > 1，座標軸自動縮放）與增量訓練 log（環形緩衝 400 行，GET /dl/train/status?log_from=N）。

7. YOLO 資料集匯出／匯入（與 VisionStereo 互通）

標記存 DB，但可與 YOLO txt 資料集雙向互通（格式相容 VisionStereo 的網頁標註工具：TAB 分隔、LF 換行、utf-8-sig 讀、6 位小數；5 欄=bbox、≥7 欄偶數座標=polygon）：

POST /api/vision/dl/projects/{id}/dataset-export   {"dir": "D:/TrainingImage/NEW", "val_ratio": 0.2}
POST /api/vision/dl/projects/{id}/dataset-import   {"dir": "D:/TrainingImage/ATD3"}
  • 匯出：images/labels/{train,val}＋data.yaml（已存在的 data.yaml 不覆寫）；寫完自動清 labels/*.cache（ultralytics 的快取坑）。
  • 匯入：接受 root/ 或 root/dataset/ 佈局、任何 split 子資料夾；data.yaml 的類別若專案沒有會自動補進類別清單，重複影像（像素雜湊）會略過。
  • 前端入口：右欄「資料集」面板的「匯出 YOLO／匯入 YOLO」（shapes 專案；填伺服器主機上的資料夾路徑）。
項目內容
kindmlp_classify（標記模式 classes；訓練產物給 dl_classify 用）
做法樣本 resize 到輸入尺寸（32～128）→ RGB、ImageNet mean/std（與工具預設一致）→ 單隱藏層全連接網路，numpy 全批次梯度下降，分層切驗證集
匯出手刻 ONNX（Flatten→MatMul→Add→Relu→MatMul→Add，權重進 initializer；apps/vision/dl/onnx_io.py，不引入 onnx／torch 依賴）
超參數輸入尺寸、隱藏層寬度、訓練回合、學習率、驗證比例（都有合理預設）
適用外觀類別區分（正反面、型號、明顯瑕疵有無）。特徵是原始像素，光照位移變化大的場景請靠 ROI 裁切與較大的輸入尺寸。

8. 擴充：新的模型種類（Trainer）

與工具／來源／連線同一套模式：繼承 apps.vision.dl.base.Trainer，丟進 plugins/ 即掛載（見擴充外掛）。前端的專案建立、標記、超參數表單、訓練面板全部由 GET /dl/trainers 目錄驅動——加新模型不用改前端。

# plugins/my_trainer.py — 丟進 plugins/ 即掛載
from apps.vision.dl.base import SampleRef, Suggestion, Trainer, TrainError, TrainResult
from apps.vision.tools.base import Param

class MyTrainer(Trainer):
    kind = "my_model"
    label = "我的模型"
    description = "…"
    label_mode = "classes"        # 封閉集合：classes（整張一類）| shapes（多個 polygon/bbox 實例）
    tool_key = "dl_classify"      # 訓練產物給哪個工具用
    devices = ("cpu", "cuda")     # 支援的訓練裝置（會與伺服器實際資源取交集）
    params = [Param("epochs", "訓練回合", kind="number", default=100)]

    def train(self, samples, classes, params, device, progress):
        # progress(0~1, "階段", metrics)：定期呼叫；取消時它會拋 TrainCancelled
        ...
        return TrainResult(onnx_bytes=..., metrics={...}, tool_key="dl_classify",
                           tool_params={"labels": "\n".join(classes), ...})

    def suggest(self, labeled, unlabeled, classes, params):  # 自動標記（選配）
        return [Suggestion(sample_id=s.id, label="OK", score=0.9) for s in unlabeled]
  • 訓練用 torch 等重依賴時附 requirements.txt（整合考量）；在 train() 內 lazy import，缺件時拋 TrainError 附安裝提示。
  • 產物必須是 ONNX bytes——這是「訓練」與「推論」的唯一合約：推論端永遠走 onnxruntime，trainer 想用什麼框架訓練都行。
  • label_mode 是封閉集合：要加 boxes（物件偵測標記）時，後端集合與前端標記介面同步擴充，其他 UI 照舊共用。

10. 內部結構與設計取捨

  • apps/vision/dl/：base.py（Trainer registry）、builtin.py（MLP 分類＋輕量語意分割）、yolo.py（YOLO-seg，延後 import）、shapes.py（shapes 驗證／YOLO txt 互轉／rasterize／資料集匯出入）、onnx_io.py（手刻 ONNX，含 Conv 與 initializer）、sam.py（SAM 點擊智慧標記，延後 import、session 快取）、devices.py、jobs.py（訓練工作＋history＋log 環形緩衝）、api.py。前端 DlPage.tsx＋components/dl/ShapeWorkspace.tsx（重用 ImageViewer 的 ROI 編輯）＋components/dl/optimize.ts（輪廓貼邊）。
  • 資料模型：DlProject／DlSample（影像檔在 ASSET_DIR/dl/<project_id>/，中文路徑用 imencode+tofile；sha256 去重、split 分割）／DlDatasetVersion（版本統計＋asset_id）／DlSettings（單列）。
  • 對照 Roboflow 式規格（Temp/gemini-code）的取捨：功能照做（去重、分割、版本、增強、SAM 點擊標記、訓練指標），但架構落在既有紅線內——Celery+Redis → 單一訓練槽背景執行緒（教導期行為不需要佇列與新基礎設施）；React-Konva → 既有自製雙層 canvas ImageViewer；DRF → 既有 django-ninja；SQLite WAL 與 0~1 正規化 JSON 座標本來就是平台慣例。Grounding DINO 文字提示與 TorchScript 匯出不做（auto-label 已由各 trainer 的 suggest() 涵蓋；ONNX 是訓練↔推論唯一合約），需要時走外掛 trainer。
  • 單一訓練槽：一次一個訓練（背景執行緒，不進檢測執行緒池），第二個回 409。訓練是教導期行為，不需要佇列；進度用輪詢（700ms），不進 SSE bus。
  • providers 是熱路徑設定：dl 工具建 session 只讀記憶體快取（devices.preferred_providers()）；DB 只在啟動與設定端點碰，改設定會 clear_sessions() 重建。
  • 不引入 torch：內建 trainer 用 numpy 訓練、手刻 ONNX 匯出，平台依賴不變；重框架留給外掛 trainer（自帶 requirements 或 sidecar）。
  • 測試 tests/test_dl_teach.py：ONNX 匯出＋dl_classify 端到端、樣本不足、自動標記正確率、API 標記流、背景訓練工作（TransactionTestCase）、split／augment 訓練行為、去重與 zip 匯入、自動分割、版本凍結、SAM 缺件提示。
