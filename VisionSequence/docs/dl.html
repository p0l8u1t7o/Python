深度學習教導：平台內標記、訓練、匯出

「深度學習」頁（/dl）讓使用者不出平台完成一輪教導：建立教導專案 → 收集樣本（上傳或從影像來源連抓）→ 標記（含自動標記加速）→ 在伺服端訓練（可看 GPU／加速器資訊並選擇裝置）→ 模型自動匯出成資產，在流程的「DL 分類」等工具直接選用。模型種類（trainer）是 registry，之後導入其他深度學習模型共用同一套 UI，前端不用改。

1. 教導流程（使用者視角）

  1. 建立教導專案：取名、選模型種類、定義類別（例如 OK, NG；之後可隨時增減）。
  2. 收集樣本：「上傳影像」（多選）或「從來源取像」（選影像來源連抓 N 張，可預先標記）。
  3. 標記：點一個類別 chip，再點縮圖即標記；再點一次取消；Alt＋點刪除樣本。每類的張數顯示在 chip 上。
  4. 訓練：右側面板調超參數（表單由 trainer 的宣告產生）、選裝置、給模型資產名稱 → 開始。進度條與指標（訓練／驗證正確率）即時更新；訓練跑在背景，不占用檢測執行緒池。
  5. 使用：完成後模型出現在資產庫（kind=model），流程裡加「DL 分類」工具、選這個模型、labels 貼上類別清單即可（trainer 會回報建議參數，內建分類器與工具預設前處理完全一致，其餘參數用預設值就對）。

2. 自動標記

標記是導入最花時間的一步，所以每個 trainer 可實作 suggest()：對未標記樣本提出「建議類別＋信心分數」。內建分類器用特徵空間的 cosine kNN（k=3）——只要每類標了幾張就開始有用，秒回、不用等訓練。

  • 按「自動標記」→ 未標記的縮圖出現虛線框建議（NG? 87%）→「接受全部」批次寫入，或個別點掉重標。
  • 自動標記的樣本記為 labeled_by=auto（縮圖上有 ~87% 標示、可用篩選「自動標記（待確認）」複查）；人工改標後轉為 human。
  • 只有 human 標記會拿來當 kNN 參考，避免自動標記自我增強。

3. 伺服端資源與裝置設定

訓練與推論都用伺服器的資源。頁面頂端顯示偵測到的加速器與 GPU（GET /dl/devices）：

欄位內容
providers此伺服器的 onnxruntime execution providers（CPU／CUDA／DirectML／TensorRT…，依安裝的 onnxruntime 套件而定）。
gpusNVIDIA GPU 名稱、記憶體用量、使用率（有 nvidia-smi 才有；查不到就空）。
preferred_providers／train_device使用者目前的選擇（PATCH /dl/settings，管理員）。
  • 推論：preferred_providers 決定 dl_* 工具建 ort session 的 providers（自動過濾不可用者、CPU 墊底）；改設定會清掉 session 快取立即生效。要用 GPU 推論，把 onnxruntime 換成 onnxruntime-gpu（或 onnxruntime-directml）後在此選擇。
  • 訓練：裝置下拉列出伺服器可用且該 trainer 支援的裝置（trainer 宣告 devices；內建 MLP 為 CPU，數秒內完成）。

4. 內建模型：影像分類（MLP）

項目內容
kindmlp_classify（標記模式 classes；訓練產物給 dl_classify 用）
做法樣本 resize 到輸入尺寸（32～128）→ RGB、ImageNet mean/std（與工具預設一致）→ 單隱藏層全連接網路，numpy 全批次梯度下降，分層切驗證集
匯出手刻 ONNX（Flatten→MatMul→Add→Relu→MatMul→Add，權重進 initializer；apps/vision/dl/onnx_io.py，不引入 onnx／torch 依賴）
超參數輸入尺寸、隱藏層寬度、訓練回合、學習率、驗證比例（都有合理預設）
適用外觀類別區分（正反面、型號、明顯瑕疵有無）。特徵是原始像素，光照位移變化大的場景請靠 ROI 裁切與較大的輸入尺寸。

5. 擴充：新的模型種類（Trainer）

與工具／來源／連線同一套模式：繼承 apps.vision.dl.base.Trainer，丟進 plugins/ 即掛載（見擴充外掛）。前端的專案建立、標記、超參數表單、訓練面板全部由 GET /dl/trainers 目錄驅動——加新模型不用改前端。

# plugins/my_trainer.py — 丟進 plugins/ 即掛載
from apps.vision.dl.base import SampleRef, Suggestion, Trainer, TrainError, TrainResult
from apps.vision.tools.base import Param

class MyTrainer(Trainer):
    kind = "my_model"
    label = "我的模型"
    description = "…"
    label_mode = "classes"        # 封閉集合：classes（boxes 保留給未來偵測）
    tool_key = "dl_classify"      # 訓練產物給哪個工具用
    devices = ("cpu", "cuda")     # 支援的訓練裝置（會與伺服器實際資源取交集）
    params = [Param("epochs", "訓練回合", kind="number", default=100)]

    def train(self, samples, classes, params, device, progress):
        # progress(0~1, "階段", metrics)：定期呼叫；取消時它會拋 TrainCancelled
        ...
        return TrainResult(onnx_bytes=..., metrics={...}, tool_key="dl_classify",
                           tool_params={"labels": "\n".join(classes), ...})

    def suggest(self, labeled, unlabeled, classes, params):  # 自動標記（選配）
        return [Suggestion(sample_id=s.id, label="OK", score=0.9) for s in unlabeled]
  • 訓練用 torch 等重依賴時附 requirements.txt（整合考量）；在 train() 內 lazy import，缺件時拋 TrainError 附安裝提示。
  • 產物必須是 ONNX bytes——這是「訓練」與「推論」的唯一合約：推論端永遠走 onnxruntime，trainer 想用什麼框架訓練都行。
  • label_mode 是封閉集合：要加 boxes（物件偵測標記）時，後端集合與前端標記介面同步擴充，其他 UI 照舊共用。

6. API

GET    /api/vision/dl/trainers                     模型種類目錄（前端表單由此產生）
GET    /api/vision/dl/devices                      providers／GPU 資訊＋目前設定
PATCH  /api/vision/dl/settings                     管理員 {"providers": [...], "train_device": "cpu"}
GET    /api/vision/dl/projects                     專案清單（含 counts）
POST   /api/vision/dl/projects                     {"name", "trainer_kind", "classes": [...]}
GET/PATCH/DELETE /api/vision/dl/projects/{id}      classes 移除類別會把該類樣本改回未標記
GET    /api/vision/dl/projects/{id}/samples        ?label= 篩選
POST   /api/vision/dl/projects/{id}/samples        multipart files[]（可帶 label）
POST   /api/vision/dl/projects/{id}/samples/from-source   {"source_id", "count", "label"?}
GET    /api/vision/dl/samples/{id}/file            縮圖（?max=；<img> 用，token 走 query）
PATCH  /api/vision/dl/samples/{id}                 {"label": "..."}（"" = 取消標記）
DELETE /api/vision/dl/samples/{id}
POST   /api/vision/dl/projects/{id}/labels         批次標記 {"items": [{"id","label","score"?,"by"?}]}
POST   /api/vision/dl/projects/{id}/auto-label     → 建議清單（不落地；接受才寫入）
POST   /api/vision/dl/projects/{id}/train          202 {"params", "device", "asset_name"}；訓練中回 409
GET    /api/vision/dl/train/status                 輪詢進度（progress／stage／metrics）
POST   /api/vision/dl/train/cancel

權限：讀取／標記／訓練 = 任何登入者（整合方金鑰亦可）；訓練另過 can_execute()（引擎鎖定時 423）；裝置設定 = 管理員。

7. 內部結構與設計取捨

  • apps/vision/dl/：base.py（Trainer registry）、builtin.py（MLP 分類）、onnx_io.py（手刻 ONNX）、devices.py、jobs.py（訓練工作）、api.py。前端 frontend/src/pages/DlPage.tsx（超參數表單直接重用編輯器的 ParamField）。
  • 資料模型：DlProject／DlSample（影像檔在 ASSET_DIR/dl/<project_id>/，中文路徑用 imencode+tofile）／DlSettings（單列）。
  • 單一訓練槽：一次一個訓練（背景執行緒，不進檢測執行緒池），第二個回 409。訓練是教導期行為，不需要佇列；進度用輪詢（700ms），不進 SSE bus。
  • providers 是熱路徑設定：dl 工具建 session 只讀記憶體快取（devices.preferred_providers()）；DB 只在啟動與設定端點碰，改設定會 clear_sessions() 重建。
  • 不引入 torch：內建 trainer 用 numpy 訓練、手刻 ONNX 匯出，平台依賴不變；重框架留給外掛 trainer（自帶 requirements 或 sidecar）。
  • 測試 tests/test_dl_teach.py：ONNX 匯出＋dl_classify 端到端、樣本不足、自動標記正確率、API 標記流、背景訓練工作（TransactionTestCase）。
