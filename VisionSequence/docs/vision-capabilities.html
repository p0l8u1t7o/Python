Inspection capabilities: ROIs, image formats, tools

Measured against what a mainstream machine-vision package offers: which ROI shapes the platform has and how they are implemented, how multiple bit depths are handled, and how each class of inspection maps onto a tool here — including what was added recently and what is deliberately left out.

1. ROI shapes and how they work

The ROI palette covers the shapes the industry expects. A region is a free-form dict — the header of tools/roi.py is the only definition of the format — and every tool goes through the same helpers: bounding_rect, mask_for, crop, region_overlay, region_center and transform_region. On the front end, roiEditor.ts and geometry.ts handle drawing, handle editing and hit testing.

Any ROI can also arrive through the region input port — that is how ROI follow works after a locate step — and transform_region() translates and rotates every shape.

2. Image formats and bit depth

The image types a machine-vision package deals with are grayscale U8, I16 and float, complex, RGB U32, HSL U32 and RGB U64. The platform maps them onto numpy dtypes (tools/imgfmt.py):

Common typeHereNotes
Grayscale U8 / RGB U32uint8 (HxW or HxWx3 BGR)The default; every tool supports it
Grayscale I16uint1616-bit PNG and TIFF are read and kept as they are; signed 16-bit is treated as unsigned with an offset
RGB U64uint16 ×3 (BGR)16 bits per channel
Grayscale floatfloat32Floating-point TIFF, FFT and calibration intermediates
HSL U32— (an encoding)No native storage needed: color_convert pulls out H, S, L or V, and color_stats reports HSV statistics
Complex— (inside a tool)Used inside fft_filter only; it never travels along the graph

The seam that makes this safe: a tool declares what it can take with Tool.accepts = ("u8", …), and ToolContext.image() normalises anything else with normalize_u8 — u16 shifted right by 8 (linear and predictable), floats min-max scaled — into a new array, never touching the input. So no tool blows up on an unexpected depth. Tools whose underlying algorithm handles more depths natively (crop, resize, blur, morphology, arithmetic, apply_mask, grayscale, rotate_flip, save_image, convert_depth, fft_filter, line_profile, warp_perspective) declare the wider set and pass the data through untouched. On the display side encode_image has always normalised before encoding. Use the bit-depth conversion tool when you want to control the conversion yourself.

4. Deliberately left out, or left to a plugin

  • Geometric matching, colour pattern matching, colour location: large algorithms, and template_match together with the deep-learning tools already covers most of what they are used for. Bring one in as a plugin tool when you need it (Plugins).
  • OCR and character verification, instrument readers (meters, LCDs): the modern answer is deep learning — train one on the teaching page, or plug in an OCR engine. text_presence covers the lightweight "is anything printed here" check.
  • Hand-eye calibration for a moving camera (camera on the robot arm): the platform calibrates a fixed camera against the plane the parts sit on, which is what an inspection station needs. A camera that travels with the arm needs the robot pose at each shot, so that pairing belongs to the robot program; feed the pairs in as robot points per position, or do it in a plugin.
  • Freehand ROIs: see §1.
  • The complex image type: it exists only inside fft_filter and is not a port type, which keeps the dataflow simple.

5. 量測精度與演算法慣例

以資深視覺工程師的角度用「已知真值」的合成影像稽核各工具後修正的項目，與所有工具共同遵守的慣例。稽核與鎖定用的測試在 tests/test_tools.py AlgorithmAccuracyTests。

項目問題做法效果（合成真值）
圓／圓弧擬合Kåsa 代數最小平方對部分圓弧有系統性偏差：60° 弧＋0.5px 噪點半徑少約 1px，30° 弧可差十幾 px；R 角、杯口圓角量測直接受害。fit_circle_lsq 改為 Taubin 代數解起始＋Gauss–Newton 最小化徑向距離（幾何擬合）；RANSAC 內點精修同樣走這條。原 Kåsa 保留為 fit_circle_kasa。60° 弧平均偏差 −0.97 → +0.10px；90° 弧 −0.23 → −0.03px；整圈不變。
扇形圓環 ROIannulus 的 a0/a1 起迄角只用在遮罩，徑向掃描仍掃整圈，只有一段弧的工件會撿到不該撿的邊緣。radial_edge_points／sector_thetas：掃描線只落在扇形內、含兩端；掃描線數＝扇形內的條數。−30°～30° 扇形 90 條線全部在扇形內（原本 360° 分佈）。
重掃精修（refine）掃描線從 ROI 中心（多邊形則是頂點平均）發射；偏心時斜切邊緣、多邊形楔形的頂點平均常落在工件外（極性無從定義、甚至掃不到邊）。擬合後若中心偏離掃描原點 > 0.5px，從擬合中心再掃一次（掃描線與邊緣垂直）再擬合；多邊形第一次掃描不分極性，重掃才套用極性。find_circle／fit_arc／fit_ellipse 都有 refine（預設開）。多邊形楔形 60° 弧：半徑誤差 +1.40 → −0.20px；部分弧橢圓從擬合失敗（0 點）到 a/b 誤差 < 0.2px。
範本比對次像素位置取相關圖整數峰值、角度只到角度步進（5° 步進最差差 2.5°）。subpixel（預設開）：位置以 3×3 拋物線內插；有旋轉搜尋時以相鄰兩個角度的分數拋物線內插角度，再於精修角度重新比對。位移 0.5px 誤差 0.50 → 0.04px；角度 7° 誤差 2.0 → 0.07°（步進 5°）。
角度慣例template_match 的角度沿用 cv2.getRotationMatrix2D（畫面逆時針為正），與 ROI 旋轉矩形、找直線（atan2、畫面順時針為正）相反；經定位補正餵給 ROI 跟隨後旋轉方向相反，10° 時 80px 外的特徵偏 28px。全平台統一：影像座標 y 向下，角度正值＝畫面順時針。範本旋轉改以 −angle 呼叫 getRotationMatrix2D，best_angle／matches[].angle／shape_align.dtheta／fixture_roi／overlay 的 angle 全部同向。定位鏈跟隨誤差 27.8 → 0.0px（test_locate_chain_direction）。
卡尺邊緣對四種取邊緣對模式都以位置或強度挑，低對比的條旁邊有高對比雜訊邊時全部挑錯。新增 pair_polarity（亮條＝先暗→亮再亮→暗、暗條相反）與 expected_width（挑寬度最接近期望值的一對，優先於模式）。寬 20px 低對比亮條旁有 0/255 雜訊線：四種模式 72／72／2.9／2.9 → 期望寬度 20.0。
Blob 面積cv2.contourArea 是輪廓多邊形幾何面積，小粒子少算約半個周長：1 像素粒子是 0、2×2 是 1、3×3 是 4；min_area 篩選連帶錯。面積改為連通元件像素數（connectedComponentsWithStats），與粒子分析軟體一致；含孔洞（預設／填洞）時只對帶洞的 blob 填輪廓數像素。圓形度仍用輪廓幾何面積與周長（同一套定義才自洽）。1／4／9／25／81 像素粒子從 0／1／4／16／64 變成正確值。
非矩形 ROI 的 Otsu圓／多邊形 ROI 的 Otsu 在外框矩形上算，落在 ROI 外的其他灰階（白邊、背板）會拉走門檻。Otsu 改以遮罩內直方圖計算（tools/hist.py），再套固定門檻。低對比物件旁有白邊：0 個 → 1 個 blob。
分離黏連粒子分水嶺種子用「距離轉換 ≥ 全圖最大值一半」：大小粒子混在一起時小粒子沒有種子，兩顆等大重疊的粒子頸部 > 半徑一半時也切不開。種子改為距離轉換的區域極大值（視窗依 min_area 推算的粒子半徑），先膨脹再取連通元件避免長條粒子沿中軸過度切割。r=40 一顆＋r=10 兩顆黏連：2 → 3 個；只有兩顆小粒子：1 → 2 個；長條矩形仍是 1 個。
FFT 高通反轉換取絕對值，把負響應翻正：階梯邊緣兩側都變亮，看不出方向。取實部；高通以中灰（u8 128／u16 32768）為零點，浮點保留帶號。邊緣兩側 12…70｜70…12 → 115…57｜198…140。
HSV 顏色距離灰／低飽和色的色相是亂數，灰目標對灰區域距離仍有 15。色相差以兩者較低的飽和度加權。#808080 對 (130,128,126)：15.1 → 2.1；紅對綠仍不符。
橢圓擬合cv2.fitEllipse（最小平方）對部分弧偏差大。改用 cv2.fitEllipseDirect（Fitzgibbon），失敗才退回。100° 弧：a/b 誤差 < 0.2px。

已驗證無需修改

  • 旋轉矩形 ROI 裁切與座標回映（crop(upright=True)／to_full）：找直線在 0°／30°／−20°／90° ROI 下法向偏移 ≤ 0.02px，沒有半像素偏差。
  • find_circle 置中時圓心誤差 < 0.05px、半徑誤差 < 0.03px（σ=3 噪聲）。
  • defect_diff 的相位相關對齊能吸收 0.5～1px 次像素位移（假缺陷 0 個），只有「不對齊」在 1px 位移時會產生邊緣假缺陷。

合成真值的注意事項

  • cv2.circle／cv2.ellipse 實心繪製會多含 1px 外框，半徑比參數大約 0.5px；做精度測試要用解析式覆蓋率（clip(r + 0.5 − dist)）或 8× 超取樣後 INTER_AREA 縮小。
  • 像素中心在整數座標：繪圖、cv2.remap 取樣、次像素邊緣位置都用同一慣例，找直線在 x=200.35 的邊回傳 200.35。
