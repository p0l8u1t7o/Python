主動輸出（Modbus TCP ／ 上位機）

自動化整合是被動的：設備或上位機呼叫我們拿結果。這一頁是主動的：流程跑完由引擎透過 Modbus TCP 把判定與量測值寫進設備的線圈／暫存器，或推一行文字給上位機。做法仿照影像來源：先在設定頁建「連線」（Connection），流程裡放一個 寫入 Modbus（write_modbus）工具指到該連線並填對映表。

0. 兩種角色：主站與從站

Modbus/TCP 有主從之分，平台兩種都支援，在「外部整合 ▸ 連線」建立時選 kind：

角色kind誰主動什麼時候用
主站（client）modbus_tcp平台連到設備的 IP／埠PLC／設備本身是 Modbus 從站，平台去讀寫它的線圈與暫存器。
從站（server）modbus_server平台開埠（預設 5020）等主站來連PLC／上位機是主站，習慣自己來輪詢。流程把結果寫進平台的暫存器讓主站來取；主站也可以寫料號、觸發旗標進來，流程用「讀取 Modbus」取用。

兩種角色的位址格式、對映表與工具完全相同，差別只在誰主動連線。從站的 size 是每一區（線圈／離散輸入／保持暫存器／輸入暫存器）的點數，預設 512。

從站會自己開埠：連線建立或修改時立刻監聽，伺服器啟動時也會自動開（manage.py serve 呼叫 writers.autostart()；--no-comm 可關掉）。PLC 不必等有人到網頁按「測試」。埠被其他程式佔用時連線狀態會直接寫出原因。停用或刪除連線就關閉。

1. 連線種類與 config

kind用途config
modbus_tcpModbus TCP：線圈（DO）與保持暫存器（數值）。用 pymodbus。 
{"host": "192.168.1.10", "port": 502, "unit_id": 1,
 "timeout_s": 2, "word_order": "big"}
word_order：32/64 位元值的高低字組順序（多數設備是 big；有些是 little）。
tcp_client長連線把結果送到上位機：一行文字（範本）或整包 JSON 一行。 
{"host": "192.168.1.20", "port": 5000, "timeout_s": 2,
 "template": "RESULT {judge} {width_px}",
 "newline": "\n", "encoding": "utf-8", "wait_reply": false}
沒有 template 就送 {"judge": 1, "width_px": 12.3}\n。範本缺欄位補空字串，不會炸。wait_reply=true 會等對方回一行，放進結果 reply。
dio_sim模擬 DIO：只把寫入值留在記憶體，供沒有設備的機器測流程；GET /state 讀回。 
{"channels": ["ok", "ng", "done"]}   或   {"channels": 8}
有列 channels 時寫到未宣告的通道算失敗（方便測降級）；不列則任何名稱都收。
plugin / 外掛 kind自訂 Writer（OPC UA、廠牌 SDK…）繼承 Writer 的 .py 丟進 plugins/ 自動掛載（出貨範例：CSV 紀錄），見 6 與擴充外掛。

共用欄位：timeout_s（每次寫入的逾時，預設 2 秒）。連線設定改了（PATCH）會關閉舊連線，下次執行重開。

1-1. 觸發：PLC 寫旗標，平台就檢測

從站模式下 PLC 是主站——它只會寫暫存器，不會呼叫平台的 HTTP／TCP。沒有這一層的話，PLC 把觸發旗標寫進來不會有任何事發生，整條線只能改用連續模式輪詢（每一輪都取像，白白吃掉相機頻寬與 CPU）。所以兩種 Modbus 連線都可以設定一個觸發位址：

{"host": "0.0.0.0", "port": 5020, "unit_id": 1, "size": 512,
 "trigger_address": "coil:0",        ← 主站寫成非零就檢測一次
 "trigger_flow": "外觀檢測",          ← 流程名稱或 id（停用的流程不會被觸發）
 "trigger_interval_ms": 50,           ← 輪詢間隔，最小 10
 "trigger_mode": "rising",            ← rising＝0 變非零才跑一次；nonzero＝只要非零就一直跑
 "trigger_clear": true,               ← 跑之前把旗標清成 0（跑很久也不會重複觸發）
 "trigger_done_address": "coil:1",    ← 跑完寫 1（選填）
 "trigger_recipe": ""}                ← 指定配方（選填）

一次完整的握手：

PLC ：trigger := 1
平台：看到 → 清 trigger → 跑流程 → 流程用「寫入 Modbus」把判定與量測值寫進暫存器 → done := 1
PLC ：看到 done → 讀結果 → done := 0
  • 結果由流程自己寫：在流程尾端放「寫入 Modbus」節點，對映表想寫幾個值都可以。觸發設定只負責清旗標與設定完成位址。
  • 一條連線一條輪詢執行緒，只做「讀一個位址」；流程本身照樣走 Runner，統計、事件與歷史與其他觸發來源完全一致（trigger 記成 modbus）。
  • PLC 斷線時輪詢會指數退避（最多 5 秒）並持續重試，連線回來就自動繼續；失敗次數與最後原因在連線狀態的 trigger 欄位。
  • 主站模式（modbus_tcp）同樣可用：輪詢 PLC 自己的暫存器當觸發源。
  • 觸發與流程的執行都會進「命令與結果」（見 6b），除錯時看得到每一次觸發跑了多久、判定是什麼。

2. 位址格式（modbus_tcp）

位址意義
coil:10線圈 10（bool）。別名 co:、c:。
holding:100保持暫存器 100，uint16（浮點會四捨五入、超出 0～65535 會夾住）。別名 hr:、register:。
holding:100:int16 / uint16 / int32 / uint32 / int64 / uint64 / float32 / float64指定型別；32 位元佔 2 個暫存器、64 位元佔 4 個，字組順序依連線的 word_order。
discrete:3、input:7離散輸入／輸入暫存器，唯讀（只有 read 與 /state 用得到；寫入會回錯）。

偏移可寫十六進位（holding:0x100）。偏移是 0 起算的協定位址（設備文件若寫 40001 就是 holding:0）。

tcp_client 的「位址」是範本裡的欄位名（{judge} → "judge"）；dio_sim 是通道名。

3. 流程工具：write_modbus 與 read_modbus

參數說明
connection（text）連線名稱（也接受數字 id）。
mapping（json）陣列，每項一個位址，見下。
on_error（select）warn（預設）：寫入失敗只記警告、run 照常；fail：讓 run failed。
timeout_s（number）0 = 用連線設定；否則覆寫這一次寫入的逾時。

輸入埠 values（any，可多條）；輸出埠 written（寫入筆數）、ok（bool）。

[
  {"src": "judge",    "address": "coil:0",              "dtype": "bool"},
  {"src": "width_px", "address": "holding:100:float32", "scale": 1.0},
  {"src": "hole_count", "address": "holding:102"},
  {"src": "v0",       "address": "holding:103:int32",   "scale": 1000, "dtype": "int"},
  {"address": "coil:1", "value": 1}
]
欄位說明
src值的來源：judge（run 判定，OK→1／NG→0）、具名輸出的名稱（output 工具寫進 _outputs 的鍵）、或本節點輸入埠 values 的第 N 條 v0、v1…（依連線順序）。
address目的地位址（省略時等於 src，tcp_client 常這樣用）。
dtypebool／int／float：寫入前的型別轉換。modbus 位址本身帶型別時，writer 會再依位址轉一次。
scale、offset值 × scale + offset（例如 mm 換成 µm 的整數：scale: 1000, dtype: int）。
value常數（例如「處理完成」握手位），有 value 就不看 src。

找不到來源的項目略過並記在 detail.missing，其他項照寫；整張表都沒東西可寫時回「沒有可寫的值」（run 仍 ok）。

節點順序：write_modbus 沒有必填輸入，建議把 judge.verdict（或最後一個工具的輸出）接到 values，確保它在判定之後才執行。tcp_client 範例：

template = "RESULT {judge} {width_px} {lot}"
mapping  = [{"src": "judge"}, {"src": "width_px"}, {"src": "lot"}]
→ 送出 "RESULT 1 12.34 A123\n"

3-1. 讀取 Modbus（read_modbus）

把線圈與暫存器的值讀進流程：主站連線是去讀設備，從站連線是讀「主站寫進平台」的值（料號、觸發旗標、配方號）。參數：

參數說明
connection連線名稱（同 write_modbus）。
mapping陣列，每項 {"name": 名稱, "address": 位址, "scale"?: 倍率, "offset"?: 加值}；名稱空白時用位址當名稱。
publish開啟後讀到的值會併進 run 的 outputs（API／TCP 回傳看得到）。
on_error讀取失敗時降級（預設）或讓 run 失敗，與 write_modbus 一致。

輸出埠：values（依 mapping 順序的清單）、value（第一個數值，接判定或分支很方便）、ok。範例：

[
  {"name": "recipe", "address": "holding:0"},
  {"name": "trigger", "address": "coil:1"},
  {"name": "temperature", "address": "holding:10:float32", "scale": 0.1}
]

典型用法：PLC 當主站，把料號寫進 holding:0、觸發旗標寫進 coil:1；流程開頭用 read_modbus 取回料號決定配方，結尾用 write_modbus 把判定寫回 coil:10。

4. 降級策略

產線寧可漏傳一筆也不要停線：寫入失敗預設不讓 run failed。
  • Writer 內部：每次寫入有逾時；失敗會關閉並重連一次再寫，第二次才算失敗（CommError）。
  • 工具：on_error=warn（預設）→ 節點 status=ok、message「寫入失敗（已降級）：…」、輸出 ok=false、節點 log 一筆 warning；run 的判定不受影響。on_error=fail → 節點 error，run failed。
  • 連線不存在／已停用／預先開啟失敗 → 同樣走降級（message 說明原因）。
  • 連線的 info() 累計 writes／errors／reconnects／last_error，設定頁與 GET /connections 看得到。

5. 連線 API

GET    /api/vision/connections/kinds
GET    /api/vision/connections                 任何登入者
POST   /api/vision/connections                 管理員   {"name", "kind", "config", "is_enabled"}
GET    /api/vision/connections/{id}
PATCH  /api/vision/connections/{id}            管理員（設定變更會重開連線）
DELETE /api/vision/connections/{id}            管理員
POST   /api/vision/connections/{id}/test       管理員：重新連線 → {"ok": true, "info": {...}} 或 {"ok": false, "error": "…"}
POST   /api/vision/connections/{id}/write      管理員：手動寫一筆 {"values": {"coil:0": 1, "holding:100:float32": 1.5}}
GET    /api/vision/connections/{id}/state      讀回 ?addresses=coil:0,holding:100（dio_sim 不帶參數回全部通道）

整合方（API 金鑰）視為管理員。test／write 失敗以 200 + ok=false 回，方便整合頁顯示原因。

6. 外掛 Writer

繼承 Writer 的 .py 檔丟進專案根目錄 plugins/ 即自動掛載（不用改 .env；規則與變數見擴充外掛；出貨範例 plugins/example_csv_writer.py）：

# plugins/opcua.py — 丟進 plugins/ 即掛載
from apps.comm.writers import Writer, CommError

class OpcUaWriter(Writer):
    kind = "opcua"
    def __init__(self, config, **kw):
        super().__init__(config, **kw)      # 取得 self.timeout、self._lock、計數器
        self._open()
    def _open(self):  ...                    # 連不上就 raise CommError
    def _write(self, values):                # {address: value} → {"written": n}
        ...
    def _read(self, addresses): ...          # 選填
    def _close(self): ...
    def info(self): return {**super().info(), "endpoint": ...}

只覆寫 _open/_write/_read/_close；lock、逾時、重連一次、計數都在基底的 write()/read()。類別內可用 label／description／enabled 變數控制顯示名稱、說明與是否掛載。也可建 kind=plugin 的連線並在 config 填 "class": "mypkg.opcua:OpcUaWriter" 直接指定類別路徑。

6b. 命令與結果（除錯）

「外部整合 ▸ 連線」與「外部整合 ▸ Modbus」頁下方都有命令與結果：頁面開著時，每一次寫入／讀取（位址、值、耗時、成功與否）與從站收到的主站請求都會即時列出，點一列展開完整內容。頁面關閉後只保留錯誤，不影響產線效能。詳見 自動化整合 §7。

7. 內部結構

  • apps/comm/models.py：Connection(name unique, kind, config JSON, is_enabled, created_at, updated_at)。
  • apps/comm/writers.py：Writer 基底、三個內建 writer、open_connection(model) 快取（updated_at 變才重開）、close_connection、get_writer(name)（純記憶體）、prefetch_connections(compiled)。
  • 熱路徑不碰資料庫：apps/comm/apps.py 在 ready() 把 prefetch_connections 掛進 Runner.prefetch_hooks；Runner 編譯流程時（呼叫者執行緒）掃出 write_modbus 節點的 connection，查 DB 並開好連線放進「名稱 → writer」快取。執行緒池內的工具只呼叫 get_writer(name)。
  • apps/vision/tools/builtin/modbus.py：write_modbus 工具。
  • apps/comm/api.py：連線 API，掛在 /api/vision。
  • 測試 tests/test_comm.py：dio_sim、tcp_client（本機臨時 socket server）、modbus_tcp（pymodbus 的 TCP server 跑在執行緒）、工具降級、Runner prefetch、API。
