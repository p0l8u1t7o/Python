VisionSequence documentation

Everything under docs/ is plain HTML: each page carries its own styling, depends on nothing external, and opens straight in a browser. New documents follow the same pattern and get a link on this page. Development conventions, the verification checklist and the Git rules live in CLAUDE.md at the project root; README.md is the quick start.

Design

DocumentWhat it covers
Workflow designThe thinking behind the platform: why an in-process dataflow DAG rather than a control-flow engine, closed sets and safety boundaries, keeping the database off the hot path, degradation strategy, and the three extension seams.
ArchitectureHow the platform is built: data model, tool framework, graph validation and compilation, the engine, Runner concurrency, image cache, image sources, HTTP/SSE/TCP, the front end, accounts and the engine lock, settings, tests and the pitfalls we hit.

Integration

DocumentWhat it covers
AutomationBeing called: HTTP synchronous runs, one-line TCP commands, live SSE events, pushing images, performance advice, identity and the engine lock.
ModbusCalling out: connection kinds (modbus_tcp client, modbus_server slave, tcp_client, dio_sim, plugins) and their config, address format, the write and read mapping tables, triggering a flow from a PLC flag, degradation, the connection API and writing your own Writer.
Deployment and operationsPutting the platform on a factory PC and keeping it running: install, start at boot, ports and firewall, reverse proxy, accounts and keys, backup and restore, upgrading and rolling back, monitoring, running several stations, disaster recovery and security notes.

Extending

DocumentWhat it covers
Deep-learning teachingLabelling and training inside the platform: teaching projects, sample collection, automatic labelling, server-side training with GPU and provider settings, exporting a model to the asset library. The trainer registry takes plugins, so new model kinds drop in. Also the five YOLO inference tools, the four YOLO trainers, SAM2 click, box and whole-image proposals, and the GPU dependency order that matters.
Capture clientWhen the camera is on another PC or needs a vendor SDK: a downloadable desktop program drives webcams, Basler and IDS cameras where they are and connects out to the server's capture port. Shared memory on the same machine, lossless TCP across machines; channels, ROI, parameters, on-demand grabs and continuous streaming; the "capture client camera" source in the web interface, protocol v1 and the acceptance checklist.
PluginsDrop a file in a folder and it loads: subclass Tool, Grabber or Writer, put it in plugins/ and it is detected automatically. Module-level variables control the display name, description and whether it loads at all; two shipped examples and the rules for writing your own.

Quality

DocumentWhat it covers
Batch testingThe batch page: image sets and the stored per-image results, expected labels and hit rate, data insights and suggested thresholds, re-running after tuning and comparing, writing the result back to the flow, a recipe or a Golden Set, AI consultation and tuning, background execution and retention.
Golden Set and exportGolden Set regression testing (expected results, baselines, the regressed list, the confusion matrix, manage.py regress) and flow export and import (a stable serialisation format, manage.py flow, the export and import API, running it in CI).
PerformanceMeasured figures for the engine and the tools, and the record of what each optimisation bought.
Inspection capabilitiesThe ROI shapes and how they are implemented, image bit depth (8-bit, 16-bit, floating point), and an overview of the inspection tools with their trade-offs.
Sample templatesThe ready-to-run templates seed_demo creates: the synthetic sample images, the tools each one covers, the assets involved and how to rebuild them.
README.md / CLAUDE.mdThe whole picture (features, architecture, code map, data model, API, extension points, settings, deployment) and the development conventions (checklists, module notes, pitfalls) — the entry point on GitHub.
User guideThe complete walkthrough in the order you would actually do things: signing in, sources and assets, editing a flow, the tool page and ROIs, running, the batch page, templates, the AI assistant, deep learning, integration, settings and the FAQ.
AI assistantUpload an image, mark the areas, describe the goal, and get a runnable flow: the offline rule engine and the optional LLM path. Also the global assistant — the chat panel on every page that answers questions from the documentation, edits the flow you are looking at, and consults on batch data.
