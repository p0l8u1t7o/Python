主動輸出到 PLC / 上位機

自動化整合是被動的：PLC 或上位機呼叫我們拿結果。這一頁是主動的：流程跑完由引擎把判定與量測值寫進 PLC 的線圈／暫存器，或推一行文字給上位機。做法仿照影像來源：先在設定頁建「連線」（Connection），流程裡放一個 寫入 PLC（write_plc）工具指到該連線並填對映表。

1. 連線種類與 config

kind用途config
modbus_tcpPLC 線圈（DO）與保持暫存器（數值）。用 pymodbus。 
{"host": "192.168.1.10", "port": 502, "unit_id": 1,
 "timeout_s": 2, "word_order": "big"}
word_order：32/64 位元值的高低字組順序（多數 PLC 是 big；有些是 little）。
tcp_client長連線把結果送到上位機：一行文字（範本）或整包 JSON 一行。 
{"host": "192.168.1.20", "port": 5000, "timeout_s": 2,
 "template": "RESULT {judge} {width_px}",
 "newline": "\n", "encoding": "utf-8", "wait_reply": false}
沒有 template 就送 {"judge": 1, "width_px": 12.3}\n。範本缺欄位補空字串，不會炸。wait_reply=true 會等對方回一行，放進結果 reply。
dio_sim模擬 DIO：只把寫入值留在記憶體，供沒有 PLC 的機器測流程；GET /state 讀回。 
{"channels": ["ok", "ng", "done"]}   或   {"channels": 8}
有列 channels 時寫到未宣告的通道算失敗（方便測降級）；不列則任何名稱都收。
plugin / 外掛 kind自訂 Writer（OPC UA、廠牌 SDK…）{"class": "plugins.opcua:OpcUaWriter", ...} 或用 VISION_COMM_PLUGINS 註冊的 kind，見 6。

共用欄位：timeout_s（每次寫入的逾時，預設 2 秒）。連線設定改了（PATCH）會關閉舊連線，下次執行重開。

2. 位址格式（modbus_tcp）

位址意義
coil:10線圈 10（bool）。別名 co:、c:。
holding:100保持暫存器 100，uint16（浮點會四捨五入、超出 0～65535 會夾住）。別名 hr:、register:。
holding:100:int16 / uint16 / int32 / uint32 / int64 / uint64 / float32 / float64指定型別；32 位元佔 2 個暫存器、64 位元佔 4 個，字組順序依連線的 word_order。
discrete:3、input:7離散輸入／輸入暫存器，唯讀（只有 read 與 /state 用得到；寫入會回錯）。

偏移可寫十六進位（holding:0x100）。偏移是 0 起算的協定位址（PLC 文件若寫 40001 就是 holding:0）。

tcp_client 的「位址」是範本裡的欄位名（{judge} → "judge"）；dio_sim 是通道名。

3. write_plc 工具與 mapping

參數說明
connection（text）連線名稱（也接受數字 id）。
mapping（json）陣列，每項一個位址，見下。
on_error（select）warn（預設）：寫入失敗只記警告、run 照常；fail：讓 run failed。
timeout_s（number）0 = 用連線設定；否則覆寫這一次寫入的逾時。

輸入埠 values（any，可多條）；輸出埠 written（寫入筆數）、ok（bool）。

[
  {"src": "judge",    "address": "coil:0",              "dtype": "bool"},
  {"src": "width_px", "address": "holding:100:float32", "scale": 1.0},
  {"src": "hole_count", "address": "holding:102"},
  {"src": "v0",       "address": "holding:103:int32",   "scale": 1000, "dtype": "int"},
  {"address": "coil:1", "value": 1}
]
欄位說明
src值的來源：judge（run 判定，OK→1／NG→0）、具名輸出的名稱（output 工具寫進 _outputs 的鍵）、或本節點輸入埠 values 的第 N 條 v0、v1…（依連線順序）。
address目的地位址（省略時等於 src，tcp_client 常這樣用）。
dtypebool／int／float：寫入前的型別轉換。modbus 位址本身帶型別時，writer 會再依位址轉一次。
scale、offset值 × scale + offset（例如 mm 換成 µm 的整數：scale: 1000, dtype: int）。
value常數（例如「處理完成」握手位），有 value 就不看 src。

找不到來源的項目略過並記在 detail.missing，其他項照寫；整張表都沒東西可寫時回「沒有可寫的值」（run 仍 ok）。

節點順序：write_plc 沒有必填輸入，建議把 judge.verdict（或最後一個工具的輸出）接到 values，確保它在判定之後才執行。tcp_client 範例：

template = "RESULT {judge} {width_px} {lot}"
mapping  = [{"src": "judge"}, {"src": "width_px"}, {"src": "lot"}]
→ 送出 "RESULT 1 12.34 A123\n"

4. 降級策略

產線寧可漏傳一筆也不要停線：寫入失敗預設不讓 run failed。
  • Writer 內部：每次寫入有逾時；失敗會關閉並重連一次再寫，第二次才算失敗（CommError）。
  • 工具：on_error=warn（預設）→ 節點 status=ok、message「寫入失敗（已降級）：…」、輸出 ok=false、節點 log 一筆 warning；run 的判定不受影響。on_error=fail → 節點 error，run failed。
  • 連線不存在／已停用／預先開啟失敗 → 同樣走降級（message 說明原因）。
  • 連線的 info() 累計 writes／errors／reconnects／last_error，設定頁與 GET /connections 看得到。

5. 連線 API

GET    /api/vision/connections/kinds
GET    /api/vision/connections                 任何登入者
POST   /api/vision/connections                 管理員   {"name", "kind", "config", "is_enabled"}
GET    /api/vision/connections/{id}
PATCH  /api/vision/connections/{id}            管理員（設定變更會重開連線）
DELETE /api/vision/connections/{id}            管理員
POST   /api/vision/connections/{id}/test       管理員：重新連線 → {"ok": true, "info": {...}} 或 {"ok": false, "error": "…"}
POST   /api/vision/connections/{id}/write      管理員：手動寫一筆 {"values": {"coil:0": 1, "holding:100:float32": 1.5}}
GET    /api/vision/connections/{id}/state      讀回 ?addresses=coil:0,holding:100（dio_sim 不帶參數回全部通道）

整合方（API 金鑰）視為管理員。test／write 失敗以 200 + ok=false 回，方便整合頁顯示原因。

6. 外掛 Writer

# .env
VISION_COMM_PLUGINS=opcua=plugins.opcua:OpcUaWriter

# plugins/opcua.py
from apps.comm.writers import Writer, CommError

class OpcUaWriter(Writer):
    kind = "opcua"
    def __init__(self, config, **kw):
        super().__init__(config, **kw)      # 取得 self.timeout、self._lock、計數器
        self._open()
    def _open(self):  ...                    # 連不上就 raise CommError
    def _write(self, values):                # {address: value} → {"written": n}
        ...
    def _read(self, addresses): ...          # 選填
    def _close(self): ...
    def info(self): return {**super().info(), "endpoint": ...}

只覆寫 _open/_write/_read/_close；lock、逾時、重連一次、計數都在基底的 write()/read()。也可不設環境變數、直接建 kind=plugin 的連線並在 config 填 "class": "plugins.opcua:OpcUaWriter"。

7. 內部結構

  • apps/comm/models.py：Connection(name unique, kind, config JSON, is_enabled, created_at, updated_at)。
  • apps/comm/writers.py：Writer 基底、三個內建 writer、open_connection(model) 快取（updated_at 變才重開）、close_connection、get_writer(name)（純記憶體）、prefetch_connections(compiled)。
  • 熱路徑不碰資料庫：apps/comm/apps.py 在 ready() 把 prefetch_connections 掛進 Runner.prefetch_hooks；Runner 編譯流程時（呼叫者執行緒）掃出 write_plc 節點的 connection，查 DB 並開好連線放進「名稱 → writer」快取。執行緒池內的工具只呼叫 get_writer(name)。
  • apps/vision/tools/builtin/plc.py：write_plc 工具。
  • apps/comm/api.py：連線 API，掛在 /api/vision。
  • 測試 tests/test_comm.py：dio_sim、tcp_client（本機臨時 socket server）、modbus_tcp（pymodbus 的 TCP server 跑在執行緒）、工具降級、Runner prefetch、API。
