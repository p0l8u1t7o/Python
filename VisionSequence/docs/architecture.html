0. 一頁總覽

編輯                                   執行                                     觀看
GET /vision/tool-types ──▶ React Flow ──PATCH graph──▶ Flow.graph
                                                         │ compile（依 version 快取）
POST /flows/{id}/run ─┐                                  ▼
TCP "RUN 1"          ─┼─▶ Runner.submit ─▶ ThreadPool(10) ─▶ engine.execute（拓樸順序）
連續模式 loop        ─┘        │ 同流程一次一個 run          │ Tool.execute(ctx) → Result
                               ▼                            ▼
                        EventBus.publish ◀──── RunReport（節點狀態、輸出、overlays、影像 ref）
                               │                            │
                               ├─▶ SSE /flows/{id}/stream   ├─▶ ImageStore（numpy，LRU）→ GET /images/{ref}
                               └─▶ 背景 Persister → FlowRun（摘要）

四句話：

  1. 圖是一份 JSON，存在 Flow.graph，編輯器整份存、引擎整份讀。
  2. 執行在記憶體：一次 run 在執行緒池的一條執行緒內以拓樸順序跑完，影像是 numpy 陣列，不落地。
  3. 工具是 registry：引擎不認識任何工具；前端調色盤與參數表單從 catalogue() 產生，加工具不改前端。
  4. 觀看是推播：結果丟進行程內事件匯流排，SSE 直接送；影像只有被看時才編碼縮圖。

1. 資料模型（apps/vision/models.py）

模型欄位理由
Flowname（唯一）、description、graph JSON、is_enabled、version、continuous_interval_ms整份圖一個欄位；version 每次存圖 +1，Runner 據此重編譯。
FlowRunid(uuid)、flow、flow_version、status(ok/ng/failed)、trigger、duration_ms、nodes 摘要、outputs、error、started_at/finished_at只存摘要，不存影像。背景執行緒批次 bulk_create，每流程保留 KEEP_RUN_ROWS 列。高速產線可 PERSIST_RUNS=0。
ImageSourcename、kind、config JSON、is_enabledkind 決定 Grabber 類別；updated_at 變了才重開設備。
Assetid(uuid)、name、kind(image/model/file)、path、size、meta範本影像、ONNX 模型；檔案在 ASSET_DIR。

graph JSON

{"nodes": [{"id": "blob-1", "type": "blob", "label": "找孔", "description": "", "enabled": true,
            "continue_on_error": false, "color": "", "params": {...}, "position": {"x": 0, "y": 0}}],
 "edges": [{"id": "e1", "source": "gray-1", "source_handle": "image", "target": "blob-1", "target_handle": "image"}]}
  • source_handle／target_handle 是埠 key；空白時 validate_graph 補上第一個埠。
  • 隱含埠：每個可執行節點有輸入 _flow（控制分支）與輸出 _overlays（該節點標記，list）。
  • type: "note" 是註解：不執行、不能被連入；從註解連出的虛線引擎忽略。

2. 工具框架（apps/vision/tools/base.py）

Param(key, label, kind, required, default, help_text, options, unit, minimum, maximum, step, visible_when, shapes, accept, group)
  kind ∈ text | multiline | number | boolean | select | range(滑桿) | roi | source | asset | color | json | expression | output_key
Port(key, label, type, required, multiple, tone)
  type ∈ image | region | number | bool | string | points | contours | matches | list | any | flow
flow_out(key, label, tone)             # 控制分支輸出把手
ToolContext: run_id, flow_id, node, inputs, context, moment, log, asset_path(id), grab(source_id), preview
  .param/.number/.integer/.flag/.image/.require_image/.roi
Result(outputs, overlays, branch, status=ok|ng|error, message, detail, context, overlay_on)
class Tool: key label description category icon params inputs outputs heavy; execute(ctx) -> Result
register(tool) / get(key) / catalogue()

Param.kind 是封閉集合：前端 ParamField 的 switch 有一個 case，後端 PARAM_KINDS 才有一項；register() 會拒絕未知 kind。

overlays 座標一律是該節點輸入影像的全圖座標。工具在 ROI 上運算時用 tools/roi.py 的 crop(image, region, upright=True)，再用 Crop.to_full()／points_to_full() 換回。旋轉矩形擺正後的反矩陣就在 Crop.inverse。

失敗語意：找不到東西 → status="ng" 或走分支（not_found），不是錯誤；可預期的錯（ROI 在影像外、資產不見）→ raise ToolError；任何其他例外引擎會接住記為 error（附 repr，preview 時附 traceback）。

控制分支：工具回 branch="true"，引擎只讓連在 true 把手上的下游執行；沒被選中的節點標 skipped，其資料下游也 skipped。

杯件量測範本（builtin:cup_measure）：template_match → shape_align → fixture_roi×3 →（find_circle 外徑、find_circle 內徑、wall_thickness）→ formula(2r) → concentricity → tolerance_judge×3 → output×3 → bool_logic → judge；每個 tolerance_judge 把 {name, value, nominal, upper, lower, unit, spec_source, in_spec} 追加到 run.outputs.tolerances，FlowRun.outputs 因此保留圖面出處。

3. 圖驗證與編譯（graph.py）

validate_graph() 在存檔（PATCH）與 submit 時跑：節點數／邊數上限、id 唯一、type 在 registry（錯誤訊息列出可用 key）、邊兩端存在、埠存在、型別相容（_compatible：同型、any、number→string、bool→number、points/matches/contours→list；flow 只能接 _flow）、單線輸入埠不能接兩條、不能連進註解、必須是 DAG（Kahn 拓樸排序）。

compile_graph() 產出 CompiledGraph(order, nodes{id: CompiledNode(tool, inputs{port: [(src, port)]}, flow_inputs, primary_image_port)}, consumed)。consumed 是「有人用到的 (node, port)」集合——沒人用的輸出影像不進快取。

4. 引擎（engine.py）

for node in order:
    逾時 → error, break
    有 flow_inputs 且沒有任一 (src ok/ng 且 branch 相符) → skipped
    收集輸入：上游 skipped/error 且該埠必填 → skipped；未連線的必填埠（非 allows_unconnected 工具）→ skipped
    enabled=False → 有 image 進出就直通（訊息「已停用（直通）」），否則 skipped
    result = tool.execute(ctx)   # ToolError → error；其他例外 → error + repr
    登記 outputs（影像：consumed / preview / source|output 類別 才 store.put）、_overlays、context 合併
    preview 時 detail._input_ref = 輸入影像 ref（讓檢視器顯示「這個節點看到的影像」）
run.status: 任一 error 且未 continue_on_error → failed；任一 ng 或 _judge=ng → ng；否則 ok
run.outputs = context["_outputs"]（judge / output 工具寫入）

沒有 token、沒有資料庫、沒有 sleep：一次 run 就是一個函式呼叫，這是毫秒級的來源。

5. Runner 與並行（runner.py）

元件做什麼
ThreadPoolExecutor(MAX_WORKERS=10)同時忙碌的流程數上限；.env 擴充。影像演算法在原生層執行、會釋放 GIL，多執行緒真的平行（實測 12 流程 40 ms）。
FlowRuntime（每流程）編譯快取（依 version）、lock（同流程一次一個 run：相機與狀態一致）、queued 計數（超過 MAX_QUEUE_PER_FLOW → 429）、stats、recent（最近 N 次 RunReport）、continuous loop。
_prefetch()在呼叫者執行緒把 source 參數的來源打開、asset 參數的路徑查好——執行緒池內的熱路徑不碰資料庫。
EventBusCondition + 環形緩衝（500 筆），SSE 用 wait(since) 取增量；重連帶 seq 不漏事件。
Persisterdaemon 執行緒、佇列 5000、每批 100 筆 bulk_create、每 500 筆修剪一次；FK 失敗（流程已刪）逐筆跳過。
ContinuousLoop每流程一條執行緒；Flow 物件帶入，每 2 秒才回 DB 確認停用／改設定；間隔 continuous_interval_ms。
引擎狀態在行程內：只能有一個 API 行程（manage.py serve = uvicorn workers=1 + TCP）。要水平擴展要把引擎拆成獨立服務，這是刻意沒做的。

6. 影像快取（images.py）

ref = "{run_id}:{node_id}:{port}"。每流程保留最近 KEEP_RUN_IMAGES 次 run 的影像；全域 IMAGE_CACHE_MB 以 bytes 計 LRU。encode(ref, max_side, fmt, quality) 延遲到有人要看才做，且依請求最長邊縮小（前端預設 1600）。浮點／16 位元影像正規化到 8 位元顯示。

7. 影像來源（sources/）

open_source(model) 依 kind 建 Grabber 並快取（updated_at 變了才重開）。內建：folder（循環讀檔、排序、pattern）、file（mtime 變了重讀）、usb（BUFFERSIZE=1，先 grab 丟舊幀）、synthetic（合成零件：隨機位移／旋轉、30% 缺孔或刮痕，讓沒相機也能走完整流程）、upload（API push）。外掛：繼承 Grabber 的 .py 丟進 plugins/ 自動掛載（或 VISION_SOURCE_PLUGINS=gige=mypkg.gige:GigEGrabber），見 plugins.html。Grabber 會被多執行緒同時呼叫，內部要加鎖。

8. API / SSE / TCP

完整清單見 apps/vision/api.py 頂端 docstring；整合方式見 automation.html。重點：

  • POST /flows/{id}/run：JSON 或 multipart 附 image；wait、timeout_s、include_images（預設不含節點輸出，產線回傳要小）。
  • POST /flows/{id}/preview：用未存檔的圖試執行，保留全部中間影像；reuse_image_ref 讓調參數時畫面固定。
  • POST /flows/{id}/preview 的 until_node／analysis：工具頁即時調參只跑到該步驟（graph.restrict_to() 取祖先子圖），並回傳直方圖與數值分布；POST /flows/{id}/scratch-image 暫存影像進快取不進來源庫；DELETE /flows/{id}/recent 重置。
  • GET /images/{ref}?max=&fmt=、GET /flows/{id}/recent、GET /flows/{id}/runs（DB）、GET /flows/{id}/stats（每小時 OK/NG）。
  • SSE 不經 ninja（config/urls.py 直接路由）：hello / stats / run_queued / run_started / run_finished / continuous / ping / bye；55 秒關閉、client 帶 since 重連；client 40 秒沒訊息（含 ping）就主動重連。
  • TCP（tcp_server.py）：一行指令一行 JSON，RUN<flow> k=v 同步回結果；每連線一條執行緒，指令交給同一個 Runner。
  • 金鑰選填：VISION_API_KEY；<img>／EventSource 帶不了 header，所以影像與串流也接受 ?api_key=。

9b. 帳號、擁有者與引擎鎖定（apps/accounts）

  • 身分（security.py）：Principal(kind)——integrator（X-API-Key＝VISION_API_KEY，機器身分）、user（Bearer 權杖，SHA-256 存 DB、預設 14 天）、bootstrap（系統尚無使用者時放行，讓 /auth/setup 能建第一個管理員）。影像／SSE 接受 ?token=。
  • 擁有者：Flow.owner；null＝共用（示範流程、被刪帳號留下的）。一般使用者看得到自己的＋共用的，只能改自己的；管理員全部。流程裡每個節點的參數本來就在 graph JSON，所以「各自的參數設定」隨流程歸屬。
  • 引擎鎖：EngineLock 單列。整合方或管理員 POST /vision/lock（reason、ttl_s）；鎖定時 run／preview／continuous 回 423 engine_locked，編輯不受影響；上鎖即停掉所有連續執行並廣播 SSE lock 事件；整合方與持有者不受限；TCP 介面視為整合方。前端以橫幅顯示並停用執行按鈕。

9c. 範本庫、批次測試、整合工具（api_more.py）

  • 範本：內建範本由 demo.py 的建構器以 {SOURCE} 佔位符產生（孔數、曝光、定位＋卡尺、顏色有無、條碼），自訂範本存 FlowTemplate；instantiate 換回來源 id 並可加節點前綴避免撞名。範本不綁機器的來源 id，這是「點選就能用」的前提。
  • 批次測試：每張影像以 preview 模式跑（影像留在快取），回每張的判定／輸出／錯誤節點與來源影像 ref；上限 50 張，記憶體受 KEEP_RUN_IMAGES 限制、舊的會被釋放。
  • 整合工具：integration/tcp 真的連本機 TCP 埠送一行指令（埠沒開時直接呼叫 handle_command 並標 via=direct），讓整合方在瀏覽器裡就能驗證設備端要送的字串。

9d. 開發計畫 v0.2 落地：參數卡、配方、站台、Golden Set、Modbus 輸出

  • Param.teach：工具把需要現場教導的參數標 teach=True，參數卡頁（/flows/:id/teach）只列這些並即時試執行到該步驟；Flow.commissioned 未確認時 RunReport 帶 warnings，不阻擋。
  • 配方 FlowRecipe：param_overrides = {node_id: {param: value}}，執行時 apply_recipe() 疊到圖上再編譯，快取鍵 (version, recipe_id, updated_at)；HTTP recipe、TCP recipe=、未指定用預設配方。覆寫只能指向存在的節點與宣告過的參數，疊完的圖要能過 validate_graph。
  • station_id：VISION_STATION_ID 寫進 FlowRun、RunReport、TCP 回應；索引 (station_id, -started_at)。
  • Golden Set（apps/golden）：案例＋期望值、回歸以非 preview 跑、只對 mismatch 取影像；基準比對列出 regressed；CLI manage.py regress 可進 CI。流程匯出入 manage.py flow export|import|run（穩定序列化：排序、整數座標、{SOURCE} 佔位符）。詳見 golden.html。
  • Modbus 主動輸出（apps/comm）：Connection（modbus_tcp／tcp_client／dio_sim／外掛）＋ write_modbus 工具，連線在 Runner.prefetch_hooks 於呼叫者執行緒開好，寫入失敗預設降級不讓 run failed。詳見 modbus.html。
  • 未做（依計畫排後）：標定子系統（§4.2）、GenICam 內建來源（§4.5）、C 級差異化。
