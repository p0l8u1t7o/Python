User guide

This guide walks through VisionSequence in the order you would actually use it: signing in, building a flow, tuning a tool, then batch testing, templates, the AI assistant, deep-learning teaching and integration. The Help page inside the product carries a condensed version of the same material plus the tool catalogue.

1. Signing in and accounts

  • With no users yet, the sign-in page offers "Create the first administrator", and you are signed in as that account.
  • An administrator adds accounts, assigns roles, disables them and resets passwords on the Users page. There are three roles:
    RoleCanCannot
    AdministratorEverything, including accounts, connections and system settings—
    EngineerCreate and edit flows, image sources and assets; deep-learning teaching, batch testing, Golden Set regression; change any parameterAccounts, outgoing connections, system settings
    OperatorRun inspections, start and stop continuous mode, change over (switch the bound recipe), adjust on-site parameters on the teach page, view statisticsChange a flow's structure, train models, batch test, edit sources or connections
    A flow belongs to the line, not to a person: every engineer can see and edit every flow (the Owner column only records who created it), so an engineer leaving never orphans a flow.
  • Image archive: the platform keeps no run images by default (memory holds the last few and a restart clears them). To be able to show what the camera saw when a customer complains, turn on "Keep reject images" on the flow's statistics page. From then on every reject and failure writes its source and result image to disk, reachable by clicking a row in the run history, and old ones are purged automatically once they exceed the retention period or the total size limit (VISION_ARCHIVE_DAYS, VISION_ARCHIVE_MAX_GB; ship a whole plant with it on using VISION_ARCHIVE_DEFAULT).
  • Role permissions: the table above is the factory setting, not a fixed rule. On the Users page an administrator ticks, function by function, what an engineer and an operator may use — take deep-learning teaching away from engineers, hand batch testing or the audit trail to operators, delegate the outgoing connections. Administrators always have everything and cannot be ticked off, so nobody can lock themselves out. The server checks every request, so a function that is not ticked cannot be reached by typing its address either.
  • On-site parameters are the ones a tool's author marked as teaching parameters — a threshold, a blob's minimum area. An operator changing those on the teach page writes straight back to the flow; changing anything else, or the structure, is refused by the server. Which parameters those are is shown in the "On-site" column of the tool page's parameter table.
  • The user menu in the top-right corner changes the password and signs out. An integrator uses an API key and never signs in.

2. Image sources and assets

  • Image sources: a capture client camera (webcams, Basler and IDS cameras, driven by the downloadable capture client on the PC they are attached to), a folder (read in a loop), a single file, pushed uploads, or a synthetic generator. Folder and file types have a Browse button that opens a server-side file browser. "Test capture" below the form grabs one image with the current settings and shows its size, the time taken and a thumbnail, so you can confirm the path or the device before saving.
  • Assets: template images (for locating and golden comparison), model files (ONNX) and dataset archives. A tool page can create a template from a box drawn on the current image and save it as an asset directly.
  • Both support groups (filter chips above the list; "Manage groups" to rename or delete). The example sources and assets are in the "Examples" group.

2-3. When the camera is on another PC: the capture client

If the camera is attached to another PC on the line, or needs a Basler or IDS SDK, you do not have to move it to the server. Use "Download capture client" at the top of the Image sources page, unzip and run VisionSequenceCapture.exe on the camera's PC, fill in the server address (port 9100) and a client name under Connection, then add the camera as a channel, open it and start acquiring (you can draw an ROI on the preview to send only that region, and adjust and save camera parameters). Back in the web interface, add a source of kind "capture client camera", pick the client and the channel, choose "on demand" (a fresh frame for every run) or "continuous stream", and press Test capture before saving. The status column shows whether the client is online, its fps and the age of the last frame; Integration ▸ Capture lists every connected client and lets you turn streaming on and preview. Details in Capture client.

3. Building and editing a flow

No image source chosen yet? A yellow banner appears at the top of the editor; pick a source from the dropdown in the banner (or upload a scratch image) and you can preview straight away. Every flow card on the dashboard also has a "Run once" button, so you need not open the editor at all. Selecting the acquire step shows the current source in a dropdown with a preview thumbnail in the panel on the right, where you can switch source directly.

Want to write a little Python? The Logic category has a "Python script" tool: write def run(ctx) in the code editor on the tool page (np, cv2 and math are available), read ctx.image, the upstream values in ctx.inputs, the on-site parameters ctx.params['p1'..'p3'] and the region from ctx.roi(), and return a number, a bool, text, data, a new image and overlays, choosing the pass or fail branch. The output ports are fixed (value, result, text, data, image). The script runs in the engine process under restrictions — allow-listed imports, a timeout, a read-only input image — and only an administrator can edit and save it, which is what approves it. Everyone else can view and run an approved script, and adjust its on-site parameters on the teach page without touching the code.

  1. "New flow" on the Flows page, or "Create from template".
  2. "Add tool" in the editor's left column opens the tool picker (grouped by category, searchable, with favourites); a click drops it in the centre of the canvas. "Add note" places a sticky note.
  3. Connecting: drag from a step's output port to the next step's input port. Only ports of the same colour (the same type) connect. Wiring a judging tool's branch port to a step's _flow port makes that step conditional.
  4. The panel on the right: with a step selected you can change its title, whether it is enabled, its colour and its parameters. "Open tool page" goes to the dedicated tuning page.
  5. Ctrl+S saves. Unsaved changes are kept as a draft and survive leaving and coming back; "Run once" and "Continuous" use the saved version.

4. The tool page and ROIs

  • The layout: parameters on the left, the before and after images in the middle, reference information below (histogram, statistics, output values), and the buttons on the right.
  • Changing a parameter does not run anything by default; press "Run to this step" to see the result. With "Auto apply" on, it runs 250 ms after each change.
  • Parameter changes are held as a draft: "Save" writes them back to the flow, and leaving with unsaved changes asks whether to discard them.
  • ROIs: a tool with a region parameter shows its ROI as soon as you open the page. Draw on the image — rectangle, rotated rectangle, circle, ellipse, annulus (optionally a sector), polygon, polyline, line or point. Coordinates are pixels in that step's input image.
  • "Upload scratch image" provides one image for previews only (it does not join the source library); "Re-run with last image" pins the same image while you tune.

5. Preview, run and continuous

ActionWhich versionWhat it does
PreviewThe current canvas, unsaved changes includedKeeps every intermediate image; nothing is written to the run history.
Run onceThe saved versionA real run, the same as an external trigger; written to the run history and the statistics.
ContinuousThe saved versionRuns repeatedly at the configured interval; the dashboard shows the live image and result.

On the dashboard, choose a flow on the left, the middle shows the latest run's image with its overlays, and the right shows the verdict and the output values. With no events it shows the last run.

6. Batch testing and the Golden Set

  1. "Batch test" in the sidebar (or in the editor toolbar): "New image set" uploads images or grabs N from an image source (200 per set at most). The list of sets spans flows, so one set of images can test any flow.
  2. "Test flow" in the top right is the flow to test with. Selecting a set fills in the flow it was created under; to compare a different flow, change the dropdown and run again. With unsaved changes in the editor you can tick "use the editor's unsaved draft".
  3. Press "Run with flow name": it runs in the background with a progress bar and can be interrupted. Every run's per-image results are kept and can be revisited from the run list (a run against a different flow shows that flow's name).
  4. On the Images tab, label each image with its expected OK or NG; the Results tab shows the hit rate and which images matched. The Insights tab lists the missed images, failing nodes, threshold suggestions, output distributions and the trend across runs, and "Apply and re-run" produces a new run.
  5. The Tuning tab edits the on-site parameters and re-runs; the Compare tab puts two runs side by side, image by image. When you are happy: "Write back to flow", "Save as recipe" or "Send to editor".
  6. The global AI assistant in the bottom-right corner (once a finished run is selected) answers questions ("why was image 3 NG?") or takes tuning instructions; the Tuning panel has "Auto-tune". All of them land as new runs.
  7. Tick images and "Save to Golden Set" to make them a regression baseline. The Golden Set page runs regressions and auto-tuning, with regressed cases at the top. See Batch testing and Golden Set and export.

7. The template gallery

Eighteen built-in templates (counting, exposure, circle gauging, edge angle, golden comparison, fabric defects, a pre-processing tutorial, circles and lines, colour presence, colour verification, barcode labels, locate and gauge, cup gauging and more), each with synthetic sample images. Pick the matching "Example: …" source when you create one and it runs immediately. Your own flow can be saved as a template for others to reuse. See Example templates.

8. The AI assistant

The global assistant: every page has an assistant button in the bottom-right corner, opening a chat panel that stays with you between pages. Type a question ("how do I create an image source from a folder?") and it answers from the platform documentation with links to the sections it used. In the flow editor, type an instruction ("set the blob minimum area to 40", "disable the noise removal") and it edits the current canvas; "Apply to canvas" writes it back, and it can be undone. On the batch page, with a finished run selected, ask about the data ("why was image 3 NG?") or give a tuning instruction, and the result becomes a new run. The mode chips at the top of the panel force a particular mode: help, edit flow, consult data, or tune from data.

The assistant page in the sidebar generates a whole flow from an image:

  1. Upload one or more images and draw the areas to inspect. Each ROI is numbered automatically (ROI01, ROI02…) and can carry a hint.
  2. Describe what you want in a sentence: "there should be 5 holes", "measure the diameter, 17.5 ± 0.4 mm", "ROI01 is good and ROI02 is bad, find the difference".
  3. Optionally mark each thumbnail with the verdict it should get. An image whose ROI hint says "good" or "bad" is labelled automatically. An ROI hinted as "locator" marks a fixed feature, and the flow then gets locate correction added in front when the part can move.
  4. Press "Generate": the assistant first checks it has enough information, asking questions if not, then generates the flow and actually runs it on every image, drawing the overlays and marking each thumbnail OK or NG. The rule engine produces several candidates and picks the best against your labels — the result card lets you switch between them — and with two or more labelled images it auto-tunes.
  5. Refine it in words ("too many false rejects", "expect 4 instead", "tolerance ±0.2"), then "Save as flow" to open it in the editor. The thumbs up or down on the result card influences whether these parameters are reused on similar images later.

History shows past sessions, and "Restore" brings back the images, ROIs, request and labels and re-runs them. The Skills page lets you read what the assistant follows, and add your own (or the site's) notes under each skill, which the assistant reads too. Setting the working mode to "agentic" in the provider settings makes the assistant draft, try, edit and verify step by step, showing a step timeline you can interrupt or answer questions in.

"AI provider" in the top right chooses the offline rule engine or Claude, GPT or Gemini with your own API key (stored on the server only, tied to your account). Saving tests the connection and reports the result, and "List models" queries which models the key can use. See AI assistant.

9. Deep-learning teaching

  1. Create a teaching project and choose the model kind (classification, semantic segmentation, instance segmentation, detection, pose, oriented boxes).
  2. Collect samples: upload, a zip, a burst from a source, or import a dataset. Duplicate images are skipped automatically.
  3. Label: for classification, click a thumbnail and choose the class; for segmentation, draw polygons or boxes, with "Smart select" clicking an object to trace it automatically. You can auto-label first and confirm afterwards.
  4. Split into train, val and test, freeze a dataset version, and press "Start training". The finished model is exported to the asset library and used in a flow through a DL tool.

See Deep-learning teaching.

10. Integration and the engine lock

  • The Integration pages provide HTTP and TCP test tools, live event monitoring, Modbus connections and outgoing output settings, and the result format reference.
  • HTTP: POST /api/vision/flows/{id}/run (optionally with an image and a recipe). TCP: RUN <id> on one line. Events: an SSE stream.
  • An integrator can lock the engine with its API key: while locked, users can only edit flows, and every continuous run stops.

See Automation and Modbus.

The Capture page offers the capture client download (version, size, SHA-256), whether the server's capture port is listening, and the setup steps; below that, every connected client and channel (size, mode, fps, last frame, which source uses it) with streaming and preview controls. See Capture client.

11. Settings and personal preferences

  • Account: your own display name can be changed right on the Settings page (an administrator still manages usernames, roles and other people's passwords on the Users page), and the password from the same card.
  • The interface language (English, 繁體中文, 简体中文) and the theme (light, dark, Cyberpunk or follow the system) are stored with your account and follow you between devices.
  • An administrator manages the API key and the engine lock on the settings page.

12. Common questions

SituationWhat to do
A preview says the image is no longer in the cacheUpload the scratch image again, or run the flow once to get a new image.
find_circle or find_line reports nothing foundCheck the ROI covers the edge (an annulus for a circle, a caliper ROI straddling both edges), lower the edge threshold, or change the polarity.
Testing an AI provider failsFollow the reason shown: an invalid key, a model that has been retired (rename it as suggested), the provider overloaded (retry later or switch model), or a timeout (check the network).
A run reports the engine is lockedAn integrator holds the lock; wait for it to be released, or ask an administrator to clear it.
Continuous mode keeps reporting a full queueIncrease the interval, or check how long the flow takes; the performance report gives the cost of each tool.

The camera is on another PC, or needs a Basler or IDS SDK

Use the capture client: "Download capture client" on the Image sources page, run it on the camera's PC and connect it to the server, then add a "capture client camera" source and pick the client and channel. On the same machine it uses shared memory automatically; across machines it is lossless over TCP. "Capture client offline" in the list means the program is not connected. See Capture client.

A capture client camera times out during a run

First check on the client that the channel says it is acquiring and the preview is live. A camera in trigger mode needs a trigger signal. With a long exposure, or across a network, increase the source's timeout in milliseconds. Turning off "require a fresh frame" lets it use whatever frame the client already has.
