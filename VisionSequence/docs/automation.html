自動化整合（Modbus TCP / 上位機 / MES）

三種接法，回傳格式相同；金鑰（VISION_API_KEY）有設定時 HTTP 帶 X-API-Key 或 ?api_key=。

1. HTTP 同步執行（最常用）

POST /api/vision/flows/{flow_id}/run
  • JSON：{"context": {"lot": "A123"}, "wait": true, "timeout_s": 5, "include_nodes": false}
  • 或 multipart：image（檔案，常見影像格式：PNG／JPG／BMP／TIFF 等）、context（JSON 字串）。附影像時 image_source 節點（mode=auto）直接用送來的影像，不抓相機。
  • ?wait=false → 202 立即回 {"queued":true,"flow_id":1,"run_id":"…"}；用那個 run_id 打 GET /api/vision/runs/{run_id} 取結果，還沒跑完會回 {"status":"queued|running","pending":true}（也可以改訂 SSE）。
  • timeout_s 是「我最多等這麼久」。逾時回 504 run_timeout，details.run_id 給你事後取結果——執行不會被中止，那是引擎自己的 VISION_RUN_TIMEOUT_S 在管。沒指定時等 RUN_TIMEOUT_S + 5 秒，讓引擎的逾時先觸發並回一份完整報告。
  • include_nodes=1（舊名 include_images，仍可用）：回應加上每個步驟的輸出與標記。影像不會內嵌在 JSON 裡，拿到的是影像 ref，畫面用 GET /api/vision/images/{ref} 取。

回應（200）：

{"id": "…", "status": "ok|ng|failed", "duration_ms": 12.3,
 "outputs": {"judge": "OK", "hole_count": 5, "width_mm": 12.34},
 "nodes": {"blob-1": {"status": "ok", "duration_ms": 0.9, "message": "5 個 blob"}}, "error": ""}
  • outputs 由流程中的 具名輸出（output） 與 OK/NG 判定（judge） 工具決定，鍵名自己取。
  • status：ok／ng（判定不良）／failed（工具錯誤、逾時、來源沒影像）。
  • 429 flow_queue_full = 該流程等待中的觸發已達 VISION_MAX_QUEUE_PER_FLOW（預設 16）。每個流程一次只跑一個 run（相機與硬體狀態要一致），多站共用同一流程時請求會排隊；上限與目前排隊數可從 GET /api/vision/capacity 或 TCP STATUS <flow> 看。409 = 流程停用。

curl 範例：

curl -X POST http://127.0.0.1:8000/api/vision/flows/1/run -H "Content-Type: application/json" -d "{}"
curl -X POST http://127.0.0.1:8000/api/vision/flows/1/run -F image=@part.png -F context='{"lot":"A1"}'

2. TCP 一行指令（設備最容易接）

連 VISION_TCP_PORT（預設 9000），每行一個指令、每行一個 JSON 回應（\n 結尾）：

指令回應
RUN 1 / RUN 零件孔數檢測 lot=A1{"ok":true,"status":"ok","judge":"OK","outputs":{…},"duration_ms":12.3,"run_id":"…"}
TRIGGER 1 / TRIGGER 1 lot=A1{"ok":true,"queued":true,"run_id":"…"}（不等結果；用 run_id 打 GET /api/vision/runs/{run_id} 取結果）
STATUS / STATUS 1容量／該流程統計
START 1 / STOP 1連續模式
LIST所有流程
PING{"ok":true,"pong":true}

key=value 會放進 context，流程內公式或輸出可引用。連線可長期保持，NODELAY 已開。

2-1. 引數的型別（料號與條碼不會被改掉）

  • 值預設是字串，只有「乾淨的十進位數字」（1、-3、2.5）才轉成數字。所以 lot=00123 保留前導零、sn=1_000 不會變成 1000、exp=1e3 原樣送達。
  • 值含空白請用引號：RUN 1 barcode="ABC DEF"。流程名稱含空白同理：RUN "我的 流程"。
  • 不是 key=value 形狀的引數會回 bad_argument（而不是靜默丟掉半個條碼）。

2-2. 錯誤碼（設備請用 code 分支）

失敗一律回 {"ok": false, "error": "中文說明", "code": "…"}。error 會隨版本潤飾，code 不會。

code意思
empty_command空白行
unknown_command不認得的指令
missing_argument指令少了流程 id 或名稱
bad_argument引數不是 key=value（值含空白要加引號）
flow_not_found流程 id／名稱不存在
flow_disabled流程已停用
flow_queue_full該流程等待中的觸發已達上限，稍後重送
recipe_not_foundrecipe= 指定的配方不存在
engine_locked引擎被鎖定（見 §5）
internal_error伺服器例外，記錄在日誌

3. SSE 即時事件（HMI / 看板）

GET /api/vision/flows/{id}/stream?since=<seq>     單一流程
GET /api/vision/events?since=<seq>                全部

事件：run_queued、run_started、run_finished（run = 完整結果、stats = 累計統計）、continuous、stats、ping（每 15 秒心跳；前端 40 秒沒收到任何訊息就當斷線重連，因為經 proxy 時後端死掉客戶端連線不一定會被關）、bye（55 秒後重連，帶回 seq 不漏事件）。?outputs=0 只送節點狀態不送輸出（省頻寬）。

4. 相機不在本機時：送圖來源

建立 kind=upload 的影像來源，POST /api/vision/sources/{id}/push（multipart image）後，流程裡選它即可；config.max_age_s 可讓過期影像不被使用。

4-1. 相機接在別台電腦：擷取端

不想自己寫送圖程式時，用擷取端：可下載的桌面程式在相機電腦驅動網路攝影機／Basler／IDS，主動連到伺服端擷取埠 9100；網頁新增「擷取端相機」來源即可讓 HTTP／TCP 觸發的執行直接向該相機要一張新影格（依需求取像）或取最新影格（連續串流）。同一台電腦走共享記憶體、跨電腦走單一 TCP 連線無損傳送。

效能建議

  • 大圖先 resize／crop 再做重工具；VISION_CV_THREADS=1~2 讓多流程並行不互搶。
  • VISION_PERSIST_RUNS=0 關掉資料庫記錄只留記憶體統計（每分鐘上千次時）。
  • 流程間彼此獨立，同一流程同時只有一個 run（相機與狀態一致），不同流程並行到 VISION_MAX_WORKERS。

5. 身分與引擎鎖定（硬體留給產線）

  • 整合方以 X-API-Key: <VISION_API_KEY>（或 ?api_key=）呼叫，是「機器身分」：永遠可執行，不受鎖定影響；TCP 介面同樣視為整合方。
  • 瀏覽器使用者以帳號登入（POST /api/auth/login → Bearer token）；每個使用者只看得到自己的流程與共用流程。

鎖定流程：

POST   /api/vision/lock   X-API-Key: ...   {"reason": "量產中", "ttl_s": 28800}   → 鎖定（ttl 選填，逾時自動釋放）
GET    /api/vision/lock                                                       → {"locked", "holder", "reason", "locked_at", "expires_at"}
DELETE /api/vision/lock   X-API-Key: ...                                      → 解鎖
  • 鎖定期間：使用者（含管理員）呼叫 run／preview／continuous 一律回 423 {"error": {"code": "engine_locked", ...}}，但仍可登入、編輯、儲存流程；鎖定當下所有連續執行會被停止。
  • 管理員也能在設定頁鎖定／解鎖（例如維護時）；持有者自己可執行。
  • 建議整合方在開機／換線程式一開始就 POST lock（帶 ttl），停機時 DELETE lock。

5b. 整合頁：每一種接法一個頁面

網頁的「外部整合」在側欄可以展開成樹狀，每一種整合方式都是獨立頁面（網址也獨立，可直接加書籤或分享）：

頁面網址內容
HTTP API/integration/http試打 POST /flows/{id}/run，產生 curl／Python／C# 片段
TCP 指令/integration/tcp送一行指令、看一行 JSON 回應，含常用指令與歷史
事件監看/integration/eventsSSE 事件串流
Modbus/integration/modbus主站／從站的差別、位址格式、對映表與讀取表範例
連線/integration/connections建立與測試主動輸出的連線（舊 /connections 會轉過來）
擷取端/integration/capture擷取端程式下載與已連線的擷取端
引擎鎖定/integration/lock鎖定與解鎖
回傳格式/integration/formatRunReport 欄位與錯誤碼

舊網址 /integration?tab=modbus 會自動轉到新的獨立網址。

5c. 命令與結果（除錯）

每個整合工具頁面下方都有命令與結果：頁面開著時，這個介面收到的命令與回覆會即時列出——時間、方向（→ 外部送進來／← 平台送出去）、來源、摘要、耗時，失敗的整列標紅；點一列展開完整內容（JSON）。

  • HTTP：每次 POST /flows/{id}/run 的觸發來源、判定、具名輸出與 run_id。
  • TCP：收到的整行指令與回傳的 JSON。
  • Modbus：每次寫入／讀取的位址與值；本平台當從站時，還會列出主站的每一則請求與我們的回應。
  • 擷取端：擷取端連線與斷線。

實作是行程內的環形緩衝（每個頻道 300 筆，apps/vision/trace.py），不落地、不進資料庫；沒有人開著整合頁時只記錄錯誤，所以產線長跑不會有額外負擔。API：GET /api/vision/integration/trace?channel=http|tcp|modbus|capture&since=&limit=、DELETE 清空。

6. 主動輸出（Modbus TCP／從站，引擎寫給你）

上面三種接法都是呼叫方來拿結果。如果設備只想等一個 DO 或暫存器變化，改用主動輸出：設定頁建一條連線（modbus_tcp／tcp_client／dio_sim），流程末端放「寫入 Modbus」（write_modbus）工具填對映表，例如 judge → coil:0、width_px → holding:100:float32。寫入失敗預設只記警告、run 照常（產線不停線）。細節、位址格式、連線 API 與外掛見 Modbus 輸出。
