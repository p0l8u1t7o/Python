擷取端：在相機所在的電腦驅動相機，把影像送到伺服端

相機常接在產線另一台電腦，或雖在同一台電腦卻需要廠牌 SDK（Basler pylon、IDS peak）；伺服端維持「單一 API 行程、不塞相機 SDK」的原則。擷取端（Capture client）是可從網頁下載的 Windows 桌面程式：在相機所在的電腦直接驅動網路攝影機／Basler／IDS 相機，主動連到伺服端的擷取埠（預設 9100）登記名稱與相機通道；網頁新增影像來源種類「擷取端相機」選擷取端與通道即可執行。同一台電腦以共享記憶體＋控制訊息傳影像（單次 memcpy），跨電腦以單一持久 TCP 連線、二進位定長表頭、無損（raw／LZ4）傳影像；伺服端接收零解析成本，直接把 ndarray 交給引擎。實測 2000 萬畫素彩色（59.9 MB／張）在同一台電腦可達 117 fps（見 §7）。伺服端重新建置後，已連線的擷取端會收到通知並可自動更新（見 §2-5）；介面支援繁中／简中／English 與深色／淺色。

1. 概念與架構

相機電腦（擷取端 VisionSequenceCapture.exe）              伺服端（單一 API 行程）
  cameras/  webcam | basler | ids | ueye | fake ──┐         apps/vision/capture/
  channel   每通道一條擷取執行緒＋最新影格槽   ──┤  TCP:9100   hub.py     CaptureHub：監聽、每個擷取端一條 ClientSession 執行緒
  transport 連線／重連／GRAB 回覆／串流推送   ──┼──────────▶ grabber.py CaptureGrabber(kind="capture") ← Runner._grab
  shm       共享記憶體環（同一台電腦）        ──┘  ＋ SHM     api.py     /vision/capture/*（clients、preview、stream、download）
  ui/       連線／通道／預覽 ROI／參數／傳送／記錄             協定共用：vscapture/protocol.py（伺服端也 import 同一份）
  • 三個角色：擷取端（驅動相機、送影像）、伺服端 hub（登錄表、每個擷取端一條讀取執行緒、把影格交給引擎）、網頁（設定來源、看狀態、開串流、下載擷取端）。
  • 兩種取像模式（每個通道可選）：依需求取像——伺服端每次執行送 GRAB，擷取端回一張觸發之後取的新影格（延遲最低、頻寬最省，適合觸發式檢測）；連續串流——擷取端依 fps 上限持續推最新影格，伺服端執行時直接用手上最新的一張（適合看板、連續執行）。
  • 為什麼擷取端主動連出：相機電腦常在 NAT／防火牆後、IP 會變；伺服端只開一個固定埠，擷取端重連、重新登記都由擷取端負責，網頁只要選名稱。
  • 接縫不變：流程的「影像來源」步驟 → ctx.grab() → grab_by_id → CaptureGrabber.grab() 回 ndarray；交給引擎的陣列一律獨占（raw 接收緩衝即陣列、LZ4 解壓輸出、或從共享記憶體槽 copy 一次）。

2. 安裝與連線

2-1. 下載與啟動

  1. 網頁「影像來源」頁首的「下載擷取端」，或「外部整合」→「擷取端」分頁（顯示版本、大小、SHA-256、建置時間）。伺服端尚未建置時按鈕停用；建置方式見 §12。
  2. 解壓縮到任意資料夾（避免過長路徑；不需要管理員權限），執行 VisionSequenceCapture.exe。第一次執行 Windows SmartScreen 可能提示「未知的發行者」，選「其他資訊」→「仍要執行」。
  3. 「連線」面板：伺服端主機名稱或 IP、埠（預設 9100）、擷取端名稱（在網頁上顯示的名稱，同一台電腦重連會取代舊連線）、金鑰（伺服端有設定 VISION_CAPTURE_AUTH 或 VISION_API_KEY 時才需要）、本機模式（自動／強制共享記憶體／一律 TCP）、啟動時自動連線。
  4. 點選「連線」。狀態列顯示已連線、往返延遲、已送影格、速率與傳送方式（共享記憶體或 TCP）。

2-2. 設定檔、記錄檔與無介面模式

  • 設定檔 %APPDATA%\VisionSequenceCapture\config.json（環境變數 VSCAPTURE_CONFIG 可覆寫）：連線（含 auto_update、shm_max_mb）、介面偏好（ui.language、ui.theme）、每個通道的相機參數／ROI／傳送設定。「檔案 → 儲存設定」寫入；結束時未儲存會詢問。缺鍵補預設、未知鍵忽略、非法值啟動時提示並改用預設。
  • 記錄檔 %APPDATA%\VisionSequenceCapture\logs\capture.log（輪替 2 MB × 3）；介面底部「記錄」可依等級過濾。
  • 無介面：VisionSequenceCapture-console.exe --headless --connect（Ctrl+C 結束），適合 Task Scheduler／NSSM 常駐；--list-cameras 列出各種相機；--server host:port、--name、--api-key、--config、--log-level DEBUG 覆寫設定；--minimized 啟動即縮到系統匣。
  • 關閉視窗會縮到系統匣（右鍵：顯示、連線、中斷、結束）。

2-3. 介面：語言與外觀

視窗右上角可切換語言（繁體中文／简体中文／English，與網頁相同的三種）與外觀（深色／淺色），立即生效、不必重開程式，並隨設定一起儲存（ui.language、ui.theme）。相機參數的標準名稱（曝光時間、增益、影格率、像素格式、寬高位移、觸發模式）會跟著翻譯；廠牌自訂的參數維持 SDK 原名，通道名稱是您自己取的字串不翻譯。

版面：左欄「連線」與「通道」、中央即時預覽與 ROI 工具列、右欄「相機參數」「傳送設定」分頁、底部「記錄」可收合；有新版時最上方出現更新橫幅。品牌色與網頁一致，深色是預設。

2-5. 自動更新

伺服端重新建置擷取端之後（scripts/build_capture_client.ps1），已連線的擷取端會自己知道——不必到現場逐台重裝：

  1. 連線時的 WELCOME 就帶著伺服端手上的版本；連線後伺服端每次心跳都會比對 manifest，版本變了就推一則通知。只有比擷取端目前版本新的才會通知。
  2. 安裝檔走同一條已驗證的擷取連線分塊拉下來（每塊 1 MiB），不必另外開埠、不必再給一次金鑰、也不受網頁登入影響；下載完比對 SHA-256，不符就整份丟棄。
  3. 解壓到 %APPDATA%\VisionSequenceCapture\updates\staging-<版本>\，再由新版的主控台執行檔接手：等舊行程結束 → 覆寫安裝資料夾 → 重新啟動。更新程式跑在新版的資料夾裡，所以不會覆寫到自己；設定檔與記錄檔都在 %APPDATA%，不受覆寫影響。

「連線」面板的自動更新三選一：off 不檢查、notify 只在最上方顯示橫幅由您決定（預設）、auto 自動下載並安裝。橫幅會顯示版本、大小與下載進度，也可以取消。「說明 → 檢查更新」可隨時問一次。無介面模式只有 auto 會自己更新（其餘只寫進記錄）。以原始碼執行時不會就地覆寫，只會下載與解壓後提示。

失敗都是安全的：下載中斷、SHA-256 不符、檔案被佔用都只是記錄一筆並保留舊版繼續取像；更新程式覆寫時會重試 30 秒（等防毒或檔案把手放開）。舊版擷取端（沒有自動更新功能的版本）連新伺服端不受影響，只是不會自己更新，請從網頁重新下載。

3. 通道、預覽與 ROI

  • 通道＝一台相機：名稱、相機種類（SDK 未安裝的種類停用並提示原因）、裝置（「掃描」列舉；也可直接輸入識別，例如網路攝影機的索引 0）、啟用（伺服端可取像）、即時預覽。開啟／關閉／開始取像／停止四個鈕；狀態燈：已關閉、開啟中、已開啟、取像中、錯誤。連續 30 次取像失敗會自動重開相機。
  • 預覽：依「preview_fps」（預設 15）取最新影格縮小顯示，HUD 顯示 seq、fps、尺寸與硬體 ROI 位移。
  • ROI 圈選：在預覽上拖曳建立、8 個把手縮放、拖移；數值欄 X／Y／寬／高雙向；「清除 ROI」回全幅。點選「套用 ROI」才生效。勾選「使用相機硬體 ROI」時，支援的相機（Basler、IDS、模擬）只讀出 ROI 範圍（影格率更高），座標依相機增量對齊後回填；不支援的相機以軟體裁切後傳送。ROI 一律以全感測器座標保存；伺服端影格 metadata 帶 roi_x/roi_y/full_w/full_h，流程座標仍是收到影像的座標。
  • 拍攝一張：觸發模式為「軟體觸發」時顯示，觸發相機拍一張。
  • 相機參數分頁：依相機回報的參數自動組表單（曝光、增益、影格率、像素格式、寬高位移、觸發模式、進階項），改動 250 ms 後套用並回填實際值；需停止取像的參數（寬高位移、像素格式）先確認、套用後自動恢復；「儲存到設定檔」下次啟動自動套用。
  • 傳送設定分頁：編碼（不壓縮／LZ4／JPEG）、JPEG 品質、轉單色、縮小 1/2、1/4、模式（依需求／連續串流）、串流 fps 上限；顯示送出尺寸與每張大小估算；「測試傳送」把目前影格送一次，顯示往返時間、位元組、編碼與伺服端解碼時間。改 ROI／單色／縮小會重新協商共享記憶體區段（期間自動改走 TCP）。

5. 同一台電腦的共享記憶體與跨電腦的 TCP

5-1. 共享記憶體（同一台電腦）

  • 判定：連線來自 loopback（或伺服端自身位址）且主機名稱相同，且擷取端「本機模式」為自動／強制。WELCOME 回 local:true。
  • 擷取端建立一個 multiprocessing.shared_memory 區段（名稱 vs_cap_<名稱>_<pid>_<隨機>）：64 B 表頭（magic、canary、槽數、槽大小）＋ K 個槽；一條連線一個區段，槽大小＝所有啟用通道中最大的影格（對齊 4096），K＝4＋2×通道數（最多 16）。SHM_OFFER → 伺服端附加並核對 canary → SHM_ACCEPT；拒絕就留在 TCP。
  • 事件機制＝控制連線上的 FRAME 訊息（slot ≥ 0、payload 為空）：loopback 約 50～100 µs，帶 seq 與 metadata。伺服端 out = np.empty(...)；out.data.cast("B")[:] = buf[off:off+n] copy 一次（1280×960×3 約 0.5～1 ms）後立刻回 SLOT_FREE。
  • 所有權：FRAME 送出後槽屬伺服端，SLOT_FREE 後歸還；擷取端只寫 FREE 的槽，依需求模式等不到槽即改走 TCP payload、串流模式直接丟幀；「最舊、seq 落後 ≥ 2K 且被持有超過 1 秒」的槽視為孤兒才覆寫（伺服端顯然沒回收）。重新協商期間丟掉尚未送出的影格（舊槽索引不能再送）。

5-2. TCP（跨電腦）

  • 單一持久連線，控制與資料以 req_id 多工；TCP_NODELAY、4 MiB 收送緩衝；每通道同時最多一個在途 GRAB。
  • 接收：raw → recv_into 直接寫進 np.empty（接收緩衝即陣列）；lz4 → 會話級 bytearray 後 lz4.block.decompress(uncompressed_size=raw_len)；jpeg（明確選用才用，有損）→ 解碼後核對尺寸。
  • 編碼「自動」：同一台電腦 raw、跨電腦兩端皆有 LZ4 則 LZ4、否則 raw。頻寬手段依效益：轉單色（÷3）、ROI 裁切、LZ4（典型 1.5～3×）、串流 fps 上限、縮小。
  • 背壓：擷取端每通道只留最新影格、一次一張在途；伺服端每通道只留 latest。心跳：閒置 ≥ 2 秒送 PING，逾 3 倍心跳無回應斷線並以指數退避重連（最長 30 秒；驗證失敗固定 30 秒）；伺服端重啟後擷取端自動重連並重送串流設定。

7. 效能與頻寬

目標：2000 萬畫素彩色（5472×3648×3＝59.9 MB／張）在伺服端達到 60 fps。60 fps 表示每張只有 16.7 ms，且要搬 3.59 GB/s——這個量級只有同一台電腦的共享記憶體做得到（見 §7-3 的網路上限）。

.venv/Scripts/python.exe scripts/bench_capture.py --fps 60             # 模擬 60 fps 相機的實機情境
.venv/Scripts/python.exe scripts/bench_capture.py --model 2 --mono     # 500 萬畫素／單色
.venv/Scripts/python.exe scripts/bench_capture.py --transport tcp --encoding lz4

7-2. 大影格的四個關鍵

  1. 接收緩衝要重用（影響最大）。60 MB 的 np.empty 每次都要向作業系統要新頁面，第一次寫入時觸發 page fault——實測配置＋寫滿要 17 ms，重用既有緩衝只要 2.4 ms（7 倍）。伺服端每個通道、擷取端每台相機都用緩衝池，只重用「池是唯一持有者」的緩衝（以參照計數判定），已交給引擎或還在發布中的影格永遠不會被覆寫。池至少要 3 張：已發布的最新影格、傳送中的、正在寫入的——少一張就會退回每張重新配置。此項讓依需求取像從 38.7 fps 變成 117.6 fps。
  2. 複製要放開 GIL。memoryview 切片指派整段持有 GIL（背景 Python 執行緒只剩 39% 速度），np.copyto 會放開（99%）。伺服端是單一 API 行程，60 fps × 60 MB 若整段鎖住 GIL 會拖垮整台；因此從共享記憶體讀出改用「暫時的 ndarray view ＋ np.copyto」，複製完立刻丟掉 view（shm.buf 上絕不能留 view，否則 close() 會 BufferError）。
  3. 送出不壓縮的影格要零複製。原本 tobytes() 一次、把表頭和 payload 接起來又一次，各 17 ms。現在 RAW 直接送陣列的 memoryview（表頭與 payload 分兩次 sendall），完全不複製。
  4. 共享記憶體區段要夠大但有上限。槽大小＝最大通道的影格（2000 萬畫素彩色＝60 MB），槽數＝4＋2×通道數，並以總量上限（預設 512 MB）收斂——單通道 6 槽＝360 MB。第一輪寫入會把頁面帶進實體記憶體，之後每張只要 2.3 ms。

7-3. 跨電腦的物理上限

影格大小 × fps 就是需要的頻寬，網路做不到就是做不到：

影格60 fps 需要1 GbE（110 MB/s）10 GbE（1.1 GB/s）共享記憶體
2000 萬畫素彩色 59.9 MB3.59 GB/s（29 Gbps）1.8 fps18 fps✓ 117 fps
2000 萬畫素單色 20.0 MB1.20 GB/s5.5 fps55 fps✓ 117 fps
500 萬畫素彩色 15.0 MB0.90 GB/s7.3 fps73 fps✓ 116 fps
500 萬畫素單色 5.0 MB0.30 GB/s22 fps220 fps✓

結論：2000 萬畫素彩色 60 fps 必須把擷取端跑在伺服器本機（相機接伺服器、SDK 裝在伺服器那台）。要跨電腦又要高影格率，依效益順序：轉單色（÷3）、先圈 ROI 只傳需要的範圍、縮小 1/2（÷4）、LZ4 無損（典型 1.5～3×，工業影像的平坦背景壓得更好）、JPEG（有損，只在頻寬真的不夠時用）、降低 fps 上限。舉例：2000 萬畫素單色＋ROI 取一半＋LZ4，在 10 GbE 上可到 60 fps 以上。

7-4. 伺服端下游

擷取端把影像交給引擎之後就是流程本身的成本：60 fps 表示每張檢測要在 16.7 ms 內跑完（見 效能報告；2000 萬畫素的工具耗時大約是 1280×960 的 16 倍，通常要先縮小或只在 ROI 上運算）。另外影像快取預設 1024 MB（VISION_IMAGE_CACHE_MB）、每流程保留最近 8 次 run 的影像（VISION_KEEP_RUN_IMAGES）——2000 萬畫素一張就 60 MB，高影格率時請把兩者調小，或只在 NG 時保存。

8. 疑難排解

  • 連不上：伺服端是否以 manage.py serve 啟動（runserver 不開擷取埠）、防火牆是否放行 9100、位址是否為伺服端可達的 IP；「外部整合」的資訊列顯示擷取埠是否監聽中。
  • 驗證失敗（auth_failed）：伺服端設了 VISION_CAPTURE_AUTH／VISION_API_KEY，擷取端「金鑰」要填同一組；失敗會固定 30 秒後重試。
  • 名稱重複（name_taken）：另一台電腦已用同名連線；同一台電腦重連會自動取代舊連線。
  • 版本不符（protocol_unsupported）：重新從網頁下載與伺服端相同版本的擷取端。
  • 網頁顯示「擷取端離線」：擷取端程式關閉或斷線中；重連後 5 秒內恢復。流程執行時會失敗並回「擷取端「名稱」未連線」。
  • 逾時：相機未開始取像、觸發模式下沒有觸發、曝光超過 timeout_ms；先在擷取端確認狀態為「取像中」、預覽有畫面。
  • 影像超過上限（too_large）：調高 VISION_CAPTURE_MAX_FRAME_MB 或在擷取端縮小／圈 ROI。
  • 共享記憶體未被接受：記錄會寫原因，程式自動留在 TCP；「本機模式」設為「一律走 TCP」可強制。
  • 掃描不到網路攝影機：被其他程式佔用（關掉會議軟體）、USB 供電不足；可直接輸入索引 0、1。
  • 更新沒有出現：伺服端要先建置（build_capture_client.ps1），且新版號要比擷取端目前的版本大；「自動更新」設成「不檢查」時不會通知。舊版（0.1.0）沒有自動更新功能，請從網頁重新下載。
  • 更新失敗：記錄會寫原因（下載中斷、SHA-256 不符、檔案被佔用）。舊版會繼續正常取像；可從網頁下載 zip 手動覆寫。防毒軟體鎖住執行檔時，更新程式會重試 30 秒。
  • SDK 尚未安裝：擷取端只打包建置時安裝的 SDK；請在伺服端以 -WithBasler／-WithIds 重新建置，客戶端另裝廠牌執行期／驅動。

9. 協定摘要（v1，vscapture/protocol.py）

小端序。每則訊息＝ENVELOPE(16 B) | header(hlen) | payload(plen)，ENVELOPE = "<HBBIII"：magic 0x5643、ver 1、type、req_id（0＝非請求）、hlen、plen。控制訊息 header 是 JSON，熱路徑訊息是定長 struct。上限：hlen ≤ 1 MiB、plen ≤ MAX_FRAME、通道 ≤ 32、名稱 [A-Za-z0-9_\-.]{1,64}。

type名稱方向header用途
0x01／0x02HELLO／WELCOMEC→S／S→CJSON連線後 5 秒內登記（protocol、name、version、auth、hostname、machine_id、features、channels[]）；回 ok、local、prefer{encoding, shm}、max_frame_bytes、heartbeat_s、stream{}；拒絕碼 auth_failed／name_taken／protocol_unsupported／bad_hello
0x03／0x04PING／PONG雙向無心跳
0x05CHANNELSC→SJSON通道清單整份替換；索引＝位置且只增不減（移除的通道留 enabled:false 墓碑，在途 GRAB 不錯位）
0x06／0x07SHM_OFFER／SHM_ACCEPTC→S／S→CJSON共享記憶體協商（name、slots、slot_bytes、canary）
0x08STREAMS→C，C 回音JSON{channel, enabled, max_fps}
0x09ERROR雙向JSON{code, message}：timeout／no_channel／channel_disabled／camera_error／busy／unsupported_encoding／too_large／malformed…
0x0ABYEC→S無正常關閉
0x0B／0x0CTEST／TEST_RESULTC→S／S→CFRAME_HDR＋payload／JSON「測試傳送」：回 decode_ms
0x0DUPDATES→CJSON{available, version, filename, size, sha256, built_at, chunk}；WELCOME 內也帶一份，之後 manifest 版本變了才推
0x0E／0x0FUPDATE_PULL／UPDATE_DATAC→S／S→CJSON／JSON＋payload{offset, length} → {offset, eof, error?}＋該段位元組；安裝檔走同一條已驗證的連線
0x10GRABS→C"<HIQBB"（chan, timeout_ms, min_seq, encoding 255=auto/0 raw/1 lz4/2 jpeg, flags bit0 AFTER_REQUEST）每次執行一則
0x11FRAMEC→S"<HBBBBQQIIIIIIIIi6x" 64 B（chan, encoding, dtype 0 u8/1 u16/2 f32, channels 1/3/4, flags bit0 FRESH bit1 CROPPED, seq, ts_ns, width, height, stride, roi_x, roi_y, full_w, full_h, raw_len, slot）slot −1 像素在 payload；slot ≥ 0 在共享記憶體槽；req_id > 0 回應 GRAB，req_id 0 串流推送
0x12SLOT_FREES→C"<HiQ2x"（chan, slot, seq）伺服端 copy 完畢，槽歸還

伺服端驗證 FRAME：chan 範圍、dtype／channels 合法、stride == width×channels×itemsize、raw_len == stride×height ≤ 上限、raw ⇒ plen == raw_len、shm ⇒ slot < slots 且 raw_len ≤ slot_bytes；不合即 ERROR(malformed) 並斷線（部分讀取的串流無法安全重同步）。改協定要同時改 vscapture/protocol.py、apps/vision/capture/hub.py 與本節。

10. 安全性

  • 登錄金鑰以 hmac.compare_digest 比對；驗證失敗延遲 0.5 秒再回覆以節流。空金鑰＝不驗證，只建議在隔離的產線網段使用。
  • HELLO 之前不處理任何訊息；每則訊息有大小上限；名稱與通道欄位白名單驗證；超大或格式錯誤立即斷線。
  • 共享記憶體只在 loopback 且主機名稱相同時協商，區段名稱含隨機字串並核對 canary。
  • 網頁端的預覽／串流／下載端點沿用平台身分（登入 token 或 API 金鑰；鎖定時串流開關回 423）。

11. 實體相機驗收清單

  1. 網路攝影機 1080p MJPG ≥ 25 fps；曝光手動／自動切換生效；拔插後自動重開。
  2. Basler USB3／GigE：Mono8／BGR8 轉換正確；硬體 ROI 依增量對齊且座標回填；軟體觸發延遲；Line1 硬體觸發；PYLON_CAMEMU=1 模擬相機。
  3. IDS peak：改 PixelFormat 後仍能取像（重配 buffer）；Line0 觸發；硬體 ROI。
  4. 乾淨 PC：有／無各 SDK 執行期時，相機種類的停用提示正確；zip 內 README 列出的支援與實際一致。
  5. 同一台電腦：共享記憶體與「一律走 TCP」的 CPU 與延遲對比；status.shm === true。
  6. 區網：兩通道各 10 fps 串流＋並行依需求取像；LZ4 與 raw 的頻寬對比。
  7. 伺服端重啟、拔網路線 30 秒後自動重連，串流設定自動恢復。
  8. Task Scheduler／NSSM 以主控台版常駐；系統匣連線／中斷／結束。
  9. 執行中改設定檔後「重新載入設定」重建通道並重連。
  10. 自動更新：伺服端重新建置後橫幅出現、下載進度、覆寫並重啟成新版；「自動下載並安裝」在無介面模式也會更新；下載途中斷線與 SHA-256 不符都只記錄不影響取像。
  11. 介面：三種語言切換即時生效（含相機標準參數名稱）、深色／淺色切換、重開程式後語言與外觀保持。
