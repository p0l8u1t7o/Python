AI 助手：上傳影像＋圈選＋提示詞 → 自動生成檢測流程

AI 助手（側欄「AI 助手」，/agent）讓不熟工具鏈的使用者用三步驟建立檢測： 上傳影像 → 在影像上圈選檢測位置（可多個 ROI、各配提示）→ 用一句話描述需求。 助手生成一個標準的流程 graph，立刻在這張影像上實跑並把檢測標記疊回圖上； 不滿意就用口語回饋（「太敏感」「漏抓」「改成 4 個」）迭代微調，滿意後一鍵存成流程、進編輯器繼續調。

架構

助手的產物就是標準 graph JSON——跑在既有的資料流引擎上、可在編輯器打開、 可掛任何影像來源、可綁配方與 TCP／HTTP 觸發。助手本身只是「會寫流程的層」，沒有第二套執行路徑。

使用者影像 + ROI + 提示詞
        │
        ▼
  analysis.py ── ROI 特徵量測（直方圖/Otsu/邊緣密度/主色/圓形試探/粒子統計）
        │
        ▼
  ┌─ 生成（二選一，自動切換）──────────────────────────┐
  │  llm.py    有 VISION_AGENT_API_KEY → Claude 生成    │
  │  intents.py + synth.py   否則 → 離線規則引擎        │
  └────────────────────────────────────────────────┘
        │  graph（一律經 validate_graph 把關）
        ▼
  service.trial_run ── 在上傳影像上實跑（engine.execute，不落 DB、不佔流程執行緒池）
        │
        ▼
  {graph, rationale, report}  ← 前端顯示 overlay／輸出值／OK-NG，可回饋微調或存成流程
模組職責
apps/vision/agent/analysis.pyROI 特徵包：平均/標準差/Otsu、暗部佔比、邊緣密度、HSV 主色、暗亮粒子統計（連通元件）、霍夫圓形試探。規則引擎靠它自動調參；LLM 拿它的文字摘要省 token。
intents.py提示詞（中英關鍵詞）＋ROI 形狀＋特徵 → 意圖（封閉集合：count / diameter / width / angle / defect / color_match / color_presence / presence / brightness / barcode / generic），並抽出期望數量、標稱值、公差、mm/px 換算。
synth.py每種意圖一個合成器：掛使用者 ROI、用特徵自動填參數（門檻極性、blob 最小面積、HSV 範圍、環形 ROI 自動生成……），輸出 graph＋設計理由。
llm.pyClaude 供應器（可選）：工具目錄＋graph 規格＋合成規則放進可快取的 system 段，影像縮圖＋ROI＋特徵摘要進 user 訊息；輸出 JSON 經 validate_graph 把關，失敗帶錯誤重試一次。
service.py編排與試跑；規則式微調（口語回饋 → 參數調整映射）。LLM 失敗自動落回規則引擎。
api.py/vision/agent/* 端點；執行類權限（鎖定時 423）。

LLM 生成（可選）

在 .env 設 VISION_AGENT_API_KEY（Anthropic API 金鑰）並 pip install anthropic 後，生成改由 Claude 執行（VISION_AGENT_MODEL 預設 claude-opus-5）。LLM 看得懂更自由的描述（「杯口內外緣都量、壁厚也要」）， 可以組合規則引擎沒有的流程形狀。

  • 把關不變：LLM 輸出的 graph 一樣經 validate_graph＋實跑驗證；無效輸出帶錯誤重試一次，再失敗自動落回規則引擎。
  • 金鑰只在伺服器：前端永遠打自己的後端；金鑰不進瀏覽器。
  • 資料外流邊界：啟用 LLM 時「縮圖後的影像＋ROI＋特徵摘要」會送到 LLM 供應商。內網／保密環境不要設金鑰——規則引擎功能完整。
  • 成本控制：工具目錄與規格放在可快取的 system 段（prompt caching），迭代微調時只付增量。

迭代微調

生成結果附「設計理由」與實跑報告。回饋框輸入口語即可：

回饋規則引擎的調整
太敏感／誤判／抓太多blob 最小面積 ×2、顏色容差 +40%、比對分數門檻 −0.1
漏抓／抓不到／太鬆blob 最小面積 ×0.5、邊緣門檻 ×0.6、顏色容差 −30%
改成 4 個數量判斷的期望值改 4
±0.2公差判定改 ±0.2
（對應不到參數）回饋併入需求重新生成

LLM 模式下微調直接把「目前 graph＋回饋」交給 LLM 修改。每次微調都重新實跑。

API

POST /api/vision/agent/image      multipart image → {ref, width, height}
POST /api/vision/agent/generate   {ref, prompt, regions:[{region, hint?}], use_llm?}
                                  → {graph, rationale, provider, intent, report}
POST /api/vision/agent/refine     {ref, prompt, regions, graph, feedback} → 同上
GET  /api/vision/agent/info       {llm, model, provider}

report 與 preview 端點同格式（各節點狀態／輸出／overlay／影像 ref）。 regions 的 region 就是標準 ROI dict（rect / rotated_rect / circle / annulus / polygon / line，全圖像素座標）。 執行類端點：引擎鎖定時 423；一般使用者可用。

設計取捨

  • 產物是 graph，不是黑盒：助手生成的每個流程都能在編輯器打開、逐工具檢視參數，現場工程師看得懂、改得動；助手是「起手式產生器」，不是取代編輯器。
  • 規則引擎當地板、LLM 當天花板：規則引擎覆蓋工廠 8 成常見檢測且完全離線；LLM 是加值選配，掛了金鑰立刻變聰明，拔了金鑰功能不缺。
  • 一律實跑驗證：不管誰生成，都要在使用者影像上真的跑一遍才回給前端——「看起來合理」不算數，OK/NG 與 overlay 才算。
  • 深度學習不自動生成：dl_* 工具需要先訓練模型，助手在需要時會在 note 提示走「深度學習教導」頁；write_modbus 需要連線設定，同樣不生成。
  • 紅線不動：不改 graph 格式、不動引擎、單一 API 行程；agent 試跑用呼叫者執行緒直跑 engine.execute，不佔流程執行緒池。
