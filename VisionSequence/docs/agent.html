AI 助手：上傳影像＋圈選＋提示詞 → 自動生成檢測流程

AI 助手（側欄「AI 助手」，/agent）讓不熟工具鏈的使用者用三步驟建立檢測： 上傳影像 → 在影像上圈選檢測位置（可多個 ROI、各配提示）→ 用一句話描述需求。 助手生成一個標準的流程 graph，立刻在這張影像上實跑並把檢測標記疊回圖上； 不滿意就用口語回饋（「太敏感」「漏抓」「改成 4 個」）迭代微調，滿意後一鍵存成流程、進編輯器繼續調。

詢問機制：先確認再生成

按下「生成檢測流程」時助手不會直接動手，而是先呼叫 POST /agent/clarify 判斷資訊是否足夠；不足就提出最多 3 個關鍵問題（選項／數值／文字／「請再圈 ROI」四種），回答後再確認一次，可能還有下一輪，直到 ready 才生成。可隨時「略過提問直接生成」，此時結果卡會列出「未提供…，已用預設值」的警示。

情況助手會問
提示詞不明確（「看一下」「檢查」）要檢測什麼？（計數／直徑／寬度／角度／缺陷／顏色／有無／讀碼／亮度）
計數但沒給數量期望數量？（可略過→只回報）；沒圈 ROI → 整張還是特定區域；暗亮粒子數相近 → 目標比背景暗還是亮？
量直徑但沒有圓形 ROI 也偵測不到圓請在孔緣圈環形 ROI；要 mm 卻沒像素尺寸 → 每像素幾 mm？
量寬度／角度缺 ROI 或第二條邊的 ROI；標稱與公差（可略過）
表面缺陷有沒有良品可比對？（有 → 走良品比對）
顏色判斷沒圈 ROI請圈要判斷的區域（目標色取自 ROI）

回答以補充句併回提示詞（例：「期望 5 個」「目標比背景暗」「標稱 17.5±0.4mm」），規則引擎與 LLM 都讀同一份；LLM 模式下由模型依 skills/design.md 的「謹慎原則」自行決定要不要問、問什麼，格式不合就落回規則版問題。

中斷：助手確認或生成中，按鈕會變成「中斷」；全域 AI 助手（編輯器修改、批次諮詢／調整）也有同樣的中斷鍵（前端取消請求，伺服器端該次呼叫結束後不會套用任何結果）。

多張影像與 ROI 編號

可以一次上傳多張影像（縮圖列切換），在每張影像上各自圈 ROI；ROI 依加入順序編號 ROI01、ROI02…，每個 ROI 可補一句提示，提示詞也能直接引用編號：

ROI01 的位置是好品，ROI02 的位置是壞品，找出差異

這句會觸發「良品比對」意圖：好品 ROI 自動裁成範本資產（資產庫群組「AI 助手」），檢測框套在壞品 ROI 的位置（尺寸與範本一致）， 生成 defect_diff 流程。生成後每張影像都會實跑，縮圖角落標 OK／NG，切換影像就看該張的 overlay 與輸出。

AI 代理來源與金鑰（每人各自儲存）

AI 助手頁右上「AI 供應商」：選 離線規則引擎／Claude／GPT／Gemini，填自己的 API 金鑰與模型名（留空用預設）。 設定存在登入帳號（UserPref.agent），別人看不到、也不會跟著 /auth/me 回到瀏覽器——API 只回「已設定＋尾 4 碼」。

來源實作預設模型
offline規則引擎（intents + synth），零外部呼叫—
claude官方 anthropic SDK（可選安裝、延後 import）claude-opus-5
openaiREST /v1/chat/completions（標準庫 urllib，零依賴）gpt-4o
geminiREST generateContent（標準庫 urllib，零依賴）gemini-3.6-flash（2.0／2.5 flash 已被 Google 下架；「-latest」別名高峰常 503）
openai_compatible任何 OpenAI 相容端點（Ollama／vLLM／LM Studio），設 base URL、金鑰可空；廠內無外網時用本地視覺模型依端點（「列出可用模型」查詢）

解析順序：使用者自己的設定（明確選 offline 也算）→ 伺服器 .env（VISION_AGENT_PROVIDER／VISION_AGENT_API_KEY／VISION_AGENT_MODEL／VISION_AGENT_BASE_URL／VISION_AGENT_TIMEOUT_S）→ offline。OpenAI／相容端點與 Gemini 要求 JSON 輸出模式；OpenAI 推理模型（o 系列／gpt-5）自動改用 max_completion_tokens。LLM 失敗改用規則引擎時，原因會列在結果的 warnings 裡。 整合方（API 金鑰身分）沒有使用者，一律用伺服器設定。LLM 呼叫失敗（金鑰錯、逾時、輸出無效）自動落回規則引擎，功能不中斷。

全域 AI 助手（任何頁面）

右下角的 AI 助手 按鈕在每個頁面都在（AssistantDock 掛在 AppShell），開啟後是常駐的聊天視窗：切換頁面不會消失，對話存在瀏覽器（localStorage）。一個輸入框依目前頁面的脈絡分流，不必到各頁找 AI 功能：

脈絡（頁面）能力後端
任何頁面使用說明問答：回答平台怎麼用（回答附「參考文件」連結，開 /docs/… 對應章節）POST /agent/chat → help.py
流程編輯器／工具頁修改流程：修改語氣的句子直接改目前畫布（未儲存的也算），回覆附「改了什麼」，按「套用到畫布」寫回（可復原）；工具頁只提供該工具的參數要領service.edit（代理模式改走 /agent/jobs task=edit）
批次測試頁（選定已完成的執行）資料諮詢（回答附可套用的參數建議）與依資料調整（結果成為新的一次執行並自動選中）consult.consult／service.tune＋persist_tune

模式晶片預設「自動」：問句（含「如何／為什麼／什麼／？」）一律走問答；有修改語氣（「改成」「停用」「放寬」「新增」…）且在編輯器就修改流程、在批次頁就依資料調整；批次頁提到「第 N 張／NG／門檻／結果」等資料字眼走諮詢。判斷不合意時可手動切「使用說明／修改流程／資料諮詢／依資料調整」。頁面用 useRegisterAssistantContext 登記脈絡（kind、目前 graph、套用回呼、批次執行 id），離開頁面自動清除。

使用說明問答的做法

agent/help.py 在第一次查詢時把 docs/*.html 拆成章節（h2／h3 為單位、帶錨點）、加上每個工具的技能（skills.base_skill_text）建成索引；分詞＝英數整詞＋中文雙字詞，BM25 計分並對標題命中與使用者手冊／批次／AI 助手頁略加權；docs 檔案更新會自動重建。有 LLM 時把最相關的 5 段（工具頁再加上該工具技能）連同最近對話與問題交給供應商，系統提示要求只依片段回答、文件沒提到就直說、300 字內、結尾列參考章節；離線或 LLM 失敗時回文件節錄與連結（warnings 註明原因）。

編輯器內離線可用的指令句型：

離線指令句型效果
把 二值化 的 threshold 改成 80依節點標題／id／工具名找節點，參數名可用 key 或中文標籤
停用 去雜訊 ／ 啟用 去雜訊切換節點 enabled
刪除 結果影像刪節點與相關連線（image_source 不可刪）
太敏感／漏抓／改成 4 個／±0.2同「迭代微調」的參數映射

接上 LLM 供應商後不限句型：可以「在找圓後面加公差判定 ±0.5」「把顏色比對換成顏色範圍＋像素計數」，LLM 收到目前 graph 與工具目錄，只動需要動的部分並保留節點 id。

跑多筆影像後請 AI 調整（批次測試頁）

批次測試頁（batch.html）在全域 AI 助手（右下角，脈絡＝批次測試頁）與調參面板提供三種能力，都以暫存的逐張資料為依據：諮詢（POST /agent/consult：規則洞察＋LLM 回答，附可套用的參數建議）、請 AI 調整（/agent/tune 或代理模式 /agent/jobs 帶 batch_run_id，結果落成新的一次執行）、自動調參（POST /batch/sets/{id}/runs {mode:"autotune"}）。以下是原本以影像快取 ref 為輸入的介面，仍可用。

「批次測試」跑完一批影像後，結果表下方有「請 AI 依這批結果調整」：輸入提示詞（「NG 的那幾張其實是好品，太敏感了」「改成 4 個」）， 助手拿到每張的判定與輸出值（LLM 模式還會看到幾張縮圖），調整流程後在同一批影像重跑，回報「調整前 → 後」的 OK／NG／失敗數與逐張變化，滿意再「套用到畫布」。

POST /api/vision/agent/tune  {graph, instruction, runs:[{name, image_ref, status, outputs}]}
→ {graph, rationale, changes, before:{ok,ng,failed}, after:{…}, items:[{name, before, after}], applied}

AI 代理技能（skills）

LLM 之所以能「照平台規則」設計流程，是因為每次都先讀 apps/vision/agent/skills/ 這三份文件——它們既是給 AI 讀的提示詞，也是給人看的說明（AI 助手頁右上「AI 技能」可瀏覽，GET /api/vision/agent/skills）：

檔案內容放在哪
platform.md平台規則：graph 格式、埠與 _flow 控制分支、ROI 座標與形狀、收尾規則（judge／output／not_found）、位深、禁止事項、note、排版system（固定、可快取）
design.md流程設計原則：標準骨架、依需求選工具表、自動調參要領、多張影像／好品壞品、常見錯誤system（固定、可快取）
tools.md每個工具的人工要領（## <type> 分段）：什麼時候用、怎麼接、參數怎麼調、陷阱。平台再自動把該工具的參數表（含範圍／選項／單位／說明）、輸入輸出埠、位深補在後面，組成完整技能依本次相關性挑選後放進使用者訊息

相關性挑選（skills.select_tools）：核心工具永遠帶（image_source／grayscale／threshold／blob／if_number／in_range／judge／output／draw_result／note）＋提示詞關鍵詞（「直徑」→ find_circle、calibration、tolerance_judge…）＋規則引擎解析出的意圖＋使用者圈的 ROI 形狀（line → wall_thickness／line_profile）＋既有 graph 已用到的工具，上限 18 個。其他工具只以一行式目錄列在 system，LLM 需要時知道有它。

這樣 system 段完全穩定（prompt caching 命中），而每次真正需要細節的工具都有完整參數與要領。想讓 AI 更懂你的場域（廠內慣用參數、特定工件的接法），直接編輯這些 markdown 即可，不用改程式。

架構

助手的產物就是標準 graph JSON——跑在既有的資料流引擎上、可在編輯器打開、 可掛任何影像來源、可綁配方與 TCP／HTTP 觸發。助手本身只是「會寫流程的層」，沒有第二套執行路徑。

使用者影像 + ROI + 提示詞
        │
        ▼
  analysis.py ── ROI 特徵量測（直方圖/Otsu/邊緣密度/主色/圓形試探/粒子統計）
        │
        ▼
  ┌─ 生成（二選一，自動切換）──────────────────────────┐
  │  llm.py    有 VISION_AGENT_API_KEY → Claude 生成    │
  │  intents.py + synth.py   否則 → 離線規則引擎        │
  └────────────────────────────────────────────────┘
        │  graph（一律經 validate_graph 把關）
        ▼
  service.trial_run ── 在上傳影像上實跑（engine.execute，不落 DB、不佔流程執行緒池）
        │
        ▼
  {graph, rationale, report}  ← 前端顯示 overlay／輸出值／OK-NG，可回饋微調或存成流程
模組職責
apps/vision/agent/analysis.pyROI 特徵包：平均/標準差/Otsu、暗部佔比、邊緣密度、HSV 主色、暗亮粒子統計（連通元件）、霍夫圓形試探。規則引擎靠它自動調參；LLM 拿它的文字摘要省 token。
intents.py提示詞（中英關鍵詞）＋ROI 形狀＋特徵 → 意圖（封閉集合：count / diameter / width / angle / defect / color_match / color_presence / presence / brightness / barcode / generic），並抽出期望數量、標稱值、公差、mm/px 換算。
synth.py每種意圖一個合成器：掛使用者 ROI、用特徵自動填參數（門檻極性、blob 最小面積、HSV 範圍、環形 ROI 自動生成……），輸出 graph＋設計理由。
providers.py供應商：offline／claude（anthropic SDK）／openai／gemini（REST）；設定解析（使用者 → 伺服器 → offline）、金鑰遮罩。
skills.py＋skills/*.mdAI 代理技能：平台規則／設計原則／每工具要領的載入與組裝，相關工具挑選，技能 API。
llm.py四種任務（generate／refine／edit／tune）共用 system（工具目錄＋graph 規格＋規則，可快取）；影像縮圖＋ROI 編號＋特徵摘要進 user；輸出 JSON 經 validate_graph 把關，失敗帶錯誤重試一次。
service.py編排與試執行（多張影像各跑一次）；規則式微調／指令解析（edit_rules）／批次調參（tune）。LLM 失敗自動落回規則引擎。
api.py/vision/agent/* 端點；執行類權限（鎖定時 423）。

LLM 生成（可選）

在 .env 設 VISION_AGENT_API_KEY（Anthropic API 金鑰）並 pip install anthropic 後，生成改由 Claude 執行（VISION_AGENT_MODEL 預設 claude-opus-5）。LLM 看得懂更自由的描述（「杯口內外緣都量、壁厚也要」）， 可以組合規則引擎沒有的流程形狀。

  • 把關不變：LLM 輸出的 graph 一樣經 validate_graph＋實跑驗證；無效輸出帶錯誤重試一次，再失敗自動落回規則引擎。
  • 金鑰只在伺服器：前端永遠打自己的後端；金鑰不進瀏覽器。儲存設定後會立刻打一個最小請求驗證（POST /agent/settings/test），成功顯示模型與延遲、失敗顯示原因（金鑰無效／缺套件／模型不存在／連不上）。
  • 資料外流邊界：啟用 LLM 時「縮圖後的影像＋ROI＋特徵摘要」會送到 LLM 供應商。內網／保密環境不要設金鑰——規則引擎功能完整。
  • 成本控制：工具目錄與規格放在可快取的 system 段（prompt caching），迭代微調時只付增量。

迭代微調

生成結果附「設計理由」與實跑報告。回饋框輸入口語即可：

回饋規則引擎的調整
太敏感／誤判／抓太多blob 最小面積 ×2、顏色容差 +40%、比對分數門檻 −0.1
漏抓／抓不到／太鬆blob 最小面積 ×0.5、邊緣門檻 ×0.6、顏色容差 −30%
改成 4 個數量判斷的期望值改 4
±0.2公差判定改 ±0.2
（對應不到參數）回饋併入需求重新生成

LLM 模式下微調直接把「目前 graph＋回饋」交給 LLM 修改。每次微調都重新實跑。

候選方案、影像標記與自動調參

規則引擎不再只給一份流程：每種意圖產出「主要方案」＋ 1～2 個參數變體（例如計數的自適應門檻／嚴格粒子、缺陷的保守／靈敏、卡尺的首尾／最強邊緣對、良品比對的保守／ECC 對齊）。全部候選先在上傳的每張影像上靜默試跑（跑完立即釋放節點影像，不佔快取），依影像標記打分（命中 +10、有錯誤節點 −5、失敗 −3），勝者才正式跑並保留 overlay；回應 candidates[] 列出每個方案的判定與分數，AI 助手頁可點選切換（POST /agent/run 在同一批影像重跑）。

影像標記：AI 助手頁縮圖右下角可把每張影像標成應判 OK／NG（GenerateIn.labels）；ROI 提示寫「好品」「壞品」的影像也自動成為標記。有 2 張以上標記且勝者尚未全部命中時，生成會對勝者做小預算自動調參（24 次評估／10 秒），有改善才採用並在 rationale 註明。

自動調參（apps/vision/agent/autotune.py）：座標下降——走訪 graph 內 teach=True 的參數，候選值＝目前值的幾何階梯（由近到遠 ×0.7／×1.4／×0.5／×2／×0.25／×4／×0.1／×10，夾在 minimum／maximum 內；0～1 型 ±0.1／±0.2；select 全選項；boolean 翻轉），在有標記的影像上以（命中數、−錯誤、−失敗）比較，嚴格變好才採納（同分不換、小改動先試，抗過擬合），命中全部或預算用完即停。不動規格類參數：公差判定、範圍判斷、數值判斷的門檻（期望數量）、像素校正、讀碼、定位補正。三個入口：

  • AI 助手生成（上述小預算）。
  • 批次測試：結果表每列可填「期望」OK／NG，按「自動調參」→ POST /agent/autotune（runs[].expected），回與「請 AI 調整」相同的前後對比可套用到畫布；「請 AI 調整」指令含「自動調參」也走此路，離線且有 2 列以上期望時亦自動改走。
  • Golden Set 頁：「自動調參」→ POST /flows/{id}/golden/autotune（用案例的期望狀態與期望輸出），不寫回流程，結果可「帶回編輯器」成為草稿。

定位補正與新意圖

提示詞提到「位置會變／定位／位移／跟隨」，或某個 ROI 的提示填「定位」（標記、marker、fiducial 亦可）：該 ROI 不參與檢測，而是裁成定位範本，流程前面自動包「範本比對 → 定位補正 → ROI 跟隨」三件套（synth.wrap_with_locate）：範本比對的搜尋區＝定位 ROI 外擴 1.5 倍、參考位置＝ROI 中心、每個帶固定 ROI 的檢測節點各接一個 fixture_roi（ROI 輸入埠優先於畫布參數），找不到範本走 NG（locate_failed）。沒有標「定位」的 ROI 時，詢問機制會先要求圈一個位置固定的標記。

新增三種意圖：text（印字有無：text_presence 筆劃密度，關鍵詞「印字／文字／序號／text」）、distance（兩孔中心距：兩個找圓 → distance → 校正／公差，關鍵詞「距離／孔距／中心距」＋孔／圓或兩個圓形 ROI）、template_presence（圖案有無：ROI 裁成範本 → template_match found／not_found，關鍵詞「圖案／範本／樣板／logo／pattern」）。詢問機制各有對應缺口問題（印字區域、第二個孔、要找的圖案）。

代理模式（agentic）：試跑→修改→驗證的迴圈

供應商設定的「工作模式」選「代理模式」（或 VISION_AGENT_MODE=agentic）後，AI 助手頁的生成、全域 AI 助手的修改流程與依資料調整都改走背景工作（POST /agent/jobs，202），前端每秒輪詢 GET /agent/jobs/{id}?step_from= 顯示步驟時間軸（回合／試跑計數、每個動作的摘要與耗時），可隨時取消；助手提問時工作進入「等待回答」，回答走 POST /agent/jobs/{id}/answer 後續跑。沒有 LLM 供應商時工作仍可建立，會立刻以規則引擎完成並在 warnings 說明；工作模式仍是「單次生成」時，背景工作也直接走單次路徑（不進代理迴圈）。

動作層（apps/vision/agent/actions.py）：LLM 能呼叫的工具——get_state（需求／ROI／特徵／標記／目前流程）、list_tools／get_tool_skill、analyze_region、draft_from_rules（規則引擎草稿，通常是起點）、use_candidate、replace_graph、patch_graph（set_param／set_params／enable／disable／remove_node／add_node／add_edge／remove_edge／set_label，整批套用後驗證）、run_trial（每張影像的狀態、具名輸出、節點訊息與標記命中）、inspect_node、crop_template、auto_tune、ask_user（最多 3 題）、finish。所有 graph 變更都經 validate_graph，並拒絕 dl_*／write_modbus／save_image 與多個 image_source；試跑走 trial_run(keep_images=False) 不佔影像快取。

迴圈（loop.py）：預算 Budget(max_turns=12, max_trials=8, max_tool_calls=30, deadline_s=240)，每回合檢查取消；狀態 done｜needs_input｜budget｜cancelled｜error。預算用完仍有流程時以目前流程為結果（warnings 註明）。模型只回文字不呼叫動作：已有流程就當完成（文字＝說明），沒有流程提醒一次後才算失敗。

供應商 shim（providers.complete_tools）：中立歷史格式（user 文字＋影像／assistant 文字＋tool_calls／tool 結果）→ Claude tools（tool_use／tool_result，連續結果合併成一則 user）、OpenAI functions（tool_calls／role=tool）、Gemini functionDeclarations／functionResponse（schema 轉 OpenAPI 子集；Gemini 3 的 functionCall 帶 thoughtSignature，歷史裡保留原生 parts 原樣回傳，否則 400）；OpenAI 相容本地端點沿用 functions 格式，不支援時代理迴圈失敗 → 自動退回單次 JSON 生成 → 規則引擎。tool_choice 一律 auto。system＝平台規則＋設計原則＋skills/agentic.md（代理工作方式）＋精簡目錄（穩定可快取）；第一則訊息附最多 4 張影像與相關工具技能。

費用與延遲：試跑結果只回精簡文字（不回影像）、動作結果上限 12k 字、預算保守；長時間工作不占檢測執行緒池（背景執行緒），一個行程同時最多 3 個工作。

記憶與學習：工作階段、先驗、自訂技能

工作階段（AgentSession）：每次生成（單次或代理）都存成一筆——影像檔（ASSET_DIR/agent/<id>/）、ROI、需求與問答、影像標記、特徵向量、產出的 graph／rationale／候選摘要、每張影像的判定、供應商與模式。success＝標記全部命中（沒有標記為 null）；使用者可在結果卡按讚／倒讚（rating ±1），存成流程時自動關聯 flow_id。AI 助手頁「歷史」可列出、還原（影像重新放進快取、ROI／需求／標記帶回、流程在原影像重跑）與刪除；API：GET /agent/sessions[/{id}]、PATCH /agent/sessions/{id}（rating／success／note／flow_id）、POST /agent/sessions/{id}/restore、DELETE。一般使用者只看得到自己的，管理員／整合方看全部。存檔為 best-effort，失敗只記 log 不影響生成。

相似案例先驗（memory.find_similar）：特徵向量＝第一個 ROI（或整張）的平均灰階／σ／穩健 σ／邊緣密度／暗部佔比／主色 HSV／面積對數；同意圖、成功或按讚（倒讚排除）、歐氏距離 ≤ 0.35 的最近 2 筆成為先驗。用在三處：規則引擎把成功流程的 teach 參數套到新草稿成為候選「沿用過去成功參數」（排第一，原主要方案第二，標記排名可否決）；自動調參把先驗值排在候選階梯最前；LLM／代理的使用者訊息多一段「過去成功案例」（需求、流程節點、關鍵參數、理由）。回應 similar[] 列出參考到的案例。

自訂技能（AgentSkill）：「AI 技能」視窗每個技能（平台規則／設計原則／代理工作方式／各工具）下方可寫補充要領：個人補充只影響自己、站點補充（管理員）影響所有人。站點補充併進可快取的 system 段（skills.build_system(epoch)，儲存時 skills.invalidate() 讓 epoch 變才重組）；個人補充放進 user 訊息（focus_text(keys, user)：工具技能全文含補充＋「個人補充：平台規則／設計原則／代理工作方式」段）。API：GET /agent/skills/custom、PUT /agent/skills/custom/{key}（{markdown, scope}，上限 20000 字）、DELETE /agent/skills/custom/{key}?scope=；GET /agent/skills/{key} 回合併後全文與原始補充。

評測基準

manage.py agent_bench 用 apps/vision/agent/bench.py 的案例（合成樣本圖＋ROI＋提示詞＋期望意圖與每張影像的期望判定）跑離線規則引擎，印出意圖準確率、判定準確率（案例／影像）、graph 有效率與耗時；--llm 改用伺服器供應商、--keys 只跑指定案例、--json 輸出完整結果。tests/test_agent_bench.py 以門檻守住回歸（目前意圖 ≥ 0.9、判定 ≥ 0.8、全部有效），之後每個能力提升都用同一把尺量。案例可帶 labels（影像標記）以覆蓋候選排名與自動調參路徑；Phase 1 新增印字、中心距、圖案、定位＋卡尺、計數＋標記五個案例（共 21 個）。

LLM 模式實測（--llm，gemini-3.5-flash-lite 單次生成，2026-09）：意圖 100%、判定 76%、有效 81%、平均每案例約 7 秒。失敗型態有三種：驗證擋下（埠型別接錯、邊指到不存在的節點）→ 已自動落回規則並回 warnings；驗證過但實跑全部失敗（範本資產 id 亂填、把輪廓接進結果影像的標記埠）→ 現在 service.generate 會在試執行全部失敗時改用規則引擎並說明原因，draw_result 也會略過不是標記的輸入；純判定錯（顏色有無門檻太鬆）→ 模型能力，交給影像標記與自動調參。規則引擎在同一組案例是 100%，所以單次 LLM 生成適合當「起點」，代理模式或標記＋自動調參才是把判定拉到位的手段。

設計取捨

  • 產物是 graph，不是黑盒：助手生成的每個流程都能在編輯器打開、逐工具檢視參數，現場工程師看得懂、改得動；助手是「起手式產生器」，不是取代編輯器。
  • 規則引擎當地板、LLM 當天花板：規則引擎覆蓋工廠 8 成常見檢測且完全離線；LLM 是加值選配，掛了金鑰立刻變聰明，拔了金鑰功能不缺。
  • 一律實跑驗證：不管誰生成，都要在使用者影像上真的跑一遍才回給前端——「看起來合理」不算數，OK/NG 與 overlay 才算。
  • 深度學習不自動生成：dl_* 工具需要先訓練模型，助手在需要時會在 note 提示走「深度學習教導」頁；write_modbus 需要連線設定，同樣不生成。
  • 紅線不動：不改 graph 格式、不動引擎、單一 API 行程；agent 試執行用呼叫者執行緒直跑 engine.execute，不佔流程執行緒池。
