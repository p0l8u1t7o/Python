## v0.2 — 客戶展示版（2026-08-22）

### 機隊模擬器與展示租戶

- **`manage.py simulate_fleet`**：一支程式跑整個機隊。每個已登錄的閘道器一條 MQTT 連線（Sparkplug B NBIRTH/DBIRTH/DDATA/NDEATH），每個場域一組物理模型：負載曲線（廠房／辦公／園區）、太陽曲線、電池 SOC 積分與上下限，**電網 = 負載 − 光電 − 電池**。設備接受 `set_power_setpoint` 與 `emergency_stop`，回 ack 並即刻回報新讀值，因此平台下的任何指令都會在電表上看到。`--faults` 注入事件與警報，`--autonomous` 讓電池在尚未收到設定點時自行削峰。
- **`manage.py seed_showcase`**：四個有設備的場域（新竹園區 A 棟廠房／B 棟研發大樓、台中工業區廠房、台北總部）＋一個父場域，20 台設備、4 台閘道器、台電牌價、四個策略各異的儲能方案（含父場域繼承與子場域覆寫）、告警規則、通知管道範例、示範工作流程。
- **`scripts/reset-demo.ps1`**：清空資料庫 → migrate → bootstrap → seed_showcase → 7 天歷史 → 啟動整個堆疊。展示流程見 `docs/demo-guide.md`。
- `dev.ps1` 現在同時啟動 **排程器**（能源彙總＋調度引擎，60 秒一輪）——之前開發堆疊沒有跑它，策略從不會真的下指令。
- 歷史產生器改為依場域的負載形狀與有效方案的策略（契約容量管理／時間電價套利／自發自用）模擬電池，和即時模擬器講同一個故事。

### 設備模擬器獨立化：真正的外部 MQTT 客戶端

- 模擬器搬到 `simulator/`（physics / config / gateway / console），**不讀資料庫、不載入平台程式**，只靠 `simulator/fleet.json` 與 MQTT；`manage.py export_fleet_config` 從平台登記匯出這份設定（也可手寫或交給廠商）。實測在沒有 `DJANGO_SETTINGS_MODULE`、零個 `apps.*` 模組載入的情況下完成整個上線／命令／離線週期。
- 主控台新增 **Broker IP / Port / 帳密 / Group ID** 欄位（可儲存回設定檔）、**設備即時量測值**面板（每 0.5 秒更新每個量測項與單位）、設定檔開啟／重新載入、連線失敗狀態顯示。
- Sparkplug 編解碼仍與平台共用同一套 `services/sparkplug`，線上格式不會漂移；`services/harness/fleet.py` 縮減為「登記 → fleet.json」的匯出器與測試用轉接。
- 延遲探針（`scripts/latency_probe.py`）改為自含，舊的 `scripts/sim_console.py` 移除。

### 修正：「全部離線」後仍有設備顯示上線

三個獨立原因疊在一起，各自修掉：

- **平台（worker）批次順序**：同一批訊息裡先 DDATA 後 DDEATH，批次結尾「有送資料者即上線」的步驟跑在死亡之後，把設備又標回上線。現在死亡會把該設備從本批的「活躍」名單移除；死亡之後的資料才算新會話（加 3 項回歸測試）。
- **模擬器競態**：平台命令在 DDEATH/NDEATH 送出後才被回覆（paho 執行緒），或重生要求在離線途中被回應而重新宣告。所有發布改在同一把鎖下，停止訊號後不再回覆命令、不再重生。
- **內建 broker 會丟掉緊跟著 DISCONNECT 的 PUBLISH**：NDEATH 以 QoS 1 送出後立刻 DISCONNECT，約三成機率 NDEATH 沒到 broker，節點永遠「上線」。模擬器在 NDEATH 後等 0.5 秒再斷線；平台另外新增**邊緣節點逾時掃描**（`DEVICE_OFFLINE_GRACE_SECONDS`，預設 180 秒沒收到任何訊息就標離線），所以即使真實設備的 NDEATH 遺失也不會永遠顯示上線。

### 設備模擬：只剩桌面主控台，啟動時一切離線

- `dev.ps1` / `dev.sh` / `reset-demo.ps1` **不再啟動任何模擬器**；堆疊起來後所有登記的設備都是離線的。
- `scripts\sim-console.ps1` 是唯一的模擬入口：列出平台登記的每台閘道器與設備，「全部上線」讓它們各自以真實 MQTT（Sparkplug B）客戶端連線並持續上傳（含場域物理模型、命令執行與回覆），「全部離線」發 DDEATH/NDEATH 中斷；可只選部分閘道器。沒有能源資產的閘道器也會以控制器身分上線。
- 手動測試區：事件注入、警報觸發／解除、手動逐步回覆命令。
- 移除 `simulate_device`、`simulate_fleet` 兩個管理命令與 `-Simulate` 旗標；機隊物理模型留在 `services/harness/fleet.py` 供主控台使用。

### 通知訊息：發生與解除分得清楚

- 每則 LINE／Email 的第一行標明 **🔴 發生 RAISED** 或 **🟢 解除 RESOLVED**（測試訊息為 🔔 測試），Email 主旨加 `[發生]`／`[解除]`。解除訊息附解除時間與持續時長；時間一律以組織時區顯示。
- 規則警報現在**解除時也會通知**（自動解除與人工解除皆是），送給當初收到發生通知的同一批管道；之前只有設備自報警報的解除會透過事件通知送出。
- 送達階段記在 `NotificationDelivery.phase`，不再於送出當下讀警報狀態——否則 worker 較晚送出的「發生」訊息會因警報已解除而印成「解除」。
- 設備警報解除的事件改記為 `info` 層級並帶 `alarm_state / alarm_level`，事件紀錄頁顯示「發生／解除」標籤；通知門檻以發生時的層級判斷，解除訊息不會因為層級較低而被漏掉。

### 全系統盤點：補齊只做一半的功能

盤點方式：搜尋未接線的 API 端點、沒有 UI 的模型欄位、沒人讀的設定、靜默吞掉的錯誤，以及 `system-logic.md` §8 宣稱已實作但實際不通的項目。補齊：

- **能源資產綁定 UI**（儲能頁「綁定資產」）：之前後端有 API、前端只有唯讀表，**全新安裝沒有任何方法把設備綁到角色**，儲能／成本／節費永遠是空的。現在可新增／編輯／解除綁定；指標從設備實際回報過的鍵選，角色預填常用鍵；含倍率、反號、**納入能源平衡**、額定值、**運轉區段參數**、**成本模型與參數**——後三組欄位之前連 API 都沒有暴露。
- **閘道器管理**（整合說明頁）：登錄閘道器並一次性顯示 MQTT 憑證、輪換憑證、**要求重生**（§1.8 所說的唯一復原路徑，之前只有 worker 會自動觸發）、移除。
- **排程調度時段**（儲能頁）：`DispatchWindow` 的 CRUD 之前無任何入口；現在可建立一次性充／放／待命／依策略時段並看到生效狀態。重複規則（`recurrence`）引擎未實作，表單不提供。
- **組織設定**（設定頁，擁有者）：名稱、預設時區、報表幣別。
- **設備**：記錄策略可逐台覆寫；被替換的設備顯示接替設備連結。
- **稽核紀錄**動作名稱本地化（之前三語都顯示英文）。
- **總覽需量費表**：電價沒有基本電費費率時顯示「電價未設基本電費」而不是 $0。
- **`scripts/dev.sh`**（POSIX）之前沒有啟動排程器，能源彙總與調度在 macOS／Linux 開發機上從不執行；並改用機隊模擬器。
- 指標目錄 API 暴露 `counter_max`（計數器回繞點）；出生宣告帶錯誤 `counter_max` 時記錄警告而非靜默忽略；排程器工作失敗進結構化日誌。
- 移除無人讀取的設定 `TIMESCALE_ENABLED`、`INGEST_AUTO_PROVISION_ORG`（README 同步）；`SITE_DEFAULT_TIMEZONE` 改為真的被用於新場域預設；移除前端 7 個未使用的匯出與 hook。
- `system-logic.md` §8 更正：需量費受益面已實作；資產 session／成本參數現在 API 與 UI 都可設定。

### 通知管道：Email 與 LINE 修正、測試按鍵

- **Email 其實從未寄出**：伺服器沒設 `EMAIL_HOST` 時 Django 走 console backend，把信印在 worker 視窗卻回報「已發送」。現在：(1) 管道可直接在畫面上填 SMTP（主機、連接埠、帳號、密碼、STARTTLS/SSL、寄件人），優先於環境變數；(2) 兩者都沒有時**拒絕**並回報「No SMTP server configured」，不再假裝成功。
- **LINE 401**：使用者填的是數字型 Basic ID／顯示名稱，LINE Messaging API 只接受 `U/C/R + 32 位十六進位` 的 ID；表單與 API 都擋下格式錯誤並說明去哪裡找 User ID。LINE 回傳的錯誤現在帶上官方訊息與對應提示（401 token 無效、400 收件者格式、403 未加好友、429 限流）。
- **測試發送按鍵**（`POST /api/notification-channels/test`）：用表單當下的設定立即送一則測試訊息，**不必先儲存**；結果就地顯示（成功含耗時、失敗含原因）。管道列表每列也有測試鍵，並顯示最近一次實際發送的成功／失敗與時間。
- SMTP 錯誤會標明主機與連接埠；`smtp_password` 與 token 一樣儲存後不回傳、留空表示保留。

### 使用者體驗與防呆

- **對話框誤關保護**：編輯中的表單（規則、通知管道、電價、場域、記錄策略、設備編輯／替換）按 Esc、點背景或 X 時，若有未儲存變更會先詢問「放棄變更？」；「取消」按鈕仍是直接關閉（`Modal.dirty` + `useFormDirty`）。
- **表單即時驗證，錯誤就地顯示、儲存鍵停用**：儲能方案（SOC 上下限順序、備援保留、往返效率、需量上限 ≤ 契約、策略必填項如套利需電價、工作流程策略需指定流程）、警報規則（上下界順序、遲滯不可寬到永不解除、時長／冷卻非負）、電價時段（HH:MM、零長度時段、負價格、未選月份、時間電價至少一個時段）。
- **設備指令對話框**：參數改為中文標籤與說明（`power_w` 註明「正值放電、負值充電，單位瓦特」），超出範圍即時標紅並停用送出。
- **工作流程編輯器**：「跳至」目標改為節點下拉（不再手打 id），指向不存在／註解／自己的目標會被驗證擋下；檢視面板提示未連線的輸出把手（最常見的「流程默默不動」原因）；按「執行」先彈確認，列出會實際送命令的節點數、未儲存變更會先儲存；節點參數名稱、說明與選項本地化。

- 總覽頁新增 **需量費受益** 表：各場域契約容量、未調度最高需量、實際最高需量、降低需量、需量費受益（含避免的超約罰款，依台電 2 倍／3 倍規則）。能源面節費只算 kWh 價差，對表後儲能而言基本電費才是大頭；這一版把兩個都算出來。

### 修正

- **策略追自己的尾巴**：契約容量管理與時間電價套利從電表讀值決定，但電表已含電池自己的功率——充電 120 kW 把電表推高 120 kW，下一輪判定超約改放電，再下一輪又看到空間改充電。現在以「電表 + 電池」還原場域本身的需量再決策。
- **夜間充電變成當月最高需量**：離峰回充的上限改為契約容量的 95%，不再剛好貼著契約充。
- 模擬器負載／日照曲線原本用 UTC 小時，台灣中午光電為 0；改用場域時區。
- 沒有設備的父場域不再被標成「資料已過期」，也不計入「回報中場域」分母。
- `bootstrap` 重複執行（同一行程內）會 KeyError——內建藍圖表被 pop 掉 key；改為複本。
- 延遲量測 e2e 在全新資料庫上找不到探針設備（探針要先發布一次才會登錄）；改為先暖身發布。

### 本輪測試抓到並修正的問題

- **穩定不變的讀值被判為「過期」**：記錄策略的死區過濾把值未變的讀值整筆丟掉，連最新值表的時間戳都不更新，SOC 停在 55% 一小時後被控制引擎視為 stale 而拒絕判斷。改為最新值表永遠反映設備最後回報，死區只決定歷史儲存密度。
- **開發伺服器隨機停止**：SSE 長連線經 Vite proxy，瀏覽器分頁關閉時的 ECONNRESET 未被處理而拖垮整個 dev server。已加錯誤處理並排除測試輸出目錄的檔案監看。
- **工作流程列表沒有刪除操作**：補上（admin 權限）。
- **全新安裝沒有示範工作流程**：「削峰與低電量保護」改為 seed 資料（設備 ID 以佔位符解析）。
- **規則頁對非 admin 發出讀不了的請求**：通知管道查詢改為依角色閘門，不再產生 403。

### 即時性（本輪新增）

- 全 console 改由單一 SSE live feed 驅動更新;MQTT 發布→畫面:遙測 ~0.5 s、警報事件 ~0.6 s、設備離線 ~0.9 s(由 `frontend/e2e/latency.spec.ts` 對真實堆疊量測)。
- 修正:滾動時間窗的結束時間曾固定在頁面載入瞬間,停留越久新資料越看不到;現在隨事件與每分鐘前移。
- 修正:桌面模擬器與探針未指定 MQTT 3.1.1 時以 MQTT 5 連內建 broker 會靜默失敗;模擬器一律使用 3.1.1。

### 已知限制（刻意的設計邊界）

- 工作流程的即時監看為 SSE；伺服器端仍以 1 秒間隔查資料庫（引擎在獨立行程、SQLite 無跨行程通知）。正式環境要真推播需 Redis pub/sub + ASGI。
- 台電電價為內建牌價表（114 年度），非即時 API；計費前請對照台電最新公告。
- 儲能策略跑在排程器週期（分鐘級），適用 15 分鐘需量與電價段落，不是毫秒級 PCS 迴路。
- 子場域的即時功率流與能源區間各自計算；跨子樹彙總在場域摘要與報表 rollup。
- 示範帳號密碼寫在版控中（`ChangeMe-2026!`），對外開放前務必更換。
