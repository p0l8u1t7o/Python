| 事項 | 決議 |

### 1.1 現況

- Batch1／Batch2 影像中的錫球與凸塊**沒有可見的空洞**。錫球內較亮的圓斑是錫球與下方焊墊重疊造成的吸收量增加，不是空洞；空洞應呈現為錫球內吸收量**較低**的區域。
- 因此本階段的演算法以「合成影像＋錫球物理模型」開發與測試。實際影像到位後，第 6 節的驗證流程才能完成，模組才能改為「已驗證」。

## 3. 空洞檢測模組（5a）

### 3.1 模組宣告

| 項目 | 內容 |
|---|---|
| 模組代碼 | `void` |
| 名稱 | 空洞檢測／Void Inspection |
| 支援影像 | 16-bit 原始影像（正式判定）；8-bit 轉存影像可分析，判定最多「需複判」（沿用平台規則） |
| 判定項目 | 單顆空洞率上限（預設 25%）、最大單一空洞佔比上限（預設不啟用）、總空洞率上限（預設不啟用）、超規焊點數上限（預設 0） |
| 方法 | `rule`（規則式，預設）、`model`（深度學習，需指定模型）、`both`（兩者都執行，差異大時列為需複判） |

### 3.2 量測流程（規則式）

1. **定位焊點**：在吸收量影像以尺度空間偵測圓形目標，半徑範圍由配方設定（例如 BGA 錫球 50～100 px、微凸塊 20～35 px），只保留範圍內的焊點；可再用檢測區域（5b）限定。
2. **逐顆建立無空洞時的預期外觀**：焊球在 X 光下的吸收量與穿透厚度成正比，無空洞時由中心往外依球體弦長平滑下降。以「二次背景＋球體弦長輪廓＋下方焊墊圓盤」擬合，並反覆排除負殘差（可能是空洞）的像素，讓空洞不影響擬合。
3. **找出空洞**：殘差低於局部雜訊的 k 倍（預設 4 倍），且相對深度超過焊球中心吸收量的一定比例（預設 5%），面積大於最小空洞面積，才判為空洞。邊緣 10% 半徑的環帶因邊緣模糊不列入。
4. **量測**：每顆焊點的空洞率（空洞總面積 ÷ 焊點投影面積）、最大單一空洞佔比、空洞數；影像層級的最大空洞率、平均空洞率、超規焊點數。有像素尺寸時同時輸出 µm²。
5. **不確定性**：每顆焊點回報空洞率的估計誤差（以雜訊與邊界像素數估算）。判定沿用平台做法：空洞率 ± k·誤差 跨越規格時列為「需複判」。

所有門檻都以焊點自身的中心吸收量與局部雜訊為基準，不使用絕對灰階，確保功率與曝光改變時結果不變（規劃書第 3.3 節）。

### 3.3 無法判定的條件（品質指標）

| 指標 | 說明 |
|---|---|
| `void.balls_found` | 可量測焊點數；過少時品質不足 |
| `void.fit_rms` | 球體模型擬合殘差（排除空洞後）；過大表示焊點外形不符（例如變形、重疊、斜射） |
| `void.contrast` | 焊點中心吸收量對局部雜訊的比值；過低時小空洞無法可靠偵測 |
| `void.min_detectable_pct` | 依雜訊推算的最小可偵測空洞率，報告中列出 |

### 3.4 結果與疊圖

- 檢測物件：`ball`（圓，含空洞率、最大空洞、空洞數）、`void`（多邊形輪廓，含面積與佔比）。
- 疊圖：焊點圓依判定著色（合格／超規），空洞以輪廓標示；平台現有的檢視器、數據表、報告自動支援，不需另外開發畫面。
- 報告：空洞率分布直方圖與超規焊點清單（以通用報告區塊呈現）。

### 3.5 合成影像產生器

`tests/synthetic_void.py`：依物理模型產生測試影像：

- 焊球（球體弦長）、下方焊墊圓盤、背景走線紋理
- 球形空洞（弦長扣除）：數量、大小、位置、深度可指定，並提供正確答案（空洞面積與位置）
- 雜訊（光子雜訊）、邊緣模糊（焦點尺寸）、曝光與功率變化（±50%）、輕微斜射

用途：演算法開發、單元測試、成像條件不變性測試、驗收基準（第 7 節）。

### 3.6 模組驗證狀態

依規劃書第 5.6 節，只有「已驗證」的模組版本可用於正式判定。做法如下：

- 每個模組版本記錄驗證狀態：`unvalidated`（未驗證）或 `validated`（已驗證，附驗證報告與核准人）。
- 未驗證模組仍可在配方中使用，但判定最多「需複判」，並在紀錄與報告上標示「模組未驗證，結果僅供參考」，做法與 8-bit 影像相同。
- 工程師以 `validate-module`（5e）產生驗證報告後，在「配方管理 > 檢測模組」核准，記入稽核紀錄。
- 微凸塊對位模組 1.1.x 已有回歸基準與重複性驗證，資料庫升級時直接標示為已驗證。

## 4. 檢測區域（5b）

- 配方可設定多個**包含區域**與**排除區域**（矩形或多邊形），模組只處理包含區域內、且不在排除區域內的目標；未設定時為整張影像。
- 在配方編輯器中選一張參考影像直接框選。
- 限制：區域以影像座標儲存，樣品擺放位置變動較大時需重新框選。以陣列自動對位的區域為後續選項，本階段不做。
- 平台共用，微凸塊對位模組也可使用。

## 5. 深度學習推論與模型管理（5c）

### 5.1 推論執行環境

| 項目 | 規劃 |
|---|---|
| 執行環境 | ONNX Runtime 的 DirectML 版本：同一套件支援 CPU 與 Windows 上的 GPU（NVIDIA、AMD、Intel 皆可），**不需另外安裝 CUDA** |
| GPU 使用 | 預設關閉；由系統管理員在「系統管理」啟用（規劃書第 8.1 節：設備可能用 GPU 做 3D 重建） |
| 資源 | 推論在分析子行程中以低優先權執行；每個子行程載入一次模型並快取 |
| 安裝包大小 | 約增加 20～30 MB；執行環境有變動，更新檔需包含執行環境 |

### 5.2 模型檔

| 項目 | 規劃 |
|---|---|
| 格式 | `.xrvmodel`（ZIP）：`model.onnx`、`model.json`（模型代碼、版本、適用模組、輸入尺寸、前處理、輸出類別、訓練資料摘要、驗證指標）與簽章 |
| 簽章 | 原廠以更新簽章金鑰簽署，平台驗證後才能匯入 |
| 版本管理 | 模型代碼＋版本；配方指定模型時與模組版本一樣在發布時鎖定 |
| 管理頁面 | 「配方管理 > 模型」：匯入、檢視資訊、停用（工程師以上） |
| 輸入 | 以焊點為中心裁切並依焊點自身正規化的吸收量影像（與規則式相同的前處理，確保不受曝光影響） |
| 輸出 | 每個焊點的空洞分割遮罩；模組再以相同方式計算空洞率 |

### 5.3 原廠端

- 模型訓練在平台外進行。提供參考訓練腳本 `tools/model_training/`（PyTorch，小型 U-Net 分割，輸出 ONNX），不隨產品發布。
- 打包工具 `tools/model_training/make_model.py`：驗證 ONNX、寫入描述並簽章，產生 `.xrvmodel`。

## 6. 標註與訓練資料（5d）

| 項目 | 規劃 |
|---|---|
| 標註 | 檢閱畫面新增「標註」模式：對空洞輪廓新增、刪除、修改（多邊形與筆刷），並可標記焊點「無空洞」；工程師以上可用 |
| 儲存 | 新增 `annotations` 資料表（影像、模組、物件、幾何、標註人、時間），保留修改歷程，不覆寫模組原始結果 |
| 與複判的關係 | 人工複判說明「判定是否正確」；標註說明「空洞正確位置」。兩者分開記錄 |
| 訓練資料匯出 | 選取紀錄匯出單一 ZIP：焊點裁切影像（16-bit 吸收量）、遮罩 PNG、`dataset.json`（來源影像雜湊、成像條件、標註人）；可去識別化 |
| 改善循環 | 使用 → 複判與標註 → 匯出交給原廠 → 原廠訓練並簽署新模型 → 匯入新模型 → 驗證 → 核准 |

## 7. 模組開發指南與驗證工具（5e）

- **開發指南** `docs/module-development-guide.md`：介面、參數、結果、品質指標、判定、語系、測試、合成影像、打包與註冊，以空洞模組為實例說明。
- **範例模組樣板** `examples/module_template/`：最小可執行的外部模組套件，含單元測試，可用來開新模組。
- **驗證工具** `python -m xrayvision validate-module <module_id> --dataset <標註資料集> --recipe <配方>`，產生驗證報告（HTML＋JSON）：
  - 檢出率、誤報率（以空洞為單位，依大小分級）
  - 空洞率誤差（每顆焊點，平均與 95% 分位）
  - 判定一致率（與標註推得的判定比較）
  - 成像條件不變性（同一視野不同曝光）與重複性（重拍）
- 驗證報告與核准流程見第 3.6 節。

## 8. 驗收標準

在實際影像到位前，以合成影像驗收：

| 項目 | 標準 |
|---|---|
| 空洞檢出 | 直徑 ≥ 焊球直徑 15% 的空洞，檢出率 ≥ 95%；無空洞焊球的誤報率 ≤ 2% |
| 空洞率誤差 | 空洞率 ≥ 3% 的焊球，絕對誤差 ≤ 2 個百分點 |
| 成像條件不變性 | 曝光與功率 ±50% 時，同一焊球的空洞率變動 ≤ 1 個百分點 |
| 焊墊干擾 | 焊球下方有焊墊（亮斑）時，焊墊不得被判為空洞 |
| 現有影像 | Batch1／Batch2 不應檢出空洞（誤報率 ≤ 2%），也不得影響微凸塊對位的回歸基準 |
| 效能 | 單張 6 百萬像素、約 300 顆焊點，規則式 ≤ 5 秒（單行程，CPU）；模型推論於 CPU ≤ 15 秒 |
| 深度學習框架 | 以合成影像訓練的示範模型可完成匯入、推論、結果顯示；推論結果與規則式的空洞率差異 ≤ 3 個百分點 |

實際影像到位後，以客戶影像與人工標註重新驗收，驗證報告核准後模組才改為「已驗證」。

## 10. 風險

| 風險 | 對策 |
|---|---|
| 合成影像與實際空洞外觀不同（形狀、對比、重疊） | 模組標示未驗證；實際影像到位後以驗證工具量化差異再調整；參數保留調整空間 |
| 焊球與焊墊、走線重疊使擬合偏差 | 擬合模型包含焊墊圓盤；擬合殘差過大時品質不足而非硬判 |
| 小空洞在雜訊中無法偵測 | 報告列出最小可偵測空洞率；低於此值的規格設定給予警示 |
| GPU 推論與設備軟體爭用 | 預設關閉；啟用後仍以低優先權、單一行程執行 |
| 沒有標註資料無法訓練實用模型 | 5c～5d 先交付框架與合成資料示範模型；實用模型待客戶影像 |

## 13. 進度

### 13.1 5a 空洞檢測模組（2026-09-23 完成）

說明見 [SPEC-006](void-inspection.md)。與本規劃書的差異：

| 項目 | 規劃 | 實際 |
|---|---|---|
| 空洞最小相對深度 | 0.05 | 0.07：0.05 在焊墊邊緣會出現雜訊層級的小誤報；0.07 約對應直徑 11% 的球形空洞，對 25% 規格沒有影響 |
| 空洞與焊墊重疊 | 未規劃 | 屬量測極限（焊墊抵消空洞深度），以擴大估計誤差轉為需複判，避免超規焊點被判為合格 |
| 深度學習方法選項（`method`） | 5a 宣告 rule／model／both | 5a 只提供規則式，`method` 參數於 5c 加入（次版號提升） |
| 驗收：成像條件不變性 | ≤ 1 個百分點 | 系統性偏移 95% 分位 0.77～1.14，與同條件重拍的差異（1.11）同一量級 |
| 驗收：Batch1／Batch2 誤報 | ≤ 2% | BGA 錫球（Batch2，半徑範圍設定正確）0／83；以複合凸塊為主的影像與 8-bit 影像有少量誤報，見 SPEC-006 第 7.1 節 |
| 疊圖依判定著色 | 焊點圓依合格／超規著色 | 焊點圓統一顏色、空洞以紅色輪廓標示；超規焊點由判定原因（標出第幾顆）與排行表呈現。依判定著色需平台疊圖支援「依量測值選樣式」，列為後續改善 |
| 資料庫結構 | 版本 3 含 `module_validations`、`models`、`annotations` | 版本 3 只有 `module_validations`；`models`、`annotations` 於 5c、5d 以後續版本加入 |

### 13.2 5b 檢測區域（2026-09-23 完成）

| 項目 | 內容 |
|---|---|
| 配方欄位 | `regions`（選用）：`reference`（參考影像寬高與紀錄編號）、`include`、`exclude`；形狀為矩形或多邊形，座標為參考影像像素座標；每類最多 50 個、多邊形最多 200 個頂點。格式錯誤時配方拒絕（`invalid_regions`） |
| 平台 | `core/regions.py` 驗證與產生遮罩；分析時放入 `ctx.region_mask`，模組以 `ctx.in_region(x, y)` 判斷。未設定包含區域時為整張影像；影像尺寸與參考影像不同時依寬高比例縮放並註記 |
| 模組 | 微凸塊對位、空洞檢測都只量測中心在區域內的目標；區域外的目標不列入未量測。未設定區域時結果與先前完全相同（回歸基準不變） |
| 配方編輯器 | 「檢測區域」卡片：從檢測紀錄選參考影像，拖拉畫矩形、逐點畫多邊形（連按兩下完成），選擇包含或排除，清單刪除、全部清除；已發布配方唯讀顯示 |
| 檢閱畫面 | 疊圖新增「檢測區域」圖層（包含綠色、排除紅色虛線） |
| 測試 | `tests/test_regions.py` 6 項；全部 82 項（不含 slow）通過 |
| 未做（依規劃） | 以陣列自動對位的區域；樣品位置變動大時需重新框選 |
