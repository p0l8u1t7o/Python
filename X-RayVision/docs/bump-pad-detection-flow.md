# Micro Bump／Pad 偏移檢測流程

本文說明微凸塊對位模組（`xrayvision/inspections/bump_alignment/`）的檢測邏輯與使用流程，只描述概念，不談程式細節。
此邏輯最初寫在批次工具 `BumpPadShift.py`，已整合為平台的檢測模組，舊工具已移除。

---

## 1. 要解決的問題

Flip-chip 封裝在 X 光俯視影像中，晶片上的 micro bump 應該正好落在基板的 pad 上。
如果整片晶片在貼合時有偏移，每顆 bump 相對於它的 pad 都會往同一個方向錯開。

目標：

1. 在每張 X 光影像中找出每顆 micro bump 與它下方的 pad。
2. 量出每顆的偏移向量（bump 圓心 − pad 圓心）。
3. 把同一個陣列的所有位點合起來，推算整片晶片的偏移量。

---

## 2. 兩種輸入影像

| | Batch1 | Batch2 |
|---|---|---|
| 格式 | 8-bit RGB（檢視軟體轉存） | 16-bit 單通道原始影像 |
| 灰階是否線性 | 否，已被拉伸、帶抖動雜訊 | 是，保留原始 X 光強度 |
| bump 半徑 | 約 17～19 px | 約 25～29 px |
| pad 的樣子 | 常見「暗圓＋一側淡瓣」，pad 露出很明顯 | pad 藏在 bump 正下方，沒有獨立可見的邊 |

程式會自動判斷是哪一種影像，並用對應的處理方式；不需要手動指定。

---

## 3. 整體流程

```
影像
 │
 ├─① 讀取與轉換 ──── 16-bit：轉成「吸收量」；8-bit：去噪後近似
 │
 ├─② 找圓盤 ──────── 自動找出所有圓形暗點，依大小分成「micro bump」與「大球」
 │
 ├─③ 單顆精修 ────── 對每顆 bump 擬合圓盤模型，扣掉局部背景
 │
 ├─④ 量 bump 與 pad ─ 取兩條輪廓線：內層＝bump、外緣＝pad
 │
 ├─⑤ 篩選與分群 ──── 剔除量不好的點，把相鄰的點連成陣列
 │
 ├─⑥ 推算晶片偏移 ── 每個陣列一起估計平移、旋轉、縮放
 │
 └─⑦ 輸出 ────────── 疊圖、CSV、整批報告
```

---

## 4. 各步驟說明

### ① 讀取與轉換

- **16-bit 原始影像**：X 光穿過材料會衰減，把亮度取對數後得到「吸收量」。
  吸收量有一個好處：兩層材料疊在一起時，吸收量可以直接相加。
  所以 bump 疊在 pad 上、或 bump 疊在大球上，都能用簡單的相加模型描述。
- **8-bit RGB 影像**：亮度已被檢視軟體改過，無法還原成真正的吸收量。
  只能先去除抖動雜訊，再把「越暗＝吸收越多」當作近似。

### ② 找圓盤

- 用不同大小的「圓形斑點偵測器」掃過整張影像，找出所有圓形暗點，並估出各自的大小。
- 數量最多的那種大小，就判定為 micro bump 的標準半徑（R0）。
- 比 R0 大很多（1.8 倍以上）的是大球（例如 BGA 球），不量；疊在大球上的 bump 背景太複雜，也不量。
- 只是貼在大球旁邊的 bump 照樣量，量的時候會避開大球那一側。

### ③ 單顆精修

- 每顆 bump 周圍的背景亮度不均勻（晶片區、走線、相鄰大球都會影響）。
- 對每顆 bump 擬合一個模型：「平滑的背景曲面」加上「邊緣有模糊的圓盤」。
- 擬合後得到較準的圓心與半徑，並把背景扣掉，讓每顆 bump 都變成「背景＝0、核心＝1」的標準尺度。
- 相鄰的其他 bump 會先遮掉，不影響這顆的擬合。

### ④ 量 bump 與 pad（核心步驟）

從 bump 中心往外打 120 條放射線，在每條線上找兩個位置：

| 輪廓線 | 高度 | 代表 |
|---|---|---|
| 內層輪廓 | 核心的 75% | **bump**：錫球最厚、最暗的部分 |
| 外緣輪廓 | 核心的 25% | **bump 與 pad 合起來的外緣**；pad 往哪邊錯開，這一側的外緣就會往外凸 |

分別對兩條輪廓擬合圓，兩個圓心的差就是這顆的偏移。

外緣輪廓會被一些不是 pad 的東西干擾，處理方式如下：

- **走線、via 接點**：只佔很窄的角度，會把某一小段輪廓往外拉。
  程式會剔除「角寬小於 40°」的異常段。
- **pad 真的露出一側**：是一段較寬的連續弧，會保留下來，因為這正是要量的訊號。

**Batch1 另有「露出弧模式」**：當外緣有一段寬度 ≥ 50° 的弧明顯超出 bump 時，判定為 pad 露出，
只用這段弧擬合 pad 圓（弧不夠完整時，pad 半徑沿用同陣列的典型值）。
這個模式只用在 Batch1；Batch2 每顆 bump 旁的淡色淚滴已確認是走線／via，開這個模式會把 via 誤當 pad。

### ⑤ 篩選與分群

- 以下的點會被剔除（疊圖上會標記原因）：
  - 太靠近影像邊界
  - 對比太低
  - 輪廓太不圓
  - 有效放射線太少
  - 模型擬合失敗
- 距離相近的點連成一個「陣列」（依各點與最近鄰的距離自動判斷 pitch）。
- 同一陣列內，半徑明顯偏離多數的點（可能被遮住，或是別種圓盤）也會剔除。

### ⑥ 推算整片晶片偏移

- 對每個陣列，把所有點的「pad 圓心 → bump 圓心」一起擬合成一個變換：
  - **平移**：晶片整體位移，也就是要報告的偏移量。
  - **旋轉**：晶片是否有轉角。
  - **縮放**：bump 與 pad 高度不同，X 光錐形束放大率會略有差異，用縮放項吸收，避免誤算成位移。
- 擬合時會反覆排除明顯不合群的點，只用多數一致的點計算。
- 報告的偏移是陣列中心處的平移量，附標準誤；晶片需修正量＝−偏移。
- 整張影像也另外算一個總值。

### ⑦ 輸出

| 檔案 | 內容 |
|---|---|
| `<影像>.overlay.jpg` | 疊圖：凸塊圓、焊墊圓、偏移向量（放大顯示）、陣列框與整體偏移箭頭、被剔除的點與原因 |
| `<影像>.result.json` | 完整結果：逐點量測、陣列平移／旋轉／縮放與標準誤、成像品質、判定 |
| `summary.csv`、`quality.csv` | 每張影像一列的結果摘要與成像品質 |

透過網頁服務分析時，同樣的內容顯示在影像檢閱頁與報告中。

可信度等級依可用點數、內點比例與標準誤分為 high／mid／low。

## 5. 使用流程

```
python -m xrayvision analyze image/Batch1 image/Batch2 --recipe recipes/bump_alignment_default.json --out temp/out
python -m xrayvision validate image/Batch2/1.tiff image/Batch2/2.tiff --recipe recipes/bump_alignment_default.json --out temp/val
```

1. 把同一批影像放在同一個資料夾（例如 `image/Batch2/`），可一次給多個資料夾。
2. 先看 `summary.csv`，找出偏移大或判定為需複判的影像。
3. 打開該影像的 `.overlay.jpg`，確認凸塊圓、焊墊圓有沒有抓對，以及被剔除的點是否合理。
4. 同視野重拍的重複性以 `validate` 指令比較。
5. 產線上改由網頁服務的匯入或資料夾監看執行，結果在影像檢閱頁查看。

常用設定：

| 配方參數 | 用途 |
|---|---|
| `pixel_size_um` | 每像素微米數，結果會多列 µm |
| `bump_level` / `pad_level` | 兩條輪廓線的高度（預設 0.75 / 0.25）；以不同高度各跑一次可看敏感度 |
| `lobe_mode` | 露出弧模式（預設 auto：只用於 8-bit 影像） |

命令列 `--workers N` 指定平行處理的數量。

## 6. 目前的驗證結果

- **重拍比對**：Batch2 的 1.tiff 與 2.tiff 是同一視野重拍，放大率差 0.73%，程式會自動對位後逐顆比較。
  - 每顆偏移的相關係數約 0.92，代表量到的是真實、可重複的訊號，不是雜訊。
  - 單顆的重拍差異約 0.32 px；整片晶片偏移兩次相差不到 0.08 px。
- **與先前人工確認的 Batch1 結果**：RD-1、LU-01 的偏移方向與先前一致。
- **Batch2 結果**：9 張的晶片偏移都在 1 px 左右或更小，x 方向一致略偏正。

## 7. 已知限制

1. **Batch2 的 pad 看不到獨立的邊**：偏移只能從外緣的不對稱量出來。
   輪廓線高度從 0.7/0.3 換到 0.8/0.2，晶片偏移會變動約 ±0.2 px，比統計誤差還大。
   這是目前最主要的系統誤差；有 pad 與 bump 的設計直徑時，可以用來校正輪廓線高度。
2. **沒有像素尺寸**：目前結果都是 px。
3. **Batch1 是轉存影像**：灰階非線性、雜訊大，單顆數據較不可靠，整體趨勢較可信。
4. **斜射視差**：若 X 光不是正射，bump 與 pad 高度不同也會產生固定方向的錯開，單張影像無法和真正的晶片偏移區分。
5. **疊在大球上的 bump 不量**：有些區域可用點數因此偏少。
