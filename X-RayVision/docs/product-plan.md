## 1. 產品定位

### 1.1 定位

本產品為**X 光半導體檢測影像分析平台**，部署於產線現場，讀取微焦點 X 光檢測設備輸出的影像，進行自動分析、判定與紀錄。平台提供影像處理、成像品質管理、配方、判定、報告、稽核等共用能力；各種檢測項目以「檢測模組」形式開發並掛載於平台上。

首個檢測模組為**微凸塊對位檢測**：辨識覆晶封裝中的微凸塊（Micro Bump）與基板焊墊（Pad），量測兩者的對位偏移，並推算整顆晶片的偏移量。後續可依客戶需求擴充裂紋（Crack）、空洞（Void）、橋接（Bridging）等瑕疵檢測模組。

本產品不控制 X 光設備。影像擷取仍由設備原廠軟體完成，本產品只負責擷取後的分析、判定與紀錄。

### 1.2 產品範圍

### 1.3 設計原則

1. **量測結果不受成像條件影響**：同一顆樣品在不同功率下拍攝，量測結果必須一致，並有數據驗證。
2. **每筆結果可追溯**：任何一筆判定都能回溯到原始影像、配方版本、檢測模組版本、軟體版本與操作人員。
3. **不確定時明確告知**：影像品質不足或量測不可靠時，系統標示「需複判」，不輸出看似精確的數字。
4. **平台與檢測分離**：新增檢測項目不修改平台核心；介面、報告、判定、稽核自動支援新模組。
5. **產品內不出現任何設備廠牌名稱**，文字使用正式商業用語，介面與報告支援繁體中文與英文。

## 2. 使用者與作業情境

| 角色 | 主要工作 |
|---|---|
| 操作員 | 拍攝影像、確認自動分析結果、處理「需複判」項目 |
| 製程／品保工程師 | 建立與維護配方、設定判定規格、檢閱趨勢與報告、執行量測系統驗證 |
| 系統管理員 | 帳號與權限、資料保留與備份、軟體與檢測模組更新 |
| 演算法開發人員 | 開發、驗證、發布檢測模組（原廠或授權的合作夥伴） |

**標準作業流程**

```
操作員於設備端拍攝並存檔
        │
        ▼
本平台監看輸出資料夾 → 偵測到新影像 → 依批次／配方執行配方內啟用的檢測模組
        │
        ├─ 成像品質不合格 → 標示「影像品質不足」，提示重拍
        │
        ▼
各模組量測與判定 → 彙整為影像判定：合格／不合格／需複判
        │
        ▼
操作員於介面檢閱（疊圖、數據），必要時人工複判
        │
        ▼
結果存入資料庫，產出報告並可匯出
```

另外保留手動匯入，用於重新分析、離線檢閱與工程驗證。

## 3. 核心議題：X 光功率變動造成的成像差異

### 3.1 問題描述

操作員每次拍攝時會視樣品調整管電壓（kV）、管電流或功率、曝光時間與積分張數，而且調整不一致。這會造成：

| 變動 | 對影像的影響 | 對量測的影響 |
|---|---|---|
| 管電流／曝光／積分張數 | 整體亮度與雜訊改變 | 固定灰階門檻失效，雜訊影響邊緣定位 |
| 管電壓（kV） | 材料間的對比改變（射束硬化），不只是亮度比例 | 凸塊、焊墊、背景的相對深淺改變，影響輪廓位置 |
| 焦點尺寸（隨功率變化） | 邊緣模糊程度改變 | 邊緣寬度改變，影響以等高線定義的輪廓 |
| 幾何放大率 | 同一結構的像素大小不同 | 以像素為單位的尺寸與偏移失去可比性 |
| 飽和或過暗 | 局部資訊遺失 | 無法量測或量測偏差 |

此問題影響平台上所有檢測模組，因此對策由平台統一提供，檢測模組直接使用校正後的影像與品質資訊。

現有資料的觀察（Batch2，同一批 9 張）：

- 背景亮度中位數介於 27,337～41,977（差約 53%）。
- 凸塊吸收對比介於 0.117～0.135（差約 15%），邊緣模糊寬度介於 2.8～3.3 px。
- 影像檔內**沒有**記錄任何拍攝參數。
- 1.tiff 與 2.tiff 為同一視野，亮度差約 30%、放大率差 0.73%。經現行正規化方法處理後，晶片偏移量測兩次相差不到 0.08 px，逐點偏移的相關係數約 0.92。這是「方法對亮度變動不敏感」的初步證據，但尚未涵蓋管電壓變動。

### 3.2 對策總覽

採取五層對策：前三層讓量測本身不受成像條件影響，後兩層負責把關與驗證。

```
第一層　物理量正規化　　　 將灰階轉為吸收量，消除亮度、曝光的影響
第二層　局部自我校正　　　 量測以局部背景與目標自身校正，消除對比、模糊差異
第三層　幾何校正　　　　　 以圖內結構的 pitch 或已知尺寸換算實際長度，消除放大率差異
第四層　成像品質閘門　　　 每張影像計算品質指標，不合格者不輸出判定
第五層　參數追溯與驗證　　 記錄拍攝條件、比對配方範圍，並以實驗驗證量測不變性
```

第一、三、四、五層由平台提供；第二層由各檢測模組依其量測對象實作，平台提供共用的工具函式。

### 3.3 各層說明

**第一層　物理量正規化（平台）**

- 16-bit 原始影像轉為吸收量（對數轉換）。在這個尺度下，曝光與管電流的改變只會造成整體偏移，重疊材料的吸收可以相加。
- 支援選用的平場校正（Flat-field）與暗場校正（Dark-field）：若能取得設備在相同條件下的空拍與暗場影像，先扣除偵測器的不均勻性。校正檔依拍攝條件分組管理。
- **不採用**直方圖匹配等「讓影像看起來一樣」的做法。這類做法會改變灰階之間的定量關係，對量測有害。

**第二層　局部自我校正（檢測模組）**

- 以微凸塊對位模組為例：每顆凸塊的量測前，先擬合局部背景曲面與模糊圓盤模型，把該顆凸塊正規化成「背景＝0、核心＝1」。
- 所有輪廓都以相對高度定義（例如核心的 75% 與 25%），不使用絕對灰階門檻。因此整體亮度、對比的差異會自動抵銷。
- 邊緣模糊寬度逐顆估計並記錄。它可作為品質指標，也用於修正輪廓位置。
- 空洞、裂紋等模組同樣以「相對於局部背景」的方式定義門檻，這是檢測模組開發規範的一部分（第 5.5 節）。
- 管電壓造成的材料對比改變無法完全靠正規化抵銷，需以第五層的實驗量化殘餘影響，必要時依管電壓區間在配方內設定不同的參數。

**第三層　幾何校正（平台）**

- 配方內設定參考結構的設計 pitch 或尺寸（µm）。每張影像由實測值換算像素尺寸，所有模組的長度與面積結果同時以 px 與 µm 輸出。
- 微凸塊對位模組的晶片偏移估計採用相似變換（平移、旋轉、縮放）。縮放項吸收凸塊與焊墊高度差造成的放大率差異，避免誤判成位移。

**第四層　成像品質閘門（平台）**

每張影像計算下列指標，並與配方內的允收範圍比較。檢測模組可再提供模組專屬的品質指標：

| 指標 | 用途 |
|---|---|
| 背景訊雜比 | 雜訊過高時，邊緣定位不可靠 |
| 飽和與過暗像素比例 | 資訊遺失 |
| 目標吸收對比（中位數） | 對比過低時，細部結構無法辨識 |
| 邊緣模糊寬度（中位數） | 對焦或焦點尺寸異常 |
| 可量測目標數與比例 | 視野或擺放異常 |
| 實測 pitch 與設計值之差 | 放大率或配方選錯 |

判定分三級：「合格」照常分析；「警告」照常分析但於報告註記；「不合格」不輸出判定，並提示重拍。

**第五層　參數追溯與驗證（平台）**

- **有拍攝參數時**：由設備匯出的參數檔自動讀取，或由操作員於批次建立時輸入。參數寫入檢測紀錄；超出配方允許範圍時提出警告。
- **沒有拍攝參數時**：以第四層的影像指標作為「成像條件指紋」，同樣可追溯與比對。
- **量測不變性驗證**：建立標準實驗程序，以同一顆樣品在不同管電壓、功率、曝光組合下拍攝，確認量測結果的變動在規格內，並訂出配方允許的參數範圍。每個檢測模組發布前都須通過此驗證。
- **每日點檢**：以固定標準樣品（Golden Sample）每日或每班拍攝一次，監控量測結果漂移。

### 3.4 需要現場配合的事項

1. 一組參數掃描影像：同一顆樣品、同一視野，在 3～5 種管電壓與功率組合下各拍 2～3 張，用於第五層的驗證。
2. 確認設備能否匯出拍攝參數（伴隨檔案或報表）。
3. 若可行，提供對應條件的空拍影像與暗場影像，用於平場校正。
4. 一顆可長期保存的標準樣品，用於每日點檢。

### 4.2 關鍵設計決定

| 決定 | 理由 |
|---|---|
| 平台核心與檢測模組分離，模組以標準介面掛載 | 新增檢測項目不修改核心；模組可獨立開發、驗證、發布與版本管理 |
| 平台核心不依賴網頁 | 可單獨測試、批次處理、日後換介面不影響演算法 |
| 前端採 React 單頁應用，後端只提供 API | 介面與後端分工清楚；互動式影像檢閱需要前端元件化 |
| 前端建置後的靜態檔由後端直接提供，服務只綁定本機 | 產線電腦離線即可運作，不需另外架設網頁伺服器；日後可擴充為多站共用的伺服器 |
| 分析以背景工作佇列執行 | 監看資料夾大量進件時介面不卡頓；單張失敗不影響其他影像 |
| 配方驅動、版本化，並鎖定檢測模組版本 | 同一產品的參數集中管理；已使用的配方版本不可修改，只能另存新版 |
| 原始影像封存並記錄雜湊值 | 確保結果可追溯，事後可用新版本重新分析並比對 |
| SQLite 單檔資料庫 | 產線單機免維運；資料量足夠；日後可換成伺服器資料庫 |

### 4.3 前端介面設計

**技術選型**

| 項目 | 規劃 |
|---|---|
| 框架 | React，以 Vite 建置 |
| 開發語言 | TypeScript |
| 語系 | 以語系檔管理全部文字，支援繁體中文與英文，執行中即時切換 |

**視覺設計原則**

- **簡潔**：以資訊為主，減少裝飾；每個畫面只放完成該工作所需的元素。
- **亮色與暗色主題**：預設跟隨作業系統設定，使用者可手動切換並記住偏好。暗色主題適合在暗室長時間檢閱 X 光影像。
- **設計代幣（Design Tokens）**：顏色、字級、間距、圓角集中定義於一處，兩種主題共用同一組元件，只切換代幣值。
- **判定顏色一致**：合格、不合格、需複判、影像品質不足四種狀態，在兩種主題下都使用固定且可分辨的顏色，並搭配文字或圖示，不只靠顏色區分。
- **影像區中性**：影像檢視區背景為中性灰，避免主題色干擾灰階判讀。

## 5. 檢測擴充

### 5.1 目標

讓平台能持續加入新的檢測項目，逐步發展為涵蓋多種瑕疵的 X 光半導體檢測影像分析平台。新增一個檢測項目時：

- 只需開發一個檢測模組，不修改平台核心、介面或資料庫結構。
- 平台自動提供配方參數畫面、疊圖、判定彙整、報告、稽核與成像品質管理。
- 模組有獨立版本，經驗證後才能於產線配方中啟用。

### 5.2 規劃中的檢測項目

| 檢測項目 | 檢測內容 | 典型量測值 | 預期方法 |
|---|---|---|---|
| 微凸塊對位（首發） | 凸塊與焊墊偏移、晶片偏移 | 偏移向量、晶片平移／旋轉 | 模型擬合（現行方法） |
| 空洞（Void） | 焊點、凸塊或晶片黏著層內的空洞 | 單顆空洞率、最大空洞面積、總空洞率 | 局部正規化後分割；必要時以深度學習分割 |
| 裂紋（Crack） | 晶片、焊點或基板的裂紋 | 裂紋長度、位置、方向 | 線狀特徵偵測；對比低時以深度學習分割 |
| 橋接（Bridging） | 相鄰焊點短路 | 橋接位置與數量 | 焊點間連通分析 |
| 缺球與異常尺寸 | 缺少、過大、過小的焊點 | 直徑、圓度、陣列缺漏位置 | 陣列比對與尺寸統計 |
| 其他 | 打線偏移（Wire Sweep）、異物等 | 依項目定義 | 依項目評估 |

上表為規劃方向，實際開發順序依客戶需求與樣品取得情況決定。

### 5.3 檢測模組介面

每個檢測模組以相同介面接上平台：

| 項目 | 說明 |
|---|---|
| 模組描述 | 代碼、名稱（繁中／英文）、版本、支援的影像類型、需要的前處理 |
| 參數結構 | 以結構化格式宣告參數、型別、單位、預設值與範圍；平台據此自動產生配方設定畫面並檢查輸入 |
| 執行 | 輸入已校正的影像、品質資訊、像素尺寸、參數與區域；輸出統一格式的結果 |
| 結果格式 | 檢測物件清單（類別、幾何、量測值、信心度）、影像層級指標、模組判定建議、疊圖圖層說明 |
| 判定規則 | 宣告模組可供設定的判定項目（例如「單顆空洞率上限」），規格值由配方設定 |
| 自我檢查 | 宣告模組專屬的品質指標與「無法判定」的條件 |

因為結果格式統一，介面的疊圖、數據表、趨勢圖與報告不需為新模組另外開發。

### 5.4 演算法類型

平台同時支援兩類模組：

- **規則式影像處理**：如現行微凸塊對位方法，可解釋性高、不需大量標註資料。
- **深度學習**：用於空洞、裂紋等外觀變化大的瑕疵。平台提供模型推論執行（ONNX 格式，可使用 CPU，有 GPU 時自動加速）與模型檔版本管理。
  - 影像檢閱畫面的人工複判與標註結果可匯出為訓練資料，形成「使用、複判、再訓練」的改善循環。
  - 模型訓練在平台外進行，平台只負責推論與版本管理。

### 5.5 模組開發規範

1. **不使用絕對灰階門檻**：門檻以局部背景或目標自身為基準（第 3.3 節第二層），確保不受成像條件影響。
2. **長度與面積以 µm 為準**：使用平台提供的像素尺寸換算；沒有像素尺寸時以 px 輸出並標示。
3. **明確回報不確定性**：量測值附信心度或標準誤；無法可靠量測時回報「無法判定」與原因。
4. **不直接存取資料庫或檔案系統**：只透過平台介面取得輸入、回傳結果。
5. **文字全部來自語系檔**，且不得包含設備廠牌名稱。

### 5.6 模組生命週期

```
開發 → 驗證 → 核准 → 發布 → 產線啟用 → 監控 → 改版
```

| 階段 | 內容 |
|---|---|
| 開發 | 依模組開發指南實作，附單元測試 |
| 驗證 | 以標註影像集驗證檢出率、誤判率；以參數掃描影像驗證成像條件不變性；以重複拍攝驗證重複性 |
| 核准 | 驗證報告經工程師核准後，模組標記為「已驗證」 |

| 產線啟用 | 只有「已驗證」的模組版本能加入正式配方 |
| 監控 | 追蹤複判推翻率、每日點檢結果；異常時提示檢討 |

## 6. 判定規則（初版）

每個檢測模組依配方規格產生模組判定，平台再彙整成影像判定：任一模組不合格即不合格；任一模組需複判且無不合格即需複判；全部合格才合格。

以微凸塊對位模組為例：

| 判定 | 條件 |
|---|---|
| 合格 | 品質閘門合格，且晶片偏移（含不確定度）小於配方規格 |
| 不合格 | 品質閘門合格，且晶片偏移扣除不確定度後仍超過規格 |
| 需複判 | 品質閘門為警告、可用位點不足、偏移接近規格邊界，或陣列之間結果不一致 |
| 影像品質不足 | 品質閘門不合格，不做判定 |

規格數值由製程工程師於配方內設定，系統不預設。

## 7. 品質保證與驗證

1. **回歸影像集**：以 Batch1、Batch2 與後續實拍影像建立標準集，每次改版自動比對結果，差異超過門檻即不得發布。每個檢測模組各自維護回歸影像集。
2. **重複性與再現性**：參考量測系統分析（MSA）概念，以同一樣品重複拍攝及不同操作員拍攝，計算量測變異佔規格的比例。
3. **成像條件不變性**：依第 3.4 節的參數掃描影像，量化功率、管電壓對量測結果的影響。
4. **已知答案驗證**：若能取得刻意偏移的樣品、已知瑕疵樣品或設計圖，驗證準確度與檢出率（非僅重複性）。
5. **軟體品質**：平台核心與模組的單元測試、API 測試、前端主要流程測試。

### 8.1 部署環境：X 光檢測設備電腦

本產品安裝於 X 光檢測設備本身的控制電腦，與設備原廠控制軟體共用同一台電腦。設備相關特性與對應設計如下：

| 設備特性 | 對本產品的影響 | 設計對策 |
|---|---|---|
| 作業系統 Windows 10 64 位元 | 需支援 Windows 10 | 以 Windows 10 64 位元為基準測試，並相容 Windows 11 |
| 與原廠控制軟體共用電腦 | 分析運算不得影響設備操作與影像擷取 | 分析行程以低於一般的優先權執行；CPU 執行緒數與記憶體用量設上限（預設使用一半核心）；GPU 使用可於設定中關閉 |

| 已安裝防毒／端點防護軟體 | 可能攔截更新程式替換檔案或封鎖服務 | 安裝程式與執行檔以程式碼簽章憑證簽署；安裝說明提供建議的排除清單；更新失敗時自動退回（第 12 節） |

| 第 1 階段　成像條件對策 | 品質指標與閘門、吸收量與平場校正、像素尺寸換算、拍攝參數紀錄 | 品質報表、參數掃描驗證程序 |
| 第 2 階段　服務與資料 | 資料庫、配方與模組版本管理、工作佇列、資料夾監看、判定彙整、HTTP API；問題回報包匯出與原廠端重現工具（提早完成，方便試用期間收集問題） | 可自動進件分析的後端 |
| 第 3 階段　React 介面與報告 | 設計代幣與亮／暗主題、影像檢視器與疊圖、各主要畫面、報告、繁中／英文 | 可供產線試用的完整介面 |
| 第 4 階段　產線化 | 權限與稽核、資料保留、安裝程式；軟體授權與原廠授權管理工具；離線更新、快照與退版，以及更新檔打包簽章工具；操作手冊、現場驗證 | 正式版安裝包、授權與更新工具、驗證報告 |
| 第 5 階段　檢測擴充 | 模組開發指南與範例模組、標註與訓練資料匯出、深度學習推論；依需求開發空洞、裂紋等模組 | 擴充機制文件、第二個檢測模組 |

每個階段完成後提交成果供審閱，核准後再進行下一階段。第 5 階段的檢測項目與順序，於第 4 階段完成前另行確認。

## 11. 軟體授權

### 11.1 原則

| 項目 | 規劃 |
|---|---|
| 授權單位 | 一台電腦一份授權；一台電腦只能安裝並執行一套本產品 |
| 綁定方式 | 綁定電腦硬體特徵產生的機器碼，不需額外硬體 |
| 期限模式 | 訂閱制，授權到期後停止分析功能 |
| 啟用方式 | 全程離線，以檔案交換完成，不需工廠電腦連網 |
| 防偽方式 | 原廠以私鑰對授權檔做數位簽章，軟體內僅含公鑰；授權檔無法被竄改或自行產生 |

### 11.2 授權啟用流程

```
客戶端（產線電腦，離線）                     原廠
────────────────────────                   ──────────────────
1. 安裝後首次開啟，網頁顯示「授權啟用」
2. 產生「授權申請檔」並下載
3. 以可連網的電腦將申請檔交給原廠 ──────────→ 4. 授權管理工具驗證申請檔、
                                              核對合約，簽發「授權檔」
6. 管理員於網頁匯入授權檔        ←────────── 5. 將授權檔交回客戶
7. 系統驗證簽章、機器碼、期限後啟用
```

**授權申請檔內容**：機器碼、安裝識別碼、產品版本、申請時間。不包含任何個人資料或檢測資料。

**授權檔內容**：

| 欄位 | 說明 |
|---|---|
| 授權編號 | 唯一識別，對應原廠合約紀錄 |
| 客戶名稱 | 顯示於介面「關於」與報告頁尾（可設定是否顯示） |
| 機器碼 | 綁定的電腦 |
| 生效日與到期日 | 訂閱期間 |
| 可用檢測模組 | 此授權可啟用的檢測模組清單（見第 11.6 節） |
| 簽發時間與簽章 | 防止竄改與時間倒退 |

### 11.3 單機單一安裝

1. 授權檔綁定機器碼，複製到其他電腦無法通過驗證。
2. 同一台電腦只允許一個授權生效；匯入新授權檔時會取代舊授權（例如續約）。
3. 安裝程式偵測到既有安裝時，只提供「升級」或「修復」，不允許安裝第二套。
4. 服務啟動時取得系統層級的單一執行鎖定，同一台電腦無法同時執行兩個服務。

### 11.4 機器碼與硬體變更

- 機器碼由多項硬體特徵組合計算（例如主機板識別碼、系統磁碟序號、處理器識別碼、作業系統安裝識別碼），只保存雜湊值，不保存原始序號。
- 容許一項特徵變更（例如更換網路卡或非系統磁碟）仍可通過驗證，避免一般維修就導致停機。
- 兩項以上特徵變更時視為不同電腦，需依第 11.7 節移轉授權。

### 11.5 訂閱期限管理

| 時間點 | 系統行為 |
|---|---|
| 到期前 30、14、7、1 天 | 介面頂部與檢測總覽顯示提醒；系統管理員登入時彈出通知 |
| 到期後 | 停止新的分析（資料夾監看暫停、手動分析無法執行），並清楚顯示原因 |
| 到期後仍可使用 | 檢視歷史紀錄、產生與匯出報告、匯出問題回報包、匯入續約授權檔 |
| 續約 | 原廠依相同機器碼簽發新授權檔，匯入後立即恢復，不需重新申請 |

- 到期後仍保留資料的檢視與匯出，確保客戶的檢測紀錄不因授權到期而無法取用。
- **時間竄改防護**：系統以簽章方式記錄「最後使用時間」。偵測到系統時間倒退超過 24 小時，或早於授權檔簽發時間時，暫停分析並提示管理員校正時間，同時寫入稽核紀錄。

### 11.6 檢測模組授權

- 授權檔列出可啟用的檢測模組；未列入的模組即使已安裝，也無法加入正式配方。
- 客戶加購模組時，原廠簽發新的授權檔，匯入後即可啟用，不需重新安裝軟體。
- 此設計同時解決待確認事項中「檢測模組是否需要授權控管」的問題。

### 11.7 授權移轉

1. 更換電腦時，管理員於舊電腦網頁執行「停用授權」，系統產生附簽章的「停用證明檔」，並立即停止舊電腦的分析功能。
2. 客戶將停用證明檔與新電腦的授權申請檔交給原廠。
3. 原廠確認後，為新電腦簽發授權檔，剩餘訂閱期間不變。
4. 舊電腦故障無法產生停用證明時，依合約條款由原廠審核處理。

### 11.8 安全性說明

- 授權驗證以公開金鑰簽章為基礎，無法偽造授權檔。
- 授權驗證相關程式以編譯方式發布，並對安裝檔案建立附簽章的檔案清單，啟動時檢查是否遭竄改。
- 軟體授權保護的目標是提高破解門檻並保留追查依據，無法做到絕對防止破解；重要客戶可另以合約條款約束。

### 11.9 原廠端工具（不隨產品發布）

- **授權管理工具**：驗證申請檔、簽發授權檔、續約、處理移轉；記錄客戶、機器碼、授權期間與簽發歷史。
- **簽章私鑰**：由原廠指定人員保管，存放於離線環境並定期備份；私鑰外洩時的換鑰程序另訂。

## 12. 軟體更新與退版

### 12.1 原則

- 工廠端無法連網，更新以「更新檔」由管理員於網頁匯入後進版。
- 更新檔由原廠數位簽章，未經簽章或遭竄改的檔案無法安裝。
- 進版前自動建立快照；進版失敗自動退回；進版後也保留客戶主動退版的選擇。

### 12.2 更新檔

| 項目 | 內容 |
|---|---|
| 形式 | 單一檔案 |
| 類型 | 「完整更新」（平台、前端、檢測模組）與「模組更新」（僅單一檢測模組） |
| 版本資訊 | 目標版本、可由哪些版本升級、發布日期 |
| 版本說明 | 新功能、修正項目、已知限制、對配方與判定的影響（繁中／英文） |
| 內容 | 程式、前端靜態檔、檢測模組、模型檔、資料庫結構變更腳本 |
| 完整性 | 每個檔案的雜湊值清單，整份檔案附原廠簽章 |

### 12.3 進版流程

管理員於「系統更新」頁依步驟操作：

1. **上傳更新檔**：系統驗證簽章、檔案完整性、版本是否可由目前版本升級，以及授權是否在訂閱期間內。
2. **檢閱版本說明**：顯示變更內容、受影響的配方與模組、預估停機時間。
3. **前置檢查**：確認分析佇列已清空或等待完成、磁碟空間足夠。
4. **確認進版**（需再次輸入密碼），系統依序執行：
   - 暫停資料夾監看與新分析
   - 建立升版前快照：資料庫、設定、配方、授權狀態，並保留目前版本程式
   - 由獨立的更新程式執行後續步驟（主服務無法替換正在執行的自身）
   - 將新版本安裝到獨立目錄，舊版本保留不動
   - 執行資料庫結構變更
   - 啟動新版本並自我檢查：服務啟動、資料庫存取、以內建標準影像執行分析並比對預期結果
5. **完成或自動退回**：
   - 自我檢查通過：切換為新版本、恢復監看、寫入稽核紀錄與版本歷史。
   - 任何步驟失敗：自動還原快照並切回原版本，顯示失敗原因，並可直接匯出問題回報包。

### 12.4 版本並存

- 每個版本安裝在獨立目錄，系統以「目前版本」指標切換。
- 預設保留最近 3 個版本與各自的升版前快照（數量可設定，受磁碟空間限制）。
- 進版與退版只切換指標並還原資料，不需要重新安裝。

### 12.5 退版

1. 管理員於「系統更新」頁的版本歷史中選擇要退回的版本。
2. 系統顯示該版本的快照時間，並提示：「退版將還原至升版前的資料快照。升版後產生的檢測紀錄會另存為封存檔，不會顯示在退回後的版本中。」
3. 管理員再次輸入密碼確認後，系統依序執行：
   - 暫停監看與新分析
   - 將升版後新增的檢測紀錄（含影像參照、結果、複判、稽核）匯出為封存檔
   - 還原升版前快照
   - 切換到指定版本並自我檢查
   - 恢復監看，寫入稽核紀錄
4. **封存檔**：日後再次升級到該版本或更新的版本時，可於網頁匯入，將紀錄合併回資料庫。原始影像檔不刪除，封存檔只保存對原始影像的參照。
5. 退版不影響授權狀態。

### 12.6 配方與模組相容

- 進版不會自動變更既有配方所使用的檢測模組版本；配方要改用新版模組，需由工程師手動更新並完成驗證。
- 新版本安裝時，檢查所有既有配方引用的模組版本是否仍可用；不可用時於版本說明畫面事先列出，並阻止進版。

### 12.7 原廠端工具（不隨產品發布）

- **更新檔打包與簽章工具**：產生更新檔、簽章，並附上回歸影像集的比對報告。
- **版本相容表**：記錄各版本可升級的來源版本、資料庫結構版本與模組相容範圍。

## 13. 問題回報包

### 13.1 目的

客戶對分析結果有疑慮時（例如疑似漏檢、誤判或結果不穩定），可將相關影像與完整分析脈絡打包成單一檔案交給原廠。開發人員不需到現場，就能在開發環境完整重現客戶的分析。

### 13.2 匯出方式

1. 在檢測總覽、批次清單或影像檢閱畫面，勾選影像、批次，或指定時間區間。
2. 點選「匯出問題回報包」，填寫問題描述，可選填期望結果或在影像上標示疑慮位置。
3. 選擇匯出選項（第 13.4 節）。
4. 系統產生單一檔案供下載，由客戶以 USB 或可連網電腦交給原廠。

### 13.3 內容

| 內容 | 說明 |
|---|---|
| 原始影像 | 與封存雜湊值一致的原始檔 |
| 分析結果 | 各檢測模組的檢測物件、量測值、品質指標、判定 |
| 配方 | 該次分析實際使用的配方版本（完整參數） |
| 版本資訊 | 軟體、各檢測模組、模型檔的版本 |
| 人工複判與備註 | 操作員的複判結果、備註、影像標示 |
| 拍攝參數 | 若有記錄 |
| 系統資訊 | 作業系統、處理器、記憶體、GPU、磁碟空間 |
| 相關日誌 | 對應時段的應用程式日誌與錯誤紀錄 |
| 問題描述 | 客戶填寫的說明 |
| 檔案清單 | 所有內容的雜湊值，確保傳遞過程未損毀 |

**不包含**：帳號密碼、授權簽章資訊、未勾選的批次與影像。

### 13.4 匯出選項

| 選項 | 說明 |
|---|---|
| 包含原始影像 | 預設包含；影像過大時可只匯出結果與縮圖 |
| 去識別化 | 遮蔽批號、產品名稱、操作員姓名等可識別資訊，以代號取代 |
| 加密 | 以原廠公鑰加密，只有原廠能開啟，保護客戶資料在傳遞過程中的安全 |
| 分割檔案 | 超過指定大小時自動分割（預設每份 2 GB，相容常見 USB 格式限制） |

### 13.5 原廠端重現工具（不隨產品發布）

1. 匯入問題回報包，檢查完整性並解密。
2. 以相同版本的平台、模組與配方重新分析，確認可重現客戶端的結果。
3. 以開發中的新版本分析同一批影像，並列比較差異。
4. 經客戶同意後，將影像加入回歸影像集，避免同樣問題再發生。
5. 修正後，連同更新檔提供回歸比對報告，說明問題影像的結果變化。

### 13.6 稽核

匯出動作寫入稽核紀錄：匯出人員、時間、包含的影像與批次、是否去識別化與加密。
