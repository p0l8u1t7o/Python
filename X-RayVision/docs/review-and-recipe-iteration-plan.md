## 1. 需求與決議（2026-09-24）

使用者需求：

1. 在檢測紀錄頁面上，可以用清單快速切換不同影像的檢測狀況與預覽圖。
2. 配方可以修改內容，修改後可再次執行檢測並更新檢測結果。

| 事項 | 決議 |
|---|---|
| 紀錄頁版面 | 左側清單＋右側預覽；點選或按 ↑↓ 切換，進入完整檢閱頁另有按鈕 |
| 已發布配方的修改 | 保留版本控管：「修改」自動建立新版本草稿，發布後產生新結果；舊結果保留並標示「已被取代」 |
| 重新分析範圍 | 發布時挑選（使用舊版本的全部影像／指定批號／不重跑）；紀錄頁也可勾選多筆重新分析 |
| 草稿試跑 | 要：配方編輯器選一張影像，以草稿參數即時分析並顯示疊圖，不產生正式紀錄 |
| 使用情境 | 產線 QC 站抽檢，非連續生產；重新分析不需要讓位給產線新影像 |
| 人工複判 | 重新分析產生的新結果不沿用舊紀錄的人工複判 |
| 重跑範圍預設 | 發布對話框預設「使用此配方舊版本的全部影像」 |

### 1.1 現況

- 紀錄頁是表格，點一列進入檢閱頁；換下一張要回上一頁再點，無法連續瀏覽。
- 已發布配方由資料庫觸發器鎖定不可修改；要調整時在「配方管理」按「另存新版本」建立草稿、修改、發布，再到檢閱頁逐張「重新分析」。
- 重新分析會產生新紀錄、原紀錄保留，但紀錄頁與總覽會把新舊兩筆都列出並一起統計，看不出哪一筆是目前有效的結果。
- 調整參數時必須先發布才能看到效果，發布後又不能改，容易產生大量試驗版本。

### 1.2 不變的原則

- 已發布配方內容不可修改、每筆結果都能追溯到配方版本與模組版本（PLAN-001 第 6 節），本次不放寬。
- 原始影像與既有紀錄不刪除、不覆寫；「更新結果」是產生新紀錄並把它設為該影像的目前結果。

## 3. A　紀錄頁清單＋預覽

### 3.1 版面

```
┌ 篩選列（判定、配方、批號、日期、僅顯示目前結果） ─────────────┐
├──────────────────────┬─────────────────────────────────────┤
│ 清單                 │ 預覽                                  │
│ ☐ 時間 檔名 判定 品質 │  影像＋疊圖（可縮放、切換圖層）         │
│ ▶ 1.tiff  合格  良好  │                                       │
│   2.tiff  需複判 警告 │  判定徽章、品質徽章、配方 v2           │
│   3.tiff  合格  良好  │  主要量測（依模組：晶片偏移／最大空洞率）│
│   …                  │  判定原因（前 3 項）                   │
│ 分頁 1/3             │  [檢閱] [報告] [重新分析]               │
└──────────────────────┴─────────────────────────────────────┘
```

- 清單欄位精簡為：勾選、時間、檔名（批號／樣品編號為第二行）、判定、品質、主要量測值；完整欄位表格保留為「表格檢視」切換（匯出 CSV 仍依表格欄位）。
- 預覽沿用檢閱頁的影像檢視器與疊圖，唯讀；不含複判與分頁。預覽影像先載入 1024 px 縮圖，放大時再載入高解析度。
- 目前選取的紀錄寫入網址（`?sel=<紀錄編號>`），重新整理或分享網址時保持選取。

### 3.2 操作

| 操作 | 行為 |
|---|---|
| 點選清單列 | 右側預覽切換到該紀錄 |
| ↑ ↓ | 上一筆／下一筆；到頁尾自動換頁 |
| Enter 或雙擊 | 進入完整檢閱頁 |
| 空白鍵 | 勾選／取消勾選目前這筆（供批次重新分析、回報包、標註匯出） |
| 檢閱頁的「上一張／下一張」 | 檢閱頁依紀錄頁當時的篩選順序切換，返回時回到原位置 |

### 3.3 效能

- 切換時只取該筆的結果 JSON 與縮圖；前後各預先載入一筆，連續按 ↓ 時不等待。
- 清單每頁 50 筆（沿用現有分頁）；Batch2 影像（約 6 MP）的縮圖由後端快取。

## 4. B　目前結果與取代關係

- **目前結果**：同一張影像（以影像雜湊識別）最新完成的一筆紀錄。較早的紀錄標示為「已被取代」，並連到取代它的紀錄。
- 不需修改資料表結構：以 `runs.image_id` 找同一影像的最新一筆即可判斷；另加索引 `runs(image_id, id)` 確保查詢速度。

| 位置 | 行為 |
|---|---|
| 紀錄頁 | 預設「僅顯示目前結果」；取消勾選時顯示全部歷程，已被取代的列以淡色顯示並標註 |
| 檢閱頁 | 已被取代的紀錄頂端顯示提示與「前往目前結果」；右側新增「分析歷程」列出同一影像的所有紀錄（時間、配方版本、判定） |
| 總覽統計 | 只計目前結果；每日分布依影像匯入時間，重新分析不會把舊影像算進今天 |
| 待複判數量 | 只計目前結果 |
| 報告 | 已被取代的紀錄報告加註「此結果已被取代」與取代紀錄編號 |
| CSV 匯出 | 依紀錄頁的「僅顯示目前結果」設定 |
| 回報包、標註 | 不受影響（仍以紀錄為單位） |

人工複判：複判屬於特定一筆結果。重新分析產生的新紀錄重新自動判定，**不沿用**舊紀錄的複判（2026-09-24 決議）；檢閱頁的分析歷程可看到舊紀錄的複判結果與說明，供複判人員參考。

## 5. C　配方「修改」與「發布並重新分析」

### 5.1 修改

- 配方管理與配方檢視頁上，已發布版本的按鈕由「另存新版本」改名為「修改」：自動以該版本內容建立下一版草稿並開啟編輯器。
- 同一配方已有草稿時，「修改」直接開啟該草稿，不再產生第二份草稿。
- 編輯器頂端顯示「修改自 v2（已發布）」，並可展開與來源版本的差異（變更的參數、舊值→新值）。

### 5.2 發布並重新分析

草稿編輯器的「發布」改為開啟發布對話框：

```
發布配方 bump_alignment v3
  變更內容：pad_level 0.25 → 0.30；judge.max_shift_um 2.0 → 1.5

  發布後重新分析：
   ◉ 使用此配方舊版本的全部影像（預設；共 128 張，其中 3 張封存影像已刪除，將略過）
   ○ 指定批號：[ LOT-0923 ▾ ]（共 18 張）
   ○ 不重新分析（只套用於之後的新影像）

  [取消]  [發布]
```

- 範圍內每張影像以新版本建立一個重新分析工作；完成後新紀錄即成為該影像的目前結果（第 4 節）。
- 資料夾監看依配方代碼使用最新發布版本（現行行為），新版本發布後新影像自動改用新版本，不需修改監看設定；監看設定頁改為顯示目前使用的版本。
- 發布與重新分析都寫入稽核紀錄（範圍、影像數、工作編號區間）。

### 5.3 佇列

- 本產品用於 QC 站抽檢，沒有連續生產的即時檢測壓力；重新分析沿用現行佇列優先權，不另行調整。分析行程仍以低優先權執行，避免影響同一台電腦上的設備操作。
- 預設範圍影像很多（例如超過 500 張）時，發布對話框依最近的平均分析時間提示預估完成時間。
- 「匯入與佇列」頁顯示重新分析進度（完成／總數），可整批取消。
- 授權到期（不可分析）時不能發布並重新分析；只能發布。

## 6. D　批次重新分析

- 紀錄頁勾選多筆後按「重新分析」，對話框選擇配方版本：預設為各紀錄所用配方的最新發布版本，也可指定其他已發布配方。
- 同一影像重複勾選時只建立一個工作；封存影像已刪除的略過並列出。
- 權限沿用現行「重新分析」（操作員以上的匯入權限）。

---

## 7. E　草稿試跑

- 配方編輯器新增「試跑」面板：從最近的紀錄選一張影像（可依批號、檔名搜尋），按「試跑」以**目前編輯中、尚未儲存**的參數分析。
- 結果以影像檢視器顯示疊圖，旁邊並列該影像目前結果與試跑結果的主要量測值與判定，方便比較參數調整的效果。
- 試跑不寫入紀錄、不影響統計、不進入佇列；以獨立的低優先權子行程執行，同時只允許一個試跑，逾時 180 秒中止。
- 試跑需要可分析的授權與「配方編輯」權限（工程師以上）；每次試跑寫入稽核紀錄（配方、影像，不含結果）。
- 試跑結果不保存；重新整理頁面即消失。

## 10. 測試與驗收

| 項目 | 驗收條件 |
|---|---|
| 清單＋預覽 | Batch2 9 張以 ↓ 連續切換，每次預覽在 1 秒內更新；選取狀態可由網址還原 |

| 回歸 | 既有測試全部通過；回歸基準不變（不改演算法） |
| 介面 | 亮／暗主題、繁中／英文截圖檢查紀錄頁、檢閱頁、發布對話框、試跑面板 |
