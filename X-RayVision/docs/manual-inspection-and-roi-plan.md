## 1. 需求與決議（2026-09-30）

使用者需求：

1. 新增**手動檢測**：不必綁定配方；匯入影像後直接修改參數（手動輸入，也可由配方帶入）即可分析並查看結果。
2. 手動檢測可以在多張影像之間快速切換。
3. 除了自動判定陣列之外，也可以**手拉 ROI 檢測區域**；正式檢測流程也要有。

| 事項 | 決議 |
|---|---|
| 正式流程的手拉 ROI | 保留配方層的檢測區域（全部影像共用），另外在檢閱頁可針對**單張影像**手拉檢測區域後重新分析；新紀錄標示「本影像自訂檢測區域」，可追溯 |
| ROI 與自動判定陣列 | 預設 ROI 只限定量測範圍，範圍內仍自動分群；個別包含區域可勾選「**視為一個陣列**」，強制將區域內的凸塊作為同一陣列估計偏移 |
| 手動檢測結果 | **不進入正式紀錄**、不計入總覽統計；工作區保存到使用者清空為止；可「另存為配方草稿」與匯出結果 |
| 使用權限 | 工程師以上（與配方編輯、試跑同級） |
| 自訂區域沿用 | 之後的重新分析預設沿用影像的自訂檢測區域，對話框可改用配方區域（R1） |
| 工作區保留 | 7 天未使用自動清除；每人上限 50 張、2 GB（R2） |
| 參數並列比較 | 本期不做（R3） |

### 1.1 現況

- 配方已有檢測區域（PLAN-002 第 4 節）：包含／排除、矩形／多邊形，於配方編輯器框選；分析影像尺寸不同時依比例縮放。
- 框選工具 `RegionEditor` 是固定寬度的畫布，不能縮放、平移，也不能移動或修改已畫的圖形，只能刪除重畫；6 MP 影像上框小區域不精準。
- 檢測區域只篩選凸塊，陣列一律由 `group_arrays` 依間距自動分群。晶片上相鄰的兩個陣列間距相近時會被併成一個，無法手動拆開。
- 配方編輯器的「試跑」可以用未儲存的參數分析一張已匯入的影像，但一次只能選一張、必須先有正式紀錄，且每次都要重新載入影像。
- 同一配方所有影像共用一組區域；晶片在視野中的位置每張不同時，固定座標的區域可能框不準，目前只能另建配方。

### 1.2 不變的原則

- 正式紀錄都能追溯到已發布配方版本與模組版本；手動檢測不產生正式紀錄，不放寬這條原則。
- 單張自訂檢測區域屬於正式流程：產生新紀錄（不覆寫舊紀錄），並完整記錄使用的區域與來源。
- 手動檢測與正式分析使用同一套分析流程（`analyze_image`），相同參數與區域得到相同結果。
- 未驗證模組、8-bit 影像、成像品質閘門的判定限制在手動檢測中同樣適用。

## 3. A　檢測區域編輯器與「視為一個陣列」

### 3.1 編輯器

以現有影像檢視器（`ImageViewer`，可縮放、平移）為底，加上區域繪製圖層，取代現有 `RegionEditor`：

```
工具列： [平移] [矩形] [多邊形] [選取]   類型：◉ 包含 ○ 排除   □ 視為一個陣列   [刪除] [全部清除]
┌───────────────────────────────────────────────┬─────────────────────┐
│                                               │ 區域清單             │
│  影像（可縮放、平移，疊上分析結果供對照）         │ ▣ 包含 1  陣列 A     │
│    ┌──────┐  ┌──────┐                         │ ▣ 包含 2  陣列 B     │
│    │  A   │  │  B   │   ╳ 排除                 │ ▣ 排除 1             │
│    └──────┘  └──────┘                         │                     │
└───────────────────────────────────────────────┴─────────────────────┘
```

| 操作 | 行為 |
|---|---|
| 矩形 | 拖拉建立；選取後可拖拉 8 個控制點調整、拖拉內部移動 |
| 多邊形 | 逐點點選，雙擊或按 Enter 完成，Esc 取消；選取後可拖拉頂點、在邊上雙擊插入頂點 |
| 選取 | 點選圖形；Delete 刪除；清單中也可點選、改名稱、改類型、勾選「視為一個陣列」 |
| 平移／縮放 | 滑鼠滾輪縮放、空白鍵＋拖拉或右鍵拖拉平移（繪製時也可平移） |
| 復原 | Ctrl+Z／Ctrl+Y（編輯期間有效） |

- 可同時顯示該影像的分析結果疊圖，方便依凸塊位置框選。
- 配方編輯器沿用「選一筆紀錄的影像作為參考影像」；參考影像尺寸與框選座標的規則不變。

### 3.2 區域格式擴充

每個圖形新增兩個選用欄位，未設定時與現行格式完全相同：

```json
{"type": "rect", "x0": 100, "y0": 120, "x1": 900, "y1": 700, "label": "A", "as_array": true}
```

| 欄位 | 說明 |
|---|---|
| `label` | 顯示名稱（最多 32 字），用於疊圖與結果；未填時自動編號 |
| `as_array` | 僅包含區域可用；區域內的凸塊強制成為同一個陣列 |

- `core/regions.py` 新增 `build_groups()`：產生區域編號遮罩；`AnalysisContext` 新增 `region_group(x, y)`，回傳所在「視為一個陣列」區域的序號（0 表示無）。
- 兩個「視為一個陣列」區域重疊時，重疊部分屬於清單中較後面的區域（與繪製順序一致），編輯器顯示提示。
- 模組以類別屬性 `supports_region_arrays` 宣告是否支援；沒有任何啟用模組支援時，編輯器隱藏此勾選。空洞模組逐顆檢測，不支援。

### 3.3 微凸塊對位模組的處理

- 位點量測完成後，中心落在「視為一個陣列」區域內的位點直接指派為該區域的陣列；其餘位點仍由 `group_arrays` 自動分群。
- 強制陣列不套用「陣列最少凸塊數」；可採用位點少於 3 個時無法估計偏移，陣列標示原因「區域內可用位點不足」。
- 半徑一致性篩選、偏移估計、逐陣列判定與自動陣列相同。
- 結果的陣列資料新增 `source`（`auto`／`region`）與 `label`；疊圖的陣列框以區域名稱標示。
- 模組版本 1.1.0 → 1.1.1（2026-09-30 決議）：舊配方不可能含「視為一個陣列」，量測結果完全不變，因此只升修訂版號，既有已發布配方與模組驗證狀態（1.1）照常可用；新功能只在配方勾選「視為一個陣列」時生效。回歸基準不變。

## 4. B　手動檢測工作區（後端）

### 4.1 工作區

- 每位使用者一個工作區，存放於資料目錄 `workspace/<帳號>/`，重新整理頁面或重新登入後仍在，直到使用者清空。
- 工作區內容：
  - 影像清單（每人上限 50 張、合計 2 GB）
  - 目前的參數組：與配方內容同格式（模組、參數、判定規格、像素尺寸、校正設定檔、品質規則、檢測區域），另記錄帶入來源（配方代碼與版本）
  - 每張影像最近一次的分析結果，連同產生該結果的參數組雜湊
- 影像來源：
  - **上傳**：拖放或選取檔案（可一併上傳同名拍攝參數檔 .json／.txt／.ini）；影像複製到工作區，不進入正式影像封存。
  - **從檢測紀錄加入**：依批號、檔名、日期挑選；只參照原影像，不複製；沿用該影像的拍攝參數。
- 工作區不寫入 `images`、`jobs`、`runs` 資料表；總覽、紀錄、CSV 都不會出現手動檢測結果。
- 資料保留：工作區超過 7 天未使用時由每小時的維護工作清除（天數可於系統設定調整）；工作區占用的空間列入「儲存空間」頁與磁碟警示。

### 4.2 分析

- 新增「互動分析執行器」（取代並擴充 `TrialRunner`，配方試跑與手動檢測共用）：
  - 一個常駐低優先權子行程；子行程保留最近 4 張影像的載入與校正結果，同一張影像換參數重新分析時不必重新讀檔與校正。
  - 同一使用者對同一張影像送出新的分析時，取消尚未開始的舊請求；單次逾時 180 秒中止。
  - 多位使用者同時使用時依序處理，畫面顯示排隊位置。
- 「分析全部影像」：依清單順序逐張分析，顯示進度，可隨時取消；已有相同參數結果的影像略過。
- 結果格式與正式紀錄相同（`AnalysisResult`），另加註 `manual: true` 與參數組雜湊；判定照常計算，但介面與匯出都標示「手動檢測（非正式結果）」。

### 4.3 參數帶入與另存

- **由配方帶入**：可選任一配方的任一版本（已發布、草稿、停用皆可），覆蓋目前參數組；之後修改的項目以標記顯示（相對來源版本的差異，沿用 `body_diff`）。
- **另存為配方草稿**，兩種方式：
  - 存為來源配方的下一版草稿（沿用「修改」：沒有草稿時建立；已有草稿時確認後覆寫該草稿）
  - 另存為新配方（輸入配方代碼與名稱）
  - 另存後依正常流程在配方管理審閱、發布。
- 檢測區域為手動檢測中畫的區域，參考影像尺寸取目前影像；存成配方時一併寫入。

### 4.4 匯出

- 匯出 ZIP：各影像結果 JSON、疊圖 PNG、結果總表 CSV、參數組 JSON；檔名與內容都標示「手動檢測（非正式結果）」。
- 匯出寫入稽核紀錄。

### 4.5 API

| 端點 | 用途 |
|---|---|
| `GET /api/workspace` | 工作區內容（影像清單、參數組、各影像結果摘要與是否過期） |
| `POST /api/workspace/images` | 上傳影像（multipart，可附拍攝參數檔） |
| `POST /api/workspace/images/from-runs` | 從檢測紀錄加入（紀錄編號清單） |
| `DELETE /api/workspace/images/{id}`、`DELETE /api/workspace` | 移除影像、清空工作區 |
| `GET /api/workspace/images/{id}/image?max_size=` | 影像（縮圖與高解析度，沿用快取） |
| `PUT /api/workspace/params` | 儲存參數組 |
| `POST /api/workspace/params/from-recipe` | 由配方版本帶入 |
| `POST /api/workspace/images/{id}/analyze` | 以目前參數組分析一張影像，同步回傳結果 |
| `POST /api/workspace/analyze-all`、`GET /api/workspace/progress`、`POST /api/workspace/analyze-all/cancel` | 分析全部影像與進度 |
| `GET /api/workspace/images/{id}/result` | 該影像最近一次的完整結果 |
| `POST /api/workspace/save-recipe` | 另存為配方草稿 |
| `GET /api/workspace/export` | 匯出 ZIP |

權限：新增 `manual_inspect`（工程師以上）。分析需要可分析的授權，且只能使用授權內的檢測模組。

稽核：加入影像、帶入配方、另存配方、匯出、清空寫入稽核紀錄；每次分析記錄影像與參數組雜湊（不含結果，與試跑相同）。

## 5. C　手動檢測畫面

新頁面「手動檢測」（導覽列位於「配方管理」之後，工程師以上可見）。

```
┌ 工具列：[加入影像 ▾] [由配方帶入 ▾]  來源：bump_alignment v3（已修改 2 項）  [另存為配方 ▾] [匯出] [清空] ┐
├──────────────┬──────────────────────────────────────┬────────────────────────┤
│ 影像清單      │ 影像檢視器                              │ 參數                    │
│ ▶ 1.tiff 合格 │  疊圖＋檢測區域圖層                      │ ▸ 模組：微凸塊對位 ☑     │
│   2.tiff 需複判│  [檢視] [編輯檢測區域]                  │   凸塊輪廓高度 [0.75]    │
│   3.tiff ◌ 未分析│                                     │   焊墊輪廓高度 [0.30]*   │
│   4.tiff ⟳ 參數已變更│                                 │   …（依參數結構產生）     │
│              │                                       │ ▸ 判定規格               │
│ [分析全部]    │ 判定徽章  品質徽章  主要量測              │ ▸ 像素尺寸／校正／品質規則 │
│              │                                       │ ▸ 檢測區域（區域清單）     │
│              │                                       │ [分析 Ctrl+Enter] ☐ 自動  │
├──────────────┴──────────────────────────────────────┴────────────────────────┤
│ 分頁：結果總表（每張影像一列：判定、晶片偏移、最大空洞率…） │ 物件 │ 陣列 │ 成像品質 │ 判定原因 │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 5.1 操作

| 操作 | 行為 |
|---|---|
| ↑ ↓（或 PageUp／PageDown） | 切換上一張／下一張影像；前後各預先載入一張 |
| 切換影像 | 有相同參數組的結果時直接顯示；參數已變更時顯示舊結果（淡色、標示「參數已變更」），勾選「自動」時自動重新分析 |
| 修改參數 | 參數旁標示與來源配方不同（*）；按「分析」或 Ctrl+Enter 分析目前影像 |
| 「自動」勾選 | 參數停止修改 1 秒後自動分析目前影像（預設不勾選） |
| 編輯檢測區域 | 檢視器切換為 A 的編輯模式；區域屬於參數組，套用到工作區所有影像（尺寸不同依比例縮放） |
| 同尺寸影像切換 | 保持目前的縮放與位置，方便比對同一位置 |
| 結果總表 | 點選列即切換到該影像；可排序；參數已變更的列標示 |

- 參數表單由模組參數結構自動產生，與配方編輯器共用同一元件（由 `RecipeEditor.tsx` 抽出）。
- 參數組變更即時存回工作區（防抖 1 秒），重新整理頁面不遺失。
- 畫面頂端固定顯示「手動檢測（非正式結果）」提示。

## 6. D　正式流程的單張自訂檢測區域

### 6.1 操作

- 檢閱頁新增「自訂檢測區域」（工程師以上）：開啟 A 的編輯器，預先填入目前生效的區域（配方區域換算到本影像尺寸，或本影像已有的自訂區域）。
- 編輯器內的按鈕：
  - **試跑**：以自訂區域分析本影像，不產生紀錄（與配方試跑相同）
  - **套用並重新分析**：以相同配方版本＋自訂區域建立重新分析工作；新紀錄成為本影像的目前結果，舊紀錄標示已被取代（沿用 PLAN-003 的目前結果規則）
  - **改回配方區域**：清除自訂區域並重新分析
- 自訂區域**取代**配方區域（不是疊加）；「視為一個陣列」同樣可用。

### 6.2 追溯與顯示

| 位置 | 行為 |
|---|---|
| 分析結果 | 記錄生效的區域與來源 `regions_source`（`recipe`／`image`） |
| 紀錄頁清單、預覽、檢閱頁 | 以「自訂檢測區域」標籤標示 |
| 報告 | 註明「本影像使用自訂檢測區域」，疊圖顯示生效的區域 |
| 分析歷程 | 每筆紀錄顯示區域來源 |
| 稽核紀錄 | `run.regions_override`：紀錄編號、配方版本、區域內容 |

### 6.3 之後的重新分析

- 單張自訂區域屬於影像：之後的重新分析（發布並重新分析、批次重新分析）**預設沿用**該影像最近一次的自訂區域；發布對話框與批次重新分析對話框顯示「其中 N 張使用自訂檢測區域（沿用）」，並可勾選「改用配方區域」。
- 資料夾監看與手動匯入的新影像一律使用配方區域。

### 6.4 資料庫

- 結構版本 7：`jobs` 新增 `regions_json`（NULL 表示使用配方區域）；`runs` 不變，從工作查得。
- `queue_reanalysis` 比照拍攝參數，沿用該影像最近一個工作的 `regions_json`。

## 8. 測試與驗收

| 項目 | 驗收條件 |
|---|---|
| 區域格式 | 舊格式配方讀取與分析結果不變；`label`／`as_array` 檢查（排除區域不可勾選、長度上限） |
| 視為一個陣列 | 合成影像：兩個相鄰陣列被自動併成一個時，以兩個區域強制拆開後各自估計的偏移與已知答案一致；區域內可用位點不足時有明確原因 |
| 回歸 | 未使用新功能時 Batch1／Batch2 回歸基準完全相同；既有測試全部通過 |
| 手動檢測 | 上傳與從紀錄加入皆可分析；結果與以相同參數建立的配方正式分析一致；不產生任何 `images`／`jobs`／`runs` 資料；總覽不變 |
| 回應時間 | Batch2（約 6 MP、16-bit）同一張影像改參數重新分析，在開發機上 3 秒內顯示結果（影像快取生效）；切換到已有結果的影像 1 秒內顯示 |
| 另存配方 | 另存為下一版草稿與新配方；內容與工作區參數組一致（含檢測區域） |
| 權限與授權 | 操作員看不到手動檢測頁、呼叫 API 回傳 403；授權不可分析時只能檢視既有結果與匯出 |
| 單張自訂區域 | 套用後新紀錄成為目前結果並標示；改回配方區域後標示消失；重新分析沿用；報告與稽核正確 |
| 介面 | 亮／暗主題、繁中／英文截圖檢查手動檢測頁、區域編輯器、檢閱頁自訂區域、報告 |
