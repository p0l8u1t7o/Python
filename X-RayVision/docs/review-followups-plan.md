## 2. A　空洞檢測預設使用模型

### 2.1 做法

空洞模組目前的參數預設為 `method = rule`（規則式）、`model` 空白。有兩種改法：

| 方案 | 內容 | 影響 |
|---|---|---|
| **V1-a 範本預設（建議）** | 模組參數預設值不變；「新增配方」與「手動檢測」勾選空洞模組時，範本改為 `method = model`，並自動帶入目前啟用中、最新版本的空洞模型；沒有啟用模型時維持規則式並提示「尚未匯入空洞模型，暫用規則式」 | 既有配方與結果完全不變；模組不升版；模型仍需系統管理員匯入 |
| V1-b 模組預設 | 模組參數預設值改為 `model` | 未明確設定方法的既有配方結果改變 → 模組須升次版（1.1→1.2），既有空洞配方要重新發布，驗證狀態重新核准；未匯入模型時分析得到「模型無法使用」 |

- 兩案都保留「模型與規則式差異大時需複判」（`model_disagree`）的既有安全機制；模組維持「未驗證」，判定最多為需複判，直到以實際影像驗證核准。
- 示範模型 `void_unet-1.0.0` 只以合成影像訓練、以開發金鑰簽章；正式使用前需以實際標註資料重新訓練並以正式金鑰簽章（README C）。

### 2.2 變更

- `GET /api/recipe-template/{module_id}`：空洞模組回傳 `method = model` 與最新啟用模型參照；沒有模型時回傳規則式並附 `notice: void_model_missing`。
- 配方編輯器與手動檢測顯示提示；操作手冊第 6.1、6.3 節更新。

## 3. B　疊圖依判定著色

檢閱畫面、預覽、報告快照、手動檢測與匯出疊圖中，被判定原因指到的目標改用判定色標示：

| 判定原因目標 | 標示方式 |
|---|---|
| `…_exceeds_limit:ballN`（空洞超規） | 該焊點外圈加粗紅色圓（不合格色） |
| `…_near_limit:ballN`、`model_disagree:ballN` | 橘色圓（需複判色） |
| `…_exceeds_limit:groupN`（陣列偏移超規） | 陣列外框改紅色、加粗 |
| `…_near_limit:groupN` | 陣列外框改橘色 |
| `…:image` | 不另外標示（屬整張影像） |

- 顏色使用設計代幣的固定判定色（亮／暗主題相同），新增圖層「判定標示」可開關。
- 前端 `buildShapes` 解析模組判定原因；後端 `core/render.py`（命令列與手動檢測匯出疊圖）同樣處理。
- 不改變任何量測或判定結果。

## 4. C　標註筆刷工具

空洞標註頁（`/#/runs/{id}/annotate`）現有工具：多邊形、選取、刪除。新增：

| 工具 | 行為 |
|---|---|
| 筆刷 | 在影像上塗抹新增空洞區域；筆刷直徑可調（滑桿，以影像像素為單位，快捷鍵 `[` `]`）；與既有空洞重疊時合併 |
| 橡皮擦 | 塗抹處從空洞區域扣除；可把一個空洞切成兩個 |

- 標註格式不變（空洞仍以多邊形儲存）：筆刷與橡皮擦在焊點範圍內以遮罩運算，放開滑鼠後以輪廓追蹤轉回多邊形並簡化（誤差 ≤ 0.5 px），訓練資料匯出與模組驗證工具不需修改。
- 支援 Ctrl+Z／Ctrl+Y 復原／重做（目前標註頁沒有）。
- 空洞內的孔洞（環狀）不支援，與現行格式一致。
