# ExpAnalysis — 高純銦金屬偏析純化製程分析平台

以**物理模型為骨架、AI 分層疊加**的離線製程分析與參數建議工具。
針對「高純銦金屬偏析純化製程」試量產設備開發，協助製程資料整理、模型建立、
品質預測與參數建議。

> **本系統不參與任何設備控制。** 它是離線決策輔助工具，所有輸出都是給工程師看的
> 建議與不確定區間，最終判斷與操作仍由人執行。

---

## 這套工具回答什麼

| 需求 | 系統做的事 |
|---|---|
| 找出影響雜質去除效率與 6N 得料率的關鍵參數 | 反解各元素的有效分配係數 k_eff，再做 `ln(1/k_eff − 1)` 對速率的回歸 |
| 預測雜質分布、判斷高純區與雜質濃縮區位置 | 用 k_eff(T, v) 跑正向模擬，找出穿過 6N 門檻的位置 |
| 提供溫度、速率、純化次數的最佳化建議 | 在參數網格上跑模擬並附上不確定範圍，給出三種用途不同的建議 |
| *（額外）* | 哪些元素用偏析法根本除不掉；pass 做到第幾次之後就白做 |

## 技術取向：這不是機器學習專案

區域熔煉有很強的解析解，而客戶批次數只有幾十批。純 ML（XGBoost / 神經網路）
在這個樣本數下必定過擬合，而且**外插不可信**——問它沒跑過的速率，只會回傳最接近的訓練值。

正確做法是先用物理方程把**每一條實測曲線壓縮成 1 個可解釋參數**，再對這少數參數做回歸：

```
一批實驗 = 8 個測點 × 4 個元素 = 32 個雜亂數字
        ↓ Pfann 方程擬合
一批實驗 = 4 個 k_eff（Cu、Fe、Ni、Sn 各一個）
```

40 批就變成「每個元素 40 個 k_eff」——這是一個 40 筆資料、2 個自變數的小問題。

### AI 放在哪裡

```
L5  LLM 對話層     自然語言查詢、報告生成      零風險（不碰計算）
L4  貝氏最佳化     建議下一批該跑什麼參數      零風險（只影響實驗設計）
L3  異常偵測       哪批資料不對勁              零風險（只保護準確度）
L2  高斯過程       k_eff = f(T, v) 映射        純升級，無代價
L1  殘差學習       物理沒解釋到的部分          有風險 → 四道護欄 + 預設關閉
L0  物理模型       Pfann + BPS                 永遠是骨架
```

每一層都可獨立關閉並退回下一層。L1 是唯一可能影響準確度的一層，
必須通過留一批交叉驗證（改善 ≥ 3%）才會啟用。

## 安裝與啟動

專案根目錄已建好 Python 3.12 虛擬環境 `.venv`。

**Windows**

```bat
cd /d "D:\Working Space\Python\ExpAnalysis"
.venv\Scripts\activate
pip install -r requirements.txt
python run.py
```

或直接執行 `setup.bat`（安裝相依）與 `run.bat`（啟動）。

**啟動後**

| 位置 | 用途 |
|---|---|
| <http://127.0.0.1:8848/> | 分析平台（瀏覽器會自動開啟） |
| <http://127.0.0.1:8848/docs/> | 說明文件 |
| <http://127.0.0.1:8848/api/docs> | 自動產生的 API 介面 |

**常用參數**

```bash
python run.py --seed-demo 20    # 啟動前先產生 20 批合成資料
python run.py --port 9000       # 換連接埠
python run.py --no-browser      # 不自動開瀏覽器
python run.py --reload          # 開發模式，改檔自動重載
```

## 五分鐘上手

1. `python run.py --seed-demo 20` — 產生一組合成資料把整套流程跑起來
2. **總覽** — 看各元素的 k_eff 與可去除性排序，以及「做幾次就夠了」
3. **批次資料** — 點一個批次，看實測點與物理模型曲線的疊圖、殘差、6N 視窗
4. **參數映射** — 看 GP 灰帶圖，以及 BPS 線性化檢查（模型的誠實度檢查）
5. **模擬與預測** — 拉滑桿即時看到分布與得料率變化
6. **最佳化建議** — 三種參數建議、得料率熱圖、DOE 省批次試算
7. **資料稽核** / **模型驗證** — 哪批資料有問題、模型到底多準
8. **AI 助理** — 直接用中文問問題

匯入自己的資料：**資料管理** 頁可下載 CSV 範本，支援「只稽核不寫入」的 dry run。

```ini
EXPA_LLM_PROVIDER=anthropic
EXPA_ANTHROPIC_API_KEY=
EXPA_OPENAI_API_KEY=
```

## 測試

```bash
pytest -q                                  # 全部 87 條，約 17 秒
pytest tests/test_physics.py -v            # 物理層正確性
pytest tests/test_pipeline.py -k recovers  # 端對端方法還原驗證
```

核心驗證方式是**已知答案的反解**：用已知的真實 k₀ 與 δ/D 生成帶雜訊與設限的資料，
再讓整套流程反解，檢查能不能還原。

| 驗證項目 | 實測結果 |
|---|---|
| 離散模擬 vs Pfann 解析解 | 相對誤差 < 1% |
| 多次 pass 質量守恆 | 誤差 < 1e-15 |
| 12% 雜訊 + 40% 設限點下的 k_eff 還原 | 中位相對誤差 < 5% |
| 映射在資料範圍內的預測 | 中位誤差 < 5% |
| 注入的異常批次（熱電偶飄移、位置顛倒） | 皆被偵測到 |
