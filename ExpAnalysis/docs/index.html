ExpAnalysis 說明文件

高純銦金屬偏析純化製程的離線分析與參數建議工具。
以物理模型為骨架、AI 分層疊加，每一層都可獨立關閉並退回物理基準。

一句話說明這個專案的技術取向

這不是機器學習專案，是物理模型 + 小資料擬合專案。區域熔煉有很強的解析解， 而客戶的批次數只有幾十批——純機器學習在這個樣本數下必定過擬合，而且做不出可靠的參數建議， 因為外插不可信。正確做法是先用物理方程把每一條雜質分布曲線壓縮成 1 個可解釋的參數， 再對這少數參數做回歸。資料量瞬間夠用，結果也可以外插。

這套工具回答什麼問題

客戶提出的需求系統實際在做的事對應畫面
建立製程參數與純化結果的關聯模型，找出影響雜質去除效率與 6N 得料率的關鍵參數 對每個元素反解有效分配係數 k_eff，再做 ln(1/k_eff − 1) 對速率的回歸。 斜率大 = 速率是關鍵參數 總覽、參數映射
預測不同製程條件下雜質的分布趨勢，判斷高純區與雜質濃縮區位置 用 k_eff(T, v) 跑正向模擬得到整條曲線，找出穿過 6N 門檻的位置 模擬與預測
提供溫度、速率、純化次數的最佳化建議，提升純化效率、批次穩定性與得料率 在參數網格上跑模擬、算每組的得料率，挑最好的並附上不確定範圍 最佳化建議
（額外交付） 哪些元素 k≈1、用偏析法根本除不掉，該由前段製程處理； pass 做到第幾次之後就完全白做 總覽、最佳化建議

先看 07 · 開發者指南 了解模組切分與關鍵設計決策， 再看 04 · 擬合、AI 與最佳化方法 理解數學部分（同樣不預設統計背景）。 API 細節在 06 · REST API 參考。

直接看 08 · 驗證、驗收與風險控管。 那一篇把「不要影響準確性」翻譯成四條可量化、可驗收的合約條款， 並說明留一批交叉驗證怎麼當作驗收文件。

我要準備匯入客戶的歷史資料

看 03 · 資料規格書。 特別注意最後一節「開案前一定要跟客戶問清楚的資料問題」—— 那些問題直接決定這個案子可不可行。

系統分層一覽

技術棧

層用了什麼為什麼是這個
數值核心NumPy、SciPy沒有一行深度學習。核心邏輯不到 1000 行
機器學習scikit-learn（GaussianProcessRegressor、Ridge、IsolationForest） 都是教科書等級的方法，寫進技術報告站得住腳
儲存SQLite（WAL 模式） 單機離線分析工具，零維運。日後要集中時 DuckDB 可直接查同一個檔
後端FastAPI + uvicorn自帶 OpenAPI 文件與參數驗證
前端原生 ES module，無框架、無建置流程 九個畫面、離線部署，引入 bundler 只會增加交付成本
圖表自寫的 SVG 模組，約 550 行 CDN 拉不到、也不見得允許裝一堆套件；SVG 可右鍵存成向量圖貼進報告
責任邊界

本系統是離線決策輔助工具。它不控制設備、不做閉迴路、不參與任何即時製程決策。 所有輸出都是給工程師看的建議與不確定區間，最終判斷與操作仍由人執行。
