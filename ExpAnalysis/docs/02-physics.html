02 · 物理模型詳解

從零開始講偏析純化在物理上到底發生什麼事、為什麼那些公式長那樣， 以及本專案怎麼把它變成程式碼。不預設冶金或統計背景。

2. 這個製程實際在做什麼

2.1 用軟體的比喻：滑動視窗

想像一個陣列，代表整根金屬棒。有一個 3 cm 寬的視窗，從左邊 index 0 開始， 以每小時 2 mm 的速度往右滑到底。視窗內的金屬是液態，視窗外是固態。

視窗往右移一格會發生兩件事：

  • 右邊緣：一格新的固體被融化，進入液池
  • 左邊緣：一格液體重新結冰，離開液池

關鍵就在左邊緣。

2.2 為什麼會純化：結冰會「挑食」

金屬結冰的時候，晶體排列很挑剔，不喜歡讓外來原子（Cu、Fe、Ni、Sn）擠進晶格。 所以左邊緣結冰時，大部分雜質被「推」回液池裡，不跟著結冰。

結果就是：剛結冰的那一格比原本乾淨；液池越來越髒； 而液池會往右移動，等於把雜質一路掃到最右端。

掃完一趟，整根棒子變成：左邊（頭）乾淨、右邊（尾）很髒，中間有個過渡帶。

偏析純化的本質

它不是把雜質消滅，是把雜質掃到同一個地方，然後把那一段切掉丟掉。 所以「總雜質量」在整根錠裡是守恆的——這也是本專案物理模擬的一條硬性檢查： 質量誤差必須小於 1e-12（見 tests/test_physics.py::test_mass_is_conserved）。

2.3 k：這個製程唯一重要的數字

「結冰有多挑食」需要一個數字量化，這就是分配係數 k：

k  =  剛結冰的固體裡的雜質濃度  /  旁邊液體裡的雜質濃度 程式中一律稱為 k_eff（有效分配係數）。「有效」的意思見第 5 節。
k 值意思判定
0.1結冰時只帶走 10% 的雜質，90% 被推回液池純化效果很好
0.9結冰時帶走 90%幾乎沒純化到
1.0完全不挑食這個雜質用偏析法根本除不掉
> 1反過來，這個雜質喜歡固體它會往頭端跑，而不是尾端

每個元素有自己的 k。Cu 可能 0.05、Fe 可能 0.3、Sn 可能 0.6。這也是為什麼要分別測 Cu / Fe / Ni / Sn——它們行為完全不同。

這個 k 是整個專案的核心

如果這套系統只做一件事，那就是把 k 從實測資料裡挖出來。 所有的映射、預測、參數建議，都是建立在「每一批、每一個元素有一個 k_eff」之上。

3. Pfann 方程：單次 pass 的分布

C(x)  =  C₀ · [ 1 − (1 − k) · exp( −k·x / l ) ] C(x)：距離頭端 x 處的雜質濃度　·　C₀：原料的初始雜質濃度（假設均勻）
l：熔區長度（不是錠長！）　·　x/l：已經掃過幾個熔區長度了
最常見的符號錯誤

指數裡的分母是熔區長度 l（幾公分），不是整根錠的長度 L（幾十公分）。 兩者差一個數量級，寫錯會讓擬合出來的 k 完全不對。本專案的程式碼一律要求呼叫端 明確傳入 zone_len 或無因次的 zone_len_frac = l / L， 不允許用預設值蒙混。

3.1 曲線長什麼樣

三個區段：

  1. 頭端：濃度從 k·C₀ 開始。k 越小，起點越低 = 越乾淨。
  2. 中段：緩慢爬回 C₀。
  3. 尾端最後一個熔區長度：雜質全部塞在這裡，濃度暴衝。 Pfann 方程不涵蓋這一段，要另外處理（見 3.2）。

3.2 終端凝固：為什麼要另外算

掃到尾端後，右邊已經沒有固體可以熔化了。剩下的液池只能自己慢慢結冰， 這叫正常凝固（normal freezing），行為完全不同：

Cs(g)  =  k · CL0 · (1 − g)k − 1 g：該終端熔區已凝固的分率（0 ~ 1）　·　CL0：終端凝固開始時的液池濃度。 k < 1 時指數是負的，所以 g → 1（最後一點液體）時濃度會發散——這就是尾端暴衝的來源。

4. 多次 pass：沒有公式，要用迭代

第 2 次 pass 的輸入不再是均勻的 C₀，而是第 1 次的輸出曲線。所以沒有封閉解， 只能一步步算。對軟體工程師來說，這只是個 for 迴圈：

C = np.full(N, C0)              # 初始均勻
for p in range(n_passes):
    C = simulate_one_pass(C, k, zone_cells)

4.1 本專案的離散化做法

把錠切成 N 個等寬單元（cell），寬度 h = L / N；熔區佔 m = round(l/h) 個單元。 掃描時每前進一格：右緣熔化一格固體進入液池、左緣凝固一格離開液池。

連續形式的質量守恆是：

l · dCL/dx  =  Cin(x + l)  −  k · CL(x) 左邊是液池溶質量的變化率，右邊是「熔進來的」減掉「凝固帶走的」。
設計決策：單格更新用解析積分，不用前向 Euler

天真的做法是「先凝固、再熔化」的一階差分（前向 Euler），誤差是 O(h)， 會隨格數變少而系統性偏移。本專案改成：在單一 cell 內把熔入濃度 Cin 視為常數， 這條 ODE 有解析解

CL(h) = Cin/k + (CL(0) − Cin/k) · exp(−k·h/l)

該格凝固出的溶質量 = Cin·h − l·(CL(h) − CL(0))， 除以 h 得到該格的平均濃度——這正好對應實際取樣時切一片下來測到的值。

好處：對均勻輸入時與 Pfann 解析解逐點吻合，不會因為格數而漂移。 tests/test_physics.py::test_single_pass_matches_pfann_analytic 對 k = 0.02 ~ 0.85 五個值驗證相對誤差 < 1%。

設計決策：終端凝固用 Scheil 的格內積分平均

如果終端段沿用主掃描的更新式，最後一格會殘留 (1−k)·S 的溶質，質量不守恆。 本專案改用 Scheil 方程在每一格上的積分平均：

Cj = m · CL0 · [ (1 − j/m)k − (1 − (j+1)/m)k ]

對 j 求和恰好等於 m · CL0，質量嚴格守恆（實測誤差 < 1e-15）。

4.2 極限分布：一個能馬上省錢的結論

一直 pass 下去，曲線會收斂到一個固定形狀（ultimate distribution）， 之後再 pass 完全沒有改善——因為「往尾端掃出去的雜質」和「熔區從右邊吃回來的雜質」 達成了平衡。

系統會回報三個數字，意義不同：

指標定義用途
recommended_passes 達到可達最大得料率的 95% 所需的最少次數 報告裡該寫的數字，也是給產線的建議
saturation_pass 最後一次仍能讓得料率增加 0.5 個百分點的 pass 在這之後每一趟都幾乎白跑
ultimate_pass 相鄰兩次分布的相對變化小於門檻（數學上的極限分布） 理論參考，通常比前兩者晚
為什麼判準用「達到上限的 95%」而不是「單次增量」

因為前幾次 pass 的得料率常常都還是 0（頭端尚未降到門檻以下）。 用「單次增量小於門檻就停」會在第 1 次就誤判收斂——這是實作時真的踩到的坑。 改成相對於可達上限的百分比，對「前段平坦、中段陡升、後段飽和」的典型曲線才穩健。

實務價值：客戶若現在跑 15 次，模型可以直接指出「第 8 次之後純度不再有意義的進步， 砍掉 7 趟」——這是 P1 階段就能交出去的立即價值。

5. 速率和溫度怎麼進來的：BPS 方程

前面的 k 是理想值（稱為 k₀，平衡分配係數）。實際跑起來會偏掉，原因是：

結冰時被推回去的雜質，來不及擴散走。

左邊緣結冰，把雜質吐回液體。這些雜質要靠擴散散進整個液池，但擴散很慢。 如果結冰速度很快，雜質還沒散開，就在介面前面堆成一坨——這坨叫邊界層。 介面旁邊的液體變得特別髒，結冰時挑食再挑，帶走的絕對量也變多。等於 k 變大了、純化變差。

這個「實際感受到的 k」叫 k_eff：

keff  =  k₀ / [ k₀ + (1 − k₀) · exp( −v·δ/D ) ] v：熔區移動速率 [mm/hr]　·　δ：邊界層厚度（攪拌越強越薄）　·　D：雜質在液態銦裡的擴散係數
δ 與 D 無法分開量測，只有比值可辨識，所以程式中一律以單一參數 delta_over_d（單位 hr/mm）表示。
條件k_eff 的行為意義
v → 0（超慢）k_eff → k₀純化效果達到理論最好
v 變大k_eff → 1純化效果趨近於零
這是這個製程唯一的核心取捨：慢 = 純，快 = 產能。

客戶需求三要的「最佳速率建議」，本質就是在這條曲線上找甜蜜點。 系統的「最佳化建議」頁還額外提供一個「產能導向建議」： 在得料率不低於最佳值 95% 的所有組合中，等效產能（速率 / 次數）最高的那一組。

5.1 對數線性化：把曲線變直線

BPS 方程長得很醜，但兩邊取對數整理一下：

ln( 1/keff − 1 )  =  ln( 1/k₀ − 1 )  −  (δ/D) · v
　　　　　　　　　　　　　└─ 截距 ─┘　　└─ 斜率 ─┘ 左邊是你從資料算出來的，右邊對 v 是一次式。

意思是：把 ln(1/k_eff − 1) 對 v 畫散點圖，應該是一條直線。 用眼睛就能看出來對不對，用最簡單的線性回歸就能求斜率和截距。 5~6 個不同速率的批次就夠畫出這條線。

這也是一個誠實度檢查

如果點根本不成直線，代表有 BPS 以外的機制在作怪（氧化夾帶、對流不穩、 取樣位置不一致、或量測不確定度大於製程效應）。這個發現本身就值錢—— 它告訴客戶該補什麼量測，而不是硬套一個不成立的模型。

系統的「參數映射」頁有一個「BPS 線性化檢查」分頁，就是專門讓工程師看這件事。 R² 低於 0.5 時，模型會主動印出警語，而不是安靜地給一組沒意義的參數。

5.2 溫度為什麼只是代理變數

溫度不是獨立的物理變數。它透過兩條路徑影響結果：

  1. 溫度高 → 熔區變長 l → 容納雜質的能力變大，曲線形狀改變
  2. 溫度高 → 液池對流變強 → 邊界層 δ 變薄 → k_eff 變好
投報率最高的補量測項目

真正的物理變數是熔區長度 l，溫度只是它的代理指標。 如果客戶目前只記錄加熱器設定溫度、沒有實測熔區長度，那麼「加裝量測 l 的方法」 會比「多跑十批實驗」更有價值——因為量到 l 之後，模型就不需要靠溫度去推。

系統的異常偵測有一條批次層級規則：如果某一批所有元素的 k_eff 都 往同一個方向偏離映射預測，那不是量測雜訊，是這一批的製程條件記錄與實際不符。 熱電偶飄移、實際熔區長度與設定值不同、氣氛洩漏，都會產生這個特徵。 逐元素的門檻永遠抓不到它，必須跨元素看。

6. 從模型到「得料率」

有了各元素的分布曲線，得料率的定義是：

從頭端算起、連續滿足門檻的最長區間，佔全錠長度的比例。

強調「連續」是因為切割是連續的——「全錠中所有合格點的比例」在物理上沒有意義。 計算時還會扣掉頭端固定切除量（實務上頭端會有接觸污染、氧化皮，客戶通常會固定切掉一小段）。

門檻支援兩種寫法，可以同時用：

  • 總雜質上限（預設 1.0 ppm，即 6N）
  • 個別元素上限：任一元素超標即不合格

系統同時回報「限制元素」——也就是在切點處離自己上限最近的那個元素。 這個資訊很有用：如果限制元素永遠是 Sn，而 Sn 的 k_eff 又接近 1， 那結論就是「Sn 用偏析法除不掉，得料率被它綁死，要往前段製程想辦法」。
