08 · 驗證、驗收與風險控管

客戶說「導入 AI，但不要影響結果準確性」。 這一篇把那句話翻譯成可以量化、可以驗收、寫得進合約的條款。

1. 先搞清楚客戶為什麼要 AI

三種動機的應對完全不同，開會時一定要探出來：

動機徵兆對策
A. 補助案／計畫書需要 提到專案名稱、智慧製造、政府補助 需要「可寫進報告的 AI 名詞」+ 架構圖。技術上照本方案做即可
B. 高層想看到 AI 講不出具體想要什麼，只說「導入 AI」 需要看得見、摸得到的 AI 介面 —— L5 對話層就是解藥
C. 真的以為 AI 比較準 提到深度學習、預測準確率、大數據 需要教育：小資料下純 ML 會過擬合，要給他證據

多數情況是 A 或 B。這兩種完全不需要犧牲任何準確度，因為他們要的是「AI 的形式」， 而正確方案本來就能提供。只有 C 需要正面溝通——而正面溝通的工具就是下面這套雙軌驗證。

2. 雙軌顯示

介面上每個預測都出兩個數字：

預測 6N 得料率
  純物理模型：  62.3%
  物理 + AI：   64.1%   （相對修正 +2.9%）

  ⚠ 兩者差異 < 3%，AI 修正在正常範圍
為什麼這件事本身就是信任的基礎

工程師隨時看得到 AI 動了多少手腳。差太多就會警覺。 這比任何「我們的模型很準」的保證都有說服力，因為它把判斷權交回給人。

實作上，「模擬與預測」頁的雙軌卡片永遠成對顯示，就算 AI 修正未啟用也會顯示 「未套用」並說明原因（未通過驗收 / 落在外插區 / 被使用者關閉），而不是安靜地隱藏。

3. 留一批交叉驗證（Leave-One-Batch-Out）

3.1 白話版

假裝沒看過第 7 批，用其他所有批訓練，然後預測第 7 批，比對真值。每一批都輪一次。

為什麼是「留一批」而不是「留一點」

同一批內的取樣點高度相關——它們共用同一組製程條件、同一次分析、同一根錠。 留一點會讓模型在訓練時「看過同一批的其他點」，等於偷看答案， 會嚴重高估模型能力。

這是製程資料最常見的資料洩漏陷阱，而且很容易在論文與報告裡出現。 本專案在每一折都把整個批次留出，映射與殘差模型都重新訓練。

3.2 兩套並跑

路徑用了什麼
純物理Pfann + BPS/GP 映射
物理 + AI再加上 L1 殘差修正

輸出的比較表就是驗收文件：

指標純物理物理 + AI判定
平均絕對誤差0.42 ppm0.31 ppm✓ AI 有幫助
最大誤差1.8 ppm1.5 ppm✓
外插情境誤差0.55 ppm0.53 ppm~ 差不多（護欄生效）
如果 AI 那欄沒有比較好呢

就誠實地只交付純物理版。這反而會建立客戶對你的信任。

本專案的預設驗收門檻是「AI 必須至少改善 3%」——低於這個數字， 多出來的複雜度與風險不值得。系統會自動把 L1 保持在關閉狀態， 並在驗證頁明說：「依驗收條件，本階段只交付純物理模型—— 這是誠實且對客戶最有利的結果。」

3.3 誤差怎麼算

  • 只用未設限測點——設限點沒有真值，不納入
  • 同時回報 ppm 空間與對數空間的誤差。ppm 空間看得懂， 對數空間才公平（濃度跨越好幾個數量級，用 ppm 會被尾端主導）
  • 逐批、逐元素都列出來。誤差特別高的批次，通常和資料稽核標記的是同一批

4. 建議寫進合約的四條驗收條件

  1. AI 模組之預測誤差不得高於純物理模型基準（以留一批交叉驗證衡量）。
  2. 所有預測同時提供物理基準值與不確定區間。
  3. 超出訓練資料範圍之查詢，系統自動退回純物理模式並標示警告。
  4. AI 不參與任何設備控制決策；本系統為離線決策輔助工具。

注意第 1 條的效果：它把「AI 可能變差」的風險完全消滅了—— 因為 AI 只有在被證明更好時才上線。這是能給客戶最強的保證，而且做得到。

第 3 條在系統裡是真的有實作的：查詢點落在訓練資料範圍（含 10% 邊界緩衝）之外時， L1 修正會自動停用、介面顯示外插警示、最佳化建議也會把「穩健建議」限制在範圍內。

5. 系統內建的其他風險控管

5.1 L1 殘差學習的四道護欄

#護欄實作位置不做會怎樣
1修正量限幅 ±20%ml/residual.py 的 correction() ML 可能整個推翻物理預測，而且沒有人會發現
2外插時停用同上，_in_range() 檢查 在沒有訓練資料的區域，ML 的外推毫無根據
3須通過 LOBO 才啟用service.lobo() 設定 corrector.enabled 交付一個「看起來很潮但實際更差」的模型
4雙軌顯示ml/residual.py 的 dual_track() + 前端 工程師無從判斷 AI 動了多少手腳，也就不會信

5.2 異常資料自動排除於模型訓練

系統會先用全部資料擬一個映射、跑一次異常偵測， 把「高嚴重度且建議排除」的批次拿掉後重新擬合映射，再重新偵測一次。

這不是可有可無的最佳化。實測顯示：只要有一批取樣位置頭尾顛倒的資料混進去， 整條 BPS 回歸線就會被拉歪，某些元素的 δ/D 甚至變成負的—— 意思是「速率越快純化越好」，與物理相反。

原始資料完整保留在資料庫中，排除理由與指標會顯示在「資料稽核」頁， 總覽頁也會列出一條警示說明排除了哪幾組。系統不會安靜地丟掉資料。

5.3 不確定性一律成對出現

  • k_eff 附 95% bootstrap 信賴區間
  • GP 預測附 95% 區間，且區間在 z 空間對稱、轉回 k 空間後不對稱 （這是正確的，因為 k 有界）
  • 得料率預測同時給樂觀 / 名目 / 悲觀三個值
  • 參數建議附「悲觀情境下的得料率」與「是否落在資料範圍內」

5.4 資料層的把關

匯入時單位與物理一致性一律嚴格檢查，不合格就擋下並說清楚哪一列、為什麼。 錯誤資料不會被靜默修正成預設值——這是實作時特別修過的一個 bug： float(x or 500) 這種寫法會讓「錠長 = 0」變成 500，後面的檢查就永遠看不到它。

6. 「不影響準確性」的完整承諾清單

可以直接拿去跟客戶對：

承諾怎麼做到的怎麼驗證
AI 不會讓預測變差L1 須通過 LOBO 才上線，門檻 3% 改善 「模型驗證」頁的比較表
AI 不會推翻物理修正量硬性限幅 ±20% 程式碼 + 雙軌顯示的修正量欄位
外插時不會亂猜自動退回純物理並標示警告 「模擬與預測」頁把範圍外的條件標成外插區
LLM 不會編造數字系統提示詞明確禁止計算；所有數字來自工具回傳 每則回覆都列出實際呼叫了哪些工具與引用的批次
爛資料不會污染模型兩階段映射 + 異常自動排除 「資料稽核」頁列出排除理由與指標
設限資料不會造成系統性偏差Tobit likelihood 「資料稽核」頁的三方法對照實驗

7. L5 對話層為什麼準確度風險為零

使用者提問
    ↓
LLM 解讀意圖 → 轉成對資料庫/模型的工具呼叫
    ↓
物理模型 + GP 算出數字        ← 所有數字只從這裡來
    ↓
LLM 把數字組織成人話
    ↓
回答（附上引用的批次 ID 與參數）

LLM 只負責「翻譯」，它根本不碰計算。系統提示詞裡的第一條絕對規則是：

你不做任何計算。回答中出現的每一個數字，都必須逐字取自工具回傳的結果。 不准心算、不准估算、不准內插、不准把百分比換算成別的單位再重算。

每個工具的回傳值都帶一個 _source 欄位，說明這個數字是怎麼算出來的， 讓 LLM 能在回答中誠實交代來源。前端則會把「本次呼叫了哪些工具、引用了哪些批次」 顯示在每則回覆下方——工程師看得到答案是怎麼來的才會採信。

沒有 API 金鑰時的降級

未設定金鑰或外部服務失敗時，系統會自動退回本地模板模式： 用規則式關鍵字判斷意圖 → 呼叫同一組工具 → 用模板把結構化結果組成中文句子。 措辭比較制式，但數字完全正確，而且離線可用。

理由很實際：demo 現場沒網路、客戶端資安不允許外連、金鑰過期——這三件事都會發生。 寧可句子生硬，也不要在客戶面前開天窗。介面上會明確標示目前是模板模式。

8. 開案前的 go / no-go 檢核點

P1 結束時要做一次誠實的判斷：

檢查項通過標準不通過怎麼辦
批次數≥ 15 批，且涵蓋至少 5 個不同速率 轉為「設計實驗」而不是「分析既有資料」
k_eff 擬合穩定性各元素的 bootstrap 區間寬度 < k 值的 50% 檢查取樣位置一致性與 C₀ 是否實測
BPS 線性假設R² > 0.5 先做量測系統分析，找出真正的干擾機制
量測不確定度對數殘差 σ < 0.45（±57%） 量測雜訊大於製程效應 → 先改善分析方法
C₀ 是否實測每批每元素都有 所有曲線無法對齊；請客戶補測，這是必要條件
如果資料品質不足以擬合出穩定的 k_eff

就轉為「量測系統改善 + 實驗設計」，不硬做模型。 這個誠實的分期反而好賣，也保護自己——因為硬做出來的模型， 上線後每一次預測失準都會回到你身上。

9. 執行驗證

介面上：「模型驗證」頁會自動執行留一批交叉驗證並顯示完整結果。 第一次執行需要數秒（20 批約 7 秒），之後走快取，資料變動時自動失效。

命令列上：

# 完整測試套件（87 條，約 17 秒）
pytest -q

# 只跑物理層的正確性驗證
pytest tests/test_physics.py -v

# 只跑端對端的方法還原驗證
pytest tests/test_pipeline.py -v -k recovers

curl http://127.0.0.1:8848/api/analysis/validation
