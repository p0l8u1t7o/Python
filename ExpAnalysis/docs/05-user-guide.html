05 · 使用者操作手冊

從安裝到看懂每一個數字。這份文件假設你是製程工程師或專案經理， 不預設你有統計學或冶金背景——所有專有名詞第一次出現時都會用白話解釋。 每個畫面都會回答三件事：它在回答什麼問題、每個數字怎麼讀、哪裡最容易誤讀。

先記住三句話，後面都好懂

1. k_eff 越低，偏析純化效果越好。它是「凝固時被固體帶走的雜質比例」， 沒有單位，介於 0 與 1 之間。
2. 6N = 總雜質小於 1 ppm。得料率是「從錠頭端算起、連續合格的那一段長度佔全錠的比例」。
3. 頭端最乾淨、尾端最髒。偏析純化不會消滅雜質，只是把它們推到尾端去。

1. 這套工具在做什麼

區域熔煉（zone refining）是讓一段熔區沿著銦錠緩慢移動，靠凝固時雜質溶解度的差異 把雜質往尾端掃。掃一趟叫一次 pass，多掃幾趟就更純。這件事本身有成熟的物理方程可以描述， 問題在於：該用多快的速率、多高的溫度、掃幾趟，而每跑一批實驗都很貴。

ExpAnalysis 做的事只有三件，正好對應客戶提出的三個需求：

客戶需求工具做的事對應畫面
找出影響雜質去除效率與 6N 得料率的關鍵參數 把每一條實測曲線壓成一個 k_eff，再建立 (速率, 溫度) → k_eff 的映射 總覽、參數映射
預測不同條件下雜質的分布趨勢，判斷高純區與雜質濃縮區 用物理模型正向模擬全錠濃度分布，標出 6N 區與濃縮區 模擬與預測
提供熔區溫度、移動速率、純化次數的最佳化建議 在參數空間上掃描得料率，給出三種取向不同的建議 最佳化建議
這是離線決策輔助工具，不參與任何設備控制。

它不會連到機台、不會自動調參數、不會做閉迴路。它產出的是「建議」與「依據」， 最後按下去的還是人。第 16 節有完整的責任邊界說明。

2. 安裝與啟動（Windows）

2.1 你需要什麼

  • Windows 10 / 11，或任何能跑 Python 3.10 以上的環境
  • Python 3.12（專案根目錄下已附 .venv 虛擬環境）
  • 一個現代瀏覽器（Edge、Chrome、Firefox 皆可）
  • 不需要網路。所有分析都在本機完成。只有 AI 助理的「外部 LLM 模式」需要連外， 而它是選配的（見第 14 節）

2.2 第一次安裝

打開「命令提示字元」或 PowerShell，切到專案根目錄：

cd C:\path\to\ExpAnalysis

REM 啟用虛擬環境
.venv\Scripts\activate

REM 安裝相依套件（第一次或更新版本後才需要）
pip install -r requirements.txt

看到 Successfully installed ... 就完成了。這一步需要網路， 之後日常使用都不需要。

2.3 啟動

python run.py

畫面會出現：

  ExpAnalysis 已啟動 → http://127.0.0.1:8848/
  API 文件           → http://127.0.0.1:8848/api/docs
  說明文件           → http://127.0.0.1:8848/docs/

約 1.5 秒後瀏覽器會自動打開 http://127.0.0.1:8848/。 命令提示字元的視窗不要關掉——關掉就等於關掉服務，網頁會顯示「無法連線到分析服務」。 要停止服務，在該視窗按 Ctrl + C。

3. 五分鐘上手

照著做一次，你就會知道整套工具的骨架。全程不需要任何真實資料。

① 產生合成資料

左側選單 →「資料管理」→ 找到「產生合成資料（demo 與方法驗證用）」→ 批次數維持 20 →「產生並取代現有資料」→ 確認。

合成資料不是隨便亂編的。它是用已知的真實 k₀ 與 δ/D 跑一次完整物理模擬、 再加上乘法性的量測誤差、再依檢測極限標記設限點所生成的。因此它可以拿來做方法驗證： 如果整套流程反解不回原本設定的真值，那就是方法有問題。它同時刻意植入了兩個異常批次 （見第 ⑥ 步）。所有由合成資料產生的批次，備註欄都會標示 「合成資料（demo 用，非實測）」，不會被誤認為實測結果。

② 看總覽

選單 →「總覽」。這一頁回答「這批資料能不能做事、瓶頸在哪」。 你會看到四個元素（Cu、Fe、Ni、Sn）的 k_eff 中位數與可去除性判定， 以及一條「純化次數的邊際效益」曲線——它直接告訴你該停在第幾次 pass。

③ 看一個批次

選單 →「批次資料」→ 左邊清單點 IN-25001。 右邊會出現實測值與物理模型的疊圖。實線是模型、圓點是實測、向下的三角形是低於檢測極限的點。 往下捲還有 k_eff 擬合表與殘差圖。

④ 拉滑桿模擬

選單 →「模擬與預測」。把「熔區移動速率」滑桿往左拉（變慢），看得料率怎麼變； 把「純化次數」往右拉，看曲線怎麼往下壓。速率越慢越純但越花時間—— 這個取捨你會在滑桿上直接感覺到。

⑤ 看最佳化建議

選單 →「最佳化建議」。頁面上方是三張建議卡：可直接執行（穩健）、理論最高、產能導向。 往下是得料率地圖（熱圖）、下一批該跑什麼實驗、以及 DOE 省批次試算。

⑥ 順手看一下稽核

選單 →「資料稽核」。你會看到 IN-25008 被標成高嚴重度（那是刻意植入的 「取樣位置頭尾顛倒」），IN-25004 被標成中嚴重度（那是刻意植入的 「熱電偶飄移 25 °C」）。系統在完全不知道我們動了手腳的情況下把它們抓出來了。

5.3 k_eff 判定表（背起來）

k_eff判定實務意義
< 0.15易去除 偏析法對它很有效。多跑幾趟就能壓到檢測極限以下。
0.15 ~ 0.40中等 可以除，但需要較多 pass 次數或較慢的速率。是最值得做參數最佳化的區間。
0.40 ~ 0.75困難 得料率會被這個元素綁住。它決定切點，其他元素再乾淨也沒用。
> 0.75偏析法無效 不要再花錢調參數了。k 接近 1 表示固體與液體幾乎一樣髒，掃再多趟也不會分離。 這個元素必須在前段製程（化學精煉、電解、真空蒸餾）處理掉。
常見誤讀：把 k_eff 當成「純化效率百分比」。

它不是。k_eff = 0.05 不代表「除掉 95%」。它是單次凝固介面上固體濃度與液體濃度的比值。 整條錠最後有多乾淨，取決於 k_eff、熔區長度比 l/L、以及 pass 次數三者的交互作用， 要靠模擬才算得出來。這正是「模擬與預測」頁存在的理由。

5.4 純化次數的邊際效益曲線

橫軸是 pass 次數，縱軸是 6N 得料率。一條往上爬、然後變平的曲線。 一直 pass 下去，雜質分布會收斂到「極限分布」——往尾端掃出去的量與熔區從右邊吃回來的量 達成平衡，之後每一趟都幾乎白跑。

下方三個標籤分別是：

  • 建議 N 次 —— 達到可達最大得料率的 95% 所需的最少次數。 這是報告裡該寫的數字。
  • 第 M 次後邊際增益 < 0.5 個百分點 —— 最後一次還算有意義的 pass。 超過這個次數，每多跑一趟得料率增加不到半個百分點。
  • 第 U 次收斂到極限分布 —— 數學上完全收斂的次數，通常比前兩者晚很多。 它是理論值，不是操作建議。
這是最快能換成錢的一個數字。

如果客戶現在固定跑 15 次，而模型說第 8 次之後得料率只再增加 0.3 個百分點， 那就是每批省下 7 趟的爐時。這個結論在拿到第一批歷史資料時就能交出去。

5.5 歷史批次的參數涵蓋範圍

三個數字：速率範圍、溫度範圍、pass 次數範圍。 模型只在這個範圍內可靠。超出去的查詢會在「模擬與預測」與「最佳化建議」頁 被標示為外插，並自動停用 AI 修正。

6. 批次資料

這一頁回答：這一批到底發生了什麼？模型有沒有把它解釋清楚？

左邊是批次清單（v = 速率 mm/hr、T = 溫度 °C、n = pass 次數），點一列切換右邊詳情。

6.1 頂部四張統計磚

  • 6N 得料率：副標給出高純區的起訖位置，例如 x/L 0.030 ~ 0.635。 x/L 是歸一化位置，0 是頭端、1 是尾端。起點就是你設定的頭端切除量。
  • 限制元素：在切點處離自己上限最近的元素。它就是「為什麼不能再往後切」的答案。
  • 製程條件 與 熔區長度比 l/L：這批的輸入條件。 l/L 是真正進入物理模型的無因次量，典型值 0.05 ~ 0.15。

6.2 濃度分布疊圖（這一頁的核心）

橫軸 x/L（0 = 頭端），縱軸是雜質濃度 ppm，縱軸是對數刻度—— 因為頭端可能是 0.001 ppm、尾端是 100 ppm，跨好幾個數量級，線性軸會什麼都看不到。

圖上元素意義
實線Pfann 多次 pass 模擬曲線，用該批擬合出的 k_eff 計算。每個元素一條，顏色對應圖例。
圓點 ●實測值（GDMS / ICP-MS 的分析結果）。
向下三角形 ▼低於檢測極限的設限點。三角形畫在 LOD 的位置，但真值可能在它下面任何地方—— 這是一個不等式，不是一個數字。滑鼠移上去會顯示 < 0.005 ppm（低於檢測極限）。

紅色區塊雜質濃縮區：總雜質超過門檻 5 倍的區域。這一段是要回爐重煉或另作處理的料。

為什麼設限點一定要單獨畫成三角形

用軟體的比喻：log 裡寫著 response_time: TIMEOUT (>30s)。統計平均時把它當成 30 秒會低估， 當成 0 更荒謬——你只知道「至少 30 秒」。
在這裡是反過來的方向：測值「< 0.05 ppm」的真值落在 0 到 0.05 之間。 當成 0 會讓頭端看起來完美、k_eff 被低估；當成 LOD 會讓頭端看起來偏髒、k_eff 被高估。 本系統用 Tobit likelihood 告訴擬合程式「這點的真值在區間內」，兩種偏差都避開了。 「資料稽核」頁有一張對照實驗表，把這三種做法的差異用同一批資料實際跑出來。

疊圖最常見的三種誤讀

  1. 「三角形沒落在線上，是不是模型不準？」——不是。三角形只代表上界。 只要模型曲線落在三角形下方，模型與觀測就完全不矛盾。真正該擔心的是模型曲線 明顯高過三角形（模型說「應該測得到」但實際測不到）。
  2. 「尾端翹得那麼高，是不是算錯了？」——那是物理的必然。最後一個熔區長度的區段 是終端凝固，沒有新固體可熔，濃度會急速上升。這一段本來就是要切掉的。
  3. 「綠區看起來很大，怎麼得料率只有 40%？」——注意對數縱軸會把視覺比例扭曲， 而且得料率算的是從頭端起算的連續合格區間，不是圖上所有低於門檻的點加總。 中間只要有一點超標，後面再乾淨也不算——因為切割是連續的。

設限點3/8 表示 8 個測點裡有 3 點低於檢測極限。 超過 60% 會出現備註提醒不確定度偏大；100% 則代表這批對這個元素完全沒有有效資訊。
σ_log對數殘差標準差。滑鼠移上去會換算成相對誤差百分比。 典型 GDMS 大約在 0.1 ~ 0.2（±10~22%）。超過 0.45 就不對勁了， 會被資料稽核抓出來。
判讀可去除性標籤，以及擬合過程產生的備註（設限點太多、σ 過大、C₀ 為推估值等）。

6.4 標準化殘差圖（判斷「資料有沒有問題」的關鍵）

殘差 = 實測與預測的差距，除以估計出的雜訊尺度。所以縱軸的 1 就是「差了一個標準差」。 綠帶是 ±1σ、黃帶是 ±2σ。設限點畫成菱形，顯示的是 Tobit 的期望殘差 （模型與「測不到」這件事有多矛盾）。

怎麼看：看形狀，不是看大小。

正常：點在零線上下隨機散布，大部分落在綠帶內。這代表誤差只是量測雜訊。
不正常：前段一致偏高、後段一致偏低（或反過來）。 這叫結構性正負分布。它不是量測雜訊——雜訊不會排隊。它幾乎一定是下面三件事之一：

  • 取樣位置記錄錯誤（最常見：頭尾顛倒，或 x_mm 與錠長單位不一致）
  • 熔區長度記錄與實際不符（溫度變了，l 就變了，但表單上還是寫設定值）
  • pass 次數對不上（中途補跑一趟沒記錄）

看到這個形狀，第一件事是去翻原始紀錄，不是去調模型參數。

其他形狀的意義：

  • 單點跳到 ±3 以外，其他都正常 → 那一點的問題。分析室送錯樣品、或該點位置抄錯。
  • 整體都偏大但沒有結構 → 量測不確定度比預期大，或這批的製程條件本身不穩。
  • 殘差呈喇叭狀（往尾端越來越散） → 正常。尾端濃度高、相對誤差本來就大一些。

7. 參數映射

這一頁回答：製程參數到底怎麼影響純化效率？模型憑什麼這樣說？

上方晶片列先選元素，右側兩個晶片切換兩種檢視： 「k_eff vs 速率」（給決策用）與 「BPS 線性化檢查」（給取信用）。

7.1 頂部四張統計磚

  • k₀（平衡分配係數）：速率趨近 0 時的理論最佳值，這是物理天花板。
  • δ/D（斜率）：速率敏感度，附標準誤。標準誤大代表這條斜率是猜的， 資料涵蓋的速率範圍可能太窄。
  • R²：BPS 直線解釋了多少變異。
  • 映射模型：高斯過程或 BPS 線性。

7.2 「k_eff vs 速率」檢視：灰帶怎麼讀

一條曲線加一片陰影。曲線是預測值，陰影是 95% 不確定區間。 直立的短線是每個批次擬合值的信賴區間，白色圓點是該批的 k_eff。

灰帶會呼吸：這是這張圖最有價值的地方。

在有資料的地方收窄、在沒資料的地方張開。這不是畫圖技巧， 這是高斯過程本身的性質——它在報告「我對這裡有多少把握」。 一般的線性回歸畫出來的信賴區間是一條均勻的帶子，看不出這件事。

所以正確的讀法是：灰帶窄的地方，模型的建議可以拿去用；灰帶寬的地方， 模型是在猜，該安排一批實驗去填。

斜線底紋區域：超出歷史批次涵蓋的速率範圍，也就是外插區。 在這個區域裡，模型會平滑地回歸到 BPS 物理直線（而不是回歸到一個沒有意義的常數）， 所以預測仍然有物理依據，但不確定度大幅上升，且 AI 修正會被自動關閉。

7.3 「BPS 線性化檢查」檢視：物理模型的誠實度檢查

這張圖的縱軸是 ln(1/k_eff − 1)，一個看起來很奇怪的變換。它的用途很單純：

ln(1/k_eff − 1) = ln(1/k₀ − 1) − (δ/D) · v 左邊由資料算出，右邊對速率 v 是一條直線。截距給你 k₀，斜率給你 δ/D。 這就是為什麼只要 5~6 個不同速率的批次就能把整條關係定出來——而且斜率有物理意義、可以往外插。

圖上有一條灰色虛線是純 BPS 直線基準，實線是實際模型（含高斯過程的修正）。

散點不成直線，這個發現本身就有價值——不要硬套模型。

如果散點明顯彎曲、或根本雜亂無章（R² < 0.5，系統會直接顯示警告框）， 代表有 BPS 以外的機制在作用。可能的原因，依查證的投報率排序：

  1. 量測不確定度大於製程效應——先做量測系統分析（MSA）。如果 GDMS 的重現性是 ±25%， 而不同速率造成的差異只有 ±15%，那再多批次也擬不出斜率。
  2. 取樣位置不一致——每批的取樣點不在同樣的相對位置，等於在比較不同的東西。
  3. 氧化夾帶或對流不穩——氣氛控制或爐體設計的問題，不是參數調得出來的。
  4. 速率與溫度同動——如果歷史批次裡「快的都比較熱」，兩個變數是共線的， 數學上無法分離。這時 δ/D 甚至可能擬出負值（速率越快 k_eff 反而越好），系統會直接警告。

這時候正確的動作是把這個發現寫進報告，而不是換一個 R² 比較好看的模型。 一個誠實說「你的資料撐不住這個結論」的工具，比一個永遠給漂亮答案的工具值錢得多。

7.4 「這對製程代表什麼」卡片

兩段固定的解釋，值得讀一次：

  • 核心取捨：慢 = 純，快 = 產能。凝固介面把雜質吐回液體，這些雜質要靠擴散散進整個液池。 凝固太快時雜質來不及散開，在介面前堆成一層高濃度邊界層，讓實際感受到的 k_eff 變大。 δ/D 就是在量化這個效應的強度。
  • 溫度是代理變數，不是物理變數。溫度透過兩條路徑影響結果： (1) 溫度高 → 熔區變長 l → 曲線形狀改變；(2) 溫度高 → 對流變強 → 邊界層變薄 → k_eff 變好。 真正的物理變數是熔區長度 l。如果客戶還沒實測 l，這是整個專案投報率最高的補量測項目—— 量到 l 就不必再靠溫度去推。

8. 模擬與預測

這一頁回答：如果我把參數設成這樣，雜質會長什麼樣？能切出多少 6N？

四個滑桿：熔區移動速率、熔區溫度、純化次數、頭端切除比例。拉動即時重算（有 160 毫秒的防抖動延遲）。

8.1 頂部四張統計磚

  • 6N 得料率（名目）：主要答案。副標同時給樂觀與悲觀值—— 分別是所有元素的 k_eff 都落在信賴區間下界／上界的情況。
    樂觀與悲觀差很多，就代表這個條件下模型沒把握，不要直接下給產線。
  • 高純區：x/L 0.030–0.612，以及決定切點的限制元素。
  • 雜質濃縮區起點：總雜質超過門檻 5 倍之處。這一段之後的料要另作處理。
  • 外插狀態：「範圍內」或「外插區」。外插區是黃色警示， 表示這組條件超出歷史批次涵蓋範圍，模型是在往外推。

8.2 雙軌顯示：AI 到底動了多少手腳

勾選「同時顯示『物理 + AI 修正』（雙軌）」後，會出現兩個並排的數字： 純物理模型 與 物理 + AI 修正。

為什麼永遠並列，而不是只給一個「更準」的數字

因為工程師要看得到 AI 動了多少手腳，才會採信這個工具。差太多就會警覺， 這件事本身就是信任的基礎。修正量硬性限制在物理預測的 ±20% 以內—— ML 永遠不能推翻物理，只能微調。

下方一行文字會說明目前的狀態，可能是：

顯示意思該怎麼辦
AI 修正量 +1.2%，在正常範圍內。正常運作兩個數字都看，以物理為主。
AI 修正量 +5.8%，超過 3%，請留意兩者差異。修正量偏大去「模型驗證」頁確認 AI 是否真的有改善。
查詢條件落在訓練資料範圍外，已自動退回純物理模式。外插保護生效正常。這是設計好的行為，不是故障。
殘差修正未通過驗收門檻或被使用者關閉，僅顯示物理模型結果。AI 沒上線正常，而且是好事——見下方提示。
可用樣本僅 N 筆（需 >= 30），不訓練殘差模型。資料量不足再累積幾批。
AI 顯示「未套用」通常是正確的結果，不是故障。

殘差修正必須先通過留一批交叉驗證、而且要比純物理至少改善 3% 才會上線。 在合成資料或資料量不足時，它通常過不了門檻——這時候只交付純物理模型是誠實的做法。 另外有個實務細節：驗收門檻是在「模型驗證」頁被實際計算的， 所以如果你剛匯入資料就直接來這一頁勾雙軌，會看到「未套用」； 先去「模型驗證」頁跑一次，回來再看就會反映真正的判定結果。

8.3 預測雜質分布圖

和「批次資料」頁的疊圖同一套讀法（對數縱軸、綠區、紅區、黃色門檻線），差別是：

  • 沒有實測點——這是純預測。
  • 多一條粗白線 = 總雜質。決定 6N 切點的就是它，各元素的細線只是拆解。
  • 勾了雙軌時會多一條藍色虛線 = 含 AI 修正的總雜質。兩條線幾乎重疊是正常的（修正量本來就小）。

8.4 各元素的預測 k_eff 表

給出每個元素在這組條件下的 k_eff 與 95% 區間，以及該元素在切點處的濃度。 切點濃度告訴你餘裕有多少：如果限制元素在切點是 0.95 ppm 而門檻是 1 ppm， 那幾乎沒有餘裕，量測誤差就足以讓這批不合格。

9. 最佳化建議

這一頁回答：參數該怎麼設？下一批該跑什麼？這樣做能省多少錢？

9.1 掃描設定：產能權重

下拉選單有三檔。它改的是目標函數：

目標 = 得料率 − w × (pass 次數 ÷ 速率) w = 0 是純追求純度，通常會建議「跑很慢、跑很多次」。 w 越大越把爐時成本算進去。0.02 是溫和的權衡，0.05 會明顯偏向產能。

9.2 三種建議 —— 用途不同，三個都要看

建議怎麼選出來的拿來做什麼
可直接執行（穩健）
綠		 只在歷史資料涵蓋範圍內挑選，而且是以悲觀情境排序—— 也就是假設所有元素的 k_eff 都落在信賴區間的壞的那一端。 這一組可以直接下給產線。它不需要先做驗證實驗。
理論最高得料率
藍		 整個掃描範圍內名目得料率最高的組合，不管它是不是外插。 當成方向看。如果它落在外插區（卡片上會標 ⚠）， 正確的動作是安排一批實驗去驗證，而不是直接下給產線。
產能導向
黃		 在得料率不低於最佳值 95% 的所有組合中，等效產能（速率 ÷ 次數）最高的一組。 這通常是真正省錢的那一組。用 5% 的得料率換一半的爐時， 在多數成本結構下是划算的。
為什麼一定要三個都給客戶看

只給一個「最佳解」是不負責任的。「最佳」取決於你在最佳化什麼—— 純度、產能、還是風險。把三組並列，客戶自己就會說出他真正在乎的是什麼， 而這通常比任何模型輸出都有價值。而且並列本身傳達了一個重要訊息： 這個工具知道自己的建議有不確定性，也知道決策不只有一個維度。

每張卡片下方都有：悲觀值與限制元素。悲觀值與名目值差距大的建議， 執行風險就高。

9.3 得料率地圖（熱圖）

  • 橫軸速率、縱軸溫度，顏色是預測得料率（越亮越好）。
  • 上方晶片切換 pass 次數。預設顯示的是穩健建議所用的次數，不是清單第一項。
  • 半透明的區域代表外插——超出歷史批次涵蓋範圍。
  • 白圈是穩健建議點的位置（只有在切到對應的 pass 次數時才出現）。
  • 滑鼠移到格子上看確切數值。

熱圖最有用的地方不是找最亮的點，而是看等高線的形狀： 如果亮區是一條沿著某個方向的長帶，代表那個方向上的參數不敏感，你有很大的操作餘裕； 如果亮區是一個小點，代表製程窗口很窄，重現性會是大問題。

9.4 該做幾次 pass

與總覽頁的曲線同一個計算，差別是這裡用的是穩健建議的條件， 而總覽用的是歷史批次的中位數條件。三個標籤：建議次數、第幾次之後幾乎白跑、可省下幾趟。

9.5 下一批該跑什麼 —— 貝氏最佳化序列實驗設計

表格列出三組建議條件，每一組附上預測得料率、不確定度、以及「這一批的目的」。 目的分兩種，讀法完全不同：

目的意思怎麼判斷成功
縮小模型的未知區（探索） 這個點的不確定度高於中位數，沒人去過。 就算結果不如預期也算成功——你買到的是資訊，不是得料率。
確認最佳點（開發） 模型在這裡已經相對有把握。 結果應該接近預測值。差很多就代表模型有問題，要回頭查。
這一層零風險。

它只建議做什麼實驗，最終的準確度來自真實實驗資料，不是模型猜的。 就算建議得不好，最壞情況也只是多跑幾批——不會產生錯誤的結論。 （順帶一提，貝氏最佳化正是 AI 界用來調神經網路超參數的標準工具， 說它是 AI 一點都不心虛。）

資料少於 4 批時這一區會顯示提示，建議先用涵蓋速率範圍的篩選性實驗跑 5~6 批， 再切換到序列最佳化。這是對的——貝氏最佳化在幾乎沒有資料時沒有意義。

9.6 DOE 省批次試算 —— 怎麼跟採購講

這一區用同一個虛擬產線（以既有資料擬合出的模型）跑兩種實驗策略， 畫出「跑到第 n 批時，目前為止的最佳得料率」：

  • 全因子 DOE：把所有參數組合都跑一遍。順序已隨機打散， 避免因為剛好先跑到最佳點而高估它的效率。
  • 貝氏最佳化：先跑 5 批分層抽樣的起始實驗，之後每一批都由模型指定。

四張統計磚給的就是可以直接放進簡報的數字：

全因子需要      36 批   最終最佳得料率 74.8%
貝氏最佳化       8 批   即達到全因子最終結果的 99%
可省批次        28 批   在相同目標下
估算節省    NT$2,800,000   以每批 NT$100,000 計
對採購／財務要這樣說，才不會被打回票

✅ 正確說法：「在以我們現有 20 批資料建立的模型上模擬，全因子設計需要 36 批才能 把參數空間掃完；序列實驗設計在第 8 批就達到相同的最佳得料率。以每批 10 萬元計， 這個方法論的預期節省是 280 萬元。這是實驗策略效率的對比，不是對真實產線的績效承諾。」

❌ 錯誤說法：「這個系統可以幫我們省 280 萬。」——會被問「怎麼保證？」然後你答不出來。

關鍵差別在於：省下來的是實驗批次，不是製程成本；而且對比是在模型上跑的， 兩種策略用的是同一個 oracle，所以比較是公平的，但絕對值會隨模型精度變化。 把每批成本改成客戶的真實數字（目前預設 10 萬），這個試算就能直接進採購案。

10. 資料稽核

這一頁回答：哪一批資料不對勁？我該去查什麼？
這一層零風險，所以應該最先做。

異常偵測不參與任何預測計算，只是把可疑批次挑出來給人看。 它只會保護準確度（把爛資料擋在模型外），不可能傷害準確度。 被標為高嚴重度的資料會自動從參數映射的訓練集中排除，但原始資料完整保留在資料庫中， 隨時可以檢視排除理由。

10.1 嚴重度分級與建議動作

嚴重度觸發條件（任一）系統做了什麼你該做什麼
HIGH 單點標準化殘差 > 4.5；曲線殘差 RMSE > 2.7； 殘差呈結構性正負分布；k_eff 偏離 (v,T) 映射超過 4 個標準差 標記「已自動排除於模型訓練」，映射會在排除後重新擬合 （前提是每個元素還剩至少 4 筆；不足時會保留並警告） 去翻原始紀錄：取樣位置、熱電偶校正紀錄、送驗單。 確認是資料問題後才正式排除；如果是真實的製程現象，反而是重要發現。
MEDIUM 同時觸發兩項以上的門檻，或整批所有元素的 k_eff 同方向偏離映射預測超過 1.2 個標準差 只標記，不排除 留意。批次層級的同向偏移特別值得追（見下一節）。
LOW 只觸發一項門檻，或只被 Isolation Forest 標記 只標記 通常不用動作。但如果同一批有多個元素同時被標記，就值得追查。

10.2 每一則發現包含什麼

  • 批次 / 元素，以及是否已自動排除
  • 理由（可能多條）：用白話寫的，而且會直接點出最可能的成因。 例如「殘差呈結構性正負分布——典型成因是取樣位置頭尾顛倒、熔區長度或 pass 次數記錄錯誤」。
  • 建議動作
  • 偵測指標（可展開）：實際的數值，供你自己判斷門檻是否合理

10.3 特別值得注意：「(全部元素)」的批次層級發現

單一元素偏 1.5 個標準差可以是雜訊；所有元素一致同向偏就不是。

當一整批的 Cu、Fe、Ni、Sn 的 k_eff 全部往同一個方向偏離映射預測時， 那不是量測雜訊，是這一批的製程條件記錄與實際不符。逐元素的門檻永遠抓不到它， 必須跨元素看。系統會直接列出最可能的三個原因（依查證投報率排序）：

  1. 熱電偶讀值與實際熔體溫度不符
  2. 實際熔區長度與設定值不同（溫度變化會直接改變 l）
  3. 氣氛不如記錄（氧化夾帶會整體抬升雜質水準）

在預設的合成資料裡，IN-25004 就是刻意植入的熱電偶飄移 25 °C， 它正是被這條規則抓到的。

10.4 設限處理的對照實驗

頁面下半部是一張表，用同一批資料、同一個模型，只換設限點的處理方式，比較擬出來的 k_eff：

方法做法典型結果
Tobit（正確）告訴模型「真值落在 [0, LOD] 區間內」接近無偏，當基準
當成 0設限點直接填 0系統性低估 k_eff（頭端看起來太完美）
當成 LOD設限點填檢測極限值系統性高估 k_eff（頭端看起來太髒）

最右兩欄直接算出偏差百分比。這張表是「為什麼不能便宜行事」的證據， 也是說服客戶（和說服自己）最有力的一頁——它不是講道理，是把同一份資料實際跑三遍。

11. 模型驗證

這一頁回答：模型到底多準？AI 有沒有真的幫上忙？ 這一頁就是驗收文件。

11.1 什麼是留一批交叉驗證（LOBO）

白話：假裝沒看過第 7 批，用其他所有批訓練模型，然後預測第 7 批，跟真值比。每一批都輪一次。

為什麼是留一「批」而不是留一「點」

同一批內的取樣點高度相關——它們共用同一組製程條件、同一次分析、同一支熱電偶。 留一點會讓模型「已經看過這一批的其他點」，於是嚴重高估模型能力。 這是製程資料最常見的資料洩漏陷阱，很多看起來很漂亮的模型報告都栽在這裡。

11.2 四張統計磚

  • 交叉驗證折數：幾批輪過，以及用了幾個未設限測點。 （設限點沒有真值，不納入誤差計算。）
  • 純物理 MAE：純 Pfann + BPS/GP 的平均絕對誤差，單位 ppm。這是基準線。
  • 物理 + AI MAE：加上 L1 殘差修正之後的誤差。
  • 上線門檻：通過 / 未通過。

11.3 驗收判定怎麼讀

通過的情況：

AI 修正使平均絕對誤差從 0.0421 ppm 降到 0.0388 ppm（改善 7.8%）， 達到 3% 的上線門檻，建議啟用並維持雙軌顯示。

未通過的情況（更常見，而且沒有不好）：

AI 修正未達 3% 的改善門檻（−36.4%）。依驗收條件，本階段只交付純物理模型—— 這是誠實且對客戶最有利的結果。
「未通過」不是失敗，是這套設計在正常運作。

AI 模組只有在被證明比純物理更好時才上線。這條規則把「AI 可能讓結果變差」的風險 完全消滅了——因為它根本進不了門。這是能給客戶最強、而且做得到的保證。 一份誠實說「這個階段 AI 沒幫上忙，所以我們只交付物理模型」的報告， 比一份硬把 AI 塞進去的報告更能建立信任。

11.4 誤差比較表與逐批檢視

  • 平均絕對誤差（ppm）：整體水準。
  • 最大誤差（ppm）：最壞情況。這個數字通常由某一批主導——去逐批表找它。
  • 對數空間平均誤差：因為濃度跨越好幾個數量級，這個指標對「相對誤差」比較敏感， 不會被尾端的大數值主導。

分元素檢視：誤差偏高的元素通常有兩種原因——k_eff 接近 1（訊號本身就弱）， 或該元素的測點大量落在檢測極限以下。
逐批檢視：每一點是「把這一批完全留出、用其他批訓練後再預測」的誤差。 若某批誤差特別高，去比對「資料稽核」頁——通常是同一批。

11.5 建議寫進合約的四條驗收條件

  1. AI 模組之預測誤差不得高於純物理模型基準（以留一批交叉驗證衡量）。
  2. 所有預測同時提供物理基準值與不確定區間。
  3. 超出訓練資料範圍之查詢，系統自動退回純物理模式並標示警告。
  4. AI 不參與任何設備控制決策；本系統為離線決策輔助工具。

第 1 條特別重要：它把客戶那句模糊的「不要影響準確性」翻譯成了可量化、可驗收的條件。 而且第 11.3 節的機制保證這條一定做得到。

12. AI 助理

這一頁回答：我可以直接用問的嗎？可以，但要知道它在做什麼。

12.1 它做什麼、不做什麼

LLM 不做任何計算。一個數字都不算。

它的工作流程是：解讀你的問題 → 決定要呼叫哪個分析工具 → 工具去打物理模型與資料庫 → 把工具回傳的數字組織成人話。每個數字都逐字取自工具結果， 系統提示詞明確禁止它心算、估算、內插、或把百分比換算成別的單位再重算。

所以它的準確度風險是零——它根本不碰計算。它負責的是「翻譯」。

12.2 怎麼用

  • 上方有一排建議問題晶片，點一下直接送出。
  • 輸入框支援 Ctrl + Enter（Mac 是 ⌘ + Enter）送出。
  • 對話有上下文，會帶入最近幾輪。

問得好的問題長這樣：

  • 「IN-25004 的 Cu 為什麼比 IN-25003 差？」（指定批次，它會去比對兩批的參數差異）
  • 「哪個製程參數對純化效率影響最大？請用數字說明。」
  • 「純化次數做到第幾次之後就沒有意義了？」
  • 「有哪些批次的資料看起來有問題？該怎麼處理？」

12.3 每則回覆下方的來源追溯

回覆下方會列出實際呼叫了哪些工具與引用了哪些批次。 這不是裝飾——工程師看得到答案是怎麼來的才會採信。 如果回覆裡出現一個數字，但下方沒有任何工具被呼叫，那就要懷疑了。

還可能出現 本地模板模式 標籤，見下一節。

13. 匯入自己的資料

13.1 流程

  1. 選單 →「資料管理」→「下載 CSV 範本」，照著範本的欄位整理。
  2. 選檔案 → 先按 「只稽核（不寫入）」。
  3. 看稽核報告。有錯誤就修正檔案再來一次；只有警告可以繼續。
  4. 按「稽核並匯入」。
永遠先跑「只稽核」。

它會用完全相同的規則檢查一遍，但一個字都不寫進資料庫。 匯入是整批原子性的：只要有任何一項錯誤，整份檔案都不會寫入， 不會出現寫到一半的髒狀態。

13.2 錯誤與警告的差別

意思典型例子
錯誤 擋下匯入，一列都不寫。錯誤訊息一定會指出第幾列、為什麼。 缺少必要欄位；歸一化位置超出 [0,1]（常見原因是 x_mm 與錠長單位不一致）； 熔區長度 ≥ 錠長；速率為 0 或負；同一批次的製程參數在不同列不一致；同一位置重複出現
警告 不擋匯入，但會影響分析品質。系統會照做，並在後續畫面持續標示。 某元素只有不到 3 個取樣點；未提供進料濃度 C₀（會用曲線推估並標為推估值）； 最靠頭端的取樣點在 x/L > 0.25（缺頭端資料會讓 k_eff 不確定度顯著變大）； 標記為設限但沒給 LOD

13.3 檢測極限的三種寫法都支援

  1. value_ppm 直接寫成 <0.05（帶小於號的字串）
  2. value_ppm 填數值，同時 censored 欄填 1
  3. value_ppm ≤ lod_ppm（有填 lod_ppm 時自動判定）

三種都會被標記為左設限並保留 LOD 值。請務必填 lod_ppm—— 沒填的話系統只能拿測值當 LOD，並會發出警告。

欄位的完整定義、單位約定、別名對照表，請看 03 · 資料規格書。 欄名支援中英文與常見別名（速率、speed、v、 zone_speed 都會被辨識），但單位與物理一致性一律嚴格檢查。

13.4 刪除與清空

「目前資料庫」表格每列最右邊有刪除鈕（會二次確認）。最下方有「清空所有資料」—— 此操作無法復原。要備份的話，直接複製 data/expanalysis.db 這個檔案就是完整備份。

14. 設定 AI 助理

14.1 預設就能用：本地模板模式

什麼都不設定，AI 助理照樣可以用。

未設定 API 金鑰時，系統自動退回本地模板模式：不呼叫任何外部服務、離線可用、 數字完全正確（因為數字本來就不是 LLM 算的），只是措辭比較制式。

這個設計是刻意的：demo 現場沒網路、客戶端資安不允許外連、API 金鑰過期—— 這三件事都會發生。寧可句子生硬，也不要在客戶面前開天窗。

本地模板模式下，助理靠關鍵字判斷你的意圖、直接呼叫對應的工具、 再把結構化結果組成中文句子。它的回覆會在結尾標註 「本回覆由本地模板模式生成（未使用外部 LLM）」，並在來源列顯示 本地模板模式。

14.2 啟用外部 LLM（選配）

在專案根目錄建立 .env 檔（可以複製 .env.example 改）：

# 二選一即可

# 用 Anthropic
EXPA_LLM_PROVIDER=anthropic
EXPA_ANTHROPIC_API_KEY=sk-ant-...
EXPA_ANTHROPIC_MODEL=claude-sonnet-4-5

# 或用 OpenAI
EXPA_LLM_PROVIDER=openai
EXPA_OPENAI_API_KEY=sk-...
EXPA_OPENAI_MODEL=gpt-4o

存檔後重新啟動 run.py（.env 只在啟動時讀一次）。 到「AI 助理」頁，最上方的提示框會從黃色變成綠色，並顯示實際使用的模型名稱。

金鑰安全

.env 已經在 .gitignore 裡，不會被提交進版本庫。 API 金鑰只從環境變數讀取，永遠不會寫進日誌、也不會回傳給前端—— /api/assistant/status 只會告訴你「有沒有設定」，不會回傳金鑰內容。

其他可調的環境變數：

變數預設作用
EXPA_DB_PATHdata/expanalysis.db資料庫檔案位置
EXPA_HOST / EXPA_PORT127.0.0.1 / 8848服務位址
EXPA_LOG_LEVELINFO日誌詳細度（除錯時設 DEBUG）
EXPA_PURITY_THRESHOLD_PPM1.06N 判定門檻（總雜質 ppm）。客戶若用不同定義可在此調整
EXPA_LLM_TIMEOUT_S60外部 LLM 的逾時秒數

15. 常見問題排除

網頁顯示「無法連線到分析服務」

  • 最常見：run.py 的命令視窗被關掉了。重新啟動即可。
  • 連接埠被佔用：啟動時會看到 Address already in use。 用 python run.py --port 9000 換一個。
  • 網址打錯：一定是 http://127.0.0.1:8848/，不是 https。
  • 公司防毒／防火牆擋掉本機連線：把 python.exe 加進例外。

第一次開很慢（十幾秒）

正常。系統刻意不在啟動時做重運算，第一次分析是在第一個請求進來時才觸發： 擬合 80 個 k_eff 約 2.5 秒、bootstrap 約 2 秒、高斯過程映射約 0.6 秒。 算完之後會快取起來，之後切頁都是毫秒級。只要匯入、刪除或產生資料，快取就會失效並重算。

「模型驗證」頁特別慢

留一批交叉驗證要把每一批都留出來重訓練一次映射與殘差模型，20 批大約 7 秒。 這個結果也會被快取，同一份資料下第二次進來是即時的。

「最佳化建議」頁的貝氏最佳化與 DOE 特別慢

是的，各約 5 秒。它們要反覆重新擬合高斯過程（DOE 對比更是要模擬跑完整整兩套實驗策略）。 這兩區是獨立載入的，不會擋住頁面上半部的熱圖與三種建議。

匯入被擋下來

錯誤訊息會直接告訴你第幾列、為什麼。最常見的三個：

  • 「歸一化位置 X 超出 [0,1]」：幾乎一定是 x_mm 與 ingot_len_mm 單位不一致（例如一個用 mm、一個用 cm）。
  • 「批次 XXX 的製程參數在不同列不一致」：同一批次的每一列都必須帶相同的 L / l / v / T / pass。通常是試算表往下填的時候有一列漏改。
  • 「缺少必要欄位」：batch_id、element、value_ppm 是必填，位置則必須有 x_norm 或 x_mm + ingot_len_mm。

另外：CSV 用 Big5 存檔也可以，系統會自動偵測；Excel 的 .xlsx / .xls 直接支援；上傳大小上限 20 MB。

看到「外插警示」

這不是錯誤，是保護機制在運作。它表示你查的條件超出歷史批次涵蓋範圍。 此時：不確定區間會明顯變寬、AI 修正自動停用、「模擬與預測」頁的外插狀態磚會變黃。

該怎麼辦：如果只是探索，繼續看沒關係，但要注意悲觀值。 如果打算實際執行，正確的做法是先安排一批實驗驗證——這正是「下一批該跑什麼」那一區的用途。

AI 助理顯示「本地模板模式」

表示沒有設定 API 金鑰（或設定的供應商沒有對應金鑰），系統自動退回了。 介面照常運作、數字完全正確，只是措辭制式。要切換請看第 14.2 節。

如果你明明設定了金鑰卻還是顯示本地模板模式：

  • 確認 .env 在專案根目錄（跟 run.py 同一層），檔名就是 .env （Windows 的檔案總管有時會偷偷加上 .txt）。
  • 確認 EXPA_LLM_PROVIDER 與你填的金鑰是同一家。
  • 改完 .env 一定要重啟服務。
  • 連外失敗時也會退回：外部 LLM 連續 3 次失敗（含逾時、429、5xx）後自動降級， 回覆下方會出現紅色提示說明原因。這是設計好的行為。

某個數字顯示「—」

代表算不出來，不是 0。到對應畫面找警告框，通常會說明原因（批次數不足、 全部測點皆設限、bootstrap 無有效重抽等）。

想從乾淨狀態重來

「資料管理」→「清空所有資料」，或直接關掉服務、刪掉 data/expanalysis.db （以及 .db-wal、.db-shm）再重啟。日誌在 logs/expanalysis.log， 出問題時把它一起附上會省很多時間。

16. 這個工具不做什麼

把邊界講清楚，比多列十項功能更能建立信任。

1. 不控制設備。

它不連機台、不下指令、不讀即時訊號。它是離線分析工具——你把跑完的批次資料匯進來， 它給你分析與建議，最後在控制面板上按下去的是人。

2. 不做閉迴路。

沒有「模型看到偏差就自動修正製程參數」這種東西。所有建議都要人看過、判斷過、決定過。 這不是技術限制，是責任邊界：閉迴路控制的驗證要求、失效模式分析、安全聯鎖，是另一個等級的專案。

3. 不承諾預測準確率。

你不會在任何畫面上看到「本模型準確率 95%」。你會看到的是： 留一批交叉驗證的實際誤差（ppm）、每個預測的不確定區間、以及查詢是否落在訓練範圍內。 準確度是量出來給你看的，不是宣稱的。它會隨資料量與資料品質改變， 所以任何固定的準確率數字都是騙人的。

4. 不取代量測。

模型預測不能拿去當出貨檢驗報告。它預測的是「在這組條件下，雜質分布應該長什麼樣」， 用途是決定該怎麼設參數、該切在哪裡、該不該再跑一趟。 成品純度仍然必須實際送驗。模型幫你少做實驗，不是幫你少做檢驗。

5. 不會替你決定「什麼是最佳」。

純度、產能、風險三者互相衝突。工具給你三種取向的建議與各自的代價， 但哪一個是「最佳」取決於客戶當下的成本結構與訂單狀況——那是人的決定。

6. 不處理偏析法本來就處理不了的元素。

k_eff > 0.75 的元素，掃再多趟也不會分離。工具會誠實地告訴你這件事， 但它給不了解法——那要靠前段製程（化學精煉、電解、真空蒸餾）。 一個會說「這條路走不通」的工具，比一個永遠給你參數建議的工具有用。
