把雜質掃到同一端

區域熔煉不消滅雜質。它只是讓一條熔融帶從頭掃到尾， 一路把雜質推到錠子的尾巴，然後把尾巴切掉。 理解這一句，就理解了整個製程——以及為什麼這個專案的資料分析 應該從物理方程開始，而不是從機器學習開始。

先把冶金術語換成白話。後面所有內容都建立在這張表上。

錠 ingot

舟 boat
裝這條金屬的細長槽，像個窄長烤盤。
熔區 molten zone
只有一小段被加熱融化的區域，例如 3 cm 寬。這段是液體，其餘是固體。

熔融帶的寬度。真正的物理變數，溫度只是它的代理指標。

02

製程實際在做什麼

用一個滑動視窗的比喻，把物理講完。

想像一個 array 代表整根金屬棒。有一個 3 cm 寬的視窗，從 index 0 開始，以每小時 2 mm 的速度往右滑到底。視窗內是液態，視窗外是固態。

視窗每往右移一格，發生兩件事：

  • 右邊緣：一格新的固體被融化，進入液池
  • 左邊緣：一格液體重新結冰，離開液池

關鍵全在左邊緣。

為什麼會純化：結冰會挑食

金屬結冰時晶體排列很挑剔，不喜歡讓外來原子（Cu、Fe、Ni、Sn）擠進晶格。所以左邊緣結冰的瞬間，大部分雜質被「推」回液池裡，不跟著結冰。

結果是：剛結冰的那一格比原本乾淨，液池則越來越髒。而液池會持續往右移動——等於把雜質一路掃到最右端。掃完一趟，整根棒子變成頭端乾淨、尾端很髒，中間有個過渡帶。

核心觀念

偏析純化不是把雜質消滅，是把雜質集中到同一個地方，然後把那一段切掉。所以「得料率」和「純度」天生互相拉扯：切得越多越純，但賣得越少。

k：整個製程唯一重要的數字

「結冰有多挑食」需要一個數字量化，這就是分配係數 k：

k = 剛結冰的固體裡的雜質濃度 ──────────────────────── 旁邊液體裡的雜質濃度
k 值物理意義
k = 0.05結冰只帶走 5% 的雜質，95% 被推回液池 → 純化效果極好
k = 0.3中等，需要多跑幾次 pass 才有效果
k = 0.9幾乎不挑食 → 純化效果很差
k = 1這個雜質用偏析法根本除不掉。要回頭改前段製程
k > 1反過來偏好固體 → 這個元素會往頭端跑，而不是尾端
對專案的意涵

每個元素有自己的 k。Cu 可能 0.05、Fe 可能 0.3、Sn 可能 0.6——這正是客戶要分別測 Cu / Fe / Ni / Sn 的原因，它們的行為完全不同。你的模型如果只做一件事，就是把每個元素的 k 從資料裡挖出來。

03

Pfann 方程：單次 pass 的分布

一條曲線，一個未知數。

C(x) = C₀ · [ 1 − (1 − k) · exp( −k·x / l ) ]

C(x)：距頭端 x 處的雜質濃度　·　C₀：原料初始濃度　·　l：熔區長度（不是錠長）　·　x/l：已經掃過幾個熔區長度

曲線分三段：

  • 頭端：濃度從 k·C₀ 起跳。k 越小，起點越低、越乾淨
  • 中段：緩慢爬回 C₀
  • 尾端最後一個熔區長度：雜質全部塞在這裡，濃度暴衝。這段不適用上面的公式，要用正常凝固（Scheil）方程另外處理
對應客戶需求 2

客戶說的「判斷高純區與雜質濃縮區位置」，就是問這條曲線在哪裡穿過 6N 門檻。高純區＝左邊那段，雜質濃縮區＝右邊那段。

多次 pass：沒有公式，用迭代

第 2 次 pass 的輸入不再是均勻的 C₀，而是第 1 次的輸出曲線。所以沒有封閉解，只能一步步算。對軟體工程師來說，這只是個 for 迴圈。

# 離散模擬：質量守恆。cell 體積視為 1
def one_pass(C, k, m):          # m = 熔區佔幾個 cell
    N = len(C); out = np.empty(N)
    S = C[:m].sum()               # 熔區內的溶質總量
    for i in range(N - m):
        CL     = S / m            # 液池濃度
        Cs     = k * CL           # 左邊緣結冰，只帶走 k 倍
        out[i] = Cs
        S     -= Cs               # 固體帶走的
        S     += C[i + m]         # 右邊緣新融化進來的
    for j in range(m):           # 尾端：正常凝固，液池不再補料
        V = m - j
        Cs = k * S / V
        out[N - m + j] = Cs
        S -= Cs
    return out

C = np.full(N, C0)
for p in range(n_passes):
    C = one_pass(C, k_eff, m)

假設進料 C₀ = 10 ppm（約 4N5），6N 門檻取 1 ppm。虛線為門檻，藍色區段為達標區。

馬上能省錢的結論

把純化次數推到 12 以上，你會發現曲線不再變化。這叫極限分布（ultimate distribution）——雜質「往尾端被掃」和「從右邊被熔區吃回來」達成平衡，再 pass 也沒有增益。

實務上大約 8～12 次到頂。如果客戶現在跑 15 次，模型可以直接告訴他「第 10 次以後純度不動了，砍掉 5 次」。這是 P1 階段就能交出去的立即價值。

04

速率與溫度從哪裡進來

BPS 方程，以及這個製程唯一的核心 trade-off。

上面用的 k 是理想值，記作 k₀。實際跑起來會偏掉，原因只有一個：被推回去的雜質來不及擴散走。

左邊緣結冰把雜質吐回液體，這些雜質要靠擴散散進整個液池，但擴散很慢。如果結冰速度太快，雜質還沒散開就在介面前面堆成一坨——這坨叫邊界層。介面旁邊的液體變得特別髒，結冰時就算挑食，帶走的絕對量也變多。

等於 k 變大了、純化變差了。這個「實際感受到的 k」叫 k_eff：

k_eff = k₀ / [ k₀ + (1 − k₀)·exp( −v·δ / D ) ]

v：熔區移動速率（客戶的參數 2）　·　δ：邊界層厚度，攪拌越強越薄　·　D：雜質在液態銦中的擴散係數

條件結果
v → 0（超慢）k_eff → k₀，純化效果達到理論最佳
v 變大k_eff → 1，純化效果趨近於零
整個專案的中心問題

慢＝純，快＝產能。客戶需求 3 要的「最佳速率建議」，本質就是在這條曲線上找甜蜜點。

對數線性化：把曲線變成直線

BPS 方程長得很醜，但兩邊取對數整理一下：

ln( 1/k_eff − 1 ) = ln( 1/k₀ − 1 ) − (δ/D) · v └─── 截距 ───┘ └─ 斜率 ─┘

左邊是你從資料算得出來的，右邊對 v 是一次式。意思是：把 ln(1/k_eff − 1) 對 v 畫散點圖，應該是一條直線。用眼睛就能看出來對不對，用最簡單的線性回歸就能求斜率和截距。5～6 個不同速率的批次就夠了。

誠實度檢查

如果那些點根本不成直線，代表有別的機制在作怪——氧化、對流不穩、量測系統不準。這個發現本身就值錢，而且是 ML 給不了的診斷資訊。

溫度的角色

溫度主要透過兩條路徑影響結果：

  1. 溫度高 → 熔區變長（l 增加） → 容納雜質的能力變大，曲線形狀改變
  2. 溫度高 → 液池對流變強 → δ 變薄 → k_eff 變好

所以真正的物理變數是熔區長度 l，溫度只是它的代理指標。如果客戶目前沒有量 l，這是整個專案投報率最高的補量測項目——只要一支紅外線相機或簡單的熱電偶陣列。

05

從曲線到數字：擬合的實作

「統計」的部分其實只是曲線擬合。零統計背景也能做完。

什麼叫擬合 k

你有一批實測資料：

x/l  :   0.5    1.5    2.5    3.5    4.5
Cu ppm:  0.8    1.6    2.9    5.1   14.2

你有一個公式，裡面只有 k 一個未知數。「擬合」就是：試不同的 k，看哪個 k 讓公式算出來的曲線最貼近這 5 個點。

from scipy.optimize import curve_fit

def pfann(x_over_l, k):
    return C0 * (1 - (1-k)*np.exp(-k*x_over_l))

k_fit, cov = curve_fit(pfann, x_data, C_data, p0=[0.2])

就這樣。它內部做的事跟訓練模型一樣（最小化平方誤差），只是參數從幾百萬個變成 1 個。

為什麼「1 個參數」這麼關鍵

機器學習有個粗略規則：資料點數要遠多於參數數量，否則就是背答案而不是學規律。

方法有效參數量40 批資料夠嗎
XGBoost / 隨機森林數百～數千✗ 背答案
小型神經網路數千✗ 背答案
Pfann 擬合 k1✓ 綽綽有餘

而且樹模型學到的東西無法外插。你問它「速率降到 1 mm/hr 會怎樣」，如果訓練資料裡沒有這麼慢的批次，它只會回傳最接近的訓練值，講不出所以然。物理模型可以，因為那條曲線的形狀是物理決定的，不是資料決定的。

降維：一批實驗 → 4 個數字

原本一批實驗＝8 個測點 × 4 個元素＝32 個數字，亂七八糟。擬合之後，一批實驗＝4 個 k_eff 值（Cu、Fe、Ni、Sn 各一個）。

40 批 → 每個元素 40 個 k_eff。接下來只要研究「k_eff 怎麼隨 T 和 v 變化」，這是個 40 筆資料、2 個自變數的小問題，非常好處理。

設限資料：6N 專案一定會遇到的坑

6N 純度下，很多測值會是 < 0.05 ppm——儀器測不到。這不是一個數字，是一個不等式。

做法後果
當成 0頭端看起來完美，k 被系統性低估
當成 LOD 值 0.05頭端看起來偏髒，k 被系統性高估
正確做法告訴擬合程式：這點的真值落在 [0, 0.05] 區間內
用工程師的語言

就像 log 裡寫 response_time: TIMEOUT (>30s)。統計時把它當 30s，平均值就被低估；當成 0 更荒謬。你只知道「至少 30s」。

實作不難：scipy 沒有現成的，自己寫 likelihood 約 30 行，或直接用 lifelines（生存分析套件，數學完全一樣）。

信賴區間：Bootstrap，不需要統計理論

擬合出 k = 0.12，客戶一定會問「有多準？」最簡單的答法叫 bootstrap，純程式操作：

ks = []
for _ in range(1000):
    idx = np.random.choice(len(x), len(x), replace=True)  # 隨機重抽
    k, _ = curve_fit(pfann, x[idx], C[idx], p0=[0.2])
    ks.append(k[0])

lo, hi = np.percentile(ks, [2.5, 97.5])   # 95% 區間

意思是：把你的 8 個點隨機重抽 1000 次、各擬合一次，看 k 飄動的範圍。飄得少代表這個 k 可信；飄得很兇代表資料撐不住這個結論——而你要把這件事說出來。

06

AI 放在哪裡才不傷準確度

物理模型負責算數字，AI 負責補物理沒說到的、選下一步、跟人溝通。

「導入 AI」和「不影響準確性」看起來衝突，其實不衝突——衝突的只有「用 AI 取代物理模型」這一種做法。

L5
LLM 對話層風險 0

自然語言查詢、批次報告自動生成。關鍵設計：LLM 不做任何計算，只把 L0–L2 算出的數字組織成人話，並附上引用的批次 ID。這是客戶眼中最「看得見」的 AI，demo 效果最好、成本最低。

L4
貝氏最佳化：建議下一批跑什麼參數風險 0

回答「下一批該設什麼參數，才能學到最多」。在「模型看好的地方」與「模型沒去過的地方」之間權衡。全因子 DOE 要 36 批，貝氏最佳化通常 10～15 批找到相近最佳點。最終準確度來自真實實驗，不是模型猜的——最壞情況只是多跑幾批。

L3
異常偵測：哪批資料不對勁風險 0

比對物理預期曲線與實測，殘差過大就標紅。抓熱電偶飄移、取樣位置記錄錯誤、送錯樣品、表面氧化夾帶。它不參與任何預測，只會保護準確度（把爛資料擋在模型外）。

L2
高斯過程：k_eff = f(T, v) 的映射純升級

線性回歸是「先假設是直線，再找最好的直線」；高斯過程是「不假設形狀，只假設相近的 v 有相近的 k_eff，讓資料自己決定」。額外送你每一點的不確定範圍——沒資料的區域灰帶會變寬，模型會誠實承認自己不知道。樣本數 10～50 正是它的甜蜜點。

L1
殘差學習：物理沒解釋到的部分需嚴格護欄

最終預測 = 物理預測（主體） + ML 修正（小修）。學氧化皮、對流不穩、舟材污染這些物理照顧不到的系統性偏差。唯一真的可能傷準確度的一層，建議排在最後、標選配。

L0
物理模型（Pfann + BPS）

永遠是骨架，不可被取代。這是整套系統裡唯一能可靠外插的東西。

L1 的四道護欄，缺一不可

護欄做法
限幅修正量硬性限制在物理預測的 ±20% 內，超過就截斷。ML 永遠不能推翻物理
禁止外插查詢點若落在訓練資料範圍外，自動關閉 ML 修正，退回純物理並標示警告
必須證明有用用留一批交叉驗證，ML 版沒有明顯贏過純物理版，就不上線
雙軌顯示介面永遠同時顯示「純物理」與「物理+AI」兩個數字
07

把「不影響準確性」變成可驗收的條款

客戶的顧慮要翻譯成能量化、能驗收的文字。

雙軌顯示

介面上每個預測都出兩個數字，讓工程師隨時看得到 AI 動了多少手腳：

預測 6N 得料率
  純物理模型  : 62.3 %
  物理 + AI   : 64.1 %   (Δ +1.8)

  ⚠ 兩者差異 < 3 %，AI 修正在正常範圍

留一批交叉驗證（Leave-One-Batch-Out）

白話：假裝沒看過第 7 批，用其他所有批訓練，然後預測第 7 批、比對真值。每一批都輪一次。跑兩套，純物理 vs 物理+AI：

指標純物理物理 + AI
平均絕對誤差0.42 ppm0.31 ppm✓ 有幫助
最大誤差1.8 ppm1.5 ppm✓
外插情境誤差0.55 ppm0.53 ppm～ 護欄生效

這張表就是驗收文件。如果 AI 那一欄沒有比較好，就誠實地只交付純物理版——這反而會建立客戶對你的信任。

建議寫進合約的四條

  1. AI 模組之預測誤差不得高於純物理模型基準（以留一批交叉驗證衡量）
  2. 所有預測同時提供物理基準值與不確定區間
  3. 超出訓練資料範圍之查詢，系統自動退回純物理模式並標示警告
  4. AI 不參與任何設備控制決策
第 1 條的效果

這條把「AI 可能變差」的風險完全消滅——因為 AI 只有在被證明更好時才上線。這是你能給客戶最強的保證，而且你做得到。

別做原因
XGBoost / 隨機森林直接吃原始資料幾十批資料配上幾百個有效參數，就是背答案。而且無法外插——問它沒跑過的速率，只會回最接近的訓練值
神經網路預測濃度曲線同上，而且完全黑盒。工程師不會信，不會信就不會用
用 AI 取代物理模型丟掉了整套系統裡唯一能可靠外插的東西
深度學習做代理模型多次 pass 模擬跑一次不到 1 秒，沒有加速需求。純粹增加風險
AI 自動調整設備客戶自己也說不要。守住這條線，責任歸屬才清楚

10

開案前一定要問清楚

這幾題直接決定可行性與報價。建議印出來帶去開會。

  1. 歷史批次有幾批？少於 15 批的話，P1 要改成「設計實驗」而不是「分析既有資料」。
  2. 溫度量的是加熱器設定值還是實際熔體溫度？真正的物理變數是熔區長度 l。如果沒量 l，這是投報率最高的補量測項目。
  3. 分析方法是 GDMS 還是 ICP-MS？各元素 LOD 多少？6N 下量測雜訊可能大於製程效應。要先做量測系統分析（MSA）。
  4. 取樣位置各批一致嗎？頭尾切除量有記錄嗎？不一致的話 x/L 正規化會出錯，所有曲線無法對齊。
  5. 每批的進料初始純度 C₀ 有測嗎？沒有的話所有曲線失去比較基準，k 擬不出來。
  6. 6N 得料率的判定規則是什麼？總雜質 < 1 ppm，還是單一元素門檻？切點目前怎麼決定的？
  7. 氣氛條件：真空還是 Ar？表面氧化情況？In 容易氧化，氧化膜會夾帶雜質，這是模型外的干擾變數。
  8. 熔區有攪拌嗎（電磁 / 機械）？攪拌直接決定 δ，會顯著改變 k_eff 對速率的敏感度。
