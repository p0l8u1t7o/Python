## 1. 結論

- **ACC-05 通過。** 改數量（增刪設備）、單價、工時與缺價時，成本都依明示的公式更新；缺價單獨列出且不當成 0；同一料對同一設備只計一次，組件總價與子件成本不會同時計入。
- 總額以兩種獨立方式核對：
  - `tests/test_costing.py` 的小型人工核算案例：期望值在測試內逐步手算，與平台程式無共用程式碼。
  - SSD 範例由 TestCode 成本試算表轉入，平台算出的每一項總額與上下限都和該試算表一致（見第 3 節）。
- 匯出的 XLSX 以 Excel 重算：摘要 9 列公式、採購明細 27 列小計，與程式計算值 0 處不一致；在 Excel 改單價、改預備費率，總額會依公式連動。
- 範圍限制：成本資料目前由手寫或範例提供，工程代理產生成本草案留待後續（依使用者選擇）；SSD 單價是 TestCode 的內部預算，並非供應商報價。

## 4. 因果驗證（`tests/test_costing.py`）

| 情境 | 結果 |
|---|---|
| 人工核算案例（含 USD 匯率、有單價組件、待報價組件展開、服務、工時、管理費、預備費、稅、毛利率） | 每一項總額與手算一致 |
| 加一台相機／移除全部相機 | 相機與鏡頭數量 +1、設備成本增加正好一台的單價；移除後不留相機列，並提示設備對應沒有對到實例 |
| 改單價 | 設備成本變化 = 數量 × 單價差 |
| 缺價 | 列入缺價清單、`complete: false`、覆蓋率少一列；補價後成本增加正好 數量 × 單價 |
| 重複計價 | 固定列與設備對應對同一模組重複計入時報 `DUPLICATE` 並只計一次；有單價組件與其子件同時計入報 `ASSEMBLY_DOUBLE_COUNT` |
| 資料錯誤 | 缺匯率、單位不符列為缺價並報錯；報價過期為警告 |
| 計價 | 毛利率與加價率各依其公式；未設定計價只出預算；毛利率 ≥ 1 被拒 |
| 版本綁定 | v1、v2 各自的 `costing.json`、API 與匯出互不混用；沒有成本資料的案子 API 回 404、「全部」匯出不受影響 |

對 9 個關鍵規則注入缺陷（缺價當 0、不展開待報價組件、有單價組件的子件也計價、不偵測重複、忽略匯率、預備費基底漏掉管理費、毛利率誤用加價公式、設備對應只計一個實例、略過明細捨入），相關測試都轉紅。
