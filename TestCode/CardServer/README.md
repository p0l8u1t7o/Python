# 名片管理伺服器

手機在同網域內用瀏覽器開啟，拍攝名片照片後自動辨識帶入聯絡資訊，
確認/補填後連同客戶需求一併存進 SQLite 資料庫；之後可在網頁上查詢、
瀏覽歷史名片與需求紀錄，並能匯出成 CSV。

## 安裝

```bash
pip install -r requirements.txt
```

名片自動辨識另外需要安裝 **Tesseract-OCR** 執行檔本體（`pip install` 只裝得到
Python 綁定 `pytesseract`，裝不到辨識引擎）：

1. Windows 下載安裝：<https://github.com/UB-Mannheim/tesseract/wiki>
   安裝精靈裡記得勾選語言包 **Chinese (Traditional)**（`chi_tra`），
   否則只能辨識英數字。
2. 安裝完成後通常**不需要**額外設定：程式會依序找環境變數 `TESSERACT_CMD`、
   系統 PATH，以及 Windows 常見的安裝路徑（如
   `C:\Program Files\Tesseract-OCR\tesseract.exe`）。
   裝在非典型路徑時才需要用 `--tesseract-cmd` 指定。
3. 啟動時終端機會印出「名片辨識: 可用 / 停用」與實際使用的 Tesseract 路徑，
   自動辨識沒作用時先看這一行就知道是不是引擎沒找到。
4. 沒有安裝 Tesseract 也完全不影響其他功能——`/api/ocr` 會回傳
   `available: false`，前端自動改成讓使用者手動輸入欄位。

`requirements.txt` 內的 **OpenCV/NumPy** 用於名片自動裁切與影像校正（見
`cardimage.py`）。沒有安裝仍可執行，但會直接把整張照片丟給 OCR，辨識率明顯下降，
啟動時會印出提示。

## 啟動

```bash
python app.py --db D:/data/cards.db --uploads D:/data/uploads --port 8001
```

- `--db`：SQLite 資料庫檔案位置（也可用環境變數 `CARD_DB_PATH` 指定）。
  不指定時預設為本資料夾下的 `cards.db`，第一次啟動會自動建表。
- `--uploads`：名片照片存放資料夾（也可用環境變數 `CARD_UPLOAD_DIR` 指定）。
- `--host`：預設 `0.0.0.0`，讓同網域內的手機可以連進來；只想本機測試可改 `127.0.0.1`。
- `--port`：預設 `8001`（避開常被佔用的 8000）。
- `--tesseract-cmd`：見上方「安裝」章節。

啟動後終端機會印出資料庫與照片資料夾的實際路徑；手機瀏覽器開啟
`http://<這台電腦的區網 IP>:8001/` 即可使用（IP 可用 `ipconfig` 查詢）。

## 頁面功能

深藍色系的商務主題，單頁下拉式版面（不需要左右切換頁籤，往下捲動就能看到所有功能）：

- **拍照建檔**：點擊照片框叫出手機相機（`capture="environment"` 預設用後鏡頭）。
  拍完立刻送到伺服器做名片文字辨識，成功辨識到的欄位（姓名/公司/職稱/電話/
  Email/地址）會自動帶入表單並用淡藍底標示；辨識不到、辨識引擎未安裝，或
  辨識錯誤，欄位就維持空白／原值，直接手動輸入或修正即可——辨識只是
  預先幫忙填，最終仍以使用者確認過的內容為準。填完備註與客戶需求後送出，
  成功後會顯示這筆的建立時間，整張表單（含照片預覽、辨識狀態）會清空，
  方便馬上拍下一張。區塊右上角的徽章顯示**目前已儲存幾筆**資料。
- **瀏覽 / 查詢**：預設只列出**最新的 20 筆**，需要更多再按「載入更多」往下取，
  資料累積到上千筆時也不會一次塞滿畫面造成延遲；清單下方會顯示「顯示 N / M 筆」。
  列表縮圖走 `/thumbs/` 端點（長邊 320px、首次存取後快取），單張從數 MB 降到數十 KB，
  這是清單捲動順不順的關鍵。
  每筆都標示建立時間；關鍵字可比對姓名、公司、電話、Email、備註與需求內容，
  搜尋時右上角另外顯示**符合條件的筆數**。
  點一張名片可在彈窗中看到照片與建立時間，並直接編輯/補上各欄位後按「儲存修改」，
  也能在下方追加新的需求紀錄。
  清單上方「匯出 CSV」會依目前的搜尋條件匯出結果（不輸入關鍵字就是匯出全部）。

### 名片詳情頁的操作

- **影像縮放**：滑鼠滾輪、雙指手勢或右下角的 `−／＋／1:1` 都能縮放（1x～6x），
  放大後可拖曳平移，連點兩下可在原始大小與 2.5 倍之間切換。
- **旋轉 90 度**：`↺／↻` 兩個按鈕。旋轉是**直接把伺服器上的照片轉正後覆寫**，
  並把累計角度存進 `cards.rotation`，所以重新整理、列表縮圖、匯出與「重新辨識」
  看到的都是轉正後的方向，不是只在畫面上轉一下。
  旋轉後縮圖會自動重建，圖片網址帶版本號 `?v=<角度>` 以避開瀏覽器快取。
  註：每次旋轉都會重新編碼 JPEG，因此存檔品質提高到 95，反覆旋轉也不易看出畫質變化。
- **重新辨識**：對已存檔的照片重跑一次辨識。結果只會填進表單並標成淡藍色，
  **不會直接寫回資料庫**——先前人工修正過的內容不會被蓋掉，確認後再按「儲存修改」才生效。
- **刪除名片**：確認後刪除該筆名片、其需求紀錄，以及照片原檔與快取縮圖。

### 拍攝輔助線

拍照欄位裡有一個名片比例（91:55）的虛線取景框，提示名片該擺多大。
另外提供「開啟相機（含對準輔助線）」：以網頁內建相機顯示即時影像，並在畫面上疊出
名片外框、四角標記與中心十字線，方便對齊後再按快門。

> 內建相機使用瀏覽器的 `getUserMedia`，只有在**安全來源**（HTTPS 或 localhost）才能取用鏡頭。
> 用區網 `http://192.168.x.x:8001/` 連進來時瀏覽器會擋掉，此時按鈕不會出現（或按了會提示），
> 請改用原生的拍照欄位——功能完全相同，只是相機畫面上沒有輔助線。
> 若需要在手機上使用輔助線，請替伺服器加上 HTTPS。

### 建立時間

每筆名片與每筆需求紀錄在寫入時都會存下建立時間，格式為帶時區位移的 ISO 字串
（例如 `2026-08-17T22:27:13+08:00`），前端再轉成瀏覽器所在時區顯示，匯出的 CSV
也含「建立時間」欄位。

## 資料結構

- `cards`：一張名片一筆，含聯絡資訊、照片檔名與建立時間 `created_at`。
- `requirements`：需求紀錄，透過 `card_id` 對應到 `cards`，一張名片可有多筆需求
  （例如每次接觸都補記一筆），刪除名片會連動刪除底下需求（`ON DELETE CASCADE`）。

## 名片辨識流程與準確度

手機拍名片時，名片往往只占畫面的 1/5 左右，還會歪斜、帶著桌面或鍵盤等背景。
直接把整張原圖丟給 Tesseract，字太小又混著背景雜訊，結果經常是**完全空白**。
因此辨識分成兩個模組：

1. `cardimage.py`：用 HSV 的「亮且低飽和」特徵找出白色名片區塊（木桌偏橘＝高飽和、
   鍵盤偏暗＝低亮度，都會被濾掉），以名片長寬比 (91:55) 評分挑出最像名片的矩形，
   再做四點透視變換拉正、轉成橫式、用 Tesseract OSD 修正上下顛倒，最後放大到
   足夠 OCR 讀取中文的解析度。偵測不到名片（例如上傳的本來就是裁好的掃描檔）
   就直接用整張圖，流程照常進行。
2. `ocr.py`：對數種前處理版本（原灰階／CLAHE 局部對比／去光暈）搭配數種版面分析
   模式各辨識一次，另外把「整張未裁切的照片放大」也辨識一次，然後把各次的欄位
   解析結果**投票合併**——裁切版在公司/電話/地址較準，整張放大版常能補回中文姓名
   與職稱，取兩者之長比賭單一次辨識穩定得多。

欄位分類仍是靠關鍵字/格式規則（電話、Email 格式、公司/職稱常見字眼、地址關鍵字），
並會排除統一編號、發票代號這類長得像電話的數字，傳真號碼也只在沒有其他號碼時才採用。

整體仍屬於 **best-effort 猜測**，不保證正確——名片版面越特殊、字體越花俏、拍照
角度越差，辨識與分類就越容易出錯或抓不到。這也是為什麼所有欄位在辨識後仍然
是可編輯的一般輸入框：辨識只是幫忙省打字，使用者送出前務必核對一遍。

### 效能

多回合辨識是**並行**執行的（`_run_passes` 用執行緒池，每個回合是一個 tesseract 子行程，
等待期間會釋放 GIL），而且送進 OCR 前會把影像統一縮放到 1800px 寬——手機動輒 4000px 的
原圖直接辨識會慢上數倍卻不會更準。兩者合計讓單張名片從約 11 秒降到約 2 秒。

### 目前的準確度

以 `uploads/` 內 15 張實拍名片加上 `Image/` 的 2 張遠景樣本（共 17 張）對照人工修正過的
`cards.db` 評分（完全正確 1 分、部分正確 0.5 分）：

| 欄位 | 準確度 |
|------|--------|
| Email | 100% |
| 電話 | 97% |
| 職稱 | 74% |
| 公司 | 71% |
| 地址 | 62% |
| 姓名 | 41% |
| **整體** | **74%** |

姓名最難，原因有三：名片上的姓名常用藝術字或加大字距；常和公司名、地址排在同一
水平線上被版面分析併成一行；不少名片的中文姓名根本印在 logo 字體裡（例如
蔚華科技那兩張），Tesseract 讀出來是純亂碼。這類情況目前會退而填入英文姓名。

辨識不準時可在詳情頁按「重新辨識」重跑，或直接手動修正——欄位一律可編輯。

## 安全性備註

- 上傳的圖片會用 Pillow 實際解碼驗證是圖片格式（非只看副檔名），並統一轉存為 JPEG、
  移除原始 EXIF（含 GPS 等隱私資訊），檔名以亂數產生，避免路徑穿越與偽裝檔案風險。
- 單檔上傳大小上限 15MB。
- 這是設計給內部區網使用的工具，**未做登入驗證**；若網域內有不信任的裝置，
  請自行加上驗證機制或限制在受信任的 VLAN / VPN 內使用。
- 內建的 Flask 開發伺服器僅適合小規模區網使用；正式或長期使用建議改用
  `waitress`（Windows 相容）等 WSGI 伺服器部署。
