# 字形無關的印刷品質檢測

只用良品建立基準，不比對字形，因此**內容、字數、字型都可以變**。
量測的是印刷的物理特性（筆畫連續性、寬度一致性、邊緣銳利度、墨色深度），
不是「這個字該長什麼樣」。

## 安裝

```bash
pip install opencv-python numpy scikit-image scipy
```

## 使用

```bash
# 1) 用一批良品建立基準（建議 >= 200 個字元樣本）
python print_qc.py fit ./good_samples/ -o baseline.json

# 2) 檢測，輸出標註影像
python print_qc.py check ./test.png -b baseline.json -o result.png

# 3) 調機用：只印出原始指標數值，不做判定
python print_qc.py dump ./test.png
```

`check` 的 exit code：0 = PASS，1 = FAIL，可直接串進產線流程。

## 量測項目

| 指標 | 抓什麼 | 層級 |
|---|---|---|
| `stroke_ratio` | 筆畫粗細（已除以字高） | 字元 + 整行 |
| `stroke_width_cv` | 筆畫寬度不均 → 糊字、暈染 | 字元 |
| `gap_count` / `gap_severity` | 骨架斷點配對 → 斷筆、缺墨 | 字元 |
| `component_excess` | 字元裂成多塊 | 字元 |
| `speckle_count` / `speckle_area` | 孤立墨點 → 噴濺、污漬 | 字元 |
| `edge_sharpness` | 邊界梯度 → 離焦、暈染、重影 | 字元 + 整行 |
| `ink_depth` | 墨色深度（灰階級數）→ 淡墨、色帶耗盡 | 字元 + 整行 |
| `ink_coverage` | 外接框內覆蓋率 | 字元 |
| `snr` | 訊雜比（參考用） | — |

判定方式：連續型指標用 robust z-score（median + MAD）；稀疏型指標
（gap / speckle / component）良品幾乎恆為 0，MAD 也是 0，改用「良品觀測上限」。

## 驗證結果（合成資料，60 張良品建基準 / 120 張獨立測試）

| 缺陷類型 | 偵測率 |
|---|---|
| 暈染 / 離焦 | 100% |
| 淡墨 / 色帶耗盡 | 100% |
| 噴濺點 / 污漬 | 98.6% |
| 斷筆 / 缺墨 | 93% |
| 墨量整體偏粗 | 41%（整行）/ 12%（單字元） |

誤報率：字元層級 0.15%，整張 0.83%。

**這些數字只證明演算法邏輯正確。** 真實產線的誤報率會高一個檔次，
主因是光源與取像變異而非演算法。上線前務必用自己的良品重新 `fit`，
並準備一批標註過的真實瑕疵驗證門檻。

## 調參順序

1. **`noise_close`（預設 3）— 最關鍵。** 它同時定義了「系統能偵測的最小缺陷尺寸」。
   設太大會把真的斷筆補起來，設太小良品會一直誤報。
   先用 `dump` 看良品的 `gap_count` / `speckle_count` 是否都是 0，是了再往下調。
2. `min_ink_delta` / `ink_sigma` — 墨水閘。背景雜訊大就調高。
3. `z_thresh`（預設 4.0）— 整體鬆緊。先固定 4.0 跑一輪，看誤報再動。
4. `gap_angle_tol`（預設 40°）— 圓弧字多（S/3/C/G）就調小，斷筆抓不到就調大。
5. `merge_overlap` / `merge_vsep` — 切字規則。字距很緊或有分離偏旁時才需要動。

## 已知限制

- **筆畫粗細本質上是字型相依的。** 混多種字型建基準會讓 MAD 變寬，
  單字元判定抓不到緩慢的墨量漂移。建議按字型分別建基準，
  或用整行漂移檢查 + SPC 管制圖追蹤趨勢。
- **斷在骨架交叉點旁邊時抓不到 gap** —— 缺口會被 junction 吸收。
  不過這種情況通常會讓字元裂成兩塊，由 `component_excess` 接住。
- **點陣噴碼（CIJ）不適用。** 點的位置與大小本來就隨機抖動，
  `stroke_width_cv` 和 `gap_count` 會大量誤報。該用點數統計與形態學規則。
- **抓不到內容錯誤。** 「該印 8 卻印成 3」外觀完全正常，必須靠 OCR 比對訂單資料。
- 解析度要求：最小缺陷至少橫跨 3 個像素，否則演算法再好也沒用。
